* 模块与依赖方向

仓库根目录是 Cargo workspace，成员为 ~core~ 、 ~harmony~ 与 ~http~ 。唯一允许的跨 crate 依赖方向是 ~harmony -> core~ 和 ~http -> core~ ；Core 不反向依赖宿主，Harmony 与 HTTP 适配层之间不互相依赖。

| 目录或入口 | 职责 |
|-
| ~org_tasks_core::merge~ | 单文件原文三方合并的同步纯函数；私有解析入口供仓库同步复用，不读网络、目录或历史。 |
| ~core::workspace~ | ~OrgWorkspace~ 的定义与统一组合入口，负责查询订阅的注册、一次启动查询和取消。 |
| ~core::http_server~ | APP 进程内的查询与批量修改 REST 适配；由 Workspace 提供启停，启动策略属于 APP，不新增独立宿主。 |
| ~core::query_subscription~ | 独立的查询成员维护与事件过滤模块，只保留 ID、文件版本与数值摘要；不引用 Workspace，model 与 editor 不引用它。 |
| ~core::model~ | 本地 ~OrgRepo~ 目录扫描、Org 文件解析、保真编辑、任务查询与同步记录数据维护。 |
| ~core::shared_file_manager~ | 单次查询的文件内容读取服务，process 独占缓存并合并同路径在途读取，查询完成释放。 |
| ~core::webdav~ | 实现 ~SyncPolicy~ ，执行 WebDAV 文件传输、下载写回、条件写入与同步记录生成。 |
| ~core/src/bin/org-tasks/~ | 操作本地 ~OrgRepo~ 的命令行入口，使用 Tokio 运行时。 |
| ~harmony/~ | Harmony 宿主的 Rust bridge，处理请求转换、跨语言参数编组、异步边界、结果投影与资源释放。 |
| ~http/src/bin/~ | ~org-tasks-httpd~ Web App 宿主，提供页面与访问控制，调用 Core 操作本地仓库。 |
| ~entry/~ | ArkUI 页面、系统日历、凭据、宿主配置、后台调度与 C++ N-API 接入。 |

~SyncPolicy~ 是接入其他同步方式的扩展点。新增仓库、查询或同步能力时，先在 Core 定义领域规则与可复用数据结构，再由宿主接入。Bridge 不得重写 ~OrgRepo~ 、 ~SyncPolicy~ 、WebDAV 或 Org 解析算法；HTTP 不实现这些领域能力，也不另外生成同步记录。

* Org 文件模型与保真边界

~OrgFile~ 是单个完整 Org 文件的根模型，使用 ~orgize~ 提供无损运行时语法树。解析、编辑、序列化与展示的语义以 Emacs 自带 ~org-element.el~ 为准，不另建不兼容的项目解析 AST。

未修改的文件直接写回读取时的原始字节。局部编辑只修改目标范围，不得改写未涉及的字节区间。宿主通过 Core 的文件对象与接口取得内容和语义，不在 ArkTS、C++ 或 HTTP 中再解析 Org。

领域模型与持久化字段见 [[file:core/数据模型.org][数据模型]]；实体关系的 TikZ UML 源码内嵌维护于该文档。调整领域模型或同步记录持久化时，必须同步更新对应说明和源码块。

* 异步运行时与调用边界

~core::model~ 的仓库加载、同步控制器以及 ~core::webdav~ 的文件与 HTTP I/O 均运行于 Tokio。CLI 使用 Tokio 驱动 Core；HTTP 和 Harmony 只提供操作入口，不另建仓库加载或同步算法。

~OrgWorkspace.start(repos).await~ 与 ~stop().await~ 定义 Core 内部服务生命周期，运行时由宿主创建和持有。Harmony 在应用启动时创建唯一的 Workspace，会话在 Core 之外持有一个持续运行的多线程 ~tokio::Runtime~ ，配置变化更新同一 Workspace 的仓库集合与设置；全部仓库请求与内嵌 HTTP 服务复用它，N-API 请求返回后仍继续驱动任务。最后一个宿主引用释放后，在工作线程等待 Workspace 停止与回调收尾，再释放运行时；等待时不持有会话表锁。CLI 复用进程运行时，在 Workspace 操作完成后显式停止。

Workspace 是可克隆的命令句柄，不暴露可变字段或 ~&mut self~ 接口，也不使用 ~Arc<Mutex<OrgWorkspace>>~ 。 ~start~ 只在当前宿主 Tokio 上启动命令处理、文件状态与通知处理三个异步 task，不创建或拥有 runtime。命令处理循环独占仓库配置、操作历史和调度状态；业务 task 使用本次独立上下文，完成后由处理循环归并状态、发布快照并交回答复。配置和历史的同步读取返回已发布的独立快照，不借出内部可变引用。

所有业务查询、修改与同步通过 Workspace channel 调度。连续查询可异步并发；修改必须等待前面的全部查询完成，同一文件按受理顺序执行，不同文件可并发准备。跨文件操作组同时登记全部文件依赖，等待中的较早操作保留其依赖，但不阻塞无关文件。后续查询不能越过已排队修改。同步、仓库加载、重置和配置更新作为独占屏障，等前面的查询和修改结束后执行；同步期间收到的新查询等待整轮同步及通知收尾。等待调用被取消不取消已受理命令。底层跨进程仓库锁继续保护磁盘快照、恢复和提交，不承担 Workspace 命令调度。

任务操作的请求内部由主任务检查仓库锁并遍历操作，按需建立本请求的文件到 task 映射：文件任务启动即加载文件、生成 FileMetadata 并按需制作完整文件副本，主任务可立即向其 channel 发送修改，不在主调度器预读或等待 Metadata。普通操作按文件 FIFO 发送，跨文件 Movement、Trash、Restore 由主任务拆解并推进依赖。各文件独占内存语法树和变更日志，仅通过 channel 传递独立数据；执行期间不存盘、不向 UI 通知。全部操作和依赖完成后由文件 task 交出纯字节 Save 候选，复用原有统一提交、外部版本校验与回退；提交确认通过 channel 返回，最终 Metadata 与任务投影仍在文件 task 中生成，主任务收齐后统一通知。Restore 插入失败保留来源，其他错误放弃本次未提交修改。Restore 原仓库需由来源上下文确定，当前采用独占调度以保护动态文件依赖；公开修改入口及请求级返回值保持不变。详见 [[file:core/任务修改调度设计.org][内部消息与执行过程]]。

每个 Workspace 只处理自己发起的通知。修改、同步与重置业务显式传递其 ~NotificationCenter~ ，不使用全局监控表或广播。NotificationCenter 持有请求 sender 与内部顺序计数器，订阅、取消和事件由 channel 交给 process；监控器和 ID 只在 process 内管理。Workspace 在业务收尾后通过 oneshot 停止 process，并等待队列排空。普通查询将已读取文件状态交给文件服务，可因此触发通知；不主动查询通知，也不保留 Workspace reload 接口。

ArkUI 线程不得执行 Core 请求。C++ N-API bridge 必须通过 ~napi_create_async_work~ 在工作线程调用 Rust；ArkTS 通过 ~NativeCoreService~ 打开并持有 native ~Workspace~ 、 ~Repo~ 与 ~WebDavSyncPolicy~ 对象。涉及仓库锁、文件或网络的操作返回 Promise，资源生命周期与释放规则遵循 [[file:harmony/Rust bridge设计.org][Rust bridge 设计]]。

TS 领域接口按 ~Workspace -> Repo -> OrgFile~ 访问对象。Rust 字段映射为属性，方法与行为归属原领域对象；结构化参数直接使用 TS 对象，JSON 编组只发生在 bridge 内部。新增或修改接口时，同时更新 Rust 实现、C++ N-API 注册、类型声明、ArkTS wrapper、全部调用方及设计对照表。

* 查询职责

UI 负责组装请求、维护分类多选等交互状态、展示任务及汇总计数。UI 不得对 Core 返回的任务列表再次按完成状态、分类、文件、日期或父子关系筛选。今天、等待、随时、某天和备忘的标签筛选条是明确的展示层例外：仅在已加载的本页任务快照上按 Core 提供的有效标签控制可见记录，不重发查询、不改变页面基础范围、侧边栏计数或同步数据。该例外不扩展到完成状态、日期、分类或其他查询条件。

Core 不持有收件箱页面或控件专属语义。页面需求统一转换为 ~TaskQuery~ 的 ~expression~ 、 ~categories~ 、 ~include_files~ 与 ~exclude_files~ ，由 Core 批量求值；系统仅提供接收 ~CoreQuery~ 数组并返回对应 ~CoreQueryResult~ 数组的异步查询接口，其中 Task、File 共用加载，通知独立订阅，TaskQuery 的状态范围统一使用表达式，每批每仓库只加锁与加载一次，所有宿主复用相同规则。参数与表达式的完整契约见 [[file:core/查询语言设计.org][查询语言设计]]。

* 仓库身份、同步元数据与备份

同步目录、稳定 Core 仓库身份、历史、版本基准、outbox、冲突备份和解决后通知统一见 [[file:core/同步核心设计.org][同步核心设计]]。其他模块遵循该文档的现行规则，不另建目录、历史或冲突规则。 ~.sync/~ 全部内容不参与普通 Org 扫描或远端传输；绝对路径、完整远端 URL 和配置凭据不进入同步记录。

同步执行状态与展示日志分开：Core 新同步只枚举历史占用时间，不加载旧内容；完成日志按 summary、单文件 JSON 和独立原文事务落盘。summary 首行是时间，按行读取名值对。历史展示使用字段 Optional 的容错结构及诊断，基线与恢复材料保持严格校验；旧整体 JSON 按需只读兼容，详见 [[file:core/同步日志存储与兼容设计.org][同步日志实现]]。

Harmony 配置 ID 与 Core 仓库 ID 当前是不同身份，必须按 [[file:harmony/配置项设计.org][配置项设计]] 使用，不能混用。修改目录或 WebDAV 地址不得随意重建已有身份或改变凭据分区；WebDAV 密码只由 ~CredentialService~ 写入 Asset Store，不放入 Preferences、日志或同步记录。

* Harmony 工程与平台接入

手机界面使用 ArkTS 与 ArkUI，领域核心使用 Rust，C++ 负责 N-API 接入。构建工具为 hvigorw 与 Makefile，IDE 为 DevEco Studio；实际 SDK 与目标版本以构建配置和本地环境为准。

| entry 内的目录或文件 | 职责 |
|-
| ~oh-package.json5~ | Harmony 模块依赖。 |
| ~src/main/cpp/napi_init.cpp~ | N-API 对象注册、参数与结果编组，链接 Rust 静态库。 |
| ~src/main/cpp/types/liborg_tasks_harmony/index.d.ts~ | Native 接口类型声明。 |
| ~src/main/module.json5~ | 模块清单、权限与后台任务注册。 |
| ~src/main/resources/~ | 字符串、颜色、媒体与页面路由；图标资源放在 ~base/media/~ 。 |
| ~src/main/ets/models/~ | ArkTS 宿主配置与数据投影。 |
| ~src/main/ets/services/~ | ~NativeCoreService~ 调用封装、 ~AppConfigService~ 配置、 ~CredentialService~ 凭据与 ~CalendarSync~ 系统日历接入。 |
| ~src/main/ets/entryability/~ | ~EntryAbility~ 应用入口及快速捕捉、分享和桌面卡片扩展。 |
| ~src/main/ets/pages/~ 与 ~src/main/ets/components/~ | 页面与共用控件，只消费 Core 结果，不实现领域规则。 |
| ~src/main/ets/components/controls/~ | 与业务无关的基础控件：图标按钮、空态、消息条、分区标题、设置行和弹出菜单；只接收展示参数与事件回调，不依赖任务、Org、仓库或同步服务。 |
| ~src/main/ets/components/editors/~ | 可复用的任务与备忘编辑器，以及日期、标签、重复、优先级、清单、移动目标、文件入口、目录选择和任务日志控件。 ~TaskEditor~ 可嵌入列表项或项目文档，编辑快照与提交通过既有宿主服务接入 Core。 |

文件同步由 Harmony 的 service 编排，经 C++ N-API 与 ~harmony~ bridge 调用 Core 的仓库和策略对象；系统日历事件由全局 ~ReminderManager~ 管理， ~CalendarSync~ 专门执行首次核对与后续事件增删改。日历、凭据、调度和 SDK 生命周期属于平台能力，不进入 Core 领域模型。

定时同步已移除，不注册或启动 WorkScheduler 作业。应用启动时清理旧版持久化的同步作业，已删除其扩展注册；同步间隔不再属于宿主配置。桌面卡片定时刷新只读取本地快照，不是同步策略。

主界面首次加载成功且进入前台后，通过 ~RepositorySyncService.start~ 受理一次 ~startup~ 入口的检查与同步请求，纯本地配置只接入已有 Workspace、不再次查询；WebDAV 同步仅返回完成状态，工作文件变化由外部文件事件刷新共享数据集，结束后不查询完整任务，使用 ~SyncStartPolicy.Reuse~ ；恢复前台、重复窗口回调与路由切换不重复触发。启动入口不等待同步完成、不申请后台任务、不发布同步通知。

上层将远端 Policy 和目录过滤绑定到 Core 的稳定仓库 ID，凭据仍由宿主安全存储提供，仅由 Policy 在运行时持有。启动自动同步调用 Workspace 的无参 ~check_remote_changes()~ ，取得各已绑定仓库的 ~Unchanged~ 、 ~Changed~ 、 ~Unknown~ 或独立错误；只读检查不获取仓库文件锁、不等待同步屏障、不写历史或扫描本地修改。上层选择有变化或未知的仓库 ID 列表调用 ~sync_repos~ ，检查失败的仓库单独反馈，其他仓库继续处理。Core 不因检查自动同步，实际同步开始时间由 Core 生成；手动与退后台入口直接提交指定仓库列表。

主界面 ~EntryAbility.onBackground~ 通过 ~BackgroundRepositorySyncService~ 触发单次文件同步。宿主先等待页面已提交的修改与缓存处理完成，再通过 NotificationManager 订阅接收当前绑定的共享快照。仅当快照包含 ~syncRequired~ 且配置启用 WebDAV 时才新建同步。没有通知时不读取同步配置，不另建 Workspace 或额外查询；比较文件与远端基线的规则仍由 Core 实现。短时任务保护排队修改、通知归并与配置读取，数据传输长时任务保护实际同步。 ~RepositorySyncService.start~ 同步返回受理结果与会话句柄，以 ~completion~ 异步返回完成结果。启动使用 ~Reuse~ 返回当前句柄，退后台使用 ~Reject~ 拒绝新建但可继续保护已有会话，手动使用 ~Wait~ 按受理顺序逐轮执行。会话先保留再异步启动，队列轮到时重新读取配置和文件；前一轮失败不阻止后续请求。队列、句柄与进度仅在 Harmony 进程内保存，不进入 Core 或 Preferences；页面切换不取消同步，返回前台不打断当前会话。

~BackgroundSyncPresentation~ 使用后台任务返回的通知 ID 更新系统代理创建的实况窗，保留系统类型码与通知槽，胶囊和展开内容复用共享进度。连续事件只保留最新快照，每秒最多更新一次，最终状态写入完成后再释放长时任务，避免迟到更新重建提示；无变化、失败和短时任务到期路径均清理宿主资源。退后台触发不写入日历同步状态、不新增配置、不在后台请求授权；同步失败后仍以共享通知中的 ~syncRequired~ 决定下次是否重试。

修改 ~calendarManager~ 接入前对照当前 SDK 签名。文件路径按设备实际可访问的同步目录处理；DevEco Studio 提供 SDK、hvigorw、hdc 与 ohpm。真机需开启开发者模式和 USB 调试，并通过 ~make devices~ 确认连接。设备命令默认选择唯一连接真机，按设备属性排除模拟器；多台真机时通过 ~HDC_TARGET~ 指定目标。 ~make deploy~ 在构建前检查并固定真机目标，依次编译、安装和启动；没有真机、指定目标未连接或指定模拟器时立即报错，不回退到其他设备。模拟器验收通过其他设备命令显式设置 ~HDC_TARGET~ 。Release 包需要华为开发者账号签名，根目录 Makefile 的 ~BUNDLE_NAME~ 必须与实际包名一致。

* 设计与交付同步

页面布局、侧边栏入口位置或交互范围变化，必须同时更新 ArkUI 实现、 [[file:harmony/设计文件索引.org][设计文件索引]] 中对应功能的当前 Harmony 画板、 [[file:harmony/UI导航设计.org][UI 导航设计]] 与 [[file:手机应用功能设计.org][手机应用功能设计]]。配置项、保存位置或凭据处理变化，同步更新 [[file:harmony/配置项设计.org][配置项设计]]。

手机应用功能设计只记录手机用户可见的功能范围、当前契约与尚未实现的设计扩展；Core、CLI、HTTP 与测试程序的能力不记录在其中。HTTP 宿主的命令行、监听、认证、数据目录和并发约束单独遵循 [[file:http/服务命令行设计.org][服务命令行设计]]。

* 冲突预览边界

[[file:core/冲突预览与合并设计.org][冲突预览与合并设计]] 使用 workspace 唯一、仓库外的临时文件，保留地址域为 ~repoId="<preview>"~ ，file 为本次创建 UUID。临时编辑复用 Core 操作组且记录成功操作，finish 仅返回按原顺序映射为真实路径的操作组，应用再通过统一数据接口提交。副本不加入扫描、查询或同步；宿主不复制文件、不解析 Org 或执行合并规则。

* 页面统一读取

普通读取通过 CoreQuery 批次取得任务和文件元信息，按输入位置消费对应结果；已迁移任务页由各个 DataSet 维护自己的固定查询订阅，文件入口有效性和标签候选随对应元信息更新。NotificationManager 独立维护应用共享通知生命周期，列表订阅回调通过该管理类发布。普通任务页、收件箱最近新增、笔记本文件列表、侧边栏、导航计数和角标由应用级 ~AppDataManager~ 持有同一 ~DataSetManager~ ，相同查询复用 DataSet，全部命名查询共用启动批次；完整契约见 [[file:core/统一批量查询接口设计.org][统一批量查询接口设计]]。

* 页面数据管理与缓存边界

收件箱、今天、计划、等待、随时、某天、备忘、日志簿、废纸篓、最近新增、笔记本文件列表、侧边栏、导航计数和角标通过 ~AppDataManager~ 共享一个 ~DataSetManager~ 、命名数据集集合与 ~app.json~ 缓存。项目详情保留独立管理器和无缓存的完整文档加载，通过可选父 Manager 按名称继承共享分类候选；本地仅查询当前文件，生命周期和刷新仅管理自己的 DataSet。管理器同步取得全局 Workspace，仅根据本地配置定义查询，先恢复只读缓存，再由管理器后台接入配置并一次提交全部查询订阅；不在缓存恢复前等待 Workspace 或单独查询仓库列表。每个 Manager 持有一个外部文件监控与跨日定时器，按各查询的仓库和文件范围合并刷新。每个 ~DataSet~ 只持有一个查询，负责自己的查询定义、私有 callback、任务索引、编辑和快照比较后的变化事件；订阅 ID 由 Manager 按数据集名管理和清理；页面分别订阅需要的数据集，编辑器直接按 ID 读写目标 DataSet。原始 Core 事件不进入界面。普通任务页缓存统一放在 ~filesDir/page-data/v1/app.json~ ，全部共享命名数据集保存于一个 JSON 文件，不进入仓库或 Preferences。队列全部提交且事件已归并后，才写整个页面的确认快照；缓存恢复版本为 0，首次查询为 1，后续阶段通过 ~operationId~ 关联。接口和生命周期见 [[file:harmony/页面数据集设计.org][页面数据集设计]]。

~AppDataManager~ 位于 ~entry/src/main/ets/services/AppDataManager.ets~ ，由 EntryAbility 在初始化 Workspace 和系统仓库后启动，后台保留订阅，销毁时关闭；独立入口需要角标时可懒创建并复用同一实例。普通任务页和笔记本直接消费共享 DataSet；分类候选统一由全局 categories DataSet 运行时维护，复用今天排序原有文件范围，项目属性编辑与转换项目不另行扫描。SidebarDataManager 只把这些 DataSet 投影成计数、文件入口与项目列表，不查询、不持有独立缓存；DeviceBadgeService 只订阅共享收件箱、截止任务和通知快照并写系统角标，不查询或注册 Core 监控。页面离开或抽屉关闭只移除展示订阅，不能关闭全局 Manager。计划筛选和废纸篓过期成员的数据集随 App 管理器构造创建并加入首次查询批次。清除计划筛选时，页面直接读取基础范围。导航返回直接读取共享收件箱计数。完整生命周期见 [[file:harmony/页面数据集设计.org::*应用级共享数据入口][应用级共享数据入口]] 。

全部普通任务页面引用应用级共享 DataSetManager，查询定义集中于 AppDataManager，由管理器处理配置和缓存，由 Manager 合并底层订阅调用并管理各 ID，每个 DataSet 自己处理按 ID 访问、编辑及事件；非任务结果由 SnapshotDataManager 及 NotebookDataManager、FileDataManager、SyncLogDataManager、SyncLogDetailDataManager 发布快照。项目详情禁用 DataManager 缓存，首次查询附带的完整文件直接返回页面，管理器与 DataSet 均不持有；后续由任务控件直接向稳定行来源注册 Monitor，局部更新标题与正文；容器只订阅成员、顺序及可见层级变化。外部失效时管理器可一次性交付恢复用完整文件，仍不保存完整文件到 DataSet 或缓存。AppShell 只组合界面，不监听 Core、不广播数据版本、不回调刷新正文；完整职责见 [[file:harmony/页面数据集设计.org::*全部页面退出外壳刷新机制][页面统一数据管理]]。

* 应用共享通知管理

~NotificationManager~ 为应用级快照与增量订阅管理器，由 EntryAbility 启停。启动注册订阅，配置变化重绑，恢复前台只重试异常订阅。范围只包含启用 WebDAV 且远端地址非空的仓库。文件状态 process 负责受保护基线、版本比较与冲突事实，通知 process 只维护贡献集合；首次发送缓存快照，随后推送增删改，不扫描文件。未读取文件没有相关提示。页面使用 AppStorage 快照，角标和后台同步订阅同一共享快照。完整边界见 [[file:core/通知订阅设计.org][通知订阅设计]]。

页面通过 AppStorage 的 ~coreNotifications~ 共享只读快照，不持有管理对象。通知及仓库展示上下文按内容比较，结果相同不发布；过期请求不能覆盖新结果，失败保留最近成功快照。任务仍由页面 DataSetManager 处理增量确认，通知刷新不驱动今天页任务重查。详细生命周期见 [[file:harmony/页面数据集设计.org][页面数据集设计]]。

* APP 临时 HTTP 接口

APP 的测试启动参数可以临时启用 Core 的 HTTP 适配，与界面共享活动 Workspace。普通点击图标不启动服务，也不保存开关；Core 不读取宿主启动参数。Core 提供查询、批量修改和通用宿主路径注册；Harmony 在同一测试监听注册导航 GET／PUT，通过 N-API 通道调用 PageNavigator。Core 不依赖 ArkTS，不保存页面语义；宿主处理器在 UI 线程执行，等待 HTTP 响应时只保留 Workspace 命令句柄。生命周期和 REST 定义见 [[file:core/APP内嵌HTTP接口.org][APP 内嵌 HTTP 接口]]。

* 外部文件变化与通知刷新

普通操作组提交后的事件为 ~DataChangeEvent::NotificationEvent~ ，携带任务／文件增量和当前仓库通知列表。同步与 reset 的文件增删改通过独立 ~ExternalFileChanged~ 广播。Core 先按各类通知条件更新通知缓存并广播列表变化，UI 通知模块只消费列表，不监听文件变化。数据管理层按查询范围合并刷新，Core 查询订阅只标记相关订阅失效，不隐式查询。完整契约见 [[file:core/外部文件变化监控设计.org][外部文件变化监控设计]] 。

* 任务提醒平台接入

Core 使用与创建时间相同的属性解析投影 ~reminder_at~ ，并以 ~SetReminder~ 封装底层属性名、时间戳序列化与保真写入。表达式支持 ~reminder~ / ~r~ 的自然日条件和完整时间排序。Harmony 的全局 ~ReminderManager~ 由 ~AppDataManager~ 注册唯一 ~reminderTasks~ DataSet，与页面共享同一个数据管理器和首次查询批次；提醒模块集中管理本机开关、授权、系统登记检查与状态订阅，首次确认后由 ~CalendarSync~ 核对应用专用日历，之后按增删改维护事件。设置列表直接使用同一数据集；管理器另以独立订阅发布内存操作日志，记录系统提醒增删改结果及启动同步、任务修改等触发原因，最近 500 条不落盘。事件身份和内容指纹存于系统日历的 identifier，本机只保存开关与默认 5 分钟的事件持续时长；事件采用 Core 已解析的 SCHEDULED／DEADLINE，按唯一提醒时间计算分钟偏移，最高优先级仅标记日历标题。无响铃秒数、间隔或手动同步按钮，设备状态不进入 Core 同步记录。详见 [[file:harmony/任务提醒设计.org][任务提醒设计]]。

* 任务记录的直接分发

DataSet 将 Core 增量与乐观修改合并为稳定行快照，通过 ~TaskDataSource~ 按 rowId 直接分发给 TaskEditor 的 Monitor。编辑器不再接收整批数据事件后查找自己；文件版本变化只推进来源快照，可见内容变化才通知界面。三字段连续编辑、失败回滚、改名身份和订阅生命周期见 [[file:harmony/页面数据集设计.org::*稳定行的 TaskDataSource 与 Monitor][TaskDataSource 与 Monitor]]。
