# 文档目录规范

- `docs/` 下的设计与说明文档使用 Org 格式；本文件仅用于提供目录级代理指令。
- Org 行内代码使用 `~...~`。标记前后必须保留空格或使用 Org 可识别的 ASCII 边界；不得与中文文字、中文标点直接相邻。
- 正确：`同步结果为 ~Succeeded~ 。`、`读取 ~.sync/id~ 文件。`
- 错误：`同步结果为~Succeeded~。`、`读取~.sync/id~文件。`
- 修改或新增带有 `~...~` 的 Org 文档后，必须以 Org AST 或 HTML/LaTeX 导出确认其被解析为行内代码，而不是原样文本。

- 仅保留持续维护的设计、接口、模型与设计资源索引；不新增验收报告、性能诊断、调研流水、实施记录或逐条测试用例清单。
- 新方案需在对应设计中明确标记尚未实现的范围；方案确认或实现变化后原位更新，删除被替代的规则，不在文末叠加相互矛盾的历史说明。
