#+TITLE: 批量查询接口设计
#+STARTUP: show2levels hidestars
#+OPTIONS: author:nil date:nil toc:nil
#+LANGUAGE: zh-CN

* 唯一查询入口

系统通过异步 ~OrgWorkspace.query(&[CoreQuery]) -> Result<Vec<CoreQueryResult>, CoreError>~ 批量读取任务、文件元信息和通知。请求字段、枚举、Harmony 编组及页面批次定义统一见 [[file:统一批量查询接口设计.org][统一批量查询接口设计]]。 ~TaskQuery~ 与 ~TaskQueryResult~ 的字段保持原定义，放入 CoreQuery 的 Task 分支；不保留独立任务、文件元信息或通知读取入口。

* 批量契约

成功时结果与输入等长，按下标一一对应，结果种类与请求种类相同。无命中和重复请求保留位置，各项排序只作用于自身任务结果。任一参数校验、加锁、恢复、读取、解析、求值或结果编组失败，整批返回错误，Promise 拒绝，不返回部分成功。空批次不取得业务锁、不读盘。

* 共享文件加载

每批固定仓库配置和本地自然日，按规范化根目录排序、去重，使用共同的 10 秒截止时间取得各仓库锁。每仓库只进行一次身份校验、恢复和 Org 文件加载；全部文件和通知所需基线索引读取完毕后释放锁，在独立快照上生成结果。Harmony 一次 worker 调用整个批次，查询不额外执行仓库身份初始化。

只有整批所有查询都不需要的文件才在读取正文前跳过。Task 的排除条件不能隐藏 File 或 Notification 需要的文件；加载后各项按自身范围求值。文件路径始终由 Core 仓库 ID 与安全相对路径共同确定，不跨仓库误排同名文件。标签配置、文件版本、项目名和任务编辑投影都来自同次加载，结果编组不回查正式文件。

通知复用已加载字节计算本地 hash，并在同次仓库锁内比较远端基线索引，覆盖修改、新增与删除。不重新扫描 Org 文件、不二次读取其正文，不读取完整同步历史或基线正文。每个查询结果独立拥有其展示数据，仓库不把这批文件保留为下一批的权威缓存。
