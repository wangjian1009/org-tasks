* 范围与统一入口

本文定义已实施的唯一通用批量查询入口，任务与文件元信息共用同次仓库访问，通知独立订阅。公开签名和错误约束见 [[file:接口文档.org][Core 接口文档]]。 ~CoreQuery~ 、 ~CoreQueryResult~ 与 ~FileQuery~ 使任务和文件元信息可以在同一个查询数组中表达；文件元信息与任务另增加 ~project()~ 访问方法。

~TaskQuery~ 通过 ~include_files~ 与 ~exclude_files~ 表达文件范围，替代旧 ~excluded_files~ 和表达式的文件条件；状态与排序继续使用表达式。 ~TaskQueryResult~ 增加可选请求所需的完整文件结果，仓库范围由外层 CoreQuery 承载。

* 统一入口与结果

#+begin_src rust
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "camelCase", deny_unknown_fields)]
pub enum CoreQuery {
    Task {
        query: TaskQuery,
        #[serde(default, rename = "repoIds")]
        repo_ids: Vec<OrgRepoId>,
    },
    File {
        query: FileQuery,
    },
}

pub enum CoreQueryResult {
    Task(TaskQueryResult),
    File(Vec<OrgFileMetadata>),
}

impl OrgWorkspace {
    pub async fn query(
        &self,
        queries: &[CoreQuery],
    ) -> Result<Vec<CoreQueryResult>, CoreError>;
}
#+end_src

成功时结果数组与输入等长， ~results[i]~ 与 ~queries[i]~ 的位置和枚举种类严格对应。空结果与重复请求保留原位置；任一请求校验、共享加载、求值或编组失败，整批返回 ~Err~ ，Harmony 拒绝整个 Promise。空数组返回空数组，不加业务锁、不读盘。

~CoreQuery::Task.repo_ids~ 是外层仓库范围，不属于 ~TaskQuery~ 。空列表或省略表示整个 workspace，非空表示所列 Core 仓库的并集；空 ID 或不属于 workspace 的 ID 返回输入错误。它用于在同一批中查询不同仓库的同名文件，避免改变 ~TaskQuery~ 或让 UI 再过滤任务。宿主配置 ID 必须先通过已初始化 workspace 的仓库对象映射成 Core 仓库 ID，不得混用。

* Task 查询附带完整文件

Harmony 与 JSON 对应 ~fullFiles~ ，查询种类仍为 ~task~ 。完整文件与节点复用同批加载和已解析语法树，不另调 ~file_at~ ，同批重复文件不重新解析。文件克隆共享不可变语法树，修改时重建自己的语法树，原始字节仍独立持有。

~full_files~ 必须属于本项外层仓库范围和包含／排除后的文件范围，越界、未知仓库或非法路径使整批失败。返回文件不受表达式与分类命中影响：零节点、零命中与零字节文件仍可返回；不存在的文件不返回。重复引用去重并保留首次请求顺序。完整原文保留冲突内容，节点和文档分段继续排除受保护冲突子树。

~TaskQuery.include_ignored: bool~ 默认 false；设置为 true 时同时保留被任务扫描规则隐藏的标题与完整文件，便于直接打开已有项目。默认行为与普通任务查询一致，不因 ~full_files~ 隐式绕过忽略规则。

订阅启动可以附带完整文件，但仅初始结果包含该值；后续按既有任务条件发送增量，不保存或刷新文件 AST。宿主取得文件后负责提取需要的展示数据，文件不是查询成员缓存。

* FileQuery 定义

#+begin_src rust
#[derive(Clone, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default, deny_unknown_fields)]
pub struct FileQuery {
    pub include_files: Vec<OrgFileRef>,
    pub exclude_files: Vec<OrgFileRef>,
    pub file_tags: Vec<String>,
    pub is_project: Option<bool>,
    pub include_ignored: bool,
}
#+end_src

| 字段 | 默认值 | 语义 |
|-
| ~include_files~ | 空数组 | 非空时只查询所列具体文件，多项取并集；空数组不限制文件范围。每项精确匹配 Core 仓库 ID 与安全相对路径，不支持裸路径或通配符。 |
| ~exclude_files~ | 空数组 | 非空时排除所列具体文件；空数组不排除。与 ~include_files~ 同时非空时，从包含集合扣除排除集合。 |
| ~file_tags~ | 空数组 | 任务标签条件，空数组不限制；匹配任务的有效标签，不解释为文件中声明的候选标签。多个标签取并集，文件中存在至少一条具有任一标签的任务即返回该文件元信息。 |
| ~is_project~ | ~None~ | 三态条件：不筛选项目属性、只保留项目文件范围、只保留非项目文件范围，依次对应 ~None~ 、 ~Some(true)~ 、 ~Some(false)~ 。项目依据文件级 ~project~ 标签判断，与标题是否有子任务无关。 |
| ~include_ignored~ | ~false~ | 是否包含被任务扫描规则隐藏的文件。为真时保留这些文件，且元信息的 ~is_ignore~ 为真；为假时不返回。 |

TaskQuery 与 FileQuery 均先取非空 ~include_files~ 指定集合（空数组表示全部），再扣除 ~exclude_files~ ，允许两者同时配置；两者均省略或为空时不限制文件范围。重复文件引用按集合处理。空仓库 ID、未知仓库 ID 和非法路径均是输入错误。

~is_project~ 在 Rust 中使用 ~Option<bool>~ ，省略或 JSON ~null~ 表示不限制， ~true~ 与 ~false~ 分别表示只保留项目或非项目；不能用默认 ~false~ 代替未指定。该字段只属于 FileQuery，不修改 TaskQuery 的既有组合任务开关。

FileQuery 返回 ~CoreQueryResult::File(Vec<OrgFileMetadata>)~ ，只返回符合条件的文件元信息，不把任务或通知塞入 TaskQueryResult。任务标签条件用于判断哪些文件包含匹配任务，具体任务列表继续由独立 Task 查询取得。

文件元信息继续复用现有轻量类型，包含来源、标题、标签候选、互斥组、冲突标记、任务数、大小和修改时间。不按 ~#+TAGS~ 的候选声明判断任务是否命中标签。未设置任务条件时，空文件仍有元信息；不存在的文件不返回，也不创建空文件。

* 文件与任务的项目访问

仓库中的现有类型名为 ~OrgFileMetadata~ ，对应本次讨论中的 FileMetaData；不因新增方法而重命名该类型。

#+begin_src rust
impl OrgFileMetadata {
    pub fn project(&self) -> Option<&str>;
}

impl FilterTask {
    pub fn project(&self) -> Option<&str> {
        self.file_metadata.project()
    }
}
#+end_src

| 所属文件状态 | ~project()~ 返回值 |
|-
| 文件级标签不含 ~project~ | ~None~ 。即使存在 ~PROJECT_NAME~ 也不视为项目。 |
| 文件级标签含 ~project~ ，文件级 ~PROJECT_NAME~ 存在 | 使用该属性值作为项目名称。 |
| 文件级标签含 ~project~ ，文件级关键字 ~PROJECT_NAME~ 不存在 | 使用文件默认属性 ~PROJECT_NAME~ ，仍缺失时使用文件的 ~title~ 。 |

项目标记来自所属文件的标签；不是某条标题的自身标签，也不是“有子标题”的组合任务规则。文件中的所有任务共享该文件的项目名称，任务方法只委托已有文件元信息快照，不读盘、不解析 Org、不另外保存一份项目计算逻辑。重新查询取得新项目状态，旧快照保留取得时的名称。

~FileQuery.is_project~ 依据文件级 ~project~ 标签判断，不能根据任务标题层级判断，也不能依赖项目名称是否为空来判断。 名称优先取文件头 ~#+PROJECT_NAME:~ ，也可回退到顶部属性 drawer 或 ~#+PROPERTY: PROJECT_NAME~ 提供的文件默认属性；名称与 title 均缺失或名称为空时返回空字符串保留项目身份，由界面显示“未命名项目”。不使用路径或文件名作为名称回退。

Harmony 的文件元信息与 Task 同时暴露 ~project(): string | null~ 方法。Rust 计算项目名称，C++ 仅包装该快照值为方法，ArkTS 不重新判断标签或属性。 项目访问方法不增加查询请求字段；文件范围继续使用 ~TaskQuery.include_files~ 与 ~exclude_files~ ， ~TaskQueryResult~ 增加可选请求所需的完整文件结果。

* 通知边界

通知仅通过 ~watch_notifications(repo_ids, callback)~ 订阅，callback 接收完整 ~Vec<CoreNotification>~ 。首次订阅在缓存就绪后默认回调一次，包括空列表；以后仅列表变化时回调。冷缓存由独立任务加载，通知处理 task 维护缓存并比较差异，宿主不主动查询。类型基线、checksum 与迟到结果规则统一见 [[file:通知订阅设计.org][通知订阅设计]]。

* Harmony 定义与请求示例

#+begin_src ts
interface FileQuery {
  includeFiles?: OrgFileRef[]
  excludeFiles?: OrgFileRef[]
  fileTags?: string[]
  isProject?: boolean | null
  includeIgnored?: boolean
}

// 现有文件元信息与 Task 类型新增以下方法。
interface OrgFileMetadata {
  project(): string | null
}
class Task {
  project(): string | null
}

type CoreQuery =
  | { type: 'task'; query: TaskQuery; repoIds?: string[] }
  | { type: 'file'; query: FileQuery }

type CoreQueryResult =
  | { type: 'task'; result: TaskQueryResult }
  | { type: 'file'; result: OrgFileMetadata[] }

class Workspace {
  query(queries: CoreQuery[]): Promise<CoreQueryResult[]>
}
#+end_src

JSON 请求使用与 TS 相同的 ~type~ 、 ~query~ 和可选 ~repoIds~ ；响应由 bridge 投影成 ~type~ 与 ~result~ ，其中任务结果继续包装为原生 Task。以下为某天文件与文件元信息的同批请求：

#+begin_src json
[
  {
    "type": "task",
    "repoIds": ["core-repo-id"],
    "query": {
      "expression": "it.todo",
      "includeFiles": [{ "repoId": "core-repo-id", "path": "someday.org" }]
    }
  },
  {
    "type": "file",
    "query": {
      "includeFiles": [{ "repoId": "core-repo-id", "path": "someday.org" }]
    }
  }
]
#+end_src

示例依次返回任务及分类摘要、文件元信息数组。元信息和任务必须属于同批快照，宿主不从另一次读取补齐标签配置，也不按文件条件重新过滤任务。

* 一次加锁与加载

整批预先校验全部请求并收集数据需求。每个涉及的仓库仅取得一次业务锁、执行一次恢复检查和一次 Org 文件加载；Harmony 在一次 worker 请求中提交整个批次，由 Core process 调度。任务和文件元信息均复用这次读取。

任务文件范围与 FileQuery 一样在扫描阶段参与候选集合计算，有限包含集合的祖先目录之外不再遍历。只有所有查询种类都不需要的文件，才允许在底层正文读取前排除。例如所有 TaskQuery 都排除某文件，但 FileQuery 需要其元信息，该文件仍加载一次；TaskQuery 的排除在其自身求值前执行。

* Harmony 页面读取

普通任务页、最近新增、笔记本文件列表、侧边栏、导航计数和角标通过应用级 ~AppDataManager~ 共享同一个 ~DataSetManager~ 与命名查询集合。全部基础查询共用启动批次；侧边栏仅投影共享快照，不单独查询。项目详情保留独立的、限定当前文件的管理器。各页查询范围和生命周期统一见 [[file:../harmony/页面数据集设计.org][页面数据集设计]]。

未配置的文件入口不组装无范围任务查询，其他有效数据集继续加载。任务和元信息由固定查询订阅维护；通知由应用级 ~NotificationManager~ 独立消费列表订阅。标签筛选仅处理已加载快照，不新增查询。

* 快照访问与业务读取

公开查询使用带 ~type~ 的 ~CoreQuery~ 数组，通知通过列表订阅取得。 ~FilterTask.file_metadata()~ 是已取得快照的同步借用，不读取文件；完整文件读取、编辑与同步操作保持各自资源接口。

~PageQueryService.query~ 用于业务服务的任务与文件混合读取，不附带通知查询，也不从结果发布通知。普通任务页面使用共享数据集订阅；抽屉开合不驱动或延迟正文读取。

默认 File 元信息读取不构造任务投影；只有 Task 请求或 File 的 ~file_tags~ 条件需要时才生成本批共享任务投影。任务标签按文件索引一次，多个 File 条件复用索引，避免逐文件反复扫描全部任务。

* 数据集订阅的批量启动

页面数据集通过 ~subscribe_query~ 的订阅项数组共享一次初始批量查询；每项仍有独立 query、callback、结果和订阅句柄。Harmony 的 DataSetManager 合并调用并管理 ID，各 DataSet 按原路径消费结果和变化事件，普通查询数组协议不变。具体接口见 [[file:查询订阅设计.org][查询订阅设计]]。
