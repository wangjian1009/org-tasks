#+TITLE: 任务日志验证机制设计
#+LANGUAGE: zh-CN
#+OPTIONS: author:nil date:nil toc:nil

* 状态与目标

本文为设计方案。基于 2026-11-11 对本机 =~/workspace/org-roam/tasks= 的只读盘点，定义如何用实际文件验证任务日志。现有状态行为参考数据、统一任务操作与保真约束继续复用。已从实际配置结构整理 10 个匿名化数据用例并补入现有回归；实际目录的独立策略比较与双副本自动回放尚未实现，手机入口未新增。

目标是确认一次状态操作是否按有效 Org 配置产生恰好应有的记录，并保持旧日志与无关内容。语义依据 [[info:org#Closing items][关闭记录]]、 [[info:org#Tracking TODO state changes][状态变化日志]]、 [[info:org#Repeated tasks][重复任务]] 和 [[info:org#Property Inheritance][属性继承]]；现行契约见 [[file:数据模型.org::*状态变化、重复调度与日志][数据模型]]。

* 实际文件提供的覆盖

盘点期间发现 ~work-o.org~ 发生内容变化，因此早期读取不视为同一份冻结输入。随后重新复制并核对源文件前后及副本三份哈希清单一致，取得本节使用的稳定快照；此检查只验证取样一致性，不代表日志行为对照已经执行。源目录始终只作读取。

最后一次复制前后哈希一致的冻结快照包含 17 个 Org 文件：1 个共享设置文件、12 个普通文件与 4 个年度归档，共 1,001,651 字节。纯文本扫描取得 2,684 个标题行、2,091 个 LOGBOOK 起始行、4,143 个状态日志行、2,817 个 CLOCK 行与 76 个 LAST_REPEAT 属性行。这些是规模统计，不代表对应文本全部已被语法树识别或语义已验证。

共享设置文件的日志相关内容为：

#+begin_src org
,#+TODO: TODO(t) NEXT(n) INPROGRESS(p) WAIT(w) | DONE(d!)
,#+TODO: | CNCL(c!)
,#+STARTUP: show2levels hidestars indent logdone logdrawer logrepeat hideblocks
#+end_src

因此普通任务进入 DONE 或 CNCL 同时涉及状态日志与关闭时间；未完成状态之间切换没有进入或离开日志标记。重复任务完成还涉及恢复状态、日期推进与 LAST_REPEAT。多个文件覆盖显示层 STARTUP 选项，应验证它们不会清除共享设置中无关的日志选项。

| 文件或结构 | 验证价值 |
|-
| ~work.org~ 、 ~work-o.org~ 、 ~inbox.org~ | 普通任务完成、取消、重新打开及已有日志保留。 |
| ~home.org~ 、 ~personal.org~ | 长重复历史、不同重复器、重复窗口、连续多次完成。 |
| ~ledger.org~ | 同一文件同时存在普通日志与父标题 ~LOGGING: nil~ 禁用区域，并混有 CLOCK。 |
| ~archive/*.org~ | 长历史、说明续行、CLOCK 与状态日志混排；主要验证读写保真。 |
| ~ann.org~ | 未引用共享任务设置，适合验证无日志配置的行为。 |
| ~slack.org~ 、 ~someday.org~ | 无任务或少量任务时的覆盖统计，不强行构造真实样本。 |
| ~note.org~ | 引用 ~../.setup.org~ ，依赖是否允许由所选仓库根目录决定。 |
| ~personal.org~ 文件头 | 有包含关键字文本的普通 PROPERTIES drawer；配置是否有效必须按真实语法与 Org 行为判断，不能仅逐行搜索。 |

实际配置没有 ~@~ 、 ~/!~ 或 ~/@~ 标记，也没有自定义日志 drawer 或正序日志设置。因此实际数据回放之外仍保留人工构造的边界样例；不能把未出现的场景宣称为已覆盖。

* 验证依据

** 静态盘点

静态检查只回答文件与配置是否可解释。它记录文件哈希、设置依赖闭包、有效 TODO 流程、进入与离开日志动作、完成日志、重复日志、日志位置与顺序，并标明每项配置来自主文件、设置文件或哪一级属性。

Core 给出自己的解析结果，Emacs 独立收集设置与属性；比较二者的有效策略。不能将 Core 已计算的期望动作交给另一段 Core 代码作为唯一判据。文件内声明覆盖设置文件中的 TODO 流程，STARTUP 选项分别生效，非空 LOGGING 重置相关日志策略，属性追加与继承沿用现行 Core 规则。

历史中存在 WAIT 日志、相同分钟的多条相同记录以及已有 CLOSED 的条目。当前共享配置不能证明它们产生时的配置和操作，因此只报告结构或格式疑点，不自动删除、不按当前配置判定旧日志错误，也不根据日志文本相同进行去重。

** 状态操作回放

一次验证从同一冻结快照派生两个工作副本。Core 副本调用 ~OrgWorkspace.execute_task_operations~ ，Emacs 副本通过 ~org-todo~ 执行同一目标状态。每一步都独立取得实际结果，再比较新增记录及原文变化。

参考端固定空的外部日志默认值，并屏蔽用户钩子、状态标签触发器与交互式说明输入；文件及允许范围内的设置文件照常生效。说明需求采用当前应用的空说明确认约定。记录 Emacs 与 Org 版本、Core 版本、时区及语言环境，防止把本机个人设置当成文件规则。

* 快照、依赖与目标身份

源目录只用于读取。首先记录相对路径、字节哈希与元信息，再复制完整文件及允许的设置依赖；复制前后校验源字节哈希，变化时重新取样，不能将不同时间点的文件拼成一次结果。Core 的控制目录、历史与 outbox 仅在工作副本中生成，不复制或绑定源仓库的同步状态，不连接远端。

仓库根目录必须成为验证上下文的一部分。以 tasks 为根时，归档文件的 ~../.setup.org~ 仍指向根内的共享设置， ~note.org~ 的同名相对引用则越出根目录；不得因 Emacs 能访问父目录就静默扩大 Core 的仓库范围。边界外依赖单独报告，不与根内完整配置样例混为通过结果。若需要验证以 org-roam 为根的使用方式，应建立另一份明确的上下文快照。

目标按原始相对文件、完整标题路径、出现序号、源区间与文件版本联合定位。不得只按标题文字或 Org ID 选择，因为当前任务身份包含路径，且重复日期可能位于标题内。每次操作重新读取 Core 返回的路径与版本；主文件的标题改名或日期变化后继续使用新快照，拒绝猜测过期身份。

每个独立场景从原始快照开始；需要连续操作的场景则在各自副本上逐步重放。普通回归优先选择含有效状态的叶任务；父标题的子任务限制作为本应用的显式场景验证，不让 Emacs 的默认依赖规则替代应用约束。

* 场景与预期

下表中的数量指本次新增记录。已有日志和 CLOCK 均必须保留。

| 场景 | 本目录共享配置下的预期 |
|-
| 普通 TODO 进入 DONE | 新增 1 条 DONE 状态日志；启用 logdone 时写 CLOSED；记录进入已有 LOGBOOK 或新建一个。 |
| 普通 TODO 进入 CNCL | 新增 1 条 CNCL 状态日志并写 CLOSED，不能将 CNCL 当成未完成状态。 |
| TODO、NEXT、INPROGRESS、WAIT 之间切换 | 当前关键词没有日志标记，不新增状态日志。 |
| DONE 重新打开为 TODO | 清理自身 CLOSED，不删除原状态日志；当前配置不新增离开日志。 |
| DONE 再次显式设置为 DONE | 按 DONE 的 ~!~ 配置再新增 1 条记录，保留已有关闭时间，不能按普通幂等操作漏记。 |
| DONE 切换为 CNCL | 按目标标记新增 1 条记录，已有关闭时间沿用现行契约。 |
| 清除任务状态 | 不新增状态日志，清理自身 CLOSED，保留旧日志及正文。 |
| 重复任务完成或取消 | 日志记录请求的完成状态；真实状态按流程恢复；日期推进，更新 LAST_REPEAT，不留下 CLOSED。 |
| LOGGING 为 nil 的条目或后代 | 不新增关闭或状态日志；重复日期仍按规则推进。已有 CLOCK 导致的 LAST_REPEAT 更新按 Org 的专门规则单独核对。 |
| 无日志配置 | 状态改变但没有新日志或 CLOSED；重复调度继续有效。 |
| 只配置 logdrawer 或 LOG_INTO_DRAWER | 仅改变已有启用日志的位置，不独立触发记录。 |
| 有有效状态子任务的父任务 | Core 拒绝状态变化，完整文件、回退历史与 outbox 保持原状；记录为应用约束通过。 |

合成边界样例覆盖： ~!~ 与 ~@~ 的进入记录、 ~/!~ 与 ~/@~ 的离开记录、目标进入记录优先、LOGGING 覆盖及追加、文件与祖先属性、正文及自定义 drawer、日志顺序、重复窗口、失效文件版本与事务回滚。配置变化的样例只修改副本，并记录变更后的配置和字节哈希。

* 时间与差异判定

确定性语义对照复用现有 Core 内部固定时间入口和 Emacs 参考生成方式，统一到指定本地分钟。固定时间属于验证环境，不修改系统时钟，也不新增面向宿主的时间参数。

仓库操作验证继续调用真实写入入口。若无法注入固定时间，则记录操作前后时间范围，要求每条新增时间戳位于该范围，并核对同一次状态操作的时间一致；跨分钟时允许实际经过的分钟。只为语义比较规范化新增时间戳，旧日志中的日期、空白及续行不能被整体替换。

结果同时经过两类比较：

1. 语义比较：最终状态、完成类别、请求状态、日志来源和目标状态、记录数量、说明、时间、drawer、顺序、CLOSED、LAST_REPEAT 及重复日期。规划字段可有不同排版，但字段值必须一致。
2. 字节比较：目标外的文件、无关标题、原日志项与续行、CLOCK、源码、未涉及属性及换行风格保持不变。新增日志造成原偏移移动时，以原节点映射和差异片段核对，不能只比较位置相同的字节，也不能直接给整个目标子树免检。

新增状态日志应产生恰好一条，进入与离开要求同时存在时仍遵循目标优先。关闭时间与状态日志是两种独立记录，不能把同时存在 CLOSED 与一条 State 日志误报为重复。

* 结果与覆盖要求

每个结果包含场景、配置来源、稳定的本地样本标识、输入版本、实际变化、参考变化、保真检查与结论。配置不完整、语法不支持、无可选目标、超时和预期受限操作分别报告，不能统一算作通过。历史疑点与新操作产生的确定性错误分开统计。

本机报告可以定位相对文件与行号；仓库内只维护经过匿名化的最小回归样例，不复制实际任务标题、正文与历史日志。长期回归固定代表性样例，大规模实际目录验证在本机按快照重跑，报告只能证明对应输入版本。

最小覆盖要求为：普通完成与取消、重新打开、未完成状态切换、重复任务、继承禁用和无配置各有可执行样例；缺少的配置类型由合成样例补足。每个场景必须同时通过行为对照与字节保真检查，且源快照在验证前后哈希一致。

按文件及场景设置独立时间预算，分别记录加载、选样、Core 操作和参考计算耗时。优先验证普通文件中的少量代表性任务，再扩大到长历史和年度归档；超时保留覆盖缺口，不无限重试或把归档静默排除。

* 已落地的数据用例

10 个匿名化用例覆盖共享设置下的普通完成与取消、完成后重新计时的重复窗口、继承禁用日志、CLOCK 保留、全完成子任务下的父任务拒绝、无配置、仅配置日志位置、重复设置同一完成状态及重新打开。输入与预期均保留旧日志、说明续行和无关条目，包含 CRLF 样例。具体定义见 [[file:任务操作测试用例.org::*日志配置与实际数据回归][日志配置与实际数据回归]]。

这部分验证固定代表性数据的状态变化及保真，不宣称已经对原始目录执行全量行为对照，也不替代界面手动验收。

* 实施顺序

先建立只读配置盘点与独立策略比较，再对实际文件的隔离副本重放最小场景，最后接入长历史保真、配置变体与事务失败检查。现有 ~task_state_emacs.json~ 、 ~task_state_oracle.el~ 和公开操作组回归提供语义基础；新增能力复用 Core，宿主与验证编排不重新实现领域日志规则。

本方案不增加手机页面、生产环境的双执行或自动修复旧日志。首轮验收以冻结输入、有效配置、独立参考、操作增量及原文保真能完整对应为完成条件。
