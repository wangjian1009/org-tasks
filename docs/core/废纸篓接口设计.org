#+TITLE: 任务修改调度与文件任务消息设计
#+LANGUAGE: zh-CN
#+STARTUP: show2levels

* 已确定的执行边界

复用现有 Workspace 操作入口，不新增批量提交方法。一个主任务处理本次请求，完成仓库锁和身份检查后遍历输入操作，并维护文件到 task 的映射。遇到尚无 task 的文件时才启动 task，每个文件在本请求内只启动一次。主任务负责将跨文件 Trash、Restore 等操作分解为单文件基础操作，普通操作直接按顺序派发。主任务与文件 task 仅通过 channel 交换消息。

所有业务修改只作用于本次请求的内存副本。所有基础操作及依赖步骤完成后统一存盘，所有文件提交成功后才统一发布通知。除 Restore 插入失败可保留来源外，任何操作错误或程序异常均使整次请求失败，放弃本次未提交修改。

操作节点限制为没有子节点的记录。Trash、Restore 都制作独立副本；删除时附加的来源与删除时间统一使用 SOURCE_ 前缀，覆盖同名前缀的旧值；恢复时清除所有 SOURCE_ 属性。CATEGORY、PROJECT_NAME 等自有业务属性保留。

本设计已由 ~core/src/model/task_operation_executor/scheduler.rs~ 与 ~file_worker.rs~ 实现。公开提交入口保持不变，新增 TaskOperation 的 Trash、Restore 变体；手机废纸篓页面、保留天数设置与过期清理已接入，见 [[file:../harmony/废纸篓设计.org][废纸篓与系统仓库设计]]。

* 自动加载与文件命令

文件身份、仓库、预期文件版本、模板请求和输出需求在创建文件 task 时绑定，命令不重复携带文件路径或请求 ID。文件 task 启动后自动读取、解析文件并返回 FileMetadata，主任务不预读文件，不等待加载完成就可以发送修改；task 完成加载后再按 channel 顺序执行这些修改。文件 task 和 channel 均归属于本次请求，不跨请求复用。

#+begin_src rust
use tokio::sync::mpsc;

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct OrderId(u64);

// Modification 指现有请求的操作类型，包含新增、字段修改、删除等，
// 不是仅表示单个字段的 TaskModification。
// 入队前已由主任务拆解成只访问当前文件的操作。
enum Modification {
    Operation(TaskOperation),
    Insert { copy: Box<RecordCopy>, position: TaskPosition, strict: bool, properties: Vec<(String, Option<String>)>, tags: Option<Vec<String>>, after_hint: bool },
    Extract { path: TaskPath },
}

enum FileCommand {
    Execute {
        order_id: OrderId,
        modification: Modification,
    },
    Discard,
    Save,
}

struct FileWorkerHandle {
    file: OrgFileRef,
    commands: mpsc::Sender<FileCommand>,
}
#+end_src

自动 Load 阶段由文件 task 完成普通文件读取、文件身份和版本检查、SETUPFILE／忽略规则／模板依赖读取、语法树解析、初始 FileMetadata 生成，以及按需复制完整 OrgFile。主调度器仅接收这些结果；逻辑锁检查和统一提交时必要的文件系统元信息检查仍由原提交器负责。复制记录的属性补丁也在目标文件 task 内应用，调度器只构造结构化补丁。

- ~Execute~ ：在当前文件内存副本上执行一项修改并返回结果。普通修改直接复用输入操作；Trash、Restore 接收主任务分解后生成的基础操作，文件 task 不执行跨文件流程。
- ~Discard~ ：放弃本次请求的文件内存、暂存事件并结束任务。它不承担已经落盘文件的回滚。
- ~Save~ ：主任务确认所有操作结束后发出的存盘指令。文件 task 通过 SaveReady 交出纯字节 SaveCandidate 与提交确认 channel，继续保留 OrgFile 和 MutationJournal。主任务复用原统一提交器完成校验、临时文件和回退保存，成功后通过 channel 告知真实提交时刻；文件 task 再生成最终 FileDataChange／TaskDataChange 并返回 Saved。SaveReady 不是落盘成功，主任务也不取得用于 Metadata 生成的语法树。

不再定义显式 Load、Bind、Copy、PrepareSave、Rollback、Finish 等文件命令。内部执行所需的节点绑定、临时副本和语义变更日志由文件任务自行维护，不能为了缩减消息而省略这些正确性保障。

* 文件任务返回的消息

#+begin_src rust
struct FileEvent {
    file: OrgFileRef,
    body: FileEventBody,
}

enum FileEventBody {
    Loaded(Result<FileLoadResult, CoreError>),
    Executed(Result<FileExecuteResult, FileExecuteError>),
    SaveReady(Result<FileSavePlan, CoreError>),
    Saved(FileSaveResult),
}

struct FileLoadResult {
    file_version: Option<String>,
    metadata: Option<OrgFileMetadata>,
    full_file: Option<OrgFile>,
    records: Vec<RecordCopy>,
    conflicts: Vec<String>,
    dependencies: ReadDependencies,
}

struct FileSavePlan {
    candidate: SaveCandidate, // 仅原字节、最终字节、路径及文件身份。
    committed: oneshot::Sender<Result<Option<FileStamp>, CoreError>>,
}

struct FileSaveResult {
    file_change: Option<FileDataChange>,
    task_changes: Vec<TaskDataChange>,
}

struct RecordCopy {
    source: TaskDataSnapshot,
    source_text: String,
    category: Option<String>,
    project_name: Option<String>,
    file_title: Option<String>,
    file_id: Option<String>,
}

struct FileExecuteResult {
    order_id: OrderId,
    // 只收集到主任务，尚未向订阅者发布。
    notification: Vec<TaskDataChange>,
    result_path: Option<TaskPath>,
    // 只有本请求后续需要复制的来源文件才导出快照。
    snapshot: Vec<RecordCopy>,
    // 既有跨文件 Movement 的来源提取结果。
    extracted: Option<Box<RecordCopy>>,
}

struct FileExecuteError {
    order_id: OrderId,
    error: CoreError,
}

#+end_src

~Loaded~ 首先返回文件任务生成的 FileMetadata 与实际版本；需要完整文件时，OrgFile 的独立副本也在文件 task 内制作，并通过同一消息返回。只读合并规划沿用该读取入口，不再在调用任务里自行读盘或 clone 完整文件。Loaded 与其他文件的 Executed 可以交错到达，主任务统一接收，不能假设全部 Loaded 都先于 Execute 回复。副本只传递拥有所有权的文本和普通结构化值，不跨文件任务传递可变 OrgFile、rowan 节点或借用引用。源节点含有子节点时不能成为叶节点副本，应在来源校验时拒绝相关操作。

~FileExecuteResult~ 只表示内存修改成功，不代表落盘。~result_path~ 是这一步完成后的准确位置，主任务据此推进有关联的后续操作。节点改名、同名出现次序与源删除顺序由主任务和文件内节点绑定共同维护，不把旧路径当作不可变化的实体身份。

execute 的成功与失败直接表示为 ~Result<FileExecuteResult, FileExecuteError>~ ，两者均携带相同的派发 ~order_id~ ，外层 Executed 不再重复保存该 ID。~notification~ 为本次操作产生的暂存变化，没有变化时为空；错误回复不携带成功通知。

不新增插入拒绝或错误分类。主任务依据 ~order_id~ 找到原操作与当前步骤：Restore 目标插入返回 Err 时不派发来源删除，保留废纸篓记录并继续处理其他操作；其他操作返回 Err 时，使整个请求失败并放弃本次修改。

插入先在独立尝试副本中执行，失败时丢弃该尝试，不得在本次文件内存或变更日志中留下半成品。文件任务不需要理解 Restore，只按普通插入返回成功或失败。panic、channel 中断与 task 意外结束仍按任务级异常直接错误返回，不新增消息中的错误种类或标志。

各文件 task 独占 MutationJournal，并在修改成功后把变更作为暂存结果返回主任务，不共享文件间的可变日志。主任务统一收集、不提前发布；SaveReady 仅移交字节候选，统一提交成功通过 channel 确认后，仍由各文件 task 按真实提交时刻、最终路径和版本生成 Metadata 及变化投影；主任务收到 Saved 后只归并结构化结果，替换中间集合，避免直接拼接中间通知造成新建后删除、同名路径变化与父级统计不一致。既有跨文件 Movement 通过 channel 传递节点令牌和独立原始快照，最终按原节点身份合并源／目标事件与移动后删除；Trash、Restore 则明确产生 Created 与 Deleted。

* order_id 的含义

~order_id~ 唯一标识本次请求内的一次 Execute 派发。普通输入操作可直接分配一个 ID；Trash、Restore 拆出的插入、删除等基础操作分别分配 ID，主任务维护它们与原操作的关联及依赖。不能让多个同时在途的基础操作共用同一个 order_id，否则调度器无法判断返回的是哪一步。

不额外增加 command_id、request_id 或 step 字段；本次请求由私有 channel 隔离，文件由 FileEvent.file 标识，只有 Execute 需要 order_id。自动加载结果、Discard、Save 由文件任务阶段和每文件唯一在途控制命令关联；Discard 结束任务不再另外发送确认消息。当前使用请求私有的 unbounded channel，通过请求持有的 JoinSet 监控任务异常并在失败时取消剩余 task。

* 调度状态

#+begin_example
启动 -> 自动加载并返回 Metadata -> Executing -> SaveReady
                                           -> 统一 commit -> channel 确认 -> Saved -> task 结束
          |
          +-> Discard -> task 结束
#+end_example

文件 task 自动加载期间，Execute 可以立即排入收件箱；实际修改在加载成功后按 FIFO 执行。调度器不等待 Metadata 再发送普通修改，也不预先启动全部文件 task。仅需要来源副本或路径依赖时等待相关结果。进入 Save 后不再接收新的 Execute；跨文件存在依赖的操作在收到相应 Executed 后派发。

执行结束条件为：输入操作都已派发或明确跳过、所有已派发 Execute 均已收到回复、没有等待派发的依赖步骤。Restore 插入成功还会派生 Deletion，因此不能把队列短暂为空当作执行结束。Deletion 结束本身不触发 Save，必须等待整个请求全部基础操作完成。

遇到错误时，主任务不再派发新的业务和 Save 命令，对仍持有内存副本的文件发送 Discard，并返回错误；迟到的执行结果不再参与成功流程。存盘阶段继续保留现有提交失败回退机制，不以 Discard 替代回滚。所有 SaveReady 到齐后统一 commit，发送提交确认并收齐各文件 task 的 Saved 结果，最后才统一通知并完成外部请求。

有界 channel 的发送背压与结果接收必须同时推进，避免主任务等发送容量、文件任务等回复容量造成相互阻塞。

* 两种高级操作

#+begin_example
Trash
  按需启动来源与废纸篓任务，自动加载并返回 Metadata 与所需快照
  主任务制作带来源、分类、项目及删除时间属性的副本
  Execute(插入副本到废纸篓文件头)
  Execute(删除来源)
  任一步失败 -> 整次请求失败并 Discard

Restore
  按需启动废纸篓及恢复目标任务，自动加载
  主任务制作副本并移除系统删除元数据
  Execute(插入副本到原位置)
    Ok(FileExecuteResult)                  -> 派发 Execute(删除废纸篓来源)
    Err(FileExecuteError)                 -> 保留来源，不派发删除，继续处理其他操作

所有输入操作及依赖步骤完成
  -> 所有文件 Save
  -> 所有 SaveReady 到齐，既有统一 commit 成功
  -> channel 确认提交，文件 task 返回最终 Metadata 与变化投影
  -> 主任务收齐 Saved 后统一通知
#+end_example

Trash 的目标插入和来源删除可以在不同文件内存上并行执行；任一失败通过放弃整次请求保证不落盘。Restore 的删除必须在插入返回 FileExecuteResult 后派发。

普通操作以 Operation 载荷直接复用现有输入，跨文件副本插入使用内部 Insert 载荷，Movement 的来源删除与令牌提取使用内部 Extract 载荷；它们都是 Execute 内的单文件基础操作，不增加文件命令或公开 Workspace 方法。Insert 先在独立探针验证，通过后才改工作副本，不生成新的 CREATED 或完成日志，保留原 CREATED、CLOSED、业务属性与日志。

* 对外兼容

上述类型是 Rust 内部消息，不进入 bridge，不新增 Workspace 提交入口。现有对外 operation_id 仍关联整次请求。

现有 Result<(), CoreError> 可以保留请求级成功或失败；但 Ok 可能包含插入失败、仍留在废纸篓的 Restore。若界面需要明确提示跳过原因与数量，需另行确定既有返回结果的表示方式，本消息结构不暗中改变它。

* 公开操作与当前恢复策略

#+begin_src rust
pub struct TaskTrash { pub path: TaskPath, pub target: OrgFileRef }
pub struct TaskRestore { pub path: TaskPath }
#+end_src

Trash 的备份属性统一使用 ~SOURCE_~ 前缀，恢复时按前缀清除所有字段，包括未知扩展字段；不兼容旧的 ARCHIVE_* 与 TRASH_ID 格式，旧记录恢复直接报错，可清空废纸篓后重新使用。

| 属性 | 含义 |
|-
| ~SOURCE_REPO~ 、 ~SOURCE_FILE~ | 原仓库持久 ID 与相对文件路径 |
| ~SOURCE_OLPATH~ 、 ~SOURCE_POSITION~ | 父标题路径展示值，以及 after 为空的完整 TaskPosition；结构化父路径保留重名序号 |
| ~SOURCE_BROTHER~ | 可选，JSON TaskPath，指定插入在原前一兄弟的完整子树之后；仅为提示，找不到或不在原父节点下时插入第一个子节点 |
| ~SOURCE_TIME~ 、 ~SOURCE_TRASH_ID~ | Core 生成的删除时间与独立删除标记 |
| ~SOURCE_TASK_TITLE~ 、 ~SOURCE_TASK_STATE~ | 原始标题与 TODO 状态，支持来源与废纸篓 TODO 配置不同 |
| ~SOURCE_CATEGORY~ 、 ~SOURCE_PROJECT_NAME~ | 来源文件的分类与项目名；不覆盖节点原有业务属性 |
| ~SOURCE_PARENT_TAGS~ | JSON 字符串数组，只记录从全部祖先补入、且本节点未直接声明的标签；去重，不包含文件标签；恢复时仅移除数组中的自有标签 |
| ~SOURCE_ID~ | 原节点自有 ID；Trash 移除 ID 并备份，Restore 先还原 ID，再清除 SOURCE_ 属性；原来无 ID 时不生成 |
| ~SOURCE_FILE_TITLE~ 、 ~SOURCE_FILE_ID~ | 来源文件标题与文件头属性抽屉 ID；未声明时为空，保留用于以后扩展，当前不参与定位 |

Trash 创建独立副本前清除旧 SOURCE_ 属性，再写入本次来源信息。祖先标签只复制缺失值；本节点直接声明的同名标签在恢复后保留，废纸篓中新增的其他标签也保留。普通 Creation 复用 TaskPosition.after 作为位置提示，找不到或不属于指定父节点时插入首位，不增加公开参数；Movement 保持严格定位。Restore 将 SOURCE_BROTHER 带入同一位置提示规则，通过内部 Insert 新建副本，不使用普通 Creation 的自动时间和状态日志逻辑，保留原 CREATED、CLOSED 与日志。


当前 Restore 原仓库、文件或父节点缺失时保留来源，前一兄弟缺失时插入父节点的第一个子节点；不自动新建文件或回退到根部，且不会生成空文件。目标 TODO 配置不兼容同样保留来源。来源信息损坏、非叶节点、版本冲突和 task 异常仍是请求失败。恢复来源文件之外的依赖从上下文动态确定，外层 Workspace 暂时将 Restore 请求作为独占命令调度，保障与查询、同步及其他修改的先后关系。

* 自动加载的读取复用

文件 task 使用本请求私有的 ReadCache 复用不可变读取结果。每个路径由首次需要它的文件 task 执行实际读取，其余 task 等待同一个 OnceCell 结果；主任务不访问读取缓存的数据。业务文件同时作为 SETUPFILE 或模板依赖时也只读一次，避免启动顺序造成重复读取或死锁。缓存只覆盖本次请求，不跨请求保留；提交前继续检查业务文件身份与配置依赖，业务文件的配置引用复用文件身份校验，不额外读正文。

新增回归覆盖同一文件只启动一个 task、Metadata 尚未接收即可连续派发修改、任务启动后才读取文件并生成 Metadata／完整文件，以及加载错误先于 Execute 派发时仍返回原始版本错误。保存后的最终 Metadata 和变化投影在文件 task 内生成，调度器不再调用 metadata 或创建完整文件副本。

自动加载调整后的完整 Cargo workspace 回归通过 585 项测试，Harmony Debug 构建无告警。独立模拟器再次验证批量 Trash／Restore、插入失败保留来源、当前页面真实刷新与普通错误整组不落盘。文件读取、初始和最终 FileMetadata、完整文件副本均由文件 task 生成，主调度器仅接收 channel 结果。
