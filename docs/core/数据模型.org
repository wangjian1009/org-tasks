* 范围与状态

本文定义以数据源为边界的核心领域模型。 ~DataSourceConfig~ 、 ~OrgFileRecord~ 、 ~SyncRun~ 与 ~SyncMonitorEvent~ 是下一阶段核心 SDK 的目标模型；当前 ~core/src/lib.rs~ 仍使用未带数据源归属的 ~FileSyncRecord~ 与 ~SyncJob~ ，尚未实现本文定义的同步接口或监控器。

数据源配置仅在 SDK 构造时提供，不能由同步请求、HTTP 请求或 UI 设置直接修改。持久化状态只使用稳定的 ~sourceId~ 关联配置，不保存本地绝对目录、密码、Authorization header、完整 org 文件或解析任务。实体关系的 TikZ UML 源码与本文同步维护。

* 基础约定

| 类型或规则    | 定义                                                                                                                       |
|---------------+----------------------------------------------------------------------------------------------------------------------------|
| ~TimestampMs~ | Unix epoch 毫秒。                                                                                                          |
| ~SourceId~    | 非空、由调用方稳定保存的 UUID 字符串；同一逻辑数据源重建 SDK 时必须使用同一 ID。                                           |
| ~SyncRunId~   | 非空 UUID 字符串，由 SDK 或调用方生成。                                                                                    |
| 相对路径      | ~relativePath~ 相对于所属数据源的 ~localDirectory~ ，不能是绝对路径或包含 ~..~ 。                                          |
| 内容版本      | ~contentHash~ 和 ~RemoteFileVersion~ 均为不透明版本元数据；core 不保存完整文件内容。                                       |
| 配置边界      | ~localDirectory~ 、 ~baseUrl~ 只保留在运行时 ~DataSourceConfig~ ；密码与认证信息不属于 core 模型。保存方式见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。 |

* 运行时配置

~DataSourceConfig~ 是 SDK 构造期的运行时对象，不是可写资源，也不写入 ~CoreStore~ 。

#+begin_src rust
pub struct DataSourceConfig {
    pub id: SourceId,
    pub local_directory: String,
    pub remote: Option<RemoteConfig>,
}

pub enum RemoteConfig {
    WebDav(WebDavRemoteConfig),
}

pub struct WebDavRemoteConfig {
    pub base_url: String,
}
#+end_src

~localDirectory~ 指向该数据源的本地 org 文件根目录。 ~remote = None~ 表示仅扫描本地目录； ~remote = Some(WebDav(...))~ 表示同步驱动还需要与该 WebDAV 根目录协调文件版本。当前只支持 WebDAV，后续新增远端类型必须扩展 ~RemoteConfig~ ，不能以未结构化字符串或 UI 开关表示。

~WebDavRemoteConfig~ 不包含用户名、密码、令牌、客户端证书或认证 header。认证材料不进入 core 的配置、持久化状态、错误或监控事件。

* 同步结果模型

WebDAV 协议及其他数据源驱动与 core 交互时，使用以下无敏感内容的数据结构。驱动只返回元数据和操作结果，core 负责将其原子写入数据源状态。

#+begin_src rust
pub struct RemoteFileVersion {
    pub etag: Option<String>,
    pub modified_at: Option<TimestampMs>,
    pub size: Option<i64>,
}

pub struct OrgFileRecord {
    pub source_id: SourceId,
    pub relative_path: String,
    pub content_hash: String,
    pub remote_version: Option<RemoteFileVersion>,
    pub sync_state: FileSyncState,
    pub updated_at: TimestampMs,
}

pub struct SyncSummary {
    pub discovered_files: u32,
    pub downloaded_files: u32,
    pub uploaded_files: u32,
    pub conflicted_files: u32,
}

pub enum SyncErrorCategory {
    Network,
    Authentication,
    Tls,
    Validation,
    Conflict,
    LocalStorage,
    Unknown,
}

pub struct SyncErrorSummary {
    pub category: SyncErrorCategory,
    pub retryable: bool,
    pub message: String,
}

pub struct SourceSyncOutcome {
    pub files: Vec<OrgFileRecord>,
    pub acknowledged_outbox_ids: Vec<String>,
    pub conflicts: Vec<ConflictRecord>,
    pub summary: SyncSummary,
}
#+end_src

~RemoteFileVersion~ 优先使用 ETag；服务器没有 ETag 时可使用修改时间和大小参与变化判断。 ~SyncErrorSummary.message~ 必须是脱敏摘要。 ~SourceSyncOutcome~ 不得携带本地绝对路径、远端完整 URL、认证 header 或 org 文件正文。

* 数据源持久化状态

数据源在领域上包含零到多个 ~OrgFileRecord~ 和零到多个 ~SyncRun~ 。 ~OrgFileRecord~ 是已发现 org 文件的元数据投影；文件尚未被扫描或被忽略时，数据源可以没有任何文件记录。

** 关联与职责

| 实体 | 关键字段 | 责任 |
|-
| ~OrgFileRecord~ | ~sourceId~ 、 ~relativePath~ 、 ~contentHash~ 、远端版本、 ~syncState~ | 一个数据源内一个 org 文件的同步元数据。唯一键为 ~(sourceId, relativePath)~ 。 |
| ~SyncRun~ | ~id~ 、 ~sourceId~ 、触发来源、状态、起止时间、统计和错误摘要 | 一次同步操作的不可变历史；完成后仅允许补充最终统计或错误摘要。 |
| ~SourceSyncState~ | ~sourceId~ 、 ~activeSyncRunId~ | 数据源当前执行权。其 ~activeSyncRunId~ 为空或指向一个 ~running~ 的 ~SyncRun~ 。 |
| ~OutboxEntry~ | ~id~ 、 ~sourceId~ 、 ~targetPath~ 、 ~orgEntry~ | 面向特定数据源的本地写入意图。 |
| ~ConflictRecord~ | ~id~ 、 ~sourceId~ 、 ~relativePath~ 、版本和状态 | 同一数据源中无法自动处理的本地与远端分歧。 |

~TaskRecord~ 仍是从 ~OrgFileRecord~ 对应文件即时解析出的短生命周期投影，不属于数据源持久化内容。

** 同步历史与并发控制

~SyncRunState~ 取值为 ~running~ 、 ~succeeded~ 、 ~failed~ 、 ~cancelled~ 与 ~interrupted~ 。 ~SyncTrigger~ 取值为 ~manual~ 、 ~background~ 、 ~retry~ 或 ~external~ 。

开始同步必须在一次原子提交中创建 ~SyncRun(running)~ 并设置 ~SourceSyncState.activeSyncRunId~ 。若该字段已有值，新的同步请求返回 ~SyncAlreadyRunning~ ，其中包含现有 ~syncRunId~ ；不得排队、替换或并行执行。结束同步必须在一次原子提交中写入最终状态、统计或错误摘要，并清空 ~activeSyncRunId~ 。

SDK 构造时会恢复未完成记录：上一次进程退出后仍为 ~running~ 的 ~SyncRun~ 必须标记为 ~interrupted~ 并释放执行权。历史由 ~sourceId~ 查询并按 ~startedAt~ 倒序返回；保留策略属于宿主配置，不改变单数据源单执行权约束。

* 持久化与迁移

新 ~CoreStore~ 持久化 ~OrgFileRecord~ 、 ~SyncRun~ 、 ~SourceSyncState~ 、 ~OutboxEntry~ 和 ~ConflictRecord~ ，并保证“开始同步”和“完成同步”各自原子可见。 ~DataSourceConfig~ 由每次 SDK 构造传入，因此不会因设备路径变化或凭据更新而进入持久化状态。

当前 Harmony 二进制快照和 HTTP CSV 仓储仅实现旧模型的 ~FileSyncRecord~ 、 ~SyncJob~ 与 ~OutboxEntry~ ，需要在引入数据源 SDK 时迁移为以 ~sourceId~ 分区的记录。迁移前不得将旧记录自动归属到任意数据源；宿主必须显式提供映射或执行一次受控重建。
