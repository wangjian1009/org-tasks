* 范围与状态

本文定义以 ~OrgWorkspace~ 为全局入口、以 ~OrgRepo~ 为文件仓库边界的核心领域模型。一个应用通常只构造一个 ~OrgWorkspace~ ，其中包含零到多个仓库。每个仓库由构造时传入的根目录指定，不持有文件快照；同步记录独立落盘于根目录的 ~.sync/history/~ 。仓库控制目录的持久化布局和本次重构目标见 [[file:同步核心设计.org][同步核心设计]]。

~OrgFile~ 使用 ~orgize~ 提供无损运行时解析，并以 Emacs ~org-element~ 作为语义基准； ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ 描述一次仓库同步及其中各文件的同步结果； ~TaskOperationGroup~ 是统一任务修改输入， ~OrgRepoWriteIntent~ 是待上传的路径与哈希。当前 ~core~ 已实现保真编辑接口和仓库级服务端口；Harmony 与 HTTP 已仅使用仓库同步记录持久化接口，不再保留旧作业模型。

调度、线程、SDK 生命周期、监控回调、认证材料、文件系统访问和网络 I/O 都是宿主或适配层的运行时概念，不是本章的核心数据结构。实体关系的 TikZ UML 源码与本文同步维护。

仓库按需读盘和跨进程同步模型见 [[file:仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]]。 ~OrgRepo~ 仅持有身份、根目录配置和默认 TODO 配置，移除 ~files~ 与扫描规则缓存； ~load_files(ignore_files)~ 异步返回操作拥有的文件集合。以下同步租约与恢复对象仍为私有执行状态。

* 同步执行与重置恢复对象

每轮同步的 ~Session~ 独立持有文件租约和阶段身份，网络阶段不占仓库锁。 ~State~ 落盘于本轮目录，关联仓库 ID、同步 ID、开始时间和阶段；根目录 ~sync~ 标记仅保存该同步 ID。 ~ResetIntent~ 记录已声明的重置及所属仓库，清理完成前持续存在。真实数据通过已有 ~Guard~ 排他访问；临时下载、合并和请求结果归属本轮同步目录。

* 基础约定

| 类型或规则 | 定义 |
|-
| ~TimestampMs~ | Unix epoch 毫秒。 |
| ~OrgRepoId~ | 非空 UUID 字符串；同一逻辑仓库重建 workspace 时必须保持不变。 |
| ~OrgRepoSyncRecordId~ | 一次同步记录的非空字符串，在所属仓库内唯一；完整定位使用仓库 ID 与同步 ID。 |
| ~OrgRepoSyncRecord.kind~ | 策略类型标识；必须与加载和执行该记录的 ~SyncPolicy::KIND~ 一致。 |
| 相对路径 | ~relativePath~ 相对于所属 ~OrgRepo.rootDirectory~ ，不能是绝对路径或包含 ~..~ 。 |
| 源位置 | ~SourceRange~ 是引用 ~OrgFile.sourceBytes~ 的半开区间 ~[start, end)~ 。 ~SourcePosition~ 同时记录 1-based 行号、0-based UTF-8 字节列号与 0-based UTF-8 字节偏移；它仅在当前文件快照内有效，不能作为跨版本稳定 ID。 |
| 内容与版本 | ~OrgFile.sourceBytes~ 保存当前解析/编辑会话的完整源字节，用于保真写回；它不写入 core 持久化状态或同步记录。内容树可由文件重新解析； ~LocalFileVersion~ 只保存内容哈希， 策略专属的文件 ~detail~ 保存远端 ETag、修改时间和大小等信息。 |

~OrgFileMetadata.category~ 是同一文件快照的文件级 CATEGORY，保留缺失与显式空值，不进入持久化。

~OrgFileMetadata.task_state_counts~ 是完整文件快照的运行时聚合，不持久化。~TaskStateCount~ 保留原始状态名、Core 状态分类与数量，只返回出现过的状态并沿用有效 TODO 声明顺序；统计全部层级，排除无状态标题、忽略文件和受保护冲突子树。项目进度使用全部数量之和作为总数，仅 ~Done~ 分类计入已完成数，~Cancel~ 只计入总数。

* 查询投影中的标题层级

~FilterTask~ 的 ~level: u32~ 是从 ~OrgFile~ 的 ~orgize~ 标题节点读取的真实星号层数，从 1 开始；它与 ~repo_id~ 、相对 ~path~ 、 ~byte_offset~ 一同保留当前快照中的来源和结构。该字段只用于运行时查询投影与宿主展示，不进入同步 CSV、历史或 outbox。宿主可据此折叠层级，不能重新解析原文推断标题结构。

~FilterTask.state()~ 返回 ~Option<&TaskState>~ ，其中包含状态名称与可空分类。任务与共享文件元信息均提供 ~task_state_of(category) -> Option<TaskState>~ ；返回首个有效匹配状态的独立副本，找不到时为空。

~FilterTask~ 的字段不作为跨模块结构契约公开；宿主和其他 crate 通过访问方法读取查询快照。时间方法返回可空值： ~closed_at()~ 从当前标题自己的 ~CLOSED~ 规划节点读取完成／取消时间，按设备本地时区解释为 Unix 毫秒；缺失、无效或时间范围返回 ~None~ ，不读取日志或文件时间。只有日期按零点解释，夏令时回拨取较早时刻，不存在的本地时刻忽略。 ~created_at()~ 是标题自身 ~CREATED~ 属性解析出的 Unix 毫秒时间， ~modified_at()~ 仅从当前标题自身的 ~LAST_MODIFIED~ 属性解析 Unix 毫秒时间，属性名不区分大小写，不继承、不扫描正文或文件前言。两者缺失或不可解析时均返回 ~None~ ，任务修改时间不读取文件 mtime，也不使用创建时间补齐；读取不生成或回填属性。

~FilterTask.is_habit()~ 返回当前标题自身属性抽屉的 ~STYLE~ 值是否为 ~habit~ ，复用 Core 属性解析；属性名不区分大小写，属性值区分大小写。不继承父标题或文件默认属性，不读取正文、日志或子标题中的字面文本，也不要求 TODO 状态或重复器。规划行含 ~.+1d/3d~ 等重复窗口、导致 ~orgize~ 未直接识别属性抽屉时，Core 仅跳过标题紧邻的连续规划行，再通过 ~orgize~ 读取其后的属性抽屉值；投影位置不用于编辑，原语法树与字节保持不变。该只读快照与 ~is_repeating()~ 独立，习惯任务可以同时为循环任务；仅在展示时由习惯图标优先占用标记位置，不写入持久化记录或修改原文。

~FilterTask.is_repeating~ 表示当前标题的计划或截止时间包含 Org-mode 重复器，由 Core 从 ~orgize~ 时间戳取得；对解析器尚未识别的写法仅在标题紧邻的规划行内兜底识别。重复器支持 ~+Nunit~ 、 ~++Nunit~ 和 ~.+Nunit~ ，其中 ~unit~ 为 ~h~ 、 ~d~ 、 ~w~ 、 ~m~ 或 ~y~ ，并支持可选的重复截止部分 ~/N~ 或 ~/Nunit~ 。正文、源码、日志和子标题中的重复器不使父任务成为循环任务。该字段只供运行时展示，不展开重复日期，不修改查询与持久化边界。

Core 内部同时保存 SCHEDULED 与 DEADLINE 的预警起始日。活动规划行中的 ~-Nunit~ 或 ~--Nunit~ 按 Org-mode 规则从实际日期向前计算；仅 ~s.le.today~ 与 ~d.le.today~ 使用该起始日匹配今天入口，任务投影中的 ~scheduled~ 与 ~deadline~ 仍保留实际日期供 UI 展示和其他关系查询。

~FilterTask.category~ 是查询时所属文件的 ~OrgFile.category()~ 快照，由 Core 每文件提取一次；未声明为 ~None~ ，显式空声明为 ~Some("")~ 。标题属性不覆盖这个文件分类。分类变化不改变任务逻辑 ID，但刷新后必须使用新任务快照。宿主通过只读数据控制分类展示，不再逐项获取文件，不额外传入分类文字。该投影不进入同步记录或 outbox。

~FilterTask.own_tags~ 与 ~inherited_tags~ 在查询内部保留原始标签用于表达式求值； ~OrgWorkspace.query~ 返回前统一排除系统标签 ~REFILE~ 与 ~ARCHIVE~ 。其余标签的内容与顺序保持不变，大小写不同的 ~refile~ 或 ~archive~ 不受影响。放置目标从 ~OrgFile~ 的标题自身标签读取，不依赖已去除系统标签的查询返回值。

* 文件信息共享与可配置标签

同一文件的一次任务投影共用 ~Arc<OrgFileMetadata>~ ，标题记录不再分别保存仓库 ID 与文件路径副本； ~repo_id()~ 与 ~path()~ 从共享元信息读取。 ~file_metadata()~ 返回该不可变快照的借用，任务克隆继续共享；仓库重新加载后旧任务保留旧文件信息，不持有仓库锁、源字节或整个语法树。通过文件对象与任务投影生成的元信息使用同一实现。

pub struct SupportTags {

* 文件项目归属

~OrgFileMetadata.project_name: Option<String>~ 是一次读取生成的项目名称快照； ~project() -> Option<&str>~ 返回该字段的借用。只有文件头 ~FILETAGS~ 精确包含 ~project~ 时才存在项目归属，名称优先取文件头关键字 ~PROJECT_NAME~ ，缺失时取文件默认属性中的同名值，仍缺失时取 ~TITLE~ 。缺失名称和标题或显式空名称时保留空字符串以区别非项目的 ~None~ 。标题任务的自身标签、候选标签和真实子标题层级均不参与项目判定。

~FilterTask.project()~ 只调用 ~file_metadata.project()~ ，同文件任务共用一次计算结果，克隆仍共享同一元信息。JSON 和 Harmony 的 ~projectName~ 字段便于保存完整展示快照，访问方法不执行 I/O；原 Org 文件及同步持久化结构保持既有格式。

~RefileTarget~ 定义于 ~core::model~ ，是从已加载文件无损语法树取得的运行时放置位置，不是持久化实体或新的解析 AST。 ~OrgRepo.refile_targets()~ 与 ~OrgWorkspace.refile_targets()~ 返回标题自身显式携带系统标签 ~REFILE~ 的目标；范围为完整文件快照，包括任务扫描忽略的文件，完成状态与普通任务查询条件不限制目标。

* 任务逻辑身份

~FilterTask.task_id() -> Option<&str>~ 仅对有效 TODO 配置识别的待办和已完成任务返回身份，非任务标题返回 ~None~ ，跨语言为 ~null~ 。原有 ~id~ 字段保留作查询记录的通用展示键，不用于新的写入定位；所有写操作使用 ~TaskPath~ 。

逻辑结构保持原有规则：仓库使用 ~OrgRepo.root_directory~ 原始字符串，文件使用安全相对路径，祖先仅包含待办或已完成标题。标题值排除 TODO、优先级和标签，去除首尾空白和首尾连续进度节点，中间进度、链接与强调原文保留。无状态祖先不进入任务身份链，状态切换、无关任务增删和首尾进度变化不改变任务身份。

身份直接返回紧凑 JSON 明文字符串，不再计算 MD5。基础形式为 ~[rootDirectory,relativeFilePath,[title1,title2,...]]~ ；同一逻辑路径从第 2 次起追加完整文件遍历中的 1-based 出现序号。分段 JSON 保留标题中的点号、斜杠、引号和 Unicode，避免字符串拼接歧义。重名项删除或重排后，出现序号可能变化；Org 的 ~ID~ 属性不覆盖本规则。改名或移动到其他任务父级、仓库、文件会改变身份。

#+begin_example
仓库：/repo
文件：inbox.org
,* Group
,** TODO [1/2] Project
,*** DONE Child [100%]

Child 的 taskId：["/repo","inbox.org",["Project","Child"]]
Group 的 taskId：null
#+end_example

明文身份仅用于运行时查询与宿主日历映射，不进入同步日志、outbox 或错误摘要。冲突比较中的 Org ID 优先级与原文单元 key 保持独立；不以任务身份替代内容版本校验。


任务查询结果另外保留同次文件读取产生的 ~file_version()~ 和 ~edit_content()~ ，后者为 ~TaskEditContent~ 值对象。它们不引用仓库或完整语法树，用于宿主直接投影版本和编辑内容；源文件后续变化不会修改已返回结果。

* 完整结构路径与插入位置

~TaskPath~ 定义于 ~core::model~ ，形式为“仓库 + 文件 + title1 + title2”。仓库和文件通过各自的 ~full_path()~ 返回路径；每个标题投影通过 ~FilterTask.full_path()~ 返回路径，包括所有无状态标题。 ~OrgFile.node_paths()~ 遍历完整标题树， ~OrgRepo.nodes()~ 返回相同范围的标题投影，均不受任务查询和忽略规则影响。

#+begin_src rust

    pub repo_id: OrgRepoId,
    pub file: Option<String>,
    pub titles: Vec<String>,
    pub occurrence: usize,
}
pub struct TaskPosition {
    pub parent: TaskPath,
    pub after: Option<TaskPath>,

#+end_src

~file=None~ 且标题链为空表示仓库；有文件且标题链为空表示文件；有标题链表示真实标题节点。路径标题保留从根到自身的全部祖先，排除状态、优先级、标签及标题直属的真实 ~COOKIE~ 进度节点，包括 ~[/]~ 、 ~[1/2]~ 、 ~[%]~ 和 ~[50%]~ ，不因进度变化改变自身或后代路径。排除进度时将其两侧空白合并为一个空格，去除尾部空白；代码、链接与强调内部的字面进度和普通文字保留。相同规范化标题链以文件原文中的 ~occurrence~ 区分，默认从 1 开始。路径使用稳定的 Core 仓库 ID，不使用宿主配置 ID；不把包含分隔符的标题再次拆分为层级。该规范化只用于结构定位与同步匹配，展示标题和源字节仍保留原始进度；写入继续校验真实文件版本。

预览文件使用固定 ~repo_id="<preview>"~ 与本次创建 UUID 作为 file，其标题路径仍使用相同结构。它是临时文档地址而非仓库，详见本文“冲突预览模型”。

~TaskPosition.parent~ 指向文件或标题，不能指向仓库节点。 ~after=None~ 表示插入为第一个子节点，位于 parent 自身正文之后；非空时 after 必须是 parent 的直属子节点，插入在其完整子树之后。文件作为 parent 时对应顶层标题。移动不能以自身或后代作为 parent 或 after；不要求目标带 REFILE 标签，展示层仍可从放置目标列表选择位置。

* 工作空间与仓库

~OrgWorkspace~ 是应用级管理对象，负责聚合仓库和提供跨仓库批量 ~TaskQuery~ 查询，不表示后台任务、线程池、网络客户端或持久化实现。一个应用通常只需要一个 workspace；测试、隔离导入或多账户场景可以构造多个 workspace。

~OrgRepo~ 是一个独立文件仓库。其 ~rootDirectory~ 在构造时由宿主提供，用于扫描和解析该仓库内的文件；该绝对路径不能写入 core 的持久化状态。 ~load_files(ignore_files)~ 每次从磁盘返回独立文件集合，仓库不保留它；同步历史属于仓库的本地控制数据，由专用历史方法读取； ~load::<P>~ 仅处理身份； ~sync~ 自行恢复并回溯，不要求外部传入或保留历史快照，历史通过既有控制目录与本轮同步状态关联，仓库对象不持有历史集合。文件路径通过 ~repoId~ 与相对 ~path~ 定位。

根目录 ~.orgzlyignore~ 每次读盘时加载到本次操作上下文； ~OrgRepo~ 不保存规则。 ~load_files~ 返回完整的本次文件集合并携带对应的元信息标记，任务查询排除命中规则的标题。规则不改变文件同步、原始字节或 outbox；WebDAV 更新配置后，下一次读取立即使用新规则。

远端地址、用户名、密码、令牌、客户端证书和 Authorization header 都属于具体 ~SyncPolicy~ 实现的运行时配置，不进入 ~OrgRepo~ 或任何其他 core 数据结构。

* Org 解析与保真

~OrgFile~ 是仓库中的完整 org 文件，保存仓库标识、相对路径与读取到的原始字节。文件头标题通过 ~title()~ 从已有语法树读取； ~OrgFileMetadata~ 包含仓库 ID、相对路径、可空标题、标题行内片段、 ~has_conflict~ 、 ~is_ignore~ 、标题记录数、字节数与可空的本地修改时间，用于轻量列表，不保存正文或语法树。扫描读取的文件时间只保留在运行时，克隆文件或更新 TODO 默认设置时继续保留，不加入同步持久化数据。它在运行时使用 ~orgize::Org~ 生成无损语法树；该缓存不属于 core 的持久化模型，也不向其他模块暴露为项目自定义 AST。解析、编辑和展示的语义以 Emacs ~org-element.el~ 为准。

未修改时， ~OrgFile~ 必须直接写回 ~sourceBytes~ ，不能经解析器重新序列化。局部编辑只替换明确的 ~SourceRange~ 或在明确 ~SourcePosition~ 插入字节；变更完成后重新构造 ~orgize::Org~ 缓存。因此空行、换行风格、缩进、行尾空格、未知语法和未改动区域保持原始字节。

** 源码保真与最小差异写回

~OrgFile.sourceBytes~ 是唯一写回基准。编辑范围使用 ~SourceRange~ ，插入位置使用 ~SourcePosition~ ；这些编辑结构与保真写回函数位于 ~core::model::editor~ 。行号从 1 开始，列号与字节偏移从 0 开始，区间采用 ~[start, end)~ 。行列仅用于诊断和定位展示，实际替换必须以 UTF-8 字节偏移执行，避免多字节字符导致偏移错误。

- 未对文件应用编辑时，序列化必须直接返回读取时的 ~sourceBytes~ ，结果须与原文件逐字节一致。这包含编码字节、换行风格、末尾换行、空行、缩进、行尾空格、注释、drawer 顺序、未知语法和未建模内容。
- 替换或删除一个元素时，只能处理其 ~sourceRange~ 覆盖的字节；插入元素时，只能在明确的容器元素边界插入所需字节。写回不得格式化、重新缩进、对齐表格、规范化换行、重排元素，或重建未修改节点。
- 每次替换或插入后必须以更新后的 ~sourceBytes~ 更新受影响节点及其后续节点的 ~SourceRange~ 。跨行变更时必须从新缓冲区重新计算行号、列号和字节偏移，不能只对后续列号累加差值。

上述规则适用于本地保存与上传前序列化。源字节快照仅在本次解析/编辑会话内保留；关闭会话后可从文件重新读取，持久化层仍只保存同步元数据。标题编辑以 TaskPath 定位，可在操作组中提供文件版本校验；标题变化后返回新路径，任务身份按新标题投影。删除移除目标标题的完整子树。

* 任务写入意图

~OrgRepoWriteIntent~ 保存待上传文件的相对路径和最终内容哈希；原始内容只保存在用户 Org 文件、运行时回退快照及既有同步快照中。操作组仅为指定仓库的实际变更文件登记意图，同一文件在一组中多次修改只登记一个最终版本。

本地保存不等于远端上传。后续同步沿用现有条件写入、历史提交和版本一致后确认 outbox 的规则；操作历史与同步历史分别管理。

* 仓库同步记录

~OrgRepoSyncRecord~ 记录一次已发起的仓库同步及其最终结果。它由 ~OrgRepo.load::<P>~ 返回或由同步策略产生，不作为 ~OrgRepo~ 的字段保存，且包含零到多个 ~OrgRepoSyncFileRecord~ 。未扫描到文件、列举失败或在首个文件前失败时，文件记录可以为空；这不代表仓库没有文件。

~OrgRepoSyncRecord.trigger_reason~ 保存本轮调用的触发原因，独立于策略和执行结果；新完成记录均由仓库服务写入 ~Some~ ，失败、取消和中断记录同样保留。旧 JSON 缺失该字段时读取为 ~None~ ，不推断或补写原因，列表摘要与详情保持一致。

~OrgRepoSyncFileRecord~ 记录一次同步中一个相对路径的结果。WebDAV 成功文件在 ~detail.synced_source~ 中保存完整同步后文件快照；其他元数据、错误摘要与 outbox 不保存正文，所有记录均不保存绝对路径、远端 URL、认证 header 或配置凭据。

* 持久化与运行时边界

持久化层在仓库根目录的 ~.sync~ 中保存 ~OrgRepoSyncRecord~ 、 ~OrgRepoSyncFileRecord~ 及其版本元数据，并以 ~.sync/id~ 保存稳定 ~OrgRepoId~ ；完整布局、提交和恢复规则见 [[file:目录结构设计.org][目录结构设计]]。Org 内容由原始文件保存，运行时 ~orgize~ 缓存不持久化。持久化不得保存仓库根目录、远端完整 URL、配置凭据或运行时调度状态；完整内容仅作为成功文件快照和冲突备份保存。

~OrgWorkspace~ 的构造、目录扫描与仓库集合管理由 core 提供；宿主负责选择仓库目录、发起调用和日历投影。 ~core::webdav~ 负责 WebDAV HTTP 传输、认证、同步决策和磁盘提交；具体 HTTP 客户端和认证材料不得反向成为核心结构字段。

* 旧接口

旧的任务记录、同步状态、完整内容 outbox 与冲突记录不是当前核心数据结构；当前 outbox 仅保存 ~OrgRepoWriteIntent~ 元数据。当前实现不读取、不转换这些数据；任务投影、队列与 UI 流程由宿主按当前仓库级接口重新建立。

* 同步基准的仓库归属

每个仓库自行恢复历史，按原相对路径回溯最近 ~Synchronized~ 文件记录；整体失败中的成功文件依然有效。无历史时单端文件直接传输，两端均存在时保存固定远端并等待显式解决。解决时的本地缺失状态独立于空内容，持久化位置和完整恢复规则见 [[file:同步核心设计.org][同步核心设计]]。

* 文件 TODO 元信息与外部全局默认

全局默认配置由宿主编辑、保存并在运行时传给 Rust；core 不读取 Preferences，也不向 ~.sync/~ 写入默认配置。Rust 的 ~TodoConfig::default()~ 是唯一缺省来源， ~to_settings()~ 返回可编辑声明文本，初始为 ~#+TODO: TODO | DONE~ 。外部只有未保存配置时才获取默认值，已经保存的空配置表示禁用默认识别。

~OrgWorkspace.todo_defaults~ 向新仓库传递默认配置， ~OrgRepo.todo_defaults~ 用于扫描、下载、新增和合并。每个 ~OrgFile.todo~ 提供源字节与默认配置共同决定的有效元信息；文件保留运行时默认配置，以便克隆和局部编辑后重新解析。这些信息不是另一套 Org AST，不写入同步记录。

** 任务运行状态分类

~TaskStateCategory~ 枚举定义 ~Todo~ 、 ~Doing~ 、 ~Wait~ 、 ~Done~ 和 ~Cancel~ 。其中 ~Done~ 与 ~Cancel~ 为终态，其余为未完成状态； 统一输出 ~Cancel~ ；旧 JSON 分类值和 Org 分类声明中的 ~Cancle~ 仅作为读取兼容别名，原文件未涉及的字节不改写。任务的 ~state()~ 返回可空 ~TaskState~，无状态标题返回 ~None~；状态自身的 ~category~ 也可以为空 。它与文件 ~CATEGORY~ 分类及普通 ~TAGS~ 候选标签相互独立。

| 分类 | 展示名称 | 不可修改的默认状态值 |
|-
| ~Todo~ | 待办 | ~TODO~ 、 ~NEXT~ |
| ~Doing~ | 进行中 | ~INPROGRESS~ |
| ~Wait~ | 等待 | ~WAIT~ |
| ~Done~ | 已完成 | ~DONE~ |
| ~Cancel~ | 已取消 | ~CNCL~ |

默认状态与分类映射由 Core 内部固定维护，不提供额外的默认值或映射操作接口。~CoreSettings.addition_states~ 保存附加的 ~TaskState~ 列表；通过 Workspace 的 ~get_settings()~ 与 ~set_settings()~ 获取和整体替换，附加值的 ~category~ 可以为空。默认名称不可加入附加列表，附加名称不可重复，名称大小写敏感。

全局 ~CoreSettings~ 提供附加分类；仓库内 ~SETUPFILE~ 和文件的真实 ~#+TASK_STATE_CATEGORY:~ 声明仍由 Core 内部读取。文件覆盖 TODO 流程时继续使用同一份 Core 设置。示例：

#+begin_src org
,#+TODO: OPEN ACTIVE HOLD | FINISHED ABORTED
,#+TASK_STATE_CATEGORY: Todo OPEN
,#+TASK_STATE_CATEGORY: Doing ACTIVE
,#+TASK_STATE_CATEGORY: Wait HOLD
,#+TASK_STATE_CATEGORY: Done FINISHED
,#+TASK_STATE_CATEGORY: Cancel ABORTED
#+end_src

声明来自 ~orgize~ CST，源码与示例块的字面文本不参与配置。分类只解释有效 TODO 流程中已识别的状态，不自动增加文件关键词。默认状态按固定分类判断；未配置分类的自定义流程状态沿用 Org 分隔规则归为 ~Todo~ 或 ~Done~。通过 ~CoreSettings~ 显式设置为 ~None~ 的状态保留未分类，仍为任务，但不作为完成或取消终态，也不匹配任何 ~task_state_of(category)~ 目标。查询、HTML、日志、重复调度、TRIGGER 与标题统计共用分类结果。

任务修改目标通过 ~Task.task_state_of(category)~ 或 ~OrgFileMetadata.task_state_of(category)~ 获取。完成使用首个 ~Done~ 状态，捕捉与“将来，也许”使用首个 ~Todo~ 状态；缺失时禁用或返回中文错误，不替换为其他分类。重复任务恢复优先使用所属流程的 ~Todo~ 状态，其次为其他未完成状态；显式 ~REPEAT_TO_STATE~ 与类型流程沿用既有语义。

** 文内覆盖规则

~#+TODO:~ 、 ~#+SEQ_TODO:~ 和 ~#+TYP_TODO:~ 多行共同组成文件配置，整组覆盖全局默认。前两者表示顺序流程，后者表示类型。与 Emacs 一致，混用时依次汇集 ~TYP_TODO~ 、 ~TODO~ 、 ~SEQ_TODO~ ，同类保持出现顺序。声明名不区分大小写，状态名区分大小写。

未显式映射分类的状态按 Org 规则归类： ~|~ 后为完成状态；无分隔符时，每套流程最后一个状态为完成状态。若全部流程都没有给出完成状态，则文件最后一个关键词作为完成状态。跨流程同名状态的完成归属以文件有效完成集合为准。空 ~#+TODO:~ 也是覆盖，表示清空文件 TODO 识别。

设置影响整份文件，允许位于标题后面；源码块和示例块中的同名文本不构成声明。Rust 从 ~orgize~ CST 的真实 keyword 节点收集声明及来源区间，再用有效 ~ParseConfig.todo_keywords~ 解析整个文件，不通过逐行正则另建解析器。文件未直接声明时，仓库加载会按相对路径展开仓库内的 ~SETUPFILE~ ，提取其中的 TODO 与 ~TASK_STATE_CATEGORY~ 声明、 ~STARTUP~ 和 ~PROPERTY~ 作为该文件的有效设置；不执行 Emacs Lisp，也忽略仓库外或不存在的设置文件。

非法配置报告错误，不静默回退全局值。未修改文件直接返回原始字节；编辑声明后重算元信息，重新解析失败时回滚此次局部编辑。新增任务使用 ~initial_state~ ，即有效配置首个未完成状态；文件尚不存在时使用外部默认。没有可用未完成状态则拒绝保存。

~set_todo_defaults~ 校验并重解析内存文件，不改写原文；有文内覆盖的文件仍使用自身配置。运行时合并版本包含全局默认配置，有效配置变化后旧比较对象失效，必须重新比较。

* 文件头元数据解析

内部 ~FileKeywords~ 在 ~OrgFile~ 创建和重新解析时由同一 ~orgize~ 无损语法树生成，使用 ~BTreeMap<String, Vec<String>>~ 保存大写关键字名称与按声明顺序排列的值，另以 ~properties: BTreeMap<String, String>~ 保存合并后的文件默认属性。 ~#+~ 和冒号是语法标记，不进入名称；每条值去除首尾空白，显式空声明保留空字符串。消费者通过属性名读取，不再各自遍历关键字节点或读取声明原文。该映射不是持久化字段，也不扩展宿主接口。

~TITLE~ 的多行值按空格合并，符合 [[info:org#Export Settings][Org Info：导出设置]]； ~CATEGORY~ 与自定义 ~PROJECT_NAME~ 取首条， ~FILETAGS~ 与 ~TAGS~ 按有序多值读取。仅收集第一个标题前的直属关键字，独立于允许整篇配置的 TODO 设置与标题属性继承。规则来源见 [[info:org#In-buffer Settings][Org Info：缓冲区设置]] 与 [[info:org#Property Syntax][Org Info：属性语法]]。

编辑成功后语法树与元数据映射一起替换，旧文件对象和已返回快照保留旧值；未涉及的源字节保持不变。阅读投影不输出配置声明原文，未知关键字同样隐藏，源码、示例和段落中的字面文本继续保留。

* Drawer 属性语义

内部 ~Properties~ 从 ~orgize~ 属性节点建立只读语义投影；每个名称保留基础值与有序追加值，基础值缺失和显式空字符串分开。 ~PropertyEntry~ 同时保留规范化名称、值、追加标记与值的源区间，供局部编辑只改目标字节。字段名不携带冒号或 ~+~ 语法，追加语义由 Core 计算；文件默认值、日志设置、时间属性、合并身份和阅读投影共用此实现。

文件默认属性先处理已展开的 SETUPFILE 设置与文件内 ~PROPERTY~ 声明，再叠加顶部属性 drawer。需要继承时从外到内叠加父标题和自身 drawer，子级基础声明覆盖继承值，只有追加声明时延续继承值；显式 ~nil~ 保留给字段消费者终止相应继承。普通属性不自动启用继承，时间属性保持只读自身。文件关键字与默认属性分开保存， ~TITLE~ 与 ~CATEGORY~ 的既有关键字含义不变；自定义项目名可在文件头关键字缺失时读取文件默认属性。

规则依据 [[info:org#Drawers][Org Info：Drawers]]、 [[info:org#Property Syntax][Org Info：属性语法]] 和 [[info:org#Property Inheritance][Org Info：属性继承]]。普通 drawer 内容由原语法树生成安全 HTML，保留默认折叠；不进入卡片备注、正文首行或列表／文本提示统计。上游 ~orgize~ 无法识别的无空格空属性 ~:EMPTY:~ 继续保留原文，本次不修改该依赖或另建解析器；已生成属性节点的空值不会再遗漏。

* 通用批量查询模型

~CoreQuery~ 是唯一通用读取请求的枚举，分为 Task、File 和 Notification； ~OrgWorkspace.query~ 返回 ~Result<Vec<CoreQueryResult>, CoreError>~ ，成功数组与输入的位置、种类一一对应。结果不含逐项错误，任一错误使整批失败。请求与结果都是运行时值，不写入同步记录、outbox 或仓库缓存。

* 只读展示投影

OrgFile.render_html() 复用同一运行时 orgize 语法树，将整篇文件投影为安全 HTML 片段；不新增持久化字段、解析 AST 或同步记录。宿主负责主题、滚动和折叠交互，源字节仍是唯一保真序列化来源。

~render_document_html()~ 为完整文档提供额外的文件头语义、普通标题／任务区分、状态分类及正文存在标记；所有内容先以非折叠语义结构输出，由宿主选择阅读交互。属性、日志和未知内容安全保留，不新增持久化字段。 ~project()~ 复用现有项目名称计算，和两个渲染方法读取同一个文件快照。

~TitlePart~ 为标题渲染的运行时数据结构，字段是显示文字 ~text~ 、可选的外部链接 ~href~ 、来源是否为链接的 ~is_link~ 标记，以及可空的分数统计 ~count: Option<TitleCount>~ 。 ~TitleCount~ 的 ~completed~ 与 ~total~ 为可空的 ~u32~ ，仅空统计的两者均为空；有效分数保留文件记录的原始计数，零总数不作为已完成。异常分数与百分比保留普通文字，不新增持久化数据。 ~OrgFile.title_parts()~ 与 ~FilterTask.title_parts()~ 返回该结构的有序数组，文件元信息的 ~title_parts~ 复用文件标题结果。原始文件标题、任务标题、文件字节、逻辑 ID 与查询语义不变；投影不进入同步历史、outbox 或其他持久化数据。链接描述与统计节点均由 Core 解析，宿主不再次解释 Org 源码。

** 创建与字段修改

创建显式指定标题、插入位置和可选状态；未提供状态时创建无状态标题。状态须属于目标文件有效 TODO 配置；宿主需要创建任务时从文件元信息取得初始状态。正文不允许引入额外标题。Core 在每次创建时自动生成精确到分钟的本地非活动 ~CREATED~ 时间戳；创建参数不接受创建时间开关或关闭时间。创建为有效完成状态时，只有文件的关闭日志配置启用才生成 ~CLOSED~ ；配置关闭说明时同时记录空说明日志，不模拟一次进入状态的切换。

~TaskModificationOperation.path~ 定位一个标题， ~modifications~ 顺序执行，每项修改指定字段；修改 ~TODO~ 时同时维护 ~CLOSED~ 。字段类型由 ~TaskModification~ 枚举表示，JSON 中字段名为大写枚举值， ~value=null~ 清除可空字段，除随状态维护的关闭时间外，未涉及的字段保持原样。多项字段修改始终定位同一标题，不会因为前面改名而丢失后续字段操作。

| 枚举 | 值与清理语义 |
|-
| ~TITLE~ | 字符串修改标题文字；空值清除文字，不改变 TODO、优先级或标签。 |
| ~BODY~ | 字符串替换当前标题自身正文；空值清空。保留规划、属性 drawer 和子标题；拒绝正文引入额外标题。 |
| ~TODO~ | 设置目标文件已配置状态；空值清除状态。进入有效完成状态时仅按显式关闭日志配置生成 CLOSED，恢复未完成或清除状态自动清理已有 CLOSED。 |
| ~PRIORITY~ | 当前文件有效分级中的单个大写字母；空值清除优先级，允许清除已不在配置中的原值。 |
| ~TAGS~ | 标签数组；空值或空数组清除自身标签，不修改继承来源。 |
| ~SCHEDULE~ 、 ~DEADLINE~ | 完整有效 Org 时间戳，保留重复器等表达式；空值清除对应规划项。 |
| ~ADDRESS_LINK~ | 提交新旧 URI，仅替换子树中首个匹配的真实链接，保留描述及其他字节；空值拒绝，不把源码块中的伪链接当成真实链接。 |

~CREATED~ 与 ~CLOSED~ 不属于可提交的字段操作，旧字段输入返回错误。创建时间仅在新建时生成，后续编辑、移动、读取及同步保留已有值，不为旧记录回填。关闭时间由 ~TODO~ 操作根据当前文件的有效 ~TodoMetadata.done_keywords~ 及日志配置自动维护；文件内 ~TODO~ 、 ~SEQ_TODO~ 、 ~TYP_TODO~ 覆盖 SETUP 的状态声明，没有声明时沿用全局默认。每次写入重新加载文件和嵌套 ~SETUPFILE~ ，不硬编码状态名。时间维护、重复调度、日志和状态变更共用版本校验、提交、失败回滚和数据通知。

移动保留整棵子树，仅调整真实标题的星号层级；目标文件配置不能改变子树标题或 TODO 状态的解释。删除移除目标完整子树。备忘整理由清除 TODO、优先级、规划字段的 Modification 和随后的 Movement 组合完成，不在 Movement 中复制字段修改语义。

** 状态变化、重复调度与日志

语义依据 [[info:org#Closing items][Org Info：关闭记录]]、 [[info:org#Tracking TODO state changes][状态变更日志]] 与 [[info:org#Repeated tasks][重复任务]]，由 Core 的 ~task_state~ 统一执行；宿主继续只提交 ~TODO~ 字段。文件与 SETUP 的配置通过真实 keyword 节点读取，不执行 Lisp。

*** 完成与关闭时间

应用默认使用 ~org-log-done=nil~ ，没有完成日志配置时只改变状态，不生成 ~CLOSED~ 。文件 ~#+STARTUP: logdone~ 或 ~lognotedone~ ，以及有效 ~LOGGING~ 中的对应设置，才启用关闭记录；从未完成状态进入文件定义的任意完成状态时，写入当前本地非活动 ~CLOSED~ 时间戳；恢复未完成或清除状态时移除自身关闭时间，保留子标题和其他规划。已完成状态之间切换保留已有关闭时间，只有关闭记录启用时，旧完成任务缺少关闭时间才会在显式设置状态时补齐。文件 ~#+STARTUP: logdone~ 、 ~lognotedone~ 、 ~nologdone~ 及有效 ~LOGGING~ 属性可覆盖关闭记录策略。状态修改生成的 ~SCHEDULED~ 、 ~DEADLINE~ 与 ~CLOSED~ 共用一行，恢复时完整移除关闭项；存在 ~PROPERTIES~ drawer 时，自动创建的 ~LOGBOOK~ drawer 放在其后。

*** 重复完成与重新调度

进入完成状态时处理当前标题自身的所有真实活动重复时间戳，包括计划、截止、标题及正文；不处理非活动时间戳、源码、示例、逐字内容或子标题中的时间戳。重复完成后移除 ~CLOSED~ 并恢复待办状态，记录本次完成的历史由显式日志配置决定。

| 重复器 | 调度规则 |
|-
| ~+Nunit~ | 按原时间向后推进一次，即使下一次仍然过期。 |
| ~++Nunit~ | 至少推进一次并追赶到未来；按小时比较当前时刻，其他单位按 Org 的自然日规则追赶。 |
| ~.+Nunit~ | 从本次完成的自然日重新计算；按小时重复则以当前时刻计算。 |

~unit~ 支持 ~h~ 、 ~d~ 、 ~w~ 、 ~m~ 、 ~y~ ；支持保留 ~/Nunit~ 窗口，单次预警 ~--Nunit~ 在重复后清除，普通预警 ~-Nunit~ 保留。按小时重复必须存在时刻，否则整个操作组失败。月和年遵循 Org 的日期溢出归一化，例如一月三十一日加一个月进入三月；时间范围保持持续时长，独立日期范围的另一端没有重复器时保持原样。

恢复状态优先使用自身或文件默认的 ~REPEAT_TO_STATE~ ，无有效指定时，顺序流程恢复该流程首状态，类型流程恢复原状态。原条目没有状态且未指定有效恢复状态时，重复后恢复无状态。存在重复时间戳时，未带重复器的 ~SCHEDULED~ 清除，未带重复器的 ~DEADLINE~ 保留。所有改写保持未涉及的正文、属性、创建时间和字节格式。

*** 文件内 TRIGGER

待办进入完成状态后，在状态日志与重复调度之后解释 ~TRIGGER~ ，支持文件内的目标查找、条件、状态、日期、标签、优先级和属性动作。联动目标共用本文件隔离快照、版本校验、回退、outbox 和单次通知；不支持跨文件联动。不支持动作静默跳过并继续后续规则，已支持动作的非法参数或循环联动使整组回滚。实现范围与 Edna 对照依据见 [[file:TRIGGER触发器设计.org][文件内 TRIGGER 触发器]] 。不新增公开模型或宿主专属操作类型。

*** 配置驱动的日志

应用默认关闭完成、普通状态及重复日志：没有对应配置时不生成关闭时间或新的日志项，已有日志保持原样。重复任务的 ~LAST_REPEAT~ 仅在重复日志启用或已有真实 CLOCK 时按 Org 规则更新。关键词 ~!~ 记录进入状态时间， ~@~ 记录带时间的说明，斜线后的标记记录离开状态；目标状态有进入日志时优先使用目标配置，不重复记录来源日志。当前接口不接收说明文本， ~@~ 按 Org 允许的空说明确认方式记录。清除为无状态不写状态日志；显式重复设置同一状态时，按 Org 的关键词配置记录。

重新打开完成或取消任务时，宿主仅提交有效待办状态；Core 清理自身 ~CLOSED~ ，保留已有状态日志、关闭说明和 CLOCK，不修改计划、截止、重复日期或 ~LAST_REPEAT~ 。是否新增重新打开日志仅由目标进入标记或来源离开标记决定，只有关闭日志配置时不自动新增状态日志。即使日志已禁用，本应用仍清理旧关闭时间；这是与 org-mode 在关闭日志禁用时保留旧 ~CLOSED~ 的明确差异。

文件 ~#+STARTUP: logrepeat~ 、 ~lognoterepeat~ 、 ~nologrepeat~ 控制重复日志；重复日志启用或当前记录含真实 CLOCK 时更新 ~LAST_REPEAT~ 。 ~LOGGING~ 属性从当前标题向祖先继承，也可来自文件 ~#+PROPERTY~ ；非空值先清空已有状态、完成与重复日志配置，再应用属性中指定的日志选项及状态标记， ~LOGGING: nil~ 禁用全部日志。

~#+STARTUP: logdrawer~ 将日志写入 ~LOGBOOK~ ， ~nologdrawer~ 写入正文；继承的 ~LOG_INTO_DRAWER~ 可指定自定义 drawer 或以 ~nil~ 覆盖。 ~logstatesreversed~ 默认新记录在前， ~nologstatesreversed~ 按时间追加。已有 drawer 原样保留，不把源码中的 drawer 样式文字当成日志容器。

*** 子任务限制

当前标题存在有效未完成状态的后代任务时，拒绝将自身切换为完成状态；检查覆盖整个子树，跨越无状态标题。全部后代任务已完成时允许完成父任务；无状态的普通标题不构成依赖。完成集合取自当前文件有效配置，不硬编码状态名。设置未完成状态或清除状态不受子任务限制，其他字段仍可编辑。该规则参考 [[info:org#TODO dependencies][Org 的未完成依赖检查]]。

任务恢复为未完成或从完成状态清除状态时，同时将所有已完成的祖先任务恢复为各自流程的待办状态；流程中优先选择待办分类状态，其次选择首个未完成状态，仅含完成状态的流程回退到文件初始状态，无可用状态则拒绝整组操作。无状态标题与已有未完成祖先保持原状态，但不阻断向上恢复；兄弟任务不变。重复完成后恢复为未完成状态也遵循该规则。祖先恢复复用普通状态修改的关闭时间清理、日志配置与标题统计；来源任务和全部祖先在同一操作组内提交，任一步失败全部回滚。

** 多记录合并操作规划

~TaskMergeRequest.paths~ 严格按用户选择顺序排列。第一条记录作为保留位置，标题改为“合并: 原始标题”；所选全部记录（包括第一条）转换为同一个正文列表，正文缩进到所属项，子记录递归转为嵌套列表。状态、日期、优先级和自身属性保留第一条记录的原值，其他元数据及日志随原始标题存入 ~#+begin_comment org_tasks_merge_original~ 块，使用逗号转义保护标题与块结束符。阅读与备注投影隐藏该归档，备注编辑保持归档字节；再次合并时旧归档平铺保留，避免复制整份历史。

~TaskMergePlan~ 包含普通 ~operation_group~ 与结果 ~main_path~ ，不增加 ~TaskOperation~ 变体。来源根及第一条记录原有的子树按原文逆序生成 Deletion，随后使用删除后的路径生成一次 Modification，修改 BODY 与 TITLE。规划复用原执行器在内存中验证版本、路径及结构，但不写盘或生成历史；真实执行只提交一组操作，复用原有文件版本、回退和 outbox 机制。

规划拒绝重复、祖先与后代重叠、跨文件、受保护冲突节点，以及转换为列表后会丢失 ID／CUSTOM_ID 或当前文件标题引用的情况。第一条记录自身 ID 保留，其余标题定位引用不自动迁移。 ~main_path~ 按最终标题与出现序号重新投影，供合并成功后定位。

** 顺序、提交与失败处理

1. 根据操作组收集所需源文件、目标 parent 和 after 所在文件；验证安全路径、仓库归属和可选的 ~file_versions~ ，将原始内容加载到隔离内存快照。不存在的 Org 文件可由创建操作产生，移动目标须已存在于本组内存快照；父目录须已存在，加载阶段不创建目录，不跟随文件符号链接。
2. 按 operations 顺序执行；后续操作使用前面步骤产生的新路径。组内改名、移动、重名项序号变化后，旧路径可能失效，Core 不猜测调用意图。提交成功后发布仓库数据变化事件；失败或无实际文件变化不发布。
3. 任一内存操作失败即丢弃全组，不修改用户文件、outbox 或操作历史。受影响但未修改的文件不重复写入。
4. 所有内存操作完成后，准备完整临时文件、回退字节和最终 outbox；再次核对原始磁盘字节，统一进入提交。普通提交 I/O 失败时以已准备的原始字节回滚已替换文件，并清理本次临时文件和意图。
5. 全部文件提交成功后释放本次文件集合并发布数据变化通知，将一次 ~TaskFallbackGroup~ 与原操作组一起追加到 ~TaskOperationHistory~ 。失败的组不形成成功历史，也不发布数据变化事件。

单文件替换采用同目录原子重命名。普通文件系统不提供跨文件、跨仓库的整体原子替换；进程崩溃、介质不可写或回滚期间的外部并发写入不能仅靠内存保证恢复。检测到回滚目标已被外部写入时保留回退文件并明确返回存储错误，不覆盖外部数据，也不将部分提交登记为成功。当前契约覆盖可正常完成回滚的执行错误，崩溃恢复与持久化事务日志另行设计。

* 日志文件备份与冲突比较模型

历史文件结果与原始快照在同步完成时固定。 ~WebDavSyncFileSummary~ 不再投影 ~Resolved~ 结果；其 ~backup~ 仅在远端删除具有 ~deleted_archive~ 材料时用于手机阅读，历史中的冲突不根据当前文件自动改为已解决。

当前文件尾部用一个自有 ~CONFLICT~ 标签的一级容器保存全部冲突点，每个直接子标题具有 ~CONFILICT_ID~ 定位属性和 ~#+CONFLICT_REASON:~ 关键字，可见后代或 example 块保存完整候选。 ~OrgFile.conflict_ids()~ 返回这些 ID， ~has_conflict()~ 根据真实标题标签取得标记；不生成额外文件头字段。

冲突比较以任务自身为最小节点，不把子任务并入父任务差异。修改候选保留修改后的完整任务记录，并按 ~TODO~ 、优先级、标题文字、标签新增／删除、 ~SCHEDULED~ 、 ~DEADLINE~ 、 ~CLOSED~ 、日志行和正文文本生成字段差异；日志新增／删除按时间升序，正文没有变化时不生成文本片段。字段差异用于展示和定位，完整记录用于无法定位时的用户确认插入。

应用修改候选时，Core 先按稳定 ~Org ID~ 或生成期标题路径定位原任务；定位成功只更新已确认的字段，保留远端未涉及字段、子任务和原始字节。定位失败不猜测同名记录，只有明确选择插入位置后才使用完整记录插入。字段应用、完整记录插入和丢弃均使用同一版本校验、冲突保护与事务提交。

* 文件冲突标记与重置恢复模型

~OrgFile.has_conflict()~ 与 ~OrgFileMetadata.has_conflict~ 取自真实标题的 ~CONFLICT~ 标签，不扫描源码块或解析旧文件头字段。 ~OrgFile.conflict_ids()~ 为文件对象提供当前冲突点定位值；查询与普通编辑排除／保护整个容器。重置仍保留仓库身份，完整事务与恢复边界见 [[file:同步核心设计.org::*仓库重置][仓库重置]]。

* 卡片编辑正文与检查清单

~OrgFile.task_edit_content~ 根据任务完整路径生成 ~TaskEditContent~ ，包含保留内部用途标签的 ~own_tags~ 、原始备注 ~notes~ 与 ~checklist~ 。规划、属性抽屉和其他 drawer 不进入备注。规划范围与任务操作器共用，兼容重复窗口（如 ~.+1w/2w~ ）导致规划行被语法树并入段落的情况；备注投影与备注修改使用同一范围，未修改的规划字节保持原样。正文内容开始后出现的同名普通文本继续作为备注保留。独立 checkbox 列表投影为清单，混有普通条目的列表整体保留在备注中；源码块中的字面 checkbox 不生成条目，子标题清单不归入父任务。嵌套 checkbox 保留深度；部分完成状态单独标记，未操作时不改写。

* 标题统计更新

规则依据 [[info:org#Breaking Down Tasks][Org Info：Breaking Down Tasks]] 与 [[info:org#Checkboxes][Org Info：Checkboxes]]。Core 使用 Org 默认层级语义，即 ~org-hierarchical-todo-statistics~ 与 ~org-checkbox-hierarchical-statistics~ 均为真，通过标题的 ~COOKIE_DATA~ 属性表达局部递归设置；统计属于保真编辑的派生修改，不新增持久化字段或宿主专属配置。

| 触发修改 | 未固定来源时的统计行为 |
|-
| ~TITLE~ | 校验标题结构后重算已有或新输入的统计；本节有 checkbox 时统计列表，否则统计子任务，相当于在标题执行显式统计更新。 |
| ~CHECKLIST~ 新增、删除、切换完成 | 更新本标题的 checkbox 统计。 |
| ~TODO~ 设置、清除、切换 | 更新直属父标题的子任务统计；递归配置可扩大统计范围并向上更新。 |

同一标题既有列表又有子任务时，两类数量不相加。Info 明确规定未固定来源的统计显示最后变化的一类； ~COOKIE_DATA: checkbox~ 固定为列表，TODO 变化不覆盖该计数； ~COOKIE_DATA: todo~ 固定为子任务，checkbox 变化不覆盖该计数。更新标题时也遵循显式来源。

checkbox 默认只统计本节最外层条目，部分完成计入总数但不计为完成；本标题的 ~COOKIE_DATA~ 包含 ~recursive~ 时统计嵌套 checkbox。TODO 默认只统计直属子标题中有有效任务状态的记录，完成集合取自文件有效的 ~TodoMetadata.done_keywords~ ，不硬编码状态名；无状态标题不计入总数。~COOKIE_DATA: todo recursive~ 统计整个子树的任务；后代任务状态变化时，从直属父级逐级更新，直至最近定义该递归属性的祖先，外部祖先不更新。内层 ~COOKIE_DATA~ 覆盖继承设置，固定为 ~checkbox~ 的节点阻止 TODO 统计继续向上传播。

分数写为 ~[completed/total]~ ，百分比向下取整；空列表写为 ~[0/0]~ 与 ~[0%]~ 。仅修改真实统计语法节点，没有统计节点时不补建；标题中的链接、代码、逐字文本以及未涉及的正文和源码块字节保持原样。父级计数变化可改变后代的完整标题路径和字节偏移，Core 在操作内维护定位，不要求宿主自行计算新路径。全部统计与原始修改共同提交、回退和校验版本，最终无字节变化不广播，失败不发布部分更新；父任务状态不随计数自动切换。

优先级采用与 TaskState 相同的值对象边界，当前值与候选均由 Core 生成。原文仍保存 Org 字母，不持久化分类或颜色。

#+begin_src rust

文件及 SETUPFILE 中有效的 ~#+PRIORITIES: A C B~ 按 Org 的最高、最低、默认顺序解析；可选字母为最高至最低的闭区间，文件头配置覆盖 SETUPFILE。最高与最低必须为单个大写字母且范围有序，默认字母必须位于范围内；正文与源码中的字面配置不参与。文件与 SETUPFILE 均未配置时使用 Core 内置 ~A C B~ ，返回 A、B、C 候选；无效声明拒绝读取，不把配置错误转换为默认选项。默认值按 [[info:org#Priorities][Org Info：Priorities]] 解析：第三项为默认字母；没有声明时使用 Org 默认 B。默认值参与优先级排序、有效优先级查询与 TRIGGER 循环，不给未设置优先级的任务回填显式字母。

默认优先级来自 [[info:org#Priorities][Org Info：Priorities]]：未声明时使用 B，文件头 ~#+PRIORITIES~ 的第三项覆盖 SETUPFILE 默认值。Core 在同次解析中生成 ~OrgFileMetadata.default_priority~ ，任务通过 ~default_priority()~ 读取共享快照， ~effective_priority()~ 取显式值或此默认值；Harmony 投影为任务和文件元信息的只读 ~defaultPriority: TaskPriority~ 。文件与 SETUPFILE 均未声明时使用 Core 内置 ~A C B~ 配置，候选 A、B、C 分别归为 ~Hight~ 、 ~Middle~ 、 ~Low~ ，默认 B 归为 ~Middle~ ；默认值不产生标题色块、不写入 Org 原文。优先级升降序与 ~p.<letter>~ 使用有效字母， ~ps.<letter>~ 只查询显式值，相同优先级沿用源次序。

~OrgFileMetadata.priority_options~ 保存可序列化的候选值对象；~priority_options()~ 返回独立副本。最小字母归为 ~Hight~ ，最大字母归为 ~Low~ ，中间字母均为 ~Middle~ ；只有一项时归为 ~Hight~ ，两项时没有 ~Middle~ 。~task_priority_of(category)~ 返回候选中按字母升序排列的首个匹配副本，没有匹配项时为空。

~FilterTask.priority()~ 返回当前显式 ~TaskPriority~ 的可空引用；原值不在候选中时保留 ~name~ 且 ~category=None~ ，未设置时整个对象为空。任务的 ~priority_options()~ 和 ~task_priority_of(category)~ 委托同一共享文件元信息，因此与文件结果使用相同配置和版本。取得的旧快照不受文件重载影响。PeriodCategory 仅表示优先级，与循环、习惯和状态分类独立。

创建和字段修改统一校验目标字母属于当前文件有效候选；未配置文件可直接设置 A、B、C，清除原值始终允许。非法分级使整个操作组回滚，不产生部分字段修改、历史或上传意图。优先级排序与 ~p.<letter>~ 按显式字母或所属文件默认字母求值；~ps.<letter>~ 仅匹配显式值。排序同值时沿用文件路径与源位置次序，不以分类代替实际字母；TRIGGER 的优先级循环使用文件有效范围与默认字母。

* 结构化任务日志

~TaskLog~ 是 ~FilterTask.logs()~ 与 ~RenderedTaskContent.logs~ 返回的只读枚举，不是新的解析 AST 或持久化实体。解析语义依据 Org 9.8 manual 的 Progress Logging、Closing items、Tracking TODO state changes、Deadlines and Scheduling、Clocking Work Time 和 Refile and Copy；记录标题按默认 ~org-log-note-headings~ 模板识别。

| 枚举分支 | 标准记录 | 专属字段 |
|-
| ~TaskStateChange~ | State "新状态" from "原状态" | ~from~ 、 ~to~ |
| ~TaskNote~ | Note taken on | 无 |
| ~TaskClosingNote~ | CLOSING NOTE | 无 |
| ~TaskReschedule~ | Rescheduled from | ~previous~ |
| ~TaskScheduleRemoval~ | Not scheduled, was | ~previous~ |
| ~TaskDeadlineChange~ | New deadline from | ~previous~ |
| ~TaskDeadlineRemoval~ | Removed deadline, was | ~previous~ |
| ~TaskRefile~ | Refiled on | 无 |
| ~TaskClock~ | CLOCK 计时间隔或运行中的计时 | ~start~ 、可空 ~end~ 、可空 ~duration~ |
| ~Other~ | 自定义模板、无效时间或其他内容 | 安全富文本 ~html~ |

除 ~TaskClock~ 与 ~Other~ 外，各分支均包含 ~timestamp: String~ 和 ~note_html: String~ 。时间使用 ~YYYY-MM-DD~ 或 ~YYYY-MM-DD HH:MM~ ，保持 Org 本地日历时间，不补造时区或缺失时刻；计时的 ~start~ 、 ~end~ 使用同一格式。 ~previous~ 保留原规划时间戳，包括重复器； ~duration~ 保留 Org CLOCK 已记录的时长，不重新计算。

只遍历当前任务正文中的真实 LOGBOOK drawer，名称不区分大小写；源码、示例和其他 drawer 中的字面标记不生成日志。每个直接列表项是一条记录，续行与嵌套列表归属当前记录的附注；不把附注中的日志样式文字再次拆分。多个 LOGBOOK 按原文顺序合并，空 drawer 返回空数组，重复记录保留。标题要求完整匹配默认模板且时间有效，自定义模板整体回退为 ~Other~ 。附注与回退内容复用 Core 的安全 HTML 投影，保留行内样式、链接、列表和代码，不执行脚本或加载外部资源。

JSON 使用 ~type~ 标签和 camelCase 字段，如 ~taskStateChange~ 、 ~taskNote~ 、 ~noteHtml~ 。旧 ~logbook_html~ 继续供既有宿主消费，手机任务日志改用结构化枚举；所有投影均不改写源文件、同步记录或 outbox。
