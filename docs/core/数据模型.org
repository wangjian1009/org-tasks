* 范围与状态

本文集中描述 Org Tasks Rust 核心的数据结构、关系与持久化映射。当前代码的唯一事实来源是 ~core/src/lib.rs~；本文中的“规划模型”仅说明后续完整数据服务的目标，不表示已经落盘或开放 HTTP 接口。

* 通用类型与枚举

| 类型或枚举      | 值或格式                                                                                   | 说明                                         |
|-----------------+--------------------------------------------------------------------------------------------+----------------------------------------------|
| ~TimestampMs~   | ~i64~                                                                                      | Unix epoch 毫秒。                            |
| ID              | 非空 UUID 字符串                                                                           | 任务、作业、outbox 和幂等键均由外层生成。    |
| 内容版本        | 小写 SHA-256 十六进制字符串                                                                | ~contentHash~、~sourceRevision~ 等字段使用。 |
| ~TodoState~     | ~TODO~、~NEXT~、~WAIT~、~DONE~、~CNCL~                                                     | org 任务状态。                               |
| ~Priority~      | ~A~、~B~、~C~                                                                              | org 优先级，可为空。                         |
| ~FileSyncState~ | ~synced~、~local_changed~、~remote_changed~、~remote_deleted~、~conflict~                  | 文件同步状态。                               |
| ~JobKind~       | ~sync~、~add_task~、~retry~、~resolve_conflict~、~rebuild_calendar~、~refresh_local_index~ | 作业类型。                                   |
| ~JobState~      | ~queued~、~running~、~retry_wait~、~blocked~、~completed~、~failed~                        | 作业生命周期。                               |
| ~JobPriority~   | ~foreground~、~background~                                                                 | 前台和后台调度优先级。                       |
| ~ConflictState~ | ~open~、~resolved~、~dismissed~                                                            | 冲突处理状态。                               |

* 当前领域实体

| 实体             | 关键字段                                                                                                     | 责任                                                       | 当前状态                         |
|------------------+--------------------------------------------------------------------------------------------------------------+------------------------------------------------------------+----------------------------------|
| ~TaskRecord~     | ~id~、~relativePath~、标题、状态、时间、标签、正文与版本                                                     | org 解析器产生的瞬态投影，用于本次同步和日历操作。          | 已定义，绝不由 ~CoreStore~ 落盘。 |
| ~FileSyncRecord~ | ~relativePath~、~contentHash~、远端 ETag/时间/大小、~lastSyncedAt~、~syncState~                              | 下次同步的文件变化检测元数据。                              | 已定义并由 HTTP/Harmony 仓储持久化。 |
| ~OutboxEntry~    | ~id~、~relativePath~、~orgEntry~、~contentHash~、~createdAt~                                                 | 本地新增任务等待条件上传的原始写入意图。                    | 已定义并由 HTTP/Harmony 仓储持久化。 |
| ~SyncJob~        | ~id~、~idempotencyKey~、~kind~、~state~、~priority~、~taskId~、~outboxEntryId~、重试与时间                   | 可合并、可恢复且保留历史的异步工作单元。                    | 已定义并由 HTTP/Harmony 仓储持久化。 |
| ~ConflictRecord~ | ~id~、~relativePath~、本地/远端版本、~state~、~message~、~createdAt~                                        | 本地与远端不能自动合并的分歧。                              | 已定义，尚未写入 CSV。           |

~relativePath~ 始终相对于同步入口本次传入的基准目录，不能是绝对路径或包含 ~..~；基准目录不进入任何持久化记录。~SyncJob.taskId~ 在 ~JobKind::AddTask~ 时标识创建意图，~outboxEntryId~ 指向可恢复的 ~OutboxEntry~。解析任务可从基准目录中的 org 文件重新生成。

* 写入请求与提交单元

| 结构                   | 组成                                                        | 作用                                                                  |
|------------------------+-------------------------------------------------------------+-----------------------------------------------------------------------|
| ~NewTask~              | 新任务内容、相对 ~.org~ 路径、标签、时间、优先级与 org 文本 | 创建任务的输入，不直接持久化。                                        |
| ~CreateTaskRequest~    | 幂等键、作业 ID、outbox ID、原因、优先级、时间与 ~NewTask~  | 生成一个 ~OutboxEntry~ 和一个 ~SyncJob(AddTask)~，不生成持久化任务投影。 |
| ~CreateSyncJobRequest~ | 幂等键、作业 ID、原因、优先级、日历开关与时间               | 创建或合并一个 ~SyncJob(Sync)~。                                      |
| ~TaskCreation~         | ~taskId~、~outboxEntry~、~job~                              | 创建任务成功后的返回值。                                              |
| ~CoreChangeSet~        | ~fileSyncRecords~、~outboxEntries~、~jobs~                  | ~CoreStore::apply~ 的原子提交单元。                                   |

~CoreService~ 先校验 ID 和任务目标路径，再进行幂等检查，最后通过一次 ~CoreStore::apply~ 提交 ~CoreChangeSet~。持久化适配器必须保证该调用的原子可见性。

* 当前 HTTP CSV 映射

~CsvCoreStore~ 只落盘下次同步所需的文件变更检测元数据、outbox 和作业历史；不落盘解析任务、完整文件或基准目录。

| CSV 文件       | 主键              | 领域实体与用途                                  |
|----------------+-------------------+---------------------------------------------------|
| ~files.csv~    | ~relativePath~    | ~FileSyncRecord~，仅保存变更检测元数据。          |
| ~jobs.csv~     | ~id~              | ~SyncJob~，保留已完成和失败作业作为同步历史。      |
| ~outbox.csv~   | ~id~              | ~OutboxEntry~，保留待上传的原始 org 写入意图。     |

这些文件位于 ~snapshots/<generation>/~，由 ~current.csv~ 指向已提交 generation。完整快照写入并同步后才原子替换 manifest，因而 ~CoreChangeSet~ 不会出现半提交状态。详细目录和服务运行约束见 [[file:../http/服务命令行设计.org][HTTP 服务命令行设计]]。

* 规划模型

完整数据服务后续会增加以下结构；当前 core 与 HTTP CSV 仓储尚未实现其持久化或路由。

| 模型              | 关键字段                                                            | 目标职责                                    |
|-------------------+---------------------------------------------------------------------+---------------------------------------------|
| ~CalendarBinding~ | ~taskId~、~calendarName~、~eventId~、~eventFingerprint~、~syncedAt~ | org 任务与系统日历事件的映射。              |
| ~ExecutionLease~  | ~id~、~jobId~、~workerId~、~leaseExpiresAt~、~actions~              | 认领后交给 Harmony 平台执行的 action 计划。 |
| ~ServiceMeta~     | schema 版本、变更游标、最近成功同步时间                             | 服务级元数据。                              |
| ~ChangeLog~       | cursor、资源类型、资源 ID、变更时间                                 | 增量 UI 刷新。                              |

规划中的 SQLite 表为 ~service_meta~、~files~、~calendar_bindings~、~outbox_entries~、~sync_jobs~、~execution_leases~、~conflicts~ 与 ~change_log~；其中 ~files~ 同样只保存相对路径同步元数据。解析任务和下载的 org 文件均不进入持久化数据库，org 文件由每次传入的基准目录定位。
