* 范围与状态

本文定义以 ~OrgWorkspace~ 为全局入口、以 ~OrgRepo~ 为文件仓库边界的核心领域模型。一个应用通常只构造一个 ~OrgWorkspace~ ，其中包含零到多个仓库。每个仓库由构造时传入的根目录指定，并拥有当前文件快照与同步记录。仓库根目录内 ~.sync~ 的持久化布局见 [[file:目录结构设计.org][目录结构设计]]。

~OrgFile~ 、递归 ~OrgEntry~ 与 ~OrgElement~ 描述解析后的 org 内容树； ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ 描述一次仓库同步及其中各文件的同步结果。当前 ~core~ 已实现这些目标数据结构、保真编辑接口和仓库级服务端口；Harmony 与 HTTP 已仅使用仓库同步记录持久化接口，不再保留旧作业模型。

调度、线程、SDK 生命周期、监控回调、认证材料、文件系统访问和网络 I/O 都是宿主或适配层的运行时概念，不是本章的核心数据结构。实体关系的 TikZ UML 源码与本文同步维护。

* 基础约定

| 类型或规则 | 定义 |
|-
| ~TimestampMs~ | Unix epoch 毫秒。 |
| ~OrgRepoId~ | 非空 UUID 字符串；同一逻辑仓库重建 workspace 时必须保持不变。 |
| ~OrgEntryId~ | 由仓库 ID、相对路径和稳定 outline 位置派生的标识。显式 ~ID~ property 存在时优先使用它。 |
| ~OrgRepoSyncRecordId~ | 一次同步记录的非空 UUID 字符串。 |
| ~OrgRepoSyncRecord.kind~ | 策略类型标识；必须与加载和执行该记录的 ~SyncPolicy::KIND~ 一致。 |
| 相对路径 | ~relativePath~ 相对于所属 ~OrgRepo.rootDirectory~ ，不能是绝对路径或包含 ~..~ 。 |
| 源位置 | ~SourceRange~ 是引用 ~OrgFile.sourceBytes~ 的半开区间 ~[start, end)~ 。 ~SourcePosition~ 同时记录 1-based 行号、0-based UTF-8 字节列号与 0-based UTF-8 字节偏移；它仅在当前文件快照内有效，不能作为跨版本稳定 ID。 |
| 内容与版本 | ~OrgFile.sourceBytes~ 保存当前解析/编辑会话的完整源字节，用于保真写回；它不写入 core 持久化状态或同步记录。内容树可由文件重新解析； ~LocalFileVersion~ 只保存内容哈希， 策略专属的文件 ~detail~ 保存远端 ETag、修改时间和大小等信息。 |

* 工作空间与仓库

~OrgWorkspace~ 是应用级管理对象，负责聚合仓库，不表示后台任务、线程池、网络客户端或持久化实现。一个应用通常只需要一个 workspace；测试、隔离导入或多账户场景可以构造多个 workspace。

~OrgRepo~ 是一个独立文件仓库。其 ~rootDirectory~ 在构造时由宿主提供，用于扫描和解析该仓库内的文件；该绝对路径不能写入 core 的持久化状态。 ~files~ 保存扫描后的文件快照， ~syncRecords~ 保存已完成同步的仓库历史。文件路径通过 ~repoId~ 与相对 ~path~ 定位。

远端地址、用户名、密码、令牌、客户端证书和 Authorization header 都属于具体 ~SyncPolicy~ 实现的运行时配置，不进入 ~OrgRepo~ 或任何其他 core 数据结构。

#+begin_src rust
pub struct OrgWorkspace {
    pub repos: Vec<OrgRepo>,
}

pub struct OrgRepo {
    pub id: OrgRepoId,
    pub root_directory: String,
    pub files: Vec<OrgFile>,
}
#+end_src

* Org 内容树

~OrgFile~ 是仓库中一个可解析 org 文件的内容投影。它以 ~repoId~ 与相对 ~path~ 标识， ~path~ 必须相对于所属 ~OrgRepo.rootDirectory~ 。 ~sourceBytes~ 是读取时得到的完整原始字节快照，并拥有零到多个顶层 ~OrgEntry~ 。没有 headline 的文件仍是有效的 ~OrgFile~ ，其 entries 为空；其前言、注释和其他未归属 entry 的片段仍由 ~sourceBytes~ 保留。

~OrgEntry~ 对应一个 org headline。 ~OrgFile~ 只直接拥有顶层 entry；子 headline 通过 ~OrgEntry.parentId~ 与递归子 entry 表达。因此一个 entry 可拥有零到多个子 entry，同时最多有一个父 entry。文件内的 outline 关系必须保持解析顺序。

~OrgEntry.elements~ 是有序元素列表。模型允许零到多个元素，以便表示解析失败后的部分投影；正常解析出的 headline entry 必须恰好包含一个 ~Title~ 元素。标题的 TODO keyword、优先级和 tags 均属于该元素，不能另建平行任务结构。

#+begin_src rust
pub struct OrgFile {
    pub repo_id: OrgRepoId,
    pub path: String,
    pub source_bytes: Vec<u8>,
    pub entries: Vec<OrgEntry>,
}

pub struct OrgEntry {
    pub id: OrgEntryId,
    pub parent_id: Option<OrgEntryId>,
    pub level: u16,
    pub elements: Vec<OrgElement>,
    pub children: Vec<OrgEntry>,
}

pub struct OrgElement {
    pub kind: OrgElementKind,
    pub source_range: SourceRange,
}

pub struct SourceRange {
    pub start: SourcePosition,
    pub end: SourcePosition,
}

pub struct SourcePosition {
    pub line: u32,
    pub column: u32,
    pub byte_offset: u64,
}
#+end_src

** OrgElement 与 org-mode 语法

~OrgElementKind~ 依照 org-mode 语法建模，不把日程、截止日期或标题拆到仓库级平行字段。元素保留在原始顺序中，写回时才能避免重排正文、drawer 或块内容。

| 元素类型 | 对应 org 语法 | 领域内容 |
|-
| ~Title~ | headline 文本 | 标题文本、TODO keyword、优先级和 tags。 |
| ~Scheduled~ | headline 后的 ~SCHEDULED: <...>~ | 活动 timestamp、时间范围、repeater、delay。 |
| ~Deadline~ | headline 后的 ~DEADLINE: <...>~ | 活动 timestamp、时间范围、repeater、warning。 |
| ~Closed~ | headline 后的 ~CLOSED: [...]~ | 非活动完成 timestamp。 |
| ~Property~ | 紧随 headline 的 ~:PROPERTIES:~ drawer | 大小写不敏感的 key 与原始 value；显式 ~ID~ 可参与 entry ID 计算。 |
| ~Timestamp~ | 正文中的活动或非活动 timestamp | 单点、日期范围或同日时间范围。 |
| ~Drawer~ | 其他 ~:NAME:~ drawer | drawer 名称与其子元素。 |
| ~Text~ 、 ~List~ 、 ~Link~ | 正文、普通列表和链接 | 保留可显示文本及链接目标。 |
| ~Block~ 、 ~Keyword~ | ~#+begin_src ... #+end_src~ 等块和 ~#+KEYWORD:~ | 块类型、参数与内容，或 keyword 的 key/value。 |
| ~Raw~ | 当前解析器尚未结构化的合法 org 片段 | 原始内容，确保升级解析器前不丢失信息。 |

~Scheduled~ 、 ~Deadline~ 和 ~Closed~ 必须位于 headline 或其 property drawer 之后的 planning 区域。 ~Scheduled~ 与 ~Deadline~ 的 timestamp 可带时间、时间范围、repeater、delay 或 warning； ~Closed~ 使用非活动 timestamp。一个 entry 同种 planning 元素最多一个，重复项属于解析错误而不是以最后一项覆盖。

** 源码保真与最小差异写回

~OrgFile.sourceBytes~ 是内容树的唯一写回基准， ~OrgElement.sourceRange~ 必须精确指向该缓冲区中该元素的完整来源。解析器必须为每个元素保存起止行、列和字节偏移；行号从 1 开始，列号与字节偏移从 0 开始，区间采用 ~[start, end)~ 。行列仅用于诊断和定位展示，实际替换必须以 UTF-8 字节偏移执行，避免多字节字符导致偏移错误。

- 未对文件应用编辑时，序列化必须直接返回读取时的 ~sourceBytes~ ，结果须与原文件逐字节一致。这包含编码字节、换行风格、末尾换行、空行、缩进、行尾空格、注释、drawer 顺序、未知语法和未建模内容。
- 替换一个元素时，只能替换其 ~sourceRange~ 覆盖的字节；插入元素时，只能在明确的元素边界或 entry 内合法锚点插入所需字节。写回不得格式化、重新缩进、对齐表格、规范化换行、重排元素，或重建未修改节点。
- 每次替换或插入后必须以更新后的 ~sourceBytes~ 更新受影响元素及其后续元素的 ~SourceRange~ 。跨行变更时必须从新缓冲区重新计算行号、列号和字节偏移，不能只对后续列号累加差值。必要时可重新解析受影响 entry 或整个文件校验结构。
- ~Raw~ 元素、未建模片段和不属于任何 entry 的内容必须按原始字节保留。编辑实现不得因解析器尚不理解某段合法 org 语法而删除或改写该片段。

上述规则适用于本地保存与上传前序列化。源字节快照仅在本次解析/编辑会话内保留；关闭会话后可从文件重新读取，持久化层仍只保存同步元数据。

* 仓库同步记录

~OrgRepoSyncRecord~ 记录一次已发起的仓库同步及其最终结果。它由 ~OrgRepo.load::<P>~ 返回或由同步策略产生，不作为 ~OrgRepo~ 的字段保存，且包含零到多个 ~OrgRepoSyncFileRecord~ 。未扫描到文件、列举失败或在首个文件前失败时，文件记录可以为空；这不代表仓库没有文件。

~OrgRepoSyncFileRecord~ 记录该次同步中一个相对路径的决策与结果。它不保存完整文件内容，也不把远端 URL、认证 header 或密码写入错误摘要。冲突、下载、上传、创建、删除和跳过均由 ~action~ 与 ~state~ 表达，不另建运行时执行权或 UI 事件实体。

#+begin_src rust
pub struct OrgRepoSyncRecord<C, F> {
    pub id: OrgRepoSyncRecordId,
    pub kind: String,
    pub started_at: TimestampMs,
    pub finished_at: Option<TimestampMs>,
    pub result: Option<OrgRepoSyncResult>,
    pub context_detail: C,
    pub files: Vec<OrgRepoSyncFileRecord<F>>,
}

pub struct OrgRepoSyncFileRecord<F> {
    pub relative_path: String,
    pub action: OrgRepoSyncFileAction,
    pub state: OrgRepoSyncFileState,
    pub local_version: Option<LocalFileVersion>,
    pub detail: F,
    pub error: Option<OrgRepoSyncErrorSummary>,
}

pub struct LocalFileVersion {
    pub content_hash: String,
}
#+end_src

进行中的 ~OrgRepoSyncRecord.result~ 与 ~finishedAt~ 均为 ~None~ ；完成后必须同时设置它们。记录及其文件记录不重复保存 ~repoId~ ，归属由包含它们的 ~OrgRepo~ 与其 ~.sync~ 目录表达。 ~OrgRepoSyncResult~ 取值为 ~Succeeded~ 、 ~Failed~ 、 ~Cancelled~ 或 ~Interrupted~ 。 ~OrgRepoSyncFileAction~ 取值为 ~Unchanged~ 、 ~Downloaded~ 、 ~Uploaded~ 、 ~Created~ 、 ~Deleted~ 、 ~Conflicted~ 或 ~Skipped~ 。 ~OrgRepoSyncFileState~ 表示最终文件状态，至少区分 ~Synchronized~ 、 ~LocalChanged~ 、 ~RemoteChanged~ 、 ~RemoteDeleted~ 、 ~Conflict~ 与 ~Failed~ 。错误摘要只包含分类、是否可重试和脱敏消息。

* 持久化与运行时边界

持久化层在仓库根目录的 ~.sync~ 中保存 ~OrgRepoSyncRecord~ 、 ~OrgRepoSyncFileRecord~ 及其版本元数据，并以 ~.sync/id~ 保存稳定 ~OrgRepoId~；完整布局、提交和恢复规则见 [[file:目录结构设计.org][目录结构设计]]。内容树可从文件重新生成，因此默认不持久化 ~OrgFile~ 、 ~OrgEntry~ 或 ~OrgElement~ 的完整内容。持久化不得保存仓库根目录、完整文件、远端完整 URL、凭据或运行时调度状态。

~OrgWorkspace~ 的构造、目录扫描、WebDAV HTTP 传输、认证、并发控制、进度通知、取消、重试与日历投影均由宿主或适配层负责。 ~core::webdav~ 负责基于传输结果作同步决策并更新仓库快照；具体 HTTP 客户端和认证材料不得反向成为核心结构字段。

* 旧接口

旧的任务记录、同步状态、outbox 与冲突记录不是当前核心数据结构。当前实现不读取、不转换这些数据；任务投影、队列与 UI 流程由宿主按当前仓库级接口重新建立。
