* 范围与状态

本文定义以 ~OrgWorkspace~ 为全局入口、以 ~OrgRepo~ 为文件仓库边界的核心领域模型。一个应用通常只构造一个 ~OrgWorkspace~ ，其中包含零到多个仓库。每个仓库由构造时传入的根目录指定，并拥有当前文件快照；同步记录独立落盘于根目录的 ~.sync/history/~ 。仓库控制目录的持久化布局见 [[file:目录结构设计.org][目录结构设计]]。

~OrgFile~ 使用 ~orgize~ 提供无损运行时解析，并以 Emacs ~org-element~ 作为语义基准； ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ 描述一次仓库同步及其中各文件的同步结果； ~NewTask~ 是运行时创建输入， ~OrgRepoWriteIntent~ 是待上传的路径与哈希。当前 ~core~ 已实现保真编辑接口和仓库级服务端口；Harmony 与 HTTP 已仅使用仓库同步记录持久化接口，不再保留旧作业模型。

调度、线程、SDK 生命周期、监控回调、认证材料、文件系统访问和网络 I/O 都是宿主或适配层的运行时概念，不是本章的核心数据结构。实体关系的 TikZ UML 源码与本文同步维护。

* 基础约定

| 类型或规则 | 定义 |
|-
| ~TimestampMs~ | Unix epoch 毫秒。 |
| ~OrgRepoId~ | 非空 UUID 字符串；同一逻辑仓库重建 workspace 时必须保持不变。 |
| ~OrgRepoSyncRecordId~ | 一次同步记录的非空 UUID 字符串。 |
| ~OrgRepoSyncRecord.kind~ | 策略类型标识；必须与加载和执行该记录的 ~SyncPolicy::KIND~ 一致。 |
| 相对路径 | ~relativePath~ 相对于所属 ~OrgRepo.rootDirectory~ ，不能是绝对路径或包含 ~..~ 。 |
| 源位置 | ~SourceRange~ 是引用 ~OrgFile.sourceBytes~ 的半开区间 ~[start, end)~ 。 ~SourcePosition~ 同时记录 1-based 行号、0-based UTF-8 字节列号与 0-based UTF-8 字节偏移；它仅在当前文件快照内有效，不能作为跨版本稳定 ID。 |
| 内容与版本 | ~OrgFile.sourceBytes~ 保存当前解析/编辑会话的完整源字节，用于保真写回；它不写入 core 持久化状态或同步记录。内容树可由文件重新解析； ~LocalFileVersion~ 只保存内容哈希， 策略专属的文件 ~detail~ 保存远端 ETag、修改时间和大小等信息。 |

* 查询投影中的标题层级

~FilterTask~ 的 ~level: u32~ 是从 ~OrgFile~ 的 ~orgize~ 标题节点读取的真实星号层数，从 1 开始；它与 ~repo_id~ 、相对 ~path~ 、 ~byte_offset~ 一同保留当前快照中的来源和结构。该字段只用于运行时查询投影与宿主展示，不进入同步 CSV、历史或 outbox。宿主可据此折叠层级，不能重新解析原文推断标题结构。

#+begin_src rust
pub struct FilterTask {
    pub id: String,
    pub repo_id: String,
    pub path: String,
    pub line: u32,
    pub column: u32,
    pub byte_offset: u64,
    pub level: u32,
    pub state: Option<String>,
    pub state_type: FilterStateType,
    pub priority: Option<String>,
    pub own_tags: Vec<String>,
    pub inherited_tags: Vec<String>,
    pub title: String,
    pub body: String,
    pub is_repeating: bool,
    pub scheduled: Option<FilterDate>,
    pub deadline: Option<FilterDate>,
    pub closed: Option<FilterDate>,
    pub created: Option<FilterDate>,
    pub events: Vec<FilterDate>,
}
#+end_src

~FilterTask.is_repeating~ 表示当前标题的计划或截止时间包含重复器，由 Core 从 ~orgize~ 时间戳取得；对解析器尚未识别的重复间隔写法仅在标题紧邻的规划行内兜底识别。正文、源码、日志和子标题中的重复器不使父任务成为循环任务。该字段只供运行时展示，不展开重复日期，不修改查询与持久化边界。

* 任务逻辑身份

~FilterTask.id~ 由 Core 在遍历文件完整标题树时生成，Harmony 的 ~Task.id~ 原样使用该值。逻辑输入为“仓库路径、文件名、任务标题祖先链、自身标题”；源行号、列号、字节偏移仍用于当前快照定位，不参与逻辑身份。

| 输入 | 规则 |
|-
| 仓库路径 | 使用 ~OrgRepo.root_directory~ 的原始 UTF-8 字符串，不依赖磁盘 canonicalize；更换根路径会改变任务 ID，改仓库显示名或 WebDAV 地址不影响。 |
| 文件名 | 使用含子目录的安全相对 ~OrgFile.path~ ，区分不同目录中的同名文件；改文件路径会改变 ID。 |
| 任务标题树 | 按真实层级从根到当前标题遍历，祖先仅包含有效 TODO 配置判定的待办或已完成标题；跳过无状态分类/组织标题，不跳过其下的任务。查询筛选在生成身份之后执行。 |
| 标题值 | 使用 ~orgize~ 已剥离状态、优先级和标签的标题节点；去掉首尾空白以及首尾直接出现的进度节点，如 ~[1/2]~ 、 ~[50%]~ 、 ~[/]~ 和 ~[%]~ ，支持连续多个。中间进度节点、链接或强调标记中的同类文字保留；大小写、内部空白和其余 Org 原文保持不变。 |
| 无状态记录 | 查询仍返回全部 headline；当前记录始终保留自身归一化标题，以区分收件箱中的无 TODO 记录，但它不会成为后代任务身份链中的祖先。 |
| 完全重名 | 同一文件中，相同归一化标题路径的第一次出现使用基础输入；第 2 次起追加该路径在完整文件中的 1-based 出现序号。无关任务的插入、删除或查询排序不影响该序号。 |

哈希输入采用紧凑 JSON 明确分段，逻辑上的点分路径不直接用点号拼接，避免标题中的点号与层级边界混淆。基础输入为 ~[rootDirectory,relativeFilePath,[title1,title2,...]]~ 的 UTF-8 字节，重复路径从第 2 项起为 ~[rootDirectory,relativeFilePath,[title1,title2,...],occurrence]~ 。输出为标准 MD5 的 32 位小写十六进制字符串。

#+begin_example
仓库：/repo
文件：inbox.org
,* TODO [1/2] Project
,** DONE Child [100%]

子任务输入：["/repo","inbox.org",["Project","Child"]]
子任务 ID：c9977ec1396cc0465b20fc09cb18600c
#+end_example

前面或无关兄弟任务的增删、重排、正文/规划时间/标签/优先级变化、待办与完成状态切换、首尾进度变化均保持 ID。自身或任务祖先改名、移动到不同任务父级、仓库或文件路径变化会改变 ID。完全同名同路径的重复项没有独立持久身份；删除或重排这些重复项时，其出现序号可能变化，不承诺区分它们的历史身份。文件中的 Org ~ID~ 属性不覆盖本规则；此处 MD5 用于身份摘要，不承担内容校验、认证或安全散列职责。

计算只读取无损语法树，不重写标题或文件字节，不把绝对路径或哈希输入写入同步日志、outbox 或错误摘要。现有合并算法的三方匹配、Org ~ID~ 优先级和历史任务指纹保持独立，不能用列表逻辑 ID 替换合并的来源版本校验。

Core 内部按文件建立 ~TaskIdentity::new(root, path)~ ，随后按原文顺序调用 ~id_for(headline, is_task)~ ，维护任务祖先栈与同路径出现次数；完成类型继续由有效 TODO 配置判断。公开接口只增加查询投影字段 ~FilterTask.id~ ，宿主不能传入自己计算的 ID 或重建标题树。

* 工作空间与仓库

~OrgWorkspace~ 是应用级管理对象，负责聚合仓库和提供跨仓库 ~Filter~ 搜索，不表示后台任务、线程池、网络客户端或持久化实现。一个应用通常只需要一个 workspace；测试、隔离导入或多账户场景可以构造多个 workspace。

~OrgRepo~ 是一个独立文件仓库。其 ~rootDirectory~ 在构造时由宿主提供，用于扫描和解析该仓库内的文件；该绝对路径不能写入 core 的持久化状态。 ~files~ 保存扫描后的文件快照；同步历史属于仓库的本地控制数据， ~load::<P>~ 可返回它供查询； ~sync~ 自行恢复并回溯，不要求外部传入或保留历史快照，也不新增历史字段或单独状态文件。文件路径通过 ~repoId~ 与相对 ~path~ 定位。

~task_scan_rules~ 是从仓库根目录 ~.orgzlyignore~ 加载的运行时任务扫描规则，默认为空。 ~files~ 仍保存全部已扫描 org 文件，规则仅在生成 ~FilterTask~ 时排除命中文件的全部标题及子标题。规则匹配不改变 Org 文件同步候选、原始字节或写入意图；运行时 matcher 不序列化到 ~.sync/~ 。WebDAV 从远端下载的根目录配置单独保存普通文件同步记录与原始 UTF-8 快照，校验后同时更新本地配置和运行时规则；不加入 ~files~ ，也不生成 Org 任务指纹。

远端地址、用户名、密码、令牌、客户端证书和 Authorization header 都属于具体 ~SyncPolicy~ 实现的运行时配置，不进入 ~OrgRepo~ 或任何其他 core 数据结构。

#+begin_src rust
pub struct OrgWorkspace {
    pub repos: Vec<OrgRepo>,
    pub todo_defaults: TodoConfig,
}

pub struct OrgRepo {
    pub id: OrgRepoId,
    pub root_directory: String,
    pub files: Vec<OrgFile>,
    pub todo_defaults: TodoConfig,
    pub task_scan_rules: TaskScanRules,
}
#+end_src

* Org 解析与保真

~OrgFile~ 是仓库中的完整 org 文件，保存仓库标识、相对路径与读取到的原始字节。文件头标题通过 ~title()~ 从已有语法树读取； ~OrgFileMetadata~ 包含仓库 ID、相对路径、可空标题、标题行内片段、~is_ignore~ 、标题记录数、字节数与可空的本地修改时间，用于轻量列表，不保存正文或语法树。扫描读取的文件时间只保留在运行时，克隆文件或更新 TODO 默认设置时继续保留，不加入同步持久化数据。它在运行时使用 ~orgize::Org~ 生成无损语法树；该缓存不属于 core 的持久化模型，也不向其他模块暴露为项目自定义 AST。解析、编辑和展示的语义以 Emacs ~org-element.el~ 为准。

未修改时， ~OrgFile~ 必须直接写回 ~sourceBytes~ ，不能经解析器重新序列化。局部编辑只替换明确的 ~SourceRange~ 或在明确 ~SourcePosition~ 插入字节；变更完成后重新构造 ~orgize::Org~ 缓存。因此空行、换行风格、缩进、行尾空格、未知语法和未改动区域保持原始字节。

** 源码保真与最小差异写回

~OrgFile.sourceBytes~ 是唯一写回基准。编辑范围使用 ~SourceRange~ ，插入位置使用 ~SourcePosition~ ；这些编辑结构与保真写回函数位于 ~core::model::editor~ 。行号从 1 开始，列号与字节偏移从 0 开始，区间采用 ~[start, end)~ 。行列仅用于诊断和定位展示，实际替换必须以 UTF-8 字节偏移执行，避免多字节字符导致偏移错误。

- 未对文件应用编辑时，序列化必须直接返回读取时的 ~sourceBytes~ ，结果须与原文件逐字节一致。这包含编码字节、换行风格、末尾换行、空行、缩进、行尾空格、注释、drawer 顺序、未知语法和未建模内容。
- 替换一个元素时，只能替换其 ~sourceRange~ 覆盖的字节；插入元素时，只能在明确的容器元素边界插入所需字节。写回不得格式化、重新缩进、对齐表格、规范化换行、重排元素，或重建未修改节点。
- 每次替换或插入后必须以更新后的 ~sourceBytes~ 更新受影响节点及其后续节点的 ~SourceRange~ 。跨行变更时必须从新缓冲区重新计算行号、列号和字节偏移，不能只对后续列号累加差值。

上述规则适用于本地保存与上传前序列化。源字节快照仅在本次解析/编辑会话内保留；关闭会话后可从文件重新读取，持久化层仍只保存同步元数据。

* 任务创建与写入意图

~NewTask~ 仅作为 ~OrgRepo.create_task~ 与 ~OrgRepo.create_task_at_top~ 的调用输入，不是新的解析 AST 或持久化任务模型。core 将标题、优先级、标签及计划日期转为 org 内容，并复用 ~OrgFileEdit~ 与 ~orgize~ 检验；默认新增任务追加到文件末尾，快速捕捉可请求在第一条标题之前插入。已存在文件的原始字节保持不变。

~OrgRepoWriteIntent~ 只包含相对路径与保存后的内容哈希，按仓库写入 ~.sync/outbox/~ 。完整任务仍保存在用户 org 文件中；多个保存意图可指向同一个文件。WebDAV 使用原始文件的最新完整字节上传，成功同步记录落盘且本地版本一致后才确认消费。写入意图不增加 ~OrgRepo~ 的持久化文件快照字段。

#+begin_src rust
pub struct NewTask {
    pub heading: String,
    pub scheduled: String,
    pub deadline: String,
    pub tags: Vec<String>,
    pub priority: String,
}

pub struct OrgRepoWriteIntent {
    pub relative_path: String,
    pub content_hash: String,
}
#+end_src

* 仓库同步记录

~OrgRepoSyncRecord~ 记录一次已发起的仓库同步及其最终结果。它由 ~OrgRepo.load::<P>~ 返回或由同步策略产生，不作为 ~OrgRepo~ 的字段保存，且包含零到多个 ~OrgRepoSyncFileRecord~ 。未扫描到文件、列举失败或在首个文件前失败时，文件记录可以为空；这不代表仓库没有文件。

~OrgRepoSyncFileRecord~ 记录一次同步中一个相对路径的结果。WebDAV 成功文件在 ~detail.synced_source~ 中保存完整同步后文件快照；其他元数据、错误摘要与 outbox 不保存正文，所有记录均不保存绝对路径、远端 URL、认证 header 或配置凭据。

#+begin_src rust
pub struct OrgRepoSyncRecord<C, F> {
    pub id: OrgRepoSyncRecordId,
    pub kind: String,
    pub started_at: TimestampMs,
    pub finished_at: Option<TimestampMs>,
    pub result: Option<OrgRepoSyncResult>,
    pub context_detail: C,
    pub files: Vec<OrgRepoSyncFileRecord<F>>,
}

pub struct OrgRepoSyncFileRecord<F> {
    pub relative_path: String,
    pub action: OrgRepoSyncFileAction,
    pub state: OrgRepoSyncFileState,
    pub local_version: Option<LocalFileVersion>,
    pub detail: F,
    pub error: Option<OrgRepoSyncErrorSummary>,
}

pub struct LocalFileVersion {
    pub content_hash: String,
}
#+end_src

进行中的 ~OrgRepoSyncRecord.result~ 与 ~finishedAt~ 均为 ~None~ ；完成后必须同时设置它们。记录及其文件记录不重复保存 ~repoId~ ，归属由包含它们的 ~OrgRepo~ 与其 ~.sync~ 目录表达。 ~OrgRepoSyncResult~ 取值为 ~Succeeded~ 、 ~Failed~ 、 ~Cancelled~ 或 ~Interrupted~ 。 ~OrgRepoSyncFileAction~ 取值为 ~Unchanged~ 、 ~Downloaded~ 、 ~Uploaded~ 、 ~Created~ 、 ~Deleted~ 、 ~Conflicted~ 或 ~Skipped~ 。 ~OrgRepoSyncFileState~ 表示最终文件状态，至少区分 ~Synchronized~ 、 ~LocalChanged~ 、 ~RemoteChanged~ 、 ~RemoteDeleted~ 、 ~Conflict~ 与 ~Failed~ 。错误摘要只包含分类、是否可重试和脱敏消息。

* 持久化与运行时边界

持久化层在仓库根目录的 ~.sync~ 中保存 ~OrgRepoSyncRecord~ 、 ~OrgRepoSyncFileRecord~ 及其版本元数据，并以 ~.sync/id~ 保存稳定 ~OrgRepoId~ ；完整布局、提交和恢复规则见 [[file:目录结构设计.org][目录结构设计]]。Org 内容由原始文件保存，运行时 ~orgize~ 缓存不持久化。持久化不得保存仓库根目录、远端完整 URL、配置凭据或运行时调度状态；完整内容仅作为成功文件快照和冲突备份保存。

~OrgWorkspace~ 的构造、目录扫描与仓库集合管理由 core 提供；宿主负责选择仓库目录、发起调用和日历投影。 ~core::webdav~ 负责 WebDAV HTTP 传输、认证、同步决策和仓库快照更新；具体 HTTP 客户端和认证材料不得反向成为核心结构字段。

* 旧接口

旧的任务记录、同步状态、完整内容 outbox 与冲突记录不是当前核心数据结构；当前 outbox 仅保存 ~OrgRepoWriteIntent~ 元数据。当前实现不读取、不转换这些数据；任务投影、队列与 UI 流程由宿主按当前仓库级接口重新建立。


* 按同步比较与合并

~WebDavMergeComparison~ 是一次仓库同步的运行时比较对象。它覆盖该同步仍未解决的全部冲突文件，保存仓库版本、远端配置指纹、逐文件版本，以及统一的变化列表；不需要准备会话 ID，也不写入 Preferences 或同步历史。 ~apply_merge~ 接受这个对象，只有 ~mode~ 与各变化项的 ~resolution~ 可以由调用方修改。

#+begin_src rust
pub enum WebDavMergeMode { AcceptRemote, MergeTasks }
pub enum OrgMergeSide { Local, Remote, Remove }

pub struct WebDavTaskMergeChange {
    pub id: String,
    pub path: String,
    pub kind: OrgMergeChange,
    pub preamble: bool,
    pub local_change: OrgMergeChange,
    pub remote_change: OrgMergeChange,
    pub local: Option<OrgMergeVersion>,
    pub remote: Option<OrgMergeVersion>,
    pub resolution: Option<OrgMergeSide>,
}

pub struct WebDavMergeComparison {
    pub sync_id: String,
    pub repo_id: String,
    pub repository_version: String,
    pub endpoint_version: String,
    pub mode: WebDavMergeMode,
    pub files: Vec<WebDavMergeFileVersion>,
    pub unchanged_count: usize,
    pub changes: Vec<WebDavTaskMergeChange>,
}

pub struct OrgTaskFingerprint {
    pub key: String,
    pub hash: String,
}

pub struct WebDavSyncFileDetail {
    pub etag: Option<String>,

#+end_src

变化的临时 ~id~ 仅用于当前比较。 ~kind~ 以远端文件为基准描述本地拟应用的新增、删除或修改； ~local_change~ 与 ~remote_change~ 表示相对最近成功文件快照的状态，取 ~Unchanged~ 、 ~Added~ 、 ~Modified~ 、 ~Deleted~ 或无基线时的 ~Unmatched~ 。本地未改的任务直接保留远端；两端内容一致也不进入列表。 ~preamble~ 标记文件前言，前言在文件级决定；其他每项对应一个标题及其自身 section。所有只读字段必须与重新比较一致。

~unchanged_count~ 统计直接保留的远端现存任务，包括未变化任务和仅远端发生变化的任务；不计入文件前言或已由远端删除的任务。

任务匹配优先使用自身 Org ~ID~ 的指纹；没有 ~ID~ 时使用祖先身份路径与当前标题的指纹，重名项附带出现序号。无 ~ID~ 的标题改名会显示为删除和新增；重名项需要逐项核对。每个标题只比较自身标题行和 section，子标题独立比较。所有来源区间均来自 ~orgize~ CST，选择结果按原始字节组合，再验证完整 Org 结构；不能静默丢弃未选择的子任务或生成失效层级。

成功文件的 ~WebDavSyncFileDetail.synced_source~ 保存完整 UTF-8 内容，包含原始换行、空白和正文，供后续重新解析共同任务基线；每次成功同步都写入该次日志，未变化文件也不例外。空文件保存空字符串，已确认文件删除由 ~local_version=None~ 表达。 ~task_versions~ 继续保存身份与内容指纹以兼容旧日志；有快照时先校验版本哈希并从快照重算指纹，无快照时回退旧指纹，两者皆无则不推断历史操作。错误摘要、凭据、绝对路径与 outbox 不保存文件内容；冲突备份仍单独保存于 ~.sync/backups/~ 。

* 同步基准的仓库归属

~OrgRepo.sync~ 内部恢复当前仓库目录中的已完成历史，并交给策略按文件回溯。每个文件最近成功记录即当前同步基准，作业整体失败不否定其中已成功文件；最新空记录、冲突与失败不能覆盖既有成功基准。控制器仅持有仓库、策略和运行进度，不保存或接收历史列表。

无历史时，本地与远端的全部候选文件均进入合并确认。没有本地文件的差异使用空的比较来源投影，但 ~WebDavMergeFileVersion.local_missing~ 明确保留不存在状态，不将其视为已经存在的空文件；成功合并后才能生成版本基准。备份仍只保存真实存在的本地原始字节。

#+begin_src rust
pub struct WebDavMergeFileVersion {
    pub path: String,

* 文件 TODO 元信息与外部全局默认

全局默认配置由宿主编辑、保存并在运行时传给 Rust；core 不读取 Preferences，也不向 ~.sync/~ 写入默认配置。Rust 的 ~TodoConfig::default()~ 是唯一缺省来源， ~to_settings()~ 返回可编辑声明文本，初始为 ~#+TODO: TODO | DONE~ 。外部只有未保存配置时才获取默认值，已经保存的空配置表示禁用默认识别。

~OrgWorkspace.todo_defaults~ 向新仓库传递默认配置， ~OrgRepo.todo_defaults~ 用于扫描、下载、新增和合并。每个 ~OrgFile.todo~ 提供源字节与默认配置共同决定的有效元信息；文件保留运行时默认配置，以便克隆和局部编辑后重新解析。这些信息不是另一套 Org AST，不写入同步记录。

** 文内覆盖规则

~#+TODO:~ 、 ~#+SEQ_TODO:~ 和 ~#+TYP_TODO:~ 多行共同组成文件配置，整组覆盖全局默认。前两者表示顺序流程，后者表示类型。与 Emacs 一致，混用时依次汇集 ~TYP_TODO~ 、 ~TODO~ 、 ~SEQ_TODO~ ，同类保持出现顺序。声明名不区分大小写，状态名区分大小写。

~|~ 后为完成状态；无分隔符时，每套流程最后一个状态为完成状态。若全部流程都没有给出完成状态，则文件最后一个关键词作为完成状态。跨流程同名状态的完成归属以文件有效完成集合为准。空 ~#+TODO:~ 也是覆盖，表示清空文件 TODO 识别。

设置影响整份文件，允许位于标题后面；源码块和示例块中的同名文本不构成声明。Rust 从 ~orgize~ CST 的真实 keyword 节点收集声明及来源区间，再用有效 ~ParseConfig.todo_keywords~ 解析整个文件，不通过逐行正则另建解析器。文件未直接声明时，仓库加载会按相对路径展开仓库内的 ~SETUPFILE~ ，只提取其中的 TODO 声明作为该文件的有效设置；不执行 Emacs Lisp，也忽略仓库外或不存在的设置文件。

非法配置报告错误，不静默回退全局值。未修改文件直接返回原始字节；编辑声明后重算元信息，重新解析失败时回滚此次局部编辑。新增任务使用 ~initial_state~ ，即有效配置首个未完成状态；文件尚不存在时使用外部默认。没有可用未完成状态则拒绝保存。

~set_todo_defaults~ 校验并重解析内存文件，不改写原文；有文内覆盖的文件仍使用自身配置。运行时合并版本包含全局默认配置，有效配置变化后旧比较对象失效，必须重新比较。

* 文件分类访问

文件分类通过 ~OrgFile.category() -> Option<String>~ 读取，值来自文件头真实的 ~CATEGORY~ keyword 节点。分类是当前语法树的派生值，不新增持久化字段； ~None~ 表示未配置，空字符串表示显式空声明。读取只考虑第一个标题之前的第一条声明，忽略大小写并去除值的首尾空白，避免将块内示例或标题属性当作文件分类。接口的详细边界见 [[file:接口文档.org][接口文档]]。

* 同步运行时参数

~SyncOptions~ 由同步调用传入 ~SyncContext~ ，不保存在仓库实体、同步历史或 outbox 中。目录过滤是当前的同步规则，后续可扩展其他规则。Rust 默认排除 ~archive~ ，显式空列表表示不过滤。 ~excluded_directories~ 只接受单个目录名，匹配任意层级的目录路径组件。

* 只读展示投影

OrgFile.render_html() 复用同一运行时 orgize 语法树，将整篇文件投影为安全 HTML 片段；不新增持久化字段、解析 AST 或同步记录。宿主负责主题、滚动和折叠交互，源字节仍是唯一保真序列化来源。

** 任务正文展示投影

RenderedTaskContent 是 FilterTask.render_content() 的运行时返回值，包含 body_html 与 logbook_html；两者均为安全 HTML，不持久化。它使用既有 body 和 orgize 语法树区分真正的 LOGBOOK drawer 与字面文本，原始 body 及源字节不变。新增 ~has_list: bool~ 表示正文中实际渲染的列表，不包含 LOGBOOK、源码、示例块及字面抽屉内容；在同一次语法树遍历中取得，不在宿主分析 HTML。文件渲染不再合成 TITLE 标题，由宿主工具栏负责展示。
