* 范围与约束

本文记录已确认的仓库访问与跨进程同步重构方案，作为 [[file:同步核心设计.org][同步核心设计]] 的访问、锁和恢复边界补充。领域规则全部由 Core 执行，Harmony、HTTP 与 CLI 只负责接入。当前实现与迁移状态见文末，不能把目标行为误记为已经交付。

仓库按需访问重构移除 ~OrgRepo.files~ 字段、 ~files()~ 借用接口及仓库持有的扫描规则，增加异步 ~load_files(ignore_files)~ 。依赖磁盘数据的查询、元信息、节点与目标读取采用异步 ~Result~ 传播 I/O 错误；查询表达式、操作组、持久化格式与既有错误枚举保持不变。Harmony 对应提供 ~loadFiles(ignoreFiles)~ ，其他页面请求与结果字段保持原约定。不新增 ~query_files~ 。 ~fileVersion~ 继续使用当前 ~LocalFileVersion~ 算法，不切换 MD5，也不改变基线、outbox 或历史的哈希格式。

仓库根目录以宿主配置为来源；Workspace 与仓库对象从结构化配置恢复。每次操作固定本次取得的根目录和必要配置，不在执行中切换目录。稳定身份由 Core 的 ~.sync/id~ 管理，不能因重新构造对象或重置而重建。

* 对象与数据生命周期

长期 Workspace 和仓库对象负责配置、稳定身份、订阅与显式会话身份，不作为文件字节、语法树、任务列表或扫描规则的实时数据缓存。具体操作取得仓库锁后按需读盘，解析与计算数据只存活于该次操作；操作结束释放临时数据和锁。

调用方持有的 ~OrgFile~ 与任务结果是独立值对象，用于展示和收集编辑输入，不是下一次操作的数据来源。写入仍重新读盘并校验调用方的 ~fileVersion~ 。冲突预览属于显式编辑会话，使用已定义的仓库外临时文件和源版本，不依赖真实仓库缓存。

~load()~ 仅确认根目录、读取或初始化仓库 ID。它不检查 ~reset~ 或 ~sync~ ，不执行恢复，不扫描 Org 文件，不读取历史、基线或 outbox。恢复检查必须位于每次业务磁盘访问的统一入口，不能只在首次初始化或开始新同步时检查。

~load_files(ignore_files: &[String])~ 返回本次独立拥有的 ~Vec<OrgFile>~ 。参数为当前仓库的安全相对路径，空列表表示不额外排除，按精确路径匹配而非通配符；排除发生在读取正文和 UTF-8 解析之前。批量任务查询先从每项 ~TaskQuery.excluded_files~ 筛选当前仓库的引用，再结合 File 与 Notification 的需求，只有整批都不需要的路径才传给本次加载；其他文件加载后按各项条件分别排除，不把其他仓库的同名文件排除。

~load_files~ 在仓库锁内检查恢复状态、读取文件与解析必要配置，返回后不把结果存入仓库。调用方可继续使用独立结果作展示或计算；下一次操作重新读盘。根目录 ~.orgzlyignore~ 每次读取，并投影到本次文件的元信息；任务查询应用该规则，完整文件加载仍保留被规则隐藏的文件。单文件读取按路径读盘，不先扫描全部文件。

任务结果同时拥有该次读取生成的 ~fileVersion~ 与 ~TaskEditContent~ 。Bridge 直接投影结果，不再从仓库快照查找源文件，也不通过第二次读盘拼接可能属于不同版本的任务和清单。

* 控制文件与锁

#+begin_example
<root>/
├── reset                         # 重置意图，存在即要求完成清理
├── sync                          # 当前同步 ID，原子写入
└── .sync/
    ├── id
    ├── .transaction.lock         # 仓库文件锁，始终保留同一锁文件
    ├── sessions/<sync-id>/
    │   ├── lock                  # 本轮同步存活锁
    │   ├── state.json            # 阶段、仓库身份与远端绑定
    │   ├── remote/               # 已完整下载的文件
    │   ├── remote.json           # 完整列举、删除信息与远端版本
    │   ├── merged/               # 合并结果及提交前置版本
    │   └── ...                   # 请求记录及提交恢复材料
    ├── remote_base/
    ├── history/
    ├── outbox/
    └── transactions/             # 既有本地提交日志，迁移时继续恢复
#+end_example

~reset~ 、 ~sync~ 为根目录保留控制文件，不扫描或传输；路径、文件类型和标记内容必须校验，不跟随符号链接。已有同名非控制文件不得覆盖或解释为已授权的重置。同步 ID 必须是合法安全路径段，并与阶段记录中的仓库身份一致。

| 锁 | 范围 | 持有规则 |
|-
| 仓库锁 | 一个规范化仓库目录 | 同进程互斥与跨进程文件锁共同保护每次真实仓库操作；忙时异步等待，不能阻塞 UI。 |
| 同步锁 | 一个同步 ID | 由 Core 同步执行上下文从标记发布前持有至真正结束；覆盖网络、合并、提交和收尾。 |
| 预览租约 | 一个仓库外预览会话 | 沿用既有租约，仅防止清理活动临时目录，不作为仓库锁。 |

同步锁是否可取得是存活依据，锁文件存在、PID 或等待时间都不能独立证明同步已经退出。权限错误、损坏或其他 I/O 错误必须与锁忙区分。进程挂起时锁仍可能有效，等待超时不能强行接管或删除其锁文件。

仓库锁内部保留异步进程内排队，并通过非阻塞 ~flock~ 配合异步退避等待跨进程锁。首版等待预算为 10 秒，使用单调时钟；同一次加锁的进程内等待和文件锁等待共享预算。跨仓库操作按规范化根目录排序、去重；同一操作使用共同截止时间。

持有仓库锁时只能非阻塞探测同步锁；不得等待活动同步释放同步锁，否则活动同步再次申请仓库锁时会死锁。内部已持锁路径通过私有执行上下文继续操作，不重复取得同一把锁。

* 统一操作入口

业务磁盘操作先取得仓库锁、校验实际仓库 ID，再检查控制状态。没有控制标记时正常按需读盘。有活动同步时保留其标记和材料，允许普通操作访问当前正式文件；网络阶段暂存内容不能作为当前正式文件展示。

存在 ~sync~ 且可取得对应同步锁时，在同时持有同步锁与仓库锁期间恢复遗留状态。恢复失败必须保留标记和材料并返回错误，禁止后续操作读取半提交文件。该检查适用于已长期持有的对象，不依赖它是否重新调用 ~load()~ 。

查询不顺带读取全部同步历史；单文件读取不先全量扫描仓库；历史接口按需读取历史；同步按阶段读取所需基线、正式文件和 outbox。返回结果可以拥有独立快照，仓库不将其保留为下一次调用的权威内容。

* 重置协议

重置在仓库锁下先创建并落盘 ~reset~ ，再开始清理。 ~load()~ 不处理标记；后续业务操作通过统一入口继续未完成的清理。清理只保留 ~.sync/id~ 、 ~.sync/.transaction.lock~ 和 ~reset~ ，清理全部完成并落盘后最后移除 ~reset~ 并刷新根目录。

清理具有幂等性，中断后继续清理，不恢复已清除的旧业务内容。存在标记但身份丢失时报告错误，不生成新身份。旧事务恢复不能重新写回已声明重置的数据。

发现活动同步时，只发布重置意图，释放仓库锁后等待活动同步结束；不能删除正在使用的同步目录或锁文件。活动同步每次重新进入仓库阶段都先检查 ~reset~ ，存在时停止后续提交并结束本轮同步。在途网络请求退出前保留同步锁，不因页面返回、超时或取消请求提前释放。

* 同步启动与存活检查

新同步在仓库锁内检查 ~reset~ 和 ~sync~ 。没有 ~sync~ 时创建唯一同步目录，先取得本轮同步锁，写入并落盘初始化阶段，再原子发布内容为同步 ID 的 ~sync~ 标记。只有发布完成后才释放仓库锁进入网络阶段。

有 ~sync~ 且同步锁忙时，本轮仍存活，不能新建第二轮；有标记且成功取得同步锁时，先恢复上一轮再决定启动新同步。标记损坏或指向缺失材料时不得猜测为正常结束。

* 同步执行阶段

| 阶段 | 仓库锁 | 同步锁 | 内容 |
|-
| 初始化 | 持有 | 持有 | 校验身份和控制状态，创建并发布同步标记。 |
| 下载 | 释放 | 持有 | 完整列举远端，下载正文，保存删除状态、ETag 与完整性信息；只写本轮目录。 |
| 比较与合并 | 持有 | 持有 | 重新校验 ID 和重置状态；读盘取得当前本地和基线，计算并暂存合并结果及版本约束。 |
| 上传 | 释放 | 持有 | 对合并结果执行条件请求；请求意图在发送前落盘，确认结果随后落盘。 |
| 提交 | 持有 | 持有 | 再校验 ID、重置、正式文件、基线与读取依赖，提交文件、基线、历史和已确认 outbox。 |
| 收尾 | 短暂持有 | 持有至真正结束 | 完成状态落盘；核对同步 ID 后移除标记，再清理可延后的暂存材料。 |

下载删除信息不等于删除正式文件。只有完整成功的远端列举才能形成删除判断；列举失败、过滤或未完成下载不得解释为远端删除。删除与空文件分别表示。网络请求全部在仓库锁之外，仍保持已有 ETag 条件更新和创建保护。

上传前后的本地编辑允许继续进行。最终提交沿用当前 ~fileVersion~ ，同时校验合并使用的基线、配置依赖和相关文件存在性；变化时停止本地提交，保留新修改和 outbox，下一轮重新核对实际远端。不能为了重试修改版本约束后覆盖新内容，也不能无限重试占住同步身份。

WebDAV 不提供整仓库原子事务。服务器可能已经接受请求而客户端未记录响应，必须记录为结果不确定；恢复不盲目重新发送，也不把它当作未上传。本地不推进未确认基线；下一轮重新读取远端。outbox 只能确认本轮已成功同步的具体版本，不能按路径清空上传期间产生的新意图。

* 崩溃恢复与完成顺序

| 遗留阶段 | 本地恢复行为 |
|-
| 初始化、下载、合并 | 正式仓库未提交，无需回滚；结束未完成同步并处理暂存。 |
| 上传或上传结果不确定 | 不伪造成功，不回滚远端；保留必要诊断，后续同步重新核对远端。 |
| 提交且无完成标记 | 按持久化日志还原旧文件、基线和 outbox；发现外部新编辑时保留现场并报错。 |
| 提交已完成 | 保留已提交结果，只清理剩余材料，不回滚成功内容。 |

提交日志及其引用的旧字节、新字节必须先完整落盘，再修改正式路径；正式内容、目录与完成标记按既有耐久性契约刷新。恢复本身再次中断时仍可重复执行。

完成后先保证正式提交与完成标记耐久，在仓库锁内核对并移除 ~sync~ 标记、刷新根目录，再清理同步目录。不能先删唯一恢复目录再删指向它的标记。无标记的孤立目录可延后回收，回收前仍需确认其同步锁可取得。清理失败不将已耐久的成功提交改报失败。

* Harmony 并发边界

网络阶段不能持有整个 Harmony workspace mutex。Bridge 从配置与身份取得本轮所需的独立操作上下文后释放全局对象锁，网络完成再通过 Core 协议进入仓库阶段；不能在 bridge 重写合并或恢复。

调用方等待超时不能被误报为 native 操作已经停止。同步锁的所有权必须覆盖真正仍在执行的工作；页面离开只影响结果接收。配置、订阅与回退历史等共享状态仍使用必要的短期互斥，避免以取消所有锁代替数据生命周期重构。

* 批量查询访问边界

唯一通用查询接口 ~OrgWorkspace.query(&[CoreQuery])~ 每批对规范化仓库根目录排序、去重，使用共同截止时间取得各仓库锁，并完成身份校验与恢复。已持锁上下文调用私有文件加载路径，每仓库加载一次；所有仓库加载结束后释放锁，在同次快照上独立求值各项查询。基础任务投影、分类、父子关系和本地自然日由整批共享，不保留为下一批缓存。

所有查询种类都不需要的文件直接在底层正文读取前跳过，否则加载后再按项排除。 ~load_files(ignore_files)~ 作为独立文件加载方法保留原签名与一次加锁边界。批量查询不得在每项内部调用此公开方法或重复调用 ~OrgRepo.load()~ 。详细规则见 [[file:批量查询接口设计.org][批量查询接口设计]]。

Notification 查询在已持锁上下文中读取基线索引并复用本次 Org 字节，不重复调用公开文件加载方法；原独立文件元信息和通知查询接口均已删除。同步配置等非 Org 控制内容按需读取，不把任务排除条件用于缩小通知范围。
