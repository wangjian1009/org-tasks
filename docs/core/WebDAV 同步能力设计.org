* 范围

本文定义 ~core::webdav~ 的 WebDAV 协议接入，以及将协议结果转换为 ~OrgRepoSyncRecord~ 和 ~OrgRepoSyncFileRecord~ 的运行时契约。通用同步行为与目录历史统一见 [[file:同步核心设计.org][同步核心设计]]。内容与同步结构见 [[file:数据模型.org][数据模型]]，仓库级 API 见 [[file:接口文档.org][接口文档]]，Harmony 的配置、凭据和保存方式见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。

WebDAV 是当前唯一规划的远端同步策略。WebDAV 地址和认证材料由策略实例持有； ~core::webdav~ 实现 core 的 ~SyncPolicy~ ，执行远端列举、下载和条件上传，由 Core 的统一同步流程管理本地提交与完成记录。org 文件扫描与解析属于 ~core::model::OrgRepo~ ，HTTP 仅创建 policy 与同步控制器，不实现 WebDAV 请求、同步决策或状态存储。

* 独立连接检查

~WebDavSyncPolicy.test_connection~ 复用策略的 HTTP client、认证参数和 endpoint，发送只读 ~PROPFIND~ 请求。请求 ~Depth: 0~ ，正文只查询 ~DAV:resourcetype~ ，不列举子文件或探测写入。

成功要求 HTTP ~207~ ，合法的 ~DAV:multistatus~ XML，以及与最终请求地址相同来源、相同目录路径的 ~response~ 。该 response 必须在成功的 ~propstat~ 中返回 ~DAV:collection~ 。不能将单独的 HTTP 成功、登录 HTML、其他目录、文件或权限失败当作目录访问成功。服务器重定向后按最终请求地址验证 href。

网络请求和响应正文读取使用 15 秒总超时。失败沿用 ~WebDavError~ 分类，错误不包含认证参数、完整 URL 或响应正文。连接检查不创建 ~OrgRepoSyncRecord~ ，不发送同步生命周期事件，也不加载仓库、修改文件或消费 outbox；检查成功不保证条件写入权限。

* Adapter 契约

~WebDavSyncPolicy~ 实现 ~SyncPolicy~ 。它接收可变 ~OrgRepo~ ，按 ~WebDavEndpoint~ 使用 Tokio runtime 上的异步 HTTP client 处理仓库文件，并在结束时返回带有全局 ~kind: "webdav"~ 和 ~WebDavSyncFileDetail~ 的完整 ~OrgRepoSyncRecord~ 。取得正文后使用 Core 的 Org 解析与统一提交能力，不自行规定历史目录或冲突状态。协议细节包含远端版本，每个文件的 action/state 和脱敏错误由同步记录表达；成功内容按统一历史契约保存。

** Monitor

调用方可在构造 policy 后通过 ~with_monitor~ 注入 ~WebDavSyncMonitor~ 。默认使用空 monitor。monitor 按发生顺序接收 ~Started~ 、 ~ListingStarted~ 、 ~Listed~ 、 ~FileStarted~ 、 ~FileProcessed~ 、 ~HttpRequest~ 、 ~HttpResponse~ 和 ~Finished~ 事件，因此可观察一次同步的完整生命周期，而不用读取或修改同步记录。

~HttpRequest~ 和 ~HttpResponse~ 只包含 HTTP 方法、相对路径或根路径，以及响应状态码；网络失败时状态码为 ~None~ 。事件不得包含密码、Authorization header、完整远端 URL、绝对本地路径或请求、响应正文。

~FileProcessed~ 表示远端文件处理结果，本地事务此时尚未提交。 ~Finished~ 由仓库持久化完成记录并释放锁后触发；成功事件必须晚于工作文件、远端基线、冲突快照、历史及 outbox 的统一提交。提交失败通过同步调用返回错误，不能先发送成功事件；失败或取消的完成记录持久化后仍可发送对应结果的完成事件。

#+begin_src rust
struct Monitor;

impl WebDavSyncMonitor for Monitor {
    fn on_event(&self, event: WebDavSyncEvent) {
        // 仅消费脱敏事件。
    }
}

let policy = WebDavSyncPolicy::new(endpoint, username, password)?
    .with_monitor(Monitor);
#+end_src

策略不得直接修改同步记录存储、日历投影或 UI 状态。 ~OrgRepoSyncController~ 在 core 内负责取消与进度快照；CLI 和 HTTP 等宿主只读取这些快照。 ~WebDavSyncPolicy~ 负责实际 HTTP、认证与 TLS；策略不得返回密码、Authorization header、仓库绝对路径或远端完整 URL；完整 Org 正文仅作为成功文件的 ~synced_source~ 随同步记录返回，供 Core 持久化，不进入进度事件或错误摘要。

* 协议能力

| 同步意图 | WebDAV 请求 | 成功条件 | 对同步文件记录的结果 |
|-
| 列举目录 | ~PROPFIND~ ， ~Depth: 1~ | ~207 Multi-Status~ | 发现相对路径和 ~WebDavSyncFileDetail~ ；列举失败时不报告远端删除。 |
| 下载文件 | ~GET~ | ~200 OK~ | action 为 ~Downloaded~ ，写入新的本地版本。 |
| 创建远端文件 | ~PUT~ + ~If-None-Match: *~ | ~201~ 、 ~200~ 或 ~204~ | action 为 ~Created~ ，确认远端版本。 |
| 更新远端文件 | ~PUT~ + ~If-Match: <etag>~ | ~200~ 或 ~204~ | action 为 ~Uploaded~ ，确认远端版本； ~412~ 表示执行时版本失效，按统一失败边界处理。 |
| 创建目录 | ~MKCOL~ | ~201~ 或已存在 | 仅为上传缺失父目录服务。 |
| 重命名 | ~MOVE~ + ~Destination~ + ~Overwrite: F~ | ~201~ 或 ~204~ | 为旧路径和新路径分别产生文件记录。 |
| 显式删除 | ~DELETE~ | ~204~ | action 为 ~Deleted~ ；只执行 Core 判定的条件删除意图。 |

已知远端版本的写入必须使用条件 ~PUT~ 。远端不提供 ETag 时，adapter 不得无条件更新已有文件，而应以 ~OrgRepoSyncFileState::Conflict~ 或可见失败结果结束该文件记录。

* Core 同步设计入口

同步目录、历史格式与恢复、文件提交与失败边界、首次同步和删除决策、冲突比较与解决接口，以及通知类型和生命周期，统一见 [[file:同步核心设计.org][同步核心设计]]。本文件不定义控制目录布局、差异持久化、resolved 命名、冲突解决状态或通知规则。

WebDAV 只将列举与条件传输的结果交给 Core。 ~412~ 或列举确认的版本变化由 Core 按统一流程处理；保存冲突远端正文时必须确认读取对应版本，不能把更新的正文标记成旧 ETag。目录过滤不能绕过 Core 的既有冲突检查。

* 协议进度与错误

WebDAV 报告列举、下载、上传和请求响应的脱敏进度，不将运行时进度保存成历史。错误区分网络、认证、TLS、协议校验和条件冲突；本地存储失败由 Core 表达。完整正文不进入进度或错误摘要，是否重试由宿主决定。

* 同步过滤目录

本次同步参数通过 ~OrgRepo.sync_with_options~ 传入 ~SyncContext.options~ ，不保存在 ~WebDavSyncPolicy~ 或 ~OrgRepo~ 中。 ~trigger_reason~ 使用通用 ~SyncTriggerReason~ 枚举，由宿主按应用启动、退到后台或手动入口传入；仓库服务将其写入本轮完成历史，WebDAV 不推断或改变原因。 ~SyncOptions::default()~ 默认排除 ~archive~ 目录；显式空列表关闭目录过滤。目录名按大小写敏感的路径组件匹配，可匹配任意层级的同名目录，文件名不参与匹配。

WebDAV 在处理文件前同时过滤远端列举结果与本地候选路径，避免被排除文件的下载、上传、冲突和远端删除判断。过滤路径不生成本轮文件记录，不消费其 outbox，也不删除已有本地文件。远端目录以 ~Depth: 1~ 逐层校验并递归列举，路径范围与删除决策统一由 Core 管理。

* 远端任务扫描配置

除 Org 文件外，列举还识别根目录的 ~.orgzlyignore~ 。每次同步先下载并验证该配置，再处理 Org 文件；有 ETag 时使用条件 GET，拒绝版本已经变化的响应。成功后通过临时文件与原子替换保存配置，后续查询与元信息读取按次加载该配置，不再保存仓库内的规则缓存。配置只影响任务投影，不缩小 Org 文件传输范围。

配置只从远端下载，不上传本地规则，也不解析成 Org 文件或加入文件清单。同步成功记录保存配置的内容哈希、远端版本与完整 UTF-8 ~synced_source~ ，不保存任务指纹，也不确认 Org 编辑的 outbox。没有远端配置且从未下载过配置时继续采用本地规则；远端删除已下载配置时，撤销与成功基线一致的本地副本。本地配置有独立修改且与远端不同，或远端内容不是合法 UTF-8 / 忽略规则时，明确报错并保留本地字节。配置下载与校验失败不生成任务合并项，不伪装成空规则。

* 验收标准

- ~PROPFIND~ 解析、条件 ~PUT~ 与 ~412~ 冲突均能映射为仓库同步文件记录的版本、action 和 state。
- 本地仓库不会调用 WebDAV；WebDAV 策略只使用其自身的远端配置。
- 一个同步记录只归属一个 ~OrgRepoId~ ，其中每个文件记录只使用相对路径。
- 策略返回的记录不包含配置凭据、绝对路径或远端完整 URL；正文保存边界遵循统一同步设计。
- 写入意图只在对应条件写入成功、历史落盘且本地版本仍一致后由 core 确认；失败与 ~412~ 不得丢弃意图。
