* 范围与状态

本文定义以数据源为中心的 core SDK API。它取代以全局 ~sync-jobs~ 、执行租约和进程内 REST 请求描述同步编排的目标接口。当前 ~core~ 、 ~harmony~ 和 ~http~ 仍实现旧的作业接口；本文所述 ~OrgTasksSdk~ 、 ~DataSourceConfig~ 、 ~SyncRun~ 和 ~SyncMonitor~ 均为待实现设计。

领域模型见 [[file:数据模型.org][数据模型]]。WebDAV 仅是远端传输适配，协议细节见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]；Harmony 的配置和保存边界见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。

* SDK 构造

数据源只能在 SDK 构造阶段注册。SDK 构造完成后，数据源集合与每个数据源的本地目录、远端类型和远端地址均不可变；修改配置必须销毁并使用新的配置重新构造 SDK，且沿用同一逻辑数据源的 ~sourceId~ 。

#+begin_src rust
pub struct SourceBinding<D> {
    pub config: DataSourceConfig,
    pub driver: D,
}

pub struct OrgTasksSdk<S, D> {
    // CoreStore 和按 sourceId 路由的同步驱动。
}

impl<S, D> OrgTasksSdk<S, D>
where
    S: CoreStore,
    D: SourceSyncDriver,
{
    pub async fn new(
        store: S,
        sources: Vec<SourceBinding<D>>,
    ) -> Result<Self, SdkInitializationError>;
}
#+end_src

构造必须校验： ~sourceId~ 唯一、 ~localDirectory~ 非空、WebDAV ~baseUrl~ 合法且每个 ~sourceId~ 恰好绑定一个同步驱动。驱动由 Harmony、HTTP 或其他宿主创建；core 只读取结构化 ~DataSourceConfig~ ，不读取或保存宿主配置、环境变量或网络凭据。

构造会恢复遗留的 ~running~ 记录，将其终止为 ~interrupted~ 并释放该数据源的执行权。构造不扫描目录、不访问网络，也不启动后台线程。

* 异步同步接口

#+begin_src rust
pub struct SyncRequest {
    pub trigger: SyncTrigger,
    pub include_calendar: bool,
    pub requested_at: TimestampMs,
}

impl<S, D> OrgTasksSdk<S, D>
where
    S: CoreStore,
    D: SourceSyncDriver,
{
    pub async fn sync(
        &mut self,
        source_id: &SourceId,
        request: SyncRequest,
        monitor: &dyn SyncMonitor,
    ) -> Result<SyncRun, SyncError>;
}
#+end_src

~sync~ 是异步操作：调用方负责 await 它，core 不创建线程、Tokio task 或平台后台任务。调用成功返回已完成的 ~SyncRun~ ；失败同样会尽力写入对应的失败历史并向 monitor 发送最终事件。

执行顺序如下：

1. 按 ~sourceId~ 查找构造期注册的数据源；未注册时返回 ~SourceNotFound~ 。
2. 原子创建 ~running~ 的 ~SyncRun~ 并占有该数据源执行权；已有活动运行时返回 ~SyncAlreadyRunning { sourceId, syncRunId }~ ，不调用驱动。
3. 发送 ~Started~ 事件，并调用 ~SourceSyncDriver~ 对本地目录和可选远端执行同步。
4. 将文件元数据、outbox 确认、冲突和最终运行状态作为原子变更提交。
5. 清空执行权，发送 ~Completed~ 、 ~Failed~ 或 ~Cancelled~ 事件，并返回最终 ~SyncRun~ 。

同一 ~sourceId~ 任意时刻最多一个 ~running~ 记录。不同数据源是否并行由宿主决定；core 不以全局锁阻塞它们。

* 同步驱动端口

~SourceSyncDriver~ 是 core 的 I/O 端口，负责读取本地目录、在存在远端配置时调用对应协议，并以领域结果返回发现文件、版本变化、冲突和传输结果。它不能绕过 SDK 直接写入 ~CoreStore~ ，也不能改变 ~SyncRun~ 状态。

#+begin_src rust
pub trait SourceSyncDriver: Send + Sync {
    fn synchronize(
        &self,
        source: &DataSourceConfig,
        request: &SyncRequest,
        observer: &dyn SyncProgressObserver,
    ) -> impl Future<Output = Result<SourceSyncOutcome, SourceSyncError>> + Send;
}
#+end_src

Harmony 驱动负责私有目录访问、WebDAV HTTP 和 CalendarKit；HTTP 宿主驱动负责其部署环境的文件与凭据访问。任何驱动都不得将密码、Authorization header 或完整文件内容放入 ~SourceSyncOutcome~ 、 ~SyncRun~ 或 monitor 事件。

* 监控接口

外部通过 ~SyncMonitor~ 观察过程和结果，而不是轮询 UI 状态或读取适配器私有文件。 ~SyncMonitor~ 必须快速返回；耗时的日志、网络或 UI 操作由宿主自行排队，不能阻塞同步。

#+begin_src rust
pub trait SyncMonitor: Send + Sync {
    fn on_event(&self, event: SyncMonitorEvent);
}

pub enum SyncMonitorEvent {
    Started { source_id: SourceId, sync_run_id: SyncRunId, at: TimestampMs },
    Progress { source_id: SourceId, sync_run_id: SyncRunId, phase: SyncPhase, completed: u32, total: Option<u32> },
    Conflict { source_id: SourceId, sync_run_id: SyncRunId, relative_path: String },
    Completed { run: SyncRun },
    Failed { run: SyncRun },
    Cancelled { run: SyncRun },
}
#+end_src

~SyncPhase~ 至少包含 ~scanning_local~ 、 ~listing_remote~ 、 ~downloading~ 、 ~uploading~ 、 ~indexing~ 和 ~finalizing~ 。事件只携带 ~sourceId~ 、 ~syncRunId~ 、相对路径、计数和脱敏错误摘要；不得包含本地绝对路径、完整 org 内容或凭据。监控器只观察，不得取消、重入或启动另一次同数据源同步。

* 查询与历史

SDK 提供按数据源查询文件与同步历史的接口：

#+begin_src rust
pub async fn list_org_files(&self, source_id: &SourceId) -> Result<Vec<OrgFileRecord>, CoreError>;
pub async fn list_sync_history(&self, source_id: &SourceId, limit: usize) -> Result<Vec<SyncRun>, CoreError>;
pub async fn active_sync(&self, source_id: &SourceId) -> Result<Option<SyncRun>, CoreError>;
#+end_src

这些查询使用构造期已知的 ~sourceId~ ，不暴露数据源配置修改接口。HTTP 宿主后续可将它们映射为资源，但 HTTP 路由不得成为 core 的公共依赖。

* 当前实现迁移

当前 ~CoreService.createSyncJob~ 、Harmony ~queueSync~ 与 HTTP ~POST /v1/sync-jobs~ 是兼容层；它们不具备数据源绑定、单源执行权或 ~SyncMonitor~ 。迁移顺序必须为：先实现数据模型和 ~CoreStore~ 原子操作，再实现 ~OrgTasksSdk.sync~ 与单元测试，最后由 Harmony 和 HTTP 替换旧入口。旧入口在迁移期间不得与新 SDK 操作同一数据源。
