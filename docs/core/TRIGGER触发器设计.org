#+TITLE: 文件内 TRIGGER 触发器
#+LANGUAGE: zh-CN
#+OPTIONS: author:nil date:nil toc:nil

* 依据与执行时机

以本机 Emacs 的 Org 9.8.10 与 org-edna 1.1.2 为参考，移植文件内可执行的 TRIGGER 规则。Core 原生解释字符串，不调用 Emacs、不执行 Lisp，也不读取或修改联动目标之外的文件。本文明确区分已支持规则和静默跳过范围，不声称支持整个 Emacs 运行时。

状态从文件有效待办集合进入有效完成集合时，先完成 Org 自身的状态日志和重复调度，再读取来源条目的 ~TRIGGER~ 。因此重复任务中的 ~self scheduled!("+2d")~ 以已经推进的日期为基准； ~todo!(NEXT)~ 可以覆盖自动恢复的待办状态。完成状态之间切换、待办之间切换、无状态标题进入完成以及新建完成记录，不触发 TRIGGER。

默认对应 ~org-edna-use-inheritance=nil~ 、 ~org-edna-from-todo-states=todo~ 、 ~org-edna-timestamp-format=short~ 。TRIGGER 与普通动作属性只读取条目自身，不继承祖先、文件级 ~#+PROPERTY~ 或 SETUP 中的默认值；条目自身的追加属性仍有效。允许值列表如 ~CHOICE_ALL~ 按 Org 规则从祖先或文件配置取得。应用不提供 Emacs 全局自定义变量配置入口。

* 日期规则

~+Nunit~ 和 ~-Nunit~ 相对目标已有日期， ~++Nunit~ 和 ~--Nunit~ 相对当前时间。目标没有日期时，单符号相对操作失败；双符号操作可以创建日期。支持年、月、日、小时、分钟，月份与年份采用 Org 的日期溢出归一化。

落点支持指定星期、weekday／wkdy 和 weekend／wknd，可向前或向后调整；小时和分钟不应用落点。float 按源码中的实际顺序读取次数、星期、可选月份和可选日，月份为零或省略时使用相邻月份。

已有时间戳决定短／长格式；没有时间戳时，小时和分钟优先使用长格式，其余读取目标的 ~EDNA_TS_FORMAT~ ，最后采用 short。目标已有短格式时，即使动作单位为小时或分钟，也遵循 Edna 的短格式输出。复制使用来源的日期和时刻，不复制其重复器；普通设置保留目标原有重复器和预警。绝对日期时刻沿用 Edna 当前将空时区转换为 UTC 再输出本地时间的行为；相对时刻使用本地时间。

* Loki 扩展动作

这三个动作是本项目与 Loki Assistant 的 Emacs 模块共同实现的扩展，不属于 Org Edna 1.1.2 内置能力。Emacs 定义位于 ~loki-assistant/emacs/loki-assistant-edna.el~ ，由已加载的 ~loki-assistant~ 在 Org Edna 加载后自动加载，无需修改个人 Emacs 配置；Core 原生执行同名动作，不调用 Lisp。原有 ~scheduled-wday?~ 属于个人自定义条件，本扩展不将任意 Emacs 函数带入 Core。

#+begin_src org
:TRIGGER: next-sibling loki-scheduled-next!(source mon wed fri) chain!("TRIGGER")
:TRIGGER: next-sibling loki-deadline-next!(today mon wed fri)
:TRIGGER: self loki-spawn-next!(source mon wed fri)
:TRIGGER: self loki-spawn-next!(today "+6m")
#+end_src

三个动作的星期集合形式均为 ~BASE DAY...~ 。该形式的参数只接受符号； ~BASE~ 为 ~source~ 、 ~target~ 或 ~today~ ，星期为 ~mon~ 、 ~tue~ 、 ~wed~ 、 ~thu~ 、 ~fri~ 、 ~sat~ 、 ~sun~ 的非空集合。星期顺序不影响结果，重复项去重；字符串、未知星期、缺失基准及空集合均报错。

| 基准 | 日期来源 | 时刻来源 |
|-
| ~source~ | 本次触发来源的对应规划日期 | 来源的对应时刻或同日时刻范围；没有时刻则输出纯日期 |
| ~target~ | 当前动作目标的对应规划日期 | 目标的对应时刻或同日时刻范围 |
| ~today~ | 本次状态操作的本地自然日 | 目标已有的对应时刻或同日时刻范围；没有则输出纯日期 |

~loki-scheduled-next!~ 使用 ~SCHEDULED~ ， ~loki-deadline-next!~ 使用 ~DEADLINE~ ， ~loki-spawn-next!~ 使用 ~SCHEDULED~ 。 ~source~ 或 ~target~ 缺少对应时间戳时失败，不回退到今天。所有落点严格晚于基准自然日；周一、三、五集合依次得到周一到周三、周三到周五、周五到下周一，周四则得到周五。仅指定周一时，周一的下一个落点是下一周周一。按自然日而非固定 24 小时推进，最长检查七天，日期溢出报错。

两个日期动作保留目标原有重复器与预警，不复制来源的重复器。 跨日期范围只从首个时间戳读取基准和时刻，写入时保留目标范围尾部的原始字节；首端没有时刻时不借用末端时刻。输出首个时间戳的日期、英文星期和选定时刻，其他规划与正文不变；小时重复器不能因切换到无时刻来源而失去时刻。

** 后继的日期间隔形式

~loki-spawn-next!~ 还接受 ~BASE "+Nunit"~ ，例如 ~self loki-spawn-next!(today "+6m")~ ：完成当前任务后，以本次状态操作的本地日期加六个月作为新兄弟任务的 SCHEDULED。~today~ 不要求原任务已有计划日期；原任务有计划时刻或同日时刻范围时保留，没有则输出纯日期。~source~ 与 ~target~ 分别使用来源和目标的首个 SCHEDULED；缺失时仍报错。

间隔必须是单个双引号字符串，正号后为正整数及单位，支持 ~d~ 、 ~w~ 、 ~m~ 、 ~y~ ，分别为日、周、月、年；小写 ~m~ 表示月。月份与年份复用既有 Org 日期溢出归一化，例如 2026-08-31 加六个月为 2027-03-03，不按固定 180 天计算。该形式不与星期集合混用，零、负数、额外参数、未知单位或日期越界均使整组回滚；两个 Loki 日期修改动作继续只支持星期集合形式。

** 后继创建

~loki-spawn-next!~ 在动作目标的整个子树之后插入同层级兄弟，来源基准仍指最初触发本条规则的任务。后续动作继续作用于原先捕获的目标，不隐式转向新节点。新节点不执行创建触发器；只有以后从待办进入完成时，才执行自己携带的规则。

新节点复制目标自身标签、显式优先级和自身 ~TRIGGER~ 。标题末尾的连续 ASCII 数字串 (0 至 9) 自动加一，其他标题文字保持原样；没有数字后缀时直接复制标题。保留前导零和原位数，进位超出时扩展位数，例如 ~练习009~ 生成 ~练习010~ 、 ~练习99~ 生成 ~练习100~ ；数字串不受固定宽度整数限制。编号只来自目标标题，不读取标签中的数字，也不扫描兄弟任务的最大编号。每次执行均按当前目标标题计算新后继标题。状态选取目标当前流程的首个有效待办状态；流程中没有待办时使用文件首个有效待办，全部缺失则失败。规划仅写入计算后的 ~SCHEDULED~ ，不复制 ~DEADLINE~ 、重复器或预警；不复制正文、清单、子任务、普通属性、历史 drawer、关闭时间或旧 ID。新节点记录当前 ~CREATED~ ，不生成或复制 ~ID~ 属性。祖先恢复与标题统计和普通状态修改共用规则。


后继创建也处理目标自身的有效 reminder：目标已有 SCHEDULED 时，新节点提醒按新旧计划的自然日差推进，保留目标提醒自身的时分与相对计划的日期差。日期范围使用首端；计划的时刻及其范围不改变提醒时分，跨夏令时也保持原时分。提醒属于复制目标，~source~ 只决定计划日期及其时刻来源，不改变提醒读取对象或提醒时分；不读取父级或文件级提醒。例如目标计划为 08:00、提醒为 10:00，来源计划为 15:00 时，后继计划采用 15:00，提醒仍为 10:00。

目标没有计划日期时，使用本次动作的日期基准：~today~ 按本次完成自然日零点，~source~ 使用来源计划自然日零点。例如本次完成日期为 2026-11-19，原目标提醒为 2026-11-19 09:00，执行 ~self loki-spawn-next!(today "+6m")~ 后，新 SCHEDULED 为 2027-05-19，新提醒为 2027-05-19 09:00。缺失或无效提醒不创建属性；旧任务保留原提醒作为历史，新节点不直接复制旧提醒时刻。新提醒越界、落入不存在的本地时刻或后续动作失败时，完成、创建与提醒写入整体回滚。

计算仅在 Core 内部完成，写入复用 ~SetReminder~ ，不新增创建参数或公开结构。新节点的同次 Created 事件即携带 reminderAt；Harmony 的已确认提醒查询移出已完成来源并纳入后继，现有协调器取消旧系统实例、安排新实例，不由 UI 再次拼接写入。

每次执行 ~loki-spawn-next!~ 都创建一个新的兄弟节点，不读取或写入后继关联属性，也不根据 ID 查找并复用已有后继。重新打开任务再完成会再次创建；同一规则显式多次调用也逐次创建。文件版本过期的请求仍按原事务规则拒绝，避免同一旧请求重复落盘。

\begin{tikzpicture}
\umlclass[x=0,y=0]{TargetTask}{}{loki-spawn-next!()}
\umlclass[x=7,y=0]{SuccessorTask}{CREATED : Timestamp\\TRIGGER : String?\\reminder\_at : TimestampMs?}{}
\umldep[arg=创建]{TargetTask}{SuccessorTask}
\end{tikzpicture}

创建复用普通 ~Creation~ 的标题、流程、优先级、标签、创建时间及结构校验原语，并在插入处登记 ~Created~ 语义事件。完成来源、创建节点及父级统计属于同一操作组，一次保存、历史与通知；失败整组回滚，旧文件版本重试不产生重复后继。

** Emacs 一致性

Emacs 使用 ~org-edna-action/loki-scheduled-next!~ 、 ~org-edna-action/loki-deadline-next!~ 与 ~org-edna-action/loki-spawn-next!~ 接入。辅助函数、变量与 feature 统一使用 ~loki-assistant-edna-~ 前缀，Edna 动作关键字保持 ~loki-~ 前缀，ID 查找只扫描当前缓冲区，不查询全局 ID 数据库或打开外部文件。finder 返回的 marker 在标题起点插入时跟随原标题，避免后续动作落到新建节点。外层 ~org-todo~ 事务包装在 Loki 动作发生错误或 Edna 报告阻塞时，回滚本次状态变化及同缓冲区联动；嵌套状态修改复用外层事务。

现有星期集合形式继续与 Emacs 扩展对照；字符串日期间隔是 Core 新增的后继形式，不以原星期形式的 Emacs 样例证明其行为。两端核对相同输入的逐步状态、日期时刻、继承规则、后继创建、标题结构与父级统计。属性 drawer 的排列与对齐不作为行为差异。Core 自定义的额外状态分类和原有 Edna finder 的明确差异仍遵循既有范围约定。

* 事务、定位与错误

全部联动只修改执行器持有的本文件隔离快照，沿用原状态操作的文件版本校验、一次提交、回退历史、同步上传意图和数据通知。宿主只提交原来的 TODO 字段，不组装联动操作，也不再次解析 TRIGGER。 数据事件按实际变更仓库发布一次，回调可观察全部来源及目标的最终文件；失败或最终字节未变不发布。手机可见任务行按同一数据版本共用批量快照，关联行和正在编辑的来源一起更新，保护未保存文字；过期结果和已离开卡片的回调不再应用，节点消失不补造另一条仓库事件。

普通 Edna 动作不增加、删除或移动标题；Loki 扩展只允许创建目标的后继兄弟。解释器用稳定的局部节点编号映射当前遍历位置，插入后更新映射，已捕获的来源、目标集合和级联栈继续指向原节点。同组后续字段由事务节点令牌继续定位原来源，不使用插入前的遍历位置或字节偏移。受保护冲突节点不能成为写入目标。

未支持动作静默跳过；已支持动作的非法参数、非法状态、日期溢出、无效语法及执行失败，均回滚整组，已完成的联动也不落盘。参数和条件嵌套限制为 64 层，联动链限制为 32 层，单次状态操作最多执行 4096 个规则或目标动作；循环联动报错回滚。顶层兄弟节点环绕使用有界遍历，不复制参考插件可能出现的无限循环。

* 验证与交付边界

参考结果通过运行本机 Emacs 的真实 Org Edna 获得，固定本地时间并隔离用户钩子和 ID 查找，记录 Org／Edna 版本与 UTC 偏移。比较任务状态、日期、属性和动作效果；规划字段的排列、属性 drawer 内的属性顺序及属性对齐不作为语义差异。Core 仍遵守原文保真约束，未涉及的字节由仓库级回归核对。

仓库级验证覆盖重复调度后执行、窗口与原日志保留、本文件目标限制、静默跳过后继续、前方目标导致来源偏移、级联、错误回滚和旧版本拒绝。手机继续复用原有完成入口和数据通知；本次未新增界面，也未进行真机验收。
