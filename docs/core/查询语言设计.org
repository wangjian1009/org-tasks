#+STARTUP: show2levels hidestars
#+OPTIONS: author:nil date:nil toc:nil
#+LANGUAGE: zh-CN

* 目的

本查询语言用于从 ~OrgRepo~ 的任务快照中选择和排序任务。语法以参考项目 Orgzly Android Revived 的 ~DottedQueryParser~ 、~QueryTokenizer~ 、~QueryInterval~ 及其 ~QueryTest~ 和 ~QueryTokenizerTest~ 为准；本项目在 ~core::filter~ 中实现同一套 dotted expression，而不使用 Android 的 SQLite 表达式实现。

对外唯一任务读取入口为 ~OrgWorkspace.query(&TaskQuery)~ 。表达式在 Core 内部解析为 ~Filter~ ：它由可选布尔表达式、零个或多个排序项和可选 agenda 天数构成。无法识别为操作符的 token 按普通文本条件处理，保持参考实现的宽容输入行为。

* 语法

空白表示隐式 ~AND~ 。关键字 ~and~ / ~AND~ 与 ~or~ / ~OR~ 不区分大小写；~AND~ 的优先级高于 ~OR~ 。圆括号可改变分组。双引号把带空白、圆括号或操作符外观的文本视作一个 token；反斜杠转义引号和反斜杠。

#+begin_example
i.todo t.work or i.next t.home
i.todo (i.next or t.work)
b."book(1) name"
#+end_example

首个点号是对下列离散条件的否定标记，例如 ~.i.done~ 、~.t.archive~ 和 ~.o.priority~ 。它不适用于日期条件；~.s.none~ 与参考实现一致，作为普通文本而不是“未计划”的日期条件。

* 条件

| 形式 | 含义 |
|-
| ~b.<name>~ | 文件路径等于 name。 |
| ~i.<state>~ | TODO 状态等于 state。 |
| ~it.todo~ / ~it.done~ / ~it.none~ | 按状态类别筛选。 |
| ~p.<letter>~ | 优先级；未设置时使用默认 ~B~ 。 |
| ~ps.<letter>~ | 显式设置的优先级。 |
| ~t.<tag>~ | 自身或祖先继承的标签。 |
| ~tn.<tag>~ | 仅自身标签。 |
| ~has.address~ / ~.has.address~ | 当前标题或自身正文包含／不包含真实的 ~geo:~ 或 ~addr:~ 链接；不包含子标题的链接。 |
| ~e.<interval>~ | 正文中的活动 timestamp。 |
| ~s.<interval>~ / ~d.<interval>~ / ~c.<interval>~ / ~cr.<interval>~ | 计划、截止、关闭、创建时间。 |
| ~text~ / ~"text with spaces"~ | 在标题、正文和标签中匹配文本。 |

日期条件可以在字段与 interval 之间插入 ~eq~ 、~ne~ 、~lt~ 、~le~ 、~gt~ 或 ~ge~ ，例如 ~s.ge.3d~ 。缺省关系与参考实现相同：~e~ 和 ~c~ 为 ~eq~ ，其余日期字段为 ~le~ 。~s~ 与 ~d~ 只匹配活动 timestamp。查询 ~s.le.today~ 或 ~d.le.today~ 时，若活动规划时间带 Org-mode 预警配置（例如 ~-2d~ ），Core 从预警起始日开始命中；其他日期关系和 interval 仍按实际规划日期匹配，避免未来 deadline 被计入过期数量。

interval 支持 ~none~ / ~no~ 、~now~ 、~today~ / ~tod~ 、~tomorrow~ / ~tmrw~ / ~tom~ 、~yesterday~ ，以及带正负号的 ~<number><unit>~ 。unit 为 ~h~ 、~d~ 、~w~ 、~m~ 和 ~y~ 。日期比较以运行时本地日期的自然日边界进行。

~has.address~ 为项目扩展条件，使用既有 ~orgize~ 语法树中的链接节点与 ~FilterTask.address_links~ 投影求值；源码、示例、注释和行内字面文本中的链接样式字符串不参与匹配。带描述和无描述的链接均识别，协议后的目标不能为空。它可与文件、状态及其他条件组合，也可前置点号取反；带双引号的 ~"has.address"~ 仍作为普通文本查询。

* 排序与选项

排序 token 为 ~o.<field>~ ；在前面增加点号表示降序。field 可为 ~book~ / ~b~ 、~title~ / ~t~ 、~scheduled~ / ~s~ 、~deadline~ / ~d~ 、~event~ / ~e~ 、~closed~ / ~c~ 、~created~ / ~cr~ 、 ~modified~ 、~priority~ / ~p~ 、~state~ / ~st~ 和 ~position~ / ~pos~ 。未指定排序时，任务按相对文件路径与源字节位置排序。

~o.modified~ 与 ~.o.modified~ 按任务的 ~modified_at()~ 分别升序和降序排列；缺失修改时间的记录在两种方向下均置末，不使用创建时间替代。相同时间继续按文件与源位置排序。

~ad.<positive-integer>~ 设置 agenda 天数，不参与匹配。多个排序项按出现顺序依次比较。

* core 映射

~FilterTask~ 从 ~OrgFile~ 的 ~orgize~ 无损语法树生成：它保存由 Core 生成的逻辑 ~id~ 、仓库 ID、相对路径、源位置、标题层级、状态、优先级、自身标签、继承标签、标题、正文和规划时间。~OrgWorkspace.query~ 汇总各仓库任务后由核心过滤器统一求值；宿主和 CLI 不得重新解释 org AST 或绕过 workspace 实现搜索。

任务投影覆盖全部 headline，以保持 ~it.none~ 和 ~.it.done~ 的 headline 语义一致。参考应用还会为每个文件的前言创建无状态根笔记；core 不投影 ~#+TITLE~ 、文件属性或第一个 headline 前的文本，因此这些文件级前言不参与任务查询。创建日期从当前标题自身属性 drawer 的 ~CREATED~ 读取，键不区分大小写，不继承祖先值；无效日期、时间或非时间戳值不投影。 ~FilterTask.created~ 保留日期，供既有 ~cr.*~ 自然日语法匹配； ~created_at()~ 保留按设备本地时区解释的 Unix 毫秒时间，缺失或无效时返回 ~None~ 。 ~modified_at()~ 仅从当前标题自身的 ~LAST_MODIFIED~ 属性解析，键不区分大小写，不继承祖先或文件级值；缺失、无效或非时间戳值返回 ~None~ ，不使用文件 mtime 或创建时间补齐。该属性与创建时间使用相同的本地时区解释规则，查询不生成或回填修改时间。只有日期时按本地 00:00 解释，夏令时回拨重复时刻选较早值，不存在的本地时刻忽略。 ~.o.created~ 按完整创建时间倒序，同一天可按时刻排序。

任务 ID 在完整文件遍历时生成，独立于当前表达式、排序、分类及包含开关。归一化标题链、明文 JSON 编码与重复项规则见 [[file:数据模型.org::*任务逻辑身份][任务逻辑身份]]；查询结果不会按逻辑标题合并记录，也不因身份计算去除原始标题中的进度文本。

** 系统标签 REFILE

精确等于 ~REFILE~ 的标签表示可放置任务的标题，目标由 ~OrgWorkspace.refile_targets()~ 或 ~OrgRepo.refile_targets()~ 单独枚举，模型与层级路径见 [[file:数据模型.org::*任务放置目标][任务放置目标]] 。放置标记只认标题自身显式标签，不从祖先或文件标签继承。

~query~ 在原始自身及继承标签上完成所有匹配后，从返回的每个 ~FilterTask~ 的 ~own_tags~ 与 ~inherited_tags~ 中移除 ~REFILE~ 与 ~ARCHIVE~ ，使宿主不将其作为普通任务标签展示。其他标签的顺序及大小写不变，标签为小写 ~refile~ 或 ~archive~ 时保留。带这些系统标签的标题仍属于正常任务查询结果，不因标记被整体排除。

~t.REFILE~ 仍按既有标签匹配规则检索自身或祖先标签， ~tn.REFILE~ 仍只检索自身标签，否定及普通文本条件也在移除前求值。这些表达式的匹配范围与放置目标的精确标签识别不同；目标枚举不通过任务查询实现。源 Org 字节与原始标签均不修改。

* 兼容性测试

core 测试从参考项目移植了 tokenizer 的括号和引号场景、~AND~ / ~OR~ 优先级、带引号的笔记本名、interval 别名、排序、agenda、状态、继承标签和计划时间筛选。测试以 core 的内存仓库快照运行，避免依赖 Android 的数据库实现。

* 任务完成判断

~FilterTask.is_done() -> bool~ 根据任务投影的 ~state_type~ 判断是否完成。该类型在所属文件的有效 TODO 元信息中计算，受文件内 ~TODO~ 、 ~SEQ_TODO~ 、 ~TYP_TODO~ 声明及已加载的 ~SETUPFILE~ 影响；无文件覆盖时沿用全局默认。同一个 ~CNCL~ 在不同文件可分别为完成、待办或普通标题，接口不按字面名称推断。无 TODO 状态的标题返回 ~false~ 。重新加载或修改默认设置后取得的新任务使用新配置，已返回任务保留取得时的状态。

#+begin_src rust
impl FilterTask {
    pub fn is_done(&self) -> bool {
        self.state_type == FilterStateType::Done
    }
}
#+end_src

* 查询职责边界（固定设计原则）

界面需求由 UI 负责组装查询请求，查询逻辑统一由 Core 完成，界面不再做任务过滤。这是所有任务查询入口的固定原则。

UI 可以维护勾选和取消等交互状态、根据页面需求填写参数，并显示或汇总分类计数。UI 不得对 core 返回的任务列表再次按完成状态、分类、文件、日期、标签或父子关系做 ~filter~ 、剔除、交并集或其他查询求值。计数可以留在展示层，但不能为得到任务结果在展示层复制核心过滤规则。任务列表直接使用查询返回的 ~tasks~ 。明确例外：今天、随时、某天的共享标签筛选条按产品要求在展示层对本页已加载的 ~tasks~ 做标签可见性过滤；基础页面查询仍由 Core 执行。只消费任务快照的有效标签，不解析 Org，不改变完成状态、时间、文件范围、源任务顺序或全局计数；其他页面及查询条件仍遵守前述约束。

Core 提供通用任务查询能力，不认识“收件箱页面”“分类多选控件”等界面概念。收件箱设置、多选切换和页面策略由 UI 转换成文件表达式、分类值、排除文件列表与两个包含开关。Core 对同一请求统一求值，确保前台、后台和其他宿主使用相同语义。

* 结构化任务查询

#+begin_src rust
#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default, deny_unknown_fields)]
pub struct TaskQuery {
    pub expression: String,
    pub categories: Vec<Option<String>>,
    pub excluded_files: Vec<OrgFileRef>,
    pub include_done: bool,
    pub include_compose_tasks: bool,
}

impl Default for TaskQuery {
    fn default() -> Self {
        Self {
            expression: String::new(),
            categories: Vec::new(),
            excluded_files: Vec::new(),
            include_done: true,
            include_compose_tasks: true,
        }
    }
}

pub struct OrgFileRef {
    pub repo_id: OrgRepoId,
    pub path: String,
}

pub struct TaskCategory {
    pub key: String,
    pub category: Option<String>,
    pub count: usize,
}

pub struct TaskQueryResult {
    pub tasks: Vec<FilterTask>,
    pub categories: Vec<TaskCategory>,
}

impl OrgWorkspace {
    pub fn query(&self, query: &TaskQuery) -> Result<TaskQueryResult, CoreError>;
}
#+end_src

| 字段 | 语义 |
|-
| ~expression~ | 现有 dotted query；空字符串表示无表达式限制，排序沿用现有查询接口。 |
| ~categories~ | 按文件有效 category 精确匹配，多项取并集；空列表不过滤分类。 ~None~ 表示缺失、显式空值或特殊分类 ~ARCHIVE~ ，与真实名称“未分类”不同；重复选项不重复任务。 |
| ~excluded_files~ | ~Vec<OrgFileRef>~ ，每项包含 Core 仓库 ID 与安全相对路径，仅两者同时匹配时排除；空数组不排除，不支持裸路径字符串或跨仓库同名路径通配。 |
| ~include_done~ | 为假时排除 ~FilterTask.is_done()~ 为真的任务，完成类型受文件有效 in-buffer 配置影响。 |
| ~include_compose_tasks~ | 为假时排除有子标题的组合任务。父子关系以原始完整文件结构判断，不能因子任务未命中表达式、已完成或被其他条件过滤而把父任务变成叶任务。 |

所有查询条件组合求值，任务按仓库 ID、相对路径和源字节偏移保持来源隔离。组合任务判断不得跨文件或跨存储库，即使两个仓库的文件名相同也不能相互影响。

~categories~ 摘要在表达式、排除文件、完成和组合任务开关求值后生成，不受当前 ~categories~ 选项影响，便于多选控件维持可选项。 ~count~ 是该范围内相应分类的记录数；不设置完成开关或设置为真时也可以统计完成记录。零记录分类不返回，缺失分类置末。

UI 的请求组装示例：分类导航请求设置 ~excluded_files = [OrgFileRef { repo_id: 所选 Core 仓库 ID, path: 配置文件路径 }]~ 和 ~include_done = false~ ；有分类选择时任务列表发送相同排除文件和所选分类，无选择时可清空排除文件以显示包含收件箱的全部未完成任务。收件箱页面使用 ~b."配置路径"~ 表达式并将两个包含开关置真，以取得所有标题记录。路径的表达式转义由 UI 作为请求组装完成，解释和文件匹配由 Core 完成。

~TaskQuery~ 不保存界面选择状态，没有 ~inbox_file~ 、 ~toggle_category~ 或专用视图枚举。 ~query~ 只读取已加载 workspace，不读宿主配置、不持久化 UI 会话。Harmony 在 worker 中加载当前仓库后调用该接口，结果任务包装为带 ~isDone()~ 的 Task 对象。

最近三天按今天、昨天和前天三个本地自然日解释，请求使用 ~cr.ge.-2d cr.le.today .o.created~ 。创建日期属于前天全天的记录均可匹配，今天晚些时候的创建时间同样属于今天；明天及更晚日期不匹配。时间条件统一由 ~expression~ 表达，不额外增加创建时间范围字段，也不扩展小时级筛选语义。

* 分享地址候选查询

~ShareLocation~ 通过 ~NativeCoreService.queryTasks -> Workspace.query -> OrgWorkspace.query~ 获得全部候选。请求按仓库范围组装，包含 ~has.address~ 与任务／备忘文件条件，并设置 ~includeDone=false~ ；页面不再按标题、地址或条数过滤返回结果。
