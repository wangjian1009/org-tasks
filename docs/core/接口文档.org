* 仓库访问与恢复边界

[[file:仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]] 定义仓库锁有界异步等待、同步独立存活租约、阶段目录和重置意图恢复。 ~OrgRepo~ 不保存文件快照或扫描规则；原 ~files~ 字段和 ~files()~ 已移除，使用异步 ~load_files(ignore_files: &[String]) -> Result<Vec<OrgFile>, CoreError>~ 按次读取。依赖磁盘的查询、文件元信息、节点和目标方法使用异步 ~Result~ ，保持既有请求数据结构和错误枚举。 ~fileVersion~ 算法不变。

~ignore_files~ 只接受当前仓库的安全相对路径，在读取正文和解析前精确排除。统一查询结合 Task、File 和 Notification 的数据需求，只把整批均不需要的文件传给底层排除；各项 Task 的 excluded_files 在其自身求值前应用。 ~.orgzlyignore~ 独立按既有任务规则生效。 ~load()~ 仅初始化身份，不读取业务数据或执行恢复；其原泛型返回类型保留并返回空集合，历史应通过专用历史方法读取。

每次真实业务访问在仓库锁内处理 ~reset~ 及失去同步租约的恢复材料；活动同步的网络阶段允许普通读写。同步在合并前重新读取本地内容，提交时校验文件版本与基线，禁止覆盖上传期间新增的编辑。查询结果中的 ~file_version()~ 和 ~edit_content()~ 来自同次读取，调用方直接消费该独立结果，不回查仓库数据。



* 范围与状态

本文定义围绕 ~OrgWorkspace~ 与 ~OrgRepo~ 的 core 接口。数据结构与源码保真规则见 [[file:数据模型.org][数据模型]]，WebDAV 协议语义见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]，Harmony 的配置与凭据边界见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。

~core::model~ 是本地仓库管理能力，直接扫描目录、解析 org 文件、按次生成文件结果并维护同步记录数据； ~core::webdav~ 是 ~SyncPolicy~ 的 WebDAV 实现，执行版本比较、下载、文件写回、创建与条件更新，并生成同步记录。仓库加载、WebDAV I/O 与同步控制器任务均运行于 Tokio；HTTP 和 Harmony 只负责选择和操作本地仓库；其他同步方式通过实现 ~SyncPolicy~ 接入。

* 核心场景

** 初始化 Workspace

宿主读取配置后只构造仓库根目录。 ~OrgRepo.load~ 初始化时从 ~.sync/id~ 读取稳定仓库标识；文件缺失时由 core 生成 UUID 并持久化。WebDAV 地址和凭据由 ~SyncPolicy~ 的 WebDAV 实现持有，不进入 ~OrgRepo~ 。

#+begin_src rust
let mut repo = OrgRepo::new("/data/org".into())?;
repo.load::<WebDavSyncPolicy>().await?;
let workspace = OrgWorkspace::new(vec![repo])?;
#+end_src

~OrgWorkspace::new~ 校验已加载仓库的 ID 唯一性； ~OrgRepo::new~ 只校验根目录。 ~load~ 仅读取或创建 ~.sync/id~ ；它不会请求 WebDAV、创建后台线程或写入同步记录。

** 解析、编辑并写回 org 文件

调用方按路径读取独立文件值，用该次内容生成定位和版本约束，再由统一操作组执行修改。未编辑区域保留原始字节；仓库不保留文件结果，也不由宿主直接写回正式文件。

#+begin_src rust
let repo = workspace.repo(&repo_id).ok_or(CoreError::InvalidInput("仓库不存在"))?;
let file = repo.file("inbox.org").await?;
let path = file.node_paths().first().cloned().ok_or(CoreError::InvalidInput("文件没有标题"))?;
let group = TaskOperationGroup {
    operations: vec![TaskOperation::Modification(TaskModificationOperation {
        path,
        modifications: vec![TaskModification::Title(Some("更新后的标题".into()))],
    })],
    file_versions: vec![TaskFileVersion {
        repo_id: file.repo_id.clone(), file: file.path.clone(),
        version: LocalFileVersion::from_bytes(file.source_bytes()).content_hash,
    }],
    ..Default::default()
};
workspace.execute_task_operations(&group).await?;
#+end_src

调用方在下一次编辑前必须使用重新解析后的来源范围；旧的 ~SourceRange~ 不能跨文件快照复用。未被替换的字节必须保持原始值。

** 同步一个仓库

宿主将同步策略传入仓库。 ~OrgRepo.sync~ 内部校验仓库身份与恢复状态，按阶段读取当前文件、outbox 和归属本仓库的完成历史，再构造 ~SyncContext~ 调用策略；调用方不传入历史，也不需要先加载旧快照。上传使用 ~serialize_file~ 的完整结果，不得在同步阶段格式化未修改区域。

#+begin_src rust
let record = repo.sync(
    &webdav_sync_policy, started_at,
    &SyncCancellation::default(), &SyncProgressReporter::default(),
).await?;
#+end_src

* 接口定义

** 单文件内容合并

Core 根模块公开纯函数 ~org_tasks_core::merge~ ，将同一 Org 文件从基线到本地的变化应用到远端内容：

#+begin_src rust
pub fn merge(
    base_data: &[u8],
    local_data: &[u8],
    remote_data: &[u8],
) -> Result<Vec<u8>, CoreError>;
#+end_src

三份输入均为完整 UTF-8 Org 原文，输出为合并后的完整原文字节。函数是同步的，不访问文件系统、网络、仓库、历史或运行时配置；相同输入产生相同输出。未涉及区域保留原始字节，内容竞争通过根节点带 ~CONFLICT~ 的候选子树表达，不作为接口错误；非法 UTF-8 或不能完成的解析、来源校验返回 ~CoreError~ 。内部任务身份与位置只作用于同一份文件内容，不需要传入仓库 ID、文件路径或远端版本。

每份内容按默认 TODO 规则和自身的 ~#+TODO~ 声明解析。 ~#+SETUPFILE~ 行作为原文保留，纯函数不读取其指向的文件。已有仓库同步先解析仓库默认值与对应快照的 SETUPFILE 上下文，再通过私有入口复用同一个合并算法，保持原有同步解析语义；不存在第二套合并规则。

前言始终采用远端原文，不生成前言候选。冲突点使用 ~CONFILICT_ID~ ，选择操作通过普通操作组提交；不再生成专用差异比较单元。

已有冲突不阻止两端继续修改普通任务或解决冲突。冲突点的 ID 与内容创建后不变，只合并 ID 集合的新增和删除：基线已有的点在任一端删除后移除，两端新增的点按 ID 去重保留。双方解决旧冲突后的主树结果另做三方合并，不能自动合并时生成新冲突，旧 ID 不恢复。完整协调与重放规则见 [[file:同步核心设计.org::*冲突容器与设计原则][冲突容器与设计原则]]。

空切片表示存在的零字节 Org 内容，不能表达“文件不存在”。整文件删除优先级、首次同步的文件集合、条件传输、 ~remote_base~ 、outbox 与仓库事务均由同步层在调用内容合并前后处理，不进入该函数。详见 [[file:同步合并测试用例设计.org][内容合并用例约定]]。

** 核心数据

*** OrgWorkspace

~OrgWorkspace~ 聚合应用中的零到多个仓库。它是运行时构造输入，不是持久化实体。

#+begin_src rust
impl OrgWorkspace {
    pub fn new(repos: Vec<OrgRepo>) -> Result<Self, OrgWorkspaceValidationError>;

    pub fn repos(&self) -> &[OrgRepo];

    pub fn repo(&self, repo_id: &OrgRepoId) -> Option<&OrgRepo>;

    pub fn repo_mut(&mut self, repo_id: &OrgRepoId) -> Option<&mut OrgRepo>;

    pub fn add_repo(&mut self, repo: OrgRepo) -> Result<(), OrgWorkspaceValidationError>;

    pub fn remove_repo_by_root_directory(&mut self, root_directory: &str) -> Result<OrgRepo, OrgWorkspaceValidationError>;

    pub async fn query(&self, queries: &[CoreQuery]) -> Result<Vec<CoreQueryResult>, CoreError>;

    pub async fn refile_targets(&self) -> Result<Vec<RefileTarget>, CoreError>;

    pub async fn execute_task_operations(
        &mut self, group: &TaskOperationGroup,
    ) -> Result<(), CoreError>;

    pub async fn task_merge_operations(
        &self, request: &TaskMergeRequest,
    ) -> Result<TaskMergePlan, CoreError>;

}
#+end_src

~new~ 与 ~add_repo~ 必须拒绝重复的仓库根目录，以及已加载仓库的重复 ~OrgRepoId~ 。新加入的仓库可以尚未加载；宿主必须逐个调用 ~OrgRepo.load::<P>~ 读取或创建稳定 ID；具体操作自行在锁内检查恢复状态并按需读盘。返回的集合不可由调用方原地修改。 ~remove_repo_by_root_directory~ 仅移除运行时集合中的仓库，不删除根目录、 ~.sync~ 历史或任何文件。对已加载仓库执行同步或编辑前，可用 ~repo_mut~ 按稳定 ID 取得该仓库。 异步批量 ~query~ 每仓库加锁一次、加载一次文件并共享 headline 基础投影，解析 ~TaskQuery.expression~ 并应用通用结构化条件，按表达式排序规则返回任务与分类统计。结果中的 ~repoId~ 与相对路径共同标识来源文件；宿主不得自行遍历仓库并实现另一套过滤逻辑。

~Filter~ 、表达式节点、日期条件、区间及排序节点均为 Core 内部实现类型，不再作为跨 crate API 导出。公开查询投影继续使用 ~FilterTask~ 、 ~FilterDate~ 、 ~FilterStateType~ 与 ~AddressLink~ 。

*** 任务展示数据

~FilterTask.category() -> Option<&str>~ 由查询过程直接从所属文件的 ~OrgFile.category()~ 提取，缺失与显式空声明分别保留为空值和空字符串。任务的 ~is_repeating()~ 继续由 Core 解析当前标题的计划或截止时间重复器；宿主直接消费这些只读快照，不解析 Org、不额外提供显示文字。分类变化后重新查询取得新快照，身份算法保持不变。

*** 任务身份与完整路径

~FilterTask.task_id()~ 对待办和已完成任务返回可空明文身份，非任务标题返回 ~None~ 。逻辑路径规则保持不变，采用紧凑 JSON 字符串直接编码，不再使用 MD5。 ~full_path()~ 对仓库、文件及所有标题节点返回 ~TaskPath~ ，标题链保留无状态祖先；身份与完整结构定位各自独立，具体定义见 [[file:数据模型.org::*任务逻辑身份][任务逻辑身份]] 和 [[file:数据模型.org::*完整结构路径与插入位置][完整结构路径与插入位置]] 。

完整路径的每个标题段排除真实进度节点，例如 ~[/]~ 、 ~[1/2]~ 和百分比统计；原始标题、列表正文和源字节保留。父标题或自身进度变化后仍使用相同结构路径，规范化后的重名项由出现序号区分；任务修改继续要求当前文件版本，不用路径稳定性绕过版本冲突。

~FilterTask.file_metadata()~ 借用同文件任务通过 ~Arc<OrgFileMetadata>~ 共享的不可变元信息； ~repo_id()~ 和 ~path()~ 继续提供原有读取接口。 ~support_tags() -> Option<&SupportTags>~ 返回候选名称与互斥组，类型为 ~SupportTags { tags: Vec<String>, groups: Vec<Vec<String>> }~ 。缺少配置返回 ~None~ ，显式空配置返回空集合，任务克隆不复制文件元信息或相同候选配置；规则与共享关系见 [[file:数据模型.org::*文件信息共享与可配置标签][数据模型]]。

~FilterTask~ 的字段不作为跨 crate 访问契约公开。宿主使用 ~id()~ 、 ~repo_id()~ 、 ~path()~ 、 ~title()~ 、 ~body()~ 、 ~state()~ 、 ~priority()~ 、 ~category()~ 、 ~own_tags()~ 、 ~inherited_tags()~ 、 ~scheduled()~ 、 ~deadline()~ 、 ~closed()~ 、 ~created()~ 与 ~address_links()~ 等方法读取查询快照；缺失的状态、优先级、分类、规划日期和地址均通过可空返回值表达。 ~created_at()~ 和 ~modified_at()~ 均返回 ~Option<TimestampMs>~ ，前者来自标题自身的 ~CREATED~ 属性，后者仅来自当前标题自身属性 drawer 中的 ~LAST_MODIFIED~ 。属性名不区分大小写，不继承父标题或文件级值；缺失或无效时返回 ~None~ ，不使用文件 mtime、创建时间或当前时间补齐。任务查询只读该属性，不自动生成或回填修改时间。

*** OrgRepo

~OrgRepo~ 定义一个本地 org 文件仓库。根目录仅在运行时使用；同步历史落盘于根目录的 ~.sync/history/~ ，由专用历史接口按需读取，不作为仓库字段保留。

当前待关注事件通过 CoreQuery 的 Notification 分支取得，文件元信息通过 File 分支取得。独立仓库／workspace 通知和文件元信息查询入口已删除。完整契约见 [[file:统一批量查询接口设计.org][统一批量查询接口设计]]。

#+begin_src rust
impl OrgRepo {
    pub fn new(root_directory: String) -> Result<Self, OrgRepoValidationError>;

    pub async fn reset(&mut self) -> Result<(), CoreError>;

    pub fn contains_path(&self, path: &str) -> bool;

    pub async fn load_files(&self, ignore_files: &[String]) -> Result<Vec<OrgFile>, CoreError>;


    pub async fn refile_targets(&self) -> Result<Vec<RefileTarget>, CoreError>;

    pub async fn file(&self, path: &str) -> Result<OrgFile, CoreError>;

    pub async fn pending_writes(&self) -> Result<Vec<OrgRepoWriteIntent>, CoreError>;

    pub async fn acknowledge_write(&self, path: &str,
        version: &LocalFileVersion) -> Result<(), CoreError>;

    pub async fn load<P: SyncPolicy>(&mut self)
        -> Result<Vec<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>>, CoreError>;

    pub async fn sync<P>(&mut self, policy: &P,
        started_at: TimestampMs,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter)
        -> Result<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>, CoreError>
    where P: SyncPolicy;

    pub async fn sync_with_options<P>(&mut self, policy: &P,
        started_at: TimestampMs,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter,
        options: SyncOptions)
        -> Result<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>, CoreError>
    where P: SyncPolicy;
}
#+end_src

~contains_path~ 必须拒绝绝对路径和包含 ~..~ 的路径。 ~load~ 先读取或创建 ~.sync/id~ ，再扫描根目录、跳过 ~.sync/~ 并解析 org 文件，最后替换仓库的完整文件快照；重复或越界路径必须失败。首次加载生成的 UUID 必须写入带换行的 ~.sync/id~ ，后续加载同一根目录必须复用该值。 ~sync~ 自行恢复最新文件与历史后委托策略执行同步，并只追加归属本仓库的完成记录；重复开始时间在调用策略前拒绝。

~file(path)~ 从当前已加载集合返回独立的 ~OrgFile~ 副本。路径尚不存在时构造未落盘的空文件，沿用该仓库的全局默认 TODO 配置；非法路径或仓库尚未加载时报错。该方法不读取磁盘、不修改仓库文件列表，也不写入 outbox。宿主需要最新内容时先加载仓库。

*** TaskScanRules

根目录 ~.orgzlyignore~ 在每次文件读取中重新加载；仓库不保存扫描规则。 ~load_files~ 和 ~file(path)~ 返回独立文件值，任务 ~query~ 依据本次读取的规则排除隐藏文件；WebDAV 下载、删除和本地修改保护见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]。

#+begin_src rust
impl TaskScanRules {
    pub fn parse(source: &str) -> Result<Self, CoreError>;
    pub fn excludes(&self, path: &str) -> bool;
}
#+end_src

~Default~ 表示没有忽略规则。 ~path~ 使用仓库内安全相对路径；非法相对路径不匹配。修改文件后需重新调用 ~load~ ，规则格式和作用范围见 [[file:目录结构设计.org][目录结构设计]]。

*** OrgFile

~OrgFile~ 保存一次解析/编辑会话内的完整源字节，并在运行时缓存 ~orgize::Org~ 无损语法树。缓存不属于 core 持久化模型； ~sourceBytes~ 是保真序列化的唯一来源。

#+begin_src rust
impl OrgFile {
    pub fn new(
        repo_id: OrgRepoId,
        path: String,
        source_bytes: Vec<u8>,
    ) -> Result<Self, OrgFileValidationError>;

    pub fn source_bytes(&self) -> &[u8];

    pub fn category(&self) -> Option<String>;

    pub fn title(&self) -> Option<String>;

    pub fn title_parts(&self) -> Vec<TitlePart>;

    pub fn render_html(&self) -> String;
}
#+end_src

~new~ 必须验证 UTF-8 编码并构造 ~orgize~ 缓存，且不改变输入字节。未应用 ~OrgFileEdit~ 时， ~serialize_file~ 必须逐字节返回 ~source_bytes~ 。解析语义以 Emacs ~org-element.el~ 为准。

~category()~ 从解析后的文件头元数据按属性名 ~CATEGORY~ 读取第一条声明。关键字不区分大小写，值去除首尾空白并保留内部空格与中文。未声明时返回 ~None~ ，显式空声明返回 ~Some(String::new())~ ；值为大小写不敏感的 ~ARCHIVE~ 时按特殊分类过滤并返回 ~None~ 。不以文件名或父目录补齐；源码块、示例块、注释及标题内部的声明不属于文件头配置。本接口只读取当前文件的声明，不展开 ~SETUPFILE~ 或标题属性。文件头元数据在解析和编辑后随无损语法树一起重建，不单独缓存分类计算结果或修改原文。

文件头关键字依据 [[info:org#In-buffer Settings][Org Info：缓冲区设置]] 解析： ~#+~ 和冒号属于语法，由 ~orgize~ 生成独立名称与值；内部 ~FileKeywords~ 按大写属性名保存有序值列表，消费者通过 ~get("PROJECT_NAME")~ 或 ~values("TAGS")~ 访问语义数据，不读取完整声明行。属性名不包含 ~#+~ 或结尾冒号，显式空值与不存在分别保留。多行标题遵循 [[info:org#Export Settings][Org Info：导出设置]]；项目名是应用自定义关键字，仍取第一条声明并优先于文件标题。

文件头身份元数据只收集第一个标题前的直属关键字，块内、注释和标题正文中的同名文字不混入。此范围不改变 TODO 等允许整篇声明的设置规则，也不把 ~#+PROPERTY: Name Value~ 与独立关键字混为一谈；二者语义见 [[info:org#Property Syntax][Org Info：属性语法]]。解析结果只在运行时存在，源字节与无损语法树继续保留完整源码。

属性 drawer 通过 Core 的 ~Properties~ 从 ~orgize~ 的 ~node_properties~ 读取，不依赖会遗漏空值的简化遍历接口。名称统一大写，去除冒号，并单独保留语法节点中的 ~+~ 追加标记与值范围；显式空值和不存在分别保留。自身属性先取基础值，再按声明顺序以空格拼接追加值；需要继承的字段先取得父级或文件默认值，子级有基础声明时覆盖，没有基础声明时继续追加。普通属性默认不继承，现有 ~LOGGING~ 与 ~LOG_INTO_DRAWER~ 等指定字段沿用其继承规则， ~CREATED~ 与 ~LAST_MODIFIED~ 仍只读取自身。

文件默认属性依次合并 SETUPFILE 提供的设置、文件内 ~#+PROPERTY:~ 声明，再由文件顶部 ~PROPERTIES~ drawer 覆盖或追加。 ~#+PROPERTY: Name Value~ 重设该默认属性， ~Name+~ 追加。文件关键字与属性保留各自语义，不将属性 drawer 中的 ~TITLE~ 或 ~CATEGORY~ 自动当成同名文件关键字。

当前保留上游 ~orgize~ 的语法限制：空属性冒号后必须至少有一个空格才会生成属性节点。完全无空格的 ~:EMPTY:~ 会导致该属性 drawer 无法识别；本项目不修改或替换 ~orgize~ ，不另建逐行解析器处理此情况。冒号后带空格且已经生成节点的空属性则由 Core 正确保留为空值。

~OrgFile.render_html()~ 与任务正文渲染消费真实语法节点，配置关键字不作为正文输出，包含未知关键字、 ~PROJECT_NAME~ 、 ~TBLFM~ 与 ~CALL~ 。 ~FILETAGS~ 仅展示解析后的标签，文件标题通过已有标题字段展示。源码、示例块及普通段落中的字面文本按原有内容渲染，不按字符串前缀删除，原文模式保持完整源码。

** 运行时端口

*** 本地仓库加载与解析

~OrgRepo.load~ 是 core 的异步本地初始化操作。它先确保 ~.sync/~ 存在，读取合法的 ~.sync/id~ 并按指定 ~SyncPolicy~ 解析历史 detail ；若文件不存在，则生成 UUID 并以独占创建、写入与刷新持久化。之后递归扫描根目录中的普通 ~.org~ 文件，跳过符号链接和 ~.sync/~ ，并以原始字节构造 ~OrgFile~ 。扫描到重复、越界或非法的相对路径时必须失败，不能部分替换文件快照。

~orgize~ 解析结果必须保持无损；WebDAV 下载获得的字节也必须复用相同的 core 解析规则，而不是在 WebDAV 模块中定义另一套内容模型。

*** OrgFileEdit 与保真序列化

编辑接口以已解析的单个 ~OrgFile~ 为边界。它只可替换、删除明确来源范围，或在明确来源位置插入内容；完成后重新构造 ~orgize~ 缓存。

*** SyncPolicy 与本地同步历史

~SyncPolicy~ 是同步策略接口，使用 ~KIND~ 标识历史所属策略，并包含 ~ContextDetail~ 与 ~FileDetail~ 两个关联类型； ~core::webdav::WebDavSyncPolicy~ 实现该接口。 ~OrgRepo.load::<P>~ 从 ~.sync/history/~ 恢复并返回完成记录，拒绝 ~kind~ 与 ~P::KIND~ 不一致的记录； ~OrgRepo.sync~ 在接受策略返回的完成记录后，将其原子写入 ~.sync/history/<started-at>.json~ 。历史归 ~OrgRepo~ 管理； ~sync~ 每次自行从本仓库恢复最新历史，控制器不缓存历史，宿主不向两者传递历史。 ~SyncPolicy.synchronize~ 只接收 ~SyncContext~ 、取消信号和进度对象；策略需要历史时通过上下文仓库的内部历史接口读取。策略接收可变仓库，因此下载成功时可替换对应 ~OrgFile~ 快照。

#+begin_src rust
pub trait SyncPolicy: Send + Sync {
    const KIND: &'static str;

    type ContextDetail: SyncContextDetail;
    type FileDetail: SyncFileDetail;

    fn synchronize(
        &self,
        context: &mut SyncContext<'_>,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter,
    ) -> impl Future<Output = Result<OrgRepoSyncRecord<Self::ContextDetail, Self::FileDetail>, CoreError>> + Send;
}

策略不得将密码、Authorization header、仓库绝对路径、远端完整 URL 或完整文件内容写入错误摘要。完整成功文件仅通过 ~detail.synced_source~ 保存于同步日志；上传和快照均使用 ~serialize_file~ 的完整字节，不格式化其他范围。

*** SyncContext 与策略细节

~SyncContext~ 表达一次同步，持有可变 ~OrgRepo~ 、 ~started_at~ 、仓库根路径 ~base~ 和本次调用的 ~SyncOptions~ 。历史仍由仓库内部管理，不作为策略接口参数。 ~SyncOptions~ 当前包含 ~excluded_directories~ ，默认由 Rust 提供为 ~["archive"]~ ，后续可扩展其他策略参数。 ~SyncContextDetail~ 与 ~SyncFileDetail~ 约束策略专属且可序列化的历史细节；前者保存到记录的 ~context_detail~ ，后者保存到每个文件的 ~detail~ 。

过滤不删除已下载的本地文件，不改写历史或确认被过滤文件的 outbox；普通同步不为被过滤路径产生下载、上传、删除或冲突记录。规则只影响传输范围，本地浏览仍读取已有文件，已有冲突仍可从历史中查询。

*** OrgRepoSyncController

~OrgRepoSyncController~ 在 core 内持有一个 ~OrgRepo~ 与启动时传入的 ~SyncPolicy~ 。它通过 Tokio task 执行一次同步，并以快照让 UI 宿主读取当前状态；HTTP、Harmony 等宿主不得自行维护同步状态或伪造完成记录。调用 ~start~ 的宿主必须运行在 Tokio runtime 中。

#+begin_src rust
let controller = OrgRepoSyncController::new(repo, policy);
controller.start(started_at).await?;
let snapshot = controller.snapshot();
controller.cancel()?;
#+end_src

~start~ 在已有同步运行时返回错误。 ~cancel~ 仅设置 ~SyncCancellation~ ，策略在列举和文件边界检查该信号后以 ~Cancelled~ 完成当前记录。 ~snapshot~ 返回 ~Idle~ 、 ~Running~ 、 ~Cancelling~ 、 ~Succeeded~ 、 ~Failed~ 或 ~Cancelled~ ，以及阶段、已完成数量、总数、当前文件和最近完成记录。进度和取消句柄是运行时数据，不属于持久化记录。

进度快照可附带本轮按发生顺序排列的脱敏 HTTP 事件，内容仅包含请求方法、相对路径或根路径，以及“请求中”或响应状态码。它供宿主展示同步过程，不属于同步记录，也不得包含完整 URL、认证材料或传输正文。

*** WebDavSyncPolicy

~WebDavSyncPolicy~ 位于 ~core::webdav~ 。它用各路径最近一条 ~Synchronized~ 文件记录的本地哈希和远端版本作为基准，处理新建、下载、条件更新、冲突、远端删除和传输失败，并直接持有 HTTPS Basic 认证配置与 HTTP client；HTTP 宿主不实现 WebDAV 端口。

~WebDavSyncMonitor~ 是 WebDAV 同步的观察接口。通过 ~WebDavSyncPolicy.with_monitor~ 注入后，调用方可按顺序获得同步开始、列举、文件处理、HTTP 请求和响应、结束事件。事件只携带仓库 ID、相对路径、文件记录和 HTTP 状态，不含凭据、完整 URL、绝对路径或文件正文。

#+end_src

~WebDavSyncPolicy.test_connection~ 提供不依赖本地仓库的独立连接检查：

#+begin_src rust

该方法只请求配置目录的 ~PROPFIND~ ，使用 ~Depth: 0~ 查询 ~resourcetype~ ，要求 ~207 Multi-Status~ 和目标自身成功返回的 DAV collection 属性。空目录可以通过，普通网页、文件地址、认证拒绝、无效或不完整 XML 均不能报告成功。请求与响应正文读取共享 15 秒总超时。方法不接收 ~OrgRepo~ ，不读写本地文件、历史、outbox 或日历，不上传下载文件；成功只证明认证与目录访问，不证明写权限。

策略内部的列举映射 ~PROPFIND~ ，下载映射 ~GET~ ，上传的 ~CreateOnly~ 映射 ~If-None-Match: *~ ， ~Match~ 映射 ~If-Match~ 。策略不得把认证材料放入领域记录。

* 旧接口

旧的全局作业接口已移除。宿主不读取、不转换也不写入旧作业状态；使用旧版本数据时，应清理数据后按当前接口重新配置和同步。


* 冲突接口与版本恢复

冲突选择通过普通 ~OrgWorkspace.execute_task_operations~ 提交 ~TaskOperation::ConfilictSelection~ ，字段为文件根 path、id、action 与可选 target。id 对应 CONFILICT_ID，Discard 保留主树并移除候选，UseLocal 按受控目标采用候选。预览、结束后路径重写和真实提交规则见本文“冲突预览接口”与 [[file:同步核心设计.org][同步核心设计]]。

OrgFile.conflict_ids 与 conflicts 分别返回 ID 和结构化描述，普通文件读取仍包含完整冲突原文。当前／预览的变化由 Core 投影，宿主不解析 Org 或复制合并规则。

* TODO 默认配置与文件元信息接口

默认值由 Rust ~Default~ 实现提供，外部负责保存自己的全局配置。配置可用结构化 ~TodoConfig~ 传入，或由原生 Org 声明文本经 ~from_settings~ 解析。空白设置文本表示空配置，不套用缺省值；配置只在运行时持有，不写入同步元数据。

#+begin_src rust
let defaults = TodoConfig::default();
let editable_settings = defaults.to_settings();
let configured = TodoConfig::from_settings(&editable_settings)?;
workspace.set_todo_defaults(configured.clone())?;
repo.set_todo_defaults(configured)?;
let file = OrgFile::with_todo_defaults(repo_id, path, bytes, defaults)?;
let metadata = &file.todo;
#+end_src

~OrgFile::new~ 使用 Rust 缺省配置， ~with_todo_defaults~ 使用外部默认配置。 ~OrgRepo.parse_file~ 在扫描、下载、创建与合并时统一传递配置。 ~OrgWorkspace.set_todo_defaults~ 校验并更新全部仓库与已加载文件， ~add_repo~ 将配置传给后续加入的仓库。配置更新失败时不产生部分重解析的状态。

每个文件快照公开 ~todo~ ，包含来源、带来源区间的文内声明、流程、状态类型、显式快捷键和日志要求、待办/完成集合与初始状态。现有 ~FilterTask.state_type()~ 来自有效配置后的语法树，宿主不得用 DONE/CNCL 字面值推测完成状态。

Creation 的显式状态按目标文件有效配置验证；文件尚不存在时使用外部默认。调用方需要创建任务时从文件元信息取得初始状态，无状态标题则不传状态。冲突重组也使用当前配置重新解析并验证输出，来源正文和层级校验均由 Core 执行。

* 通用结构化任务查询

~OrgWorkspace.query(&[CoreQuery])~ 返回与请求逐项对应的结果数组，Task 结果分支包含 Core 过滤后的任务列表和分类摘要，File 分支返回文件元信息数组，Notification 分支返回当前通知数组。Task 分支的请求字段为 ~expression~ 、 ~categories~ 、 ~excluded_files~ 、 ~include_done~ 与 ~include_compose_tasks~ ，完整 Rust 定义及语义见 [[file:查询语言设计.org][查询语言设计]] 。界面需求由 UI 组装为通用请求，Core 不持有收件箱或控件专属字段。所有任务过滤统一由 Core 执行，宿主不得对返回的列表再实现分类、完成、文件或父子关系过滤。

~query~ 完成查询匹配后，从每个任务返回值的 ~own_tags~ 和 ~inherited_tags~ 中排除精确等于 ~REFILE~ 或 ~ARCHIVE~ 的系统标签，其他标签顺序不变。表达式仍在完整原始标签上求值，因此 ~t.REFILE~ 、~tn.REFILE~ 与对应的 ~ARCHIVE~ 查询保留原有匹配语义；不隐藏带这些标签的任务，不修改源文件。

* 任务放置目标

~REFILE~ 是大小写敏感的系统标签，表示该标题可以作为放置任务的位置。 ~OrgRepo.refile_targets()~ 返回当前仓库的目标， ~OrgWorkspace.refile_targets()~ 异步按次读取并汇总各仓库；不修改文件或同步记录。

~CoreQuery::File~ 从本批完整文件快照返回轻量清单；提供仓库 ID、相对路径、标题、标题记录数、原始字节数和本地磁盘修改时间，不克隆源字节，无任务标签条件时不构建任务对象。需要新状态时重新提交统一批量查询，元信息在 File 结果分支中返回。 ~OrgFile.title()~ 从解析后的文件头元数据按名称 ~TITLE~ 读取值，关键字不区分大小写，每条值去除首尾空白，多行声明按顺序以空格合并，空行值不额外插入空格。缺少为 ~None~ ，显式空值为 ~Some(String::new())~ ，标题内声明、注释与源码块不作为文件标题。不限定前几行，不以文件名补齐领域值。

当前轻量接口减少响应构建和跨层复制，首次加载仍需完整解析。后续若优化首次列表扫描，可评估由 Core 缓存文件版本与已解析元信息，或提供专门头部扫描；需要保持注释、块结构、第一条声明和文件头边界语义，并避免固定行数遗漏合法 TITLE。任何缓存都不得改变同步读取完整原始字节的要求。

~OrgFile.tag_options() -> Vec<String>~ 返回文件头 ~TAGS~ 定义的候选，去重并去除系统标签；~tag(k)~ 去掉快捷键，没有快捷键的标签也保留。~OrgFile.tag_groups() -> Vec<Vec<String>>~ 返回花括号定义的互斥组，保留组及成员的声明顺序。~OrgFileMetadata.tag_options~ 与 ~tag_groups~ 携带相同的轻量投影，空文件仍保留配置，宿主无需复制正文或另行解析。配置不向任务赋标签，完整语义见 [[file:查询语言设计.org::*文件头 TAGS 配置][文件头 TAGS 配置]] 。

* 整篇只读渲染

OrgFile.render_html() 直接遍历已有 orgize 语法树，返回不含宿主样式的 HTML 文档片段。文件 TITLE 由宿主工具栏展示，片段不重复生成文件标题；真实标题节点照常保留。它是运行时展示投影，不是新的解析模型，不修改 source_bytes，也不写入同步记录。标题层级及其子树、TODO 完成类型、优先级、标签、计划时间、属性抽屉、正文行内样式、链接文字、列表、表格与代码块均按语法节点生成；没有标题的文件仍呈现文件前言。未专门排版的 HTML 导出块、snippet、LaTeX 等以转义后的字面文本呈现，不执行其内容。

标题使用嵌套 details，默认展开；drawer 默认收起，折叠只改变阅读状态。表格和代码块由宿主提供横向滚动容器，表格公式不在阅读正文展示，也不求值。支持的外部链接显示文字并提供锚点，图片引用不自动加载；不加载远端资源或本地附件，也不提供状态修改或复选框写回行为。完整原文始终可从 source_bytes 获取。

** 正文首行投影

~FilterTask.body_first_line() -> Option<String>~ 返回当前标题正文首个非空段落的第一行，跳过开头空行、规划、属性 drawer、日志及其他 drawer，不包含子标题正文；Org 行内样式、链接和实体转为可读文字。没有可读段落时返回 ~None~ ，源字节不变。该通用只读接口不持有备忘页面语义。

** 标题文字与外部链接投影

~OrgFile.title_parts()~ 读取文件头 ~TITLE~ ， ~FilterTask.title_parts()~ 读取已有任务标题；两者复用 ~orgize~ 的行内语法解析，返回有序文字与链接片段，不改变 ~title()~ 、原始任务标题、查询语义或文件字节。带描述的 Org 链接显示描述，不带描述的链接显示地址；标题中的行内格式转为可读文字。空标题返回空数组，宿主可回退相对文件路径。 ~OrgFileMetadata.title_parts~ 携带同一轻量投影，避免文件列表再次读取全文或由 UI 解析 Org。

~href~ 只对合法的 ~http~ 、 ~https~ 、 ~mailto~ 、 ~tel~ 、 ~geo~ 与 ~addr~ 地址提供值；坐标地址使用 Org 外部链接形式，例如 ~[[geo:39.9042,116.4074][北京市]]~ 。文字地址使用应用约定的 ~addr:~ 协议，例如 ~[[addr:北京市朝阳区][北京市朝阳区]]~ ，宿主点击时转换为地图搜索 URI。坐标为 ~0,0~ 时必须提供 ~q~ 参数，例如 ~[[geo:0,0?q=北京市][北京市]]~ ；缺少 ~q~ 时宿主提示链接无效。其他类型保留可读文字且值为 ~None~ 。链接中不接受控制字符。完整文档、任务正文与日志中的同类链接生成经过 HTML 属性转义的 ~a.link~ ，其他类型为带 ~unsupported~ 类与禁用语义的 ~span.link~ ；不自动加载图片、附件或网页，不执行 Org 文内代码。宿主在用户点击时调用系统应用打开，阅读内容本身不导航到网页。

~TitlePart.is_link~ 区分普通文字和已经解析但目标尚不支持的链接；该字段在 JSON 中为 ~isLink~ 。 ~is_link=true~ 且 ~href=None~ 表示未支持链接，宿主可保留不同的链接样式，不把它与邻接普通文字合并。

~TitlePart.count~ 为可空的分数统计投影；普通文字、链接、代码与逐字文本的片段值为空。有效统计节点投影为 ~TitleCount~ ， ~text~ 为去掉方括号的显示值， ~href=None~ 且 ~is_link=false~ 。例如 ~[1/2]~ 得到 ~completed=Some(1)~ 与 ~total=Some(2)~ ， ~[/]~ 的两个字段均为空且显示为“—/—”； ~[0/0]~ 保留零值。分子大于分母、单边为空或超出 ~u32~ 范围时保留原文，不产生计数；百分比统计也保留原文。多个计数按出现顺序返回，不与邻接文字合并，不重新统计子任务或 checkbox。文档的真实标题同样生成 ~span.title-count~ ，携带安全的比例样式和无障碍说明；正文中的计数不转换为进度标记。所有投影均不影响原文、查询、逻辑 ID 或写入行为。

** 任务列表提示投影

~FilterTask.is_repeating() -> bool~ 由 Core 读取当前标题的计划与截止时间重复器生成，不包含正文或子标题中的重复器，也不展开重复日期。重复器遵循 Org-mode timestamp 规则，识别 ~+Nunit~ 、 ~++Nunit~ 、 ~.+Nunit~ 及可选的重复截止 ~/N~ 或 ~/Nunit~ （~unit~ 为 ~h~ 、 ~d~ 、 ~w~ 、 ~m~ 、 ~y~）；解析器未识别的合法规划行由 Core 在标题范围内兜底。与 ~RenderedTaskContent.has_list~ 、 ~has_text~ 一起提供只读展示提示。Harmony 映射为 ~Task.isRepeating~ 、 ~Task.hasList~ 与 ~Task.hasText~ ，宿主不解析 Org。三个字段均不进入同步记录、outbox 或仓库身份。

** 分享地点写入与地址替换

~RenderedTaskContent.body_html~ 是任务正文展示投影，规划字段独立展示。分享地点通过 Creation 的 body 写入原始 Org 地址链接；已有链接通过 ~TaskModification::AddressLink~ 指定新旧 URI 更新，由 Core 无损语法树定位，不在宿主扫描或拼接任务源文件。

* 统一任务操作组执行

新建任务及无状态标题时，Core 自动写入本地非活动 ~CREATED~ 时间戳，后续不可通过字段操作设置或清除；不再接受 ~recordCreated~ 开关或创建参数 ~closed~ 。 ~TODO~ 操作按当前文件加载后的有效完成集合自动维护 ~CLOSED~ ，包含文件内覆盖与嵌套 ~SETUPFILE~ ，不按状态名硬编码。默认不记录关闭时间；只有文件或 SETUP 中的 ~logdone~ 、 ~lognotedone~ 或有效 ~LOGGING~ 配置启用关闭记录时，进入完成状态才写入当前时间。新建完成任务遵循同一关闭记录开关，创建本身不模拟状态切换；已完成且已有关闭时间时保留；恢复为未完成或清除状态时移除。文件日志配置可覆盖关闭记录策略。重复任务完成时自动推进真实活动重复时间戳并恢复流程状态，不保留 CLOSED；随后按 [[file:TRIGGER触发器设计.org][TRIGGER 规则]] 执行本文件内联动，不支持动作静默跳过；普通状态及重复日志仅由文件或 SETUP 中的显式配置触发。存在有效子任务时禁止改变父任务状态，其他字段仍可编辑。完整规则见 [[file:数据模型.org::*状态变化、重复调度与日志][状态变化、重复调度与日志]]。 ~CREATED~ 与 ~CLOSED~ 显式字段输入拒绝。

~OrgWorkspace.execute_task_operations~ 是唯一任务写入入口。操作组可组合 Creation、Modification、Movement、Deletion 和 ConfilictSelection；每类数据独立，字段设置和清除由 ~TaskModification~ 枚举表达。目标位置使用 ~TaskPosition { parent, after }~ ，不再使用字节位置作跨快照输入。

~task_merge_operations~ 接受 ~TaskMergeRequest { paths, file_version }~ ，按选择顺序把同一文件内至少两条互不重叠的记录转换为正文列表，结果标题为“合并: 第一条所选记录的原始标题”。第一条记录保留原位置及自身状态、规划和属性，原子记录转为嵌套列表。元数据与日志保存在专用 Org comment 块中，阅读与备注编辑不展示这些归档。

返回 ~TaskMergePlan { operation_group, main_path }~ ，操作组仅包含普通 Deletion 和 Modification，以及原文件版本。删除按原文逆序排列，修改使用删除后的完整路径；规划在内存副本中验证，不写盘、不产生历史或通知。调用方仅补充需要 outbox 的仓库 ID，再通过既有 ~execute_task_operations~ 一次提交； ~main_path~ 供成功后定位，不作为提交修改的路径。该接口是内容操作规划，不创建预览页面或临时文档。

路径重复、祖先与后代重叠、跨文件、受保护冲突节点、将被转换为列表的记录带 ID／CUSTOM_ID，或当前文件存在其标题链接引用时拒绝。未涉及范围保留原字节；其他文件与仓库外的标题定位链接不自动重写。

Core 先收集并读取本组所需文件到隔离内存，按顺序执行全部操作；任一步失败丢弃全部工作快照，磁盘、历史与 outbox 不变。全部内存操作完成后才准备临时文件、校验磁盘原始字节并提交。普通提交失败回滚已修改文件；回滚期间发生外部写入时保留恢复材料并报错，不能宣称跨文件崩溃原子性。

~file_versions~ 可由调用方提交源或目标文件的已读版本，过期时整组拒绝。 ~queue_repo_ids~ 指定需要 outbox 的 Core 仓库 ID，一组内同一文件仅登记最终变更版本。任务正文和回退原文不写入 outbox，执行操作组不自动上传远端。

~TaskFallbackGroup~ 在提交成功后自动加入运行时 ~TaskOperationHistory~ ，保存实际变更文件的原始前后字节及文件是否原先存在。失败不追加历史；后续 undo、redo 可复用这些记录，本轮未提供相应执行入口。完整类型、顺序规则及错误边界见 [[file:数据模型.org::*统一任务操作模型][统一任务操作模型]] 。

* 查询文件定位与创建日期条件

~TaskQuery.excluded_files~ 类型为 ~Vec<OrgFileRef>~ ，每项包含 ~repo_id~ 与 ~path~ ，两者共同表示具体文件。仓库 ID 使用 Core 的稳定身份，路径是安全的仓库相对文件路径；空仓库 ID 或非法路径返回输入错误。一个排除对象仅影响所属仓库中的该文件，不影响其他仓库的同名文件。数组省略或为空表示不排除；接口不再接受裸路径字符串数组。JSON 对应 ~excludedFiles: [{ repoId, path }]~ 。

创建日期筛选通过 ~TaskQuery.expression~ 表达，不新增时间范围字段。 ~FilterTask.created()~ 与 ~created_at()~ 从任务自身的 ~CREATED~ 属性投影；缺失或非法值不匹配 ~cr.ge.-2d cr.le.today~ 。该表达式覆盖今天及前两个本地自然日，而非滚动 72 小时。完整时刻排序通过 ~o.created~ 或 ~.o.created~ 取得；日内时间用于排序和展示投影，不改变自然日筛选边界。所有能力继续通过 ~OrgWorkspace.query~ 暴露。

* WebDAV 同步历史摘要

~core::webdav::sync_history_summaries(history) -> Result<Vec<WebDavSyncRecordSummary>, CoreError>~ 将按开始时间升序恢复的完整 WebDAV 历史投影为运行时摘要，顺序不变。单条实时结果可调用 ~WebDavSyncRecordSummary::from_record(record)~ ，没有后续历史时已解决数量为零；未完成记录返回错误。

摘要保留原始作业结果，另行给出独立执行结果、四态传输方向、下载与上传各自成功的文件数、固定冲突路径，以及可空错误分类和原记录已有的错误消息。只有冲突而没有执行错误时，日志执行结果为成功；网络、认证及其他执行错误保持失败。仅统计已成功的文件动作，两种方向可以同时出现，失败尝试不虚构传输。各条日志的冲突由当次记录固定，后续操作不投影已解决状态；完整规则及运行时 TikZ UML 见 [[file:数据模型.org::*WebDAV 同步历史运行时摘要][同步历史运行时摘要]] 。

摘要投影不读取宿主配置、不修改原始历史，也不替代同步编排继续使用的原结果。宿主将摘要映射为颜色、图标和标签，不重新实现历史回放。


~sync_history_detail(history, sync_id) -> Result<WebDavSyncRecordDetail, CoreError>~ 读取指定历史的统一同步详情，返回摘要、逐文件结果与已有错误信息。缺失的错误详情保持为空，找不到同步 ID 时返回错误。所有文件路径均相对仓库，不返回成功文件的源内容、ETag、版本哈希或凭据。纯投影接口只读取传入日志；宿主需要文件系统中的 resolved 状态及备份元信息时调用下文的仓库异步历史接口。

* 待关注事件

~CoreQuery::Notification { query: NotificationQuery {} }~ 通过唯一批量入口返回 ~CoreQueryResult::Notification(Vec<CoreNotification>)~ 。每个当前含 CONFLICT 容器的文件生成一条 SyncConflict；任一仓库字节 hash 与基线索引不同则追加一条 SyncRequired。两类事件都从当前快照派生，不消费、不持久化，不依赖历史或进程内去重标记。

通知使用整批加载的完整文件范围，包括被任务忽略规则隐藏或被某项 Task 排除的文件。基线索引在同次仓库锁内读取，本地 hash 从同批字节计算，不二次加载正文。错误导致整个批次失败。订阅继续只发出失效事件，宿主将通知和页面正文一起放入下一批读取。


* 日志备份与单文件本地解决

~OrgRepo.webdav_history()~ 只读取不可变的完成记录； ~history_summaries()~ 与 ~history_detail(sync_id)~ 从该记录取得固定结果，不读取当前任务树推导“已解决”。 ~history_file~ 保留原文和旧布局兼容读取。手机日志展开项仅在 ~Deleted~ 文件具有 ~deleted_archive~ 时返回 ~backup~ 供阅读；其他状态没有进入箭头，错误独立展示。当前冲突处理统一使用普通操作组，不通过历史记录选择写入。

* 最近有效同步与通知更新监控

~OrgRepo.last_effect_sync()~ 仍按时间取得最近成功完成的记录，返回内容不因后续任务编辑而变化。当前冲突通知改从文件标记生成，每文件一条 ~{ type: 'syncConflict', repoId, path }~ 。 NotificationQuery 复用已加载的文件字节比较本地与基线 hash，在任一仓库有变化时附加唯一 ~syncRequired~ 通知。

冲突与同步提示只由 Rust 的统一批量查询从当前文件及基线索引计算，不回放历史，也不依赖进程内标记。查询接口和展示接口分离，手机通知界面不调用 ~lastEffectSync~ 、历史或仓库清单接口决定是否展示；缺少备份的历史仍可在详情显示冲突与“未备份”标签。


~OrgWorkspace.watch_data_changes(callback) -> DataChangeSubscription~ 是独立的数据失效订阅。每次调用创建一个可单独销毁的订阅，同一 workspace 可同时存在多个订阅；回调只携带 Core 仓库 ID，不携带任务快照。任务操作、同步提交、冲突解决、重置和显式 ~reload~ 成功后按仓库发送 ~DataChangeEvent::RepositoryChanged~ ；失败、无实际变化与只读查询不发送。宿主必须异步重新查询，不能在回调中重入 workspace 锁。
~OrgWorkspace.watch_notifications(callback) -> NotificationSubscription~ 保留通知失效订阅；回调不查询内容，由宿主调度统一批次，完整数据类型见通知模型。

全局同步提示产生或清除使用 ~NotificationUpdate::GlobalNotificationsChanged~ ，不虚构仓库 ID，完整契约见 [[file:同步核心设计.org::*通知更新、模型与职责][同步核心设计]]。

订阅对象销毁即解除，回调在注册表锁外执行；回调不能重入调用时仍持有的仓库锁，宿主通过线程安全队列转到 UI 后再查询。页面监听数据失效后，在下一批同时重读正文和通知，通知区域只消费该批返回的通知快照；同步控件只负责发起同步和展示进度，不在 Promise 完成后直接刷新正文。

* 失败同步的本地提交边界

单个仓库整轮同步通过可恢复本地事务提交工作文件、实际远端基线、成功历史及 outbox 确认。执行错误或取消不推进这些本地状态，已成功的远端请求不保证回滚；任务内容冲突不是执行错误。完整边界见 [[file:同步核心设计.org::*同步提交与失败边界][同步核心设计]]。

* 放置目标的具体文件范围

~OrgWorkspace.query_refile_targets(&RefileTargetQuery)~ 异步按次读盘取得 REFILE 目标，参数 ~files~ 与 ~excluded_files~ 均为 ~Vec<OrgFileRef>~ 。 ~files~ 非空时只遍历所列具体文件，空时不限制； ~excluded_files~ 优先排除指定文件。仓库 ID 和安全相对路径必须同时匹配，非法路径或空仓库 ID 拒绝。Core 在读取文件 CATEGORY 和遍历 REFILE 标题之前应用范围，不先生成分类再由 UI 移除。无参数的 ~refile_targets()~ 保持完整枚举语义，供内部校验及已有调用使用。

设置移动根任务状态与清理规划使用统一操作组：先提交包含 ~TODO~ 、 ~SCHEDULE~ 、 ~DEADLINE~ 的 ~TaskModificationOperation~ ，再提交 ~TaskMovement~ 。状态在含 ~SETUPFILE~ 的源文件有效配置中验证， ~CLOSED~ 随状态自动维护，移动同时验证目标文件保持子树的标题和 TODO 语义；整组失败不修改文件或 outbox。规划清理只影响根条目，保留正文、子条目规划、标签、优先级和 ~CREATED~ 。

统一任务操作组在完整提交文件、更新内存与回退历史后，按实际变更的仓库发布一次 ~DataChangeEvent::RepositoryChanged~；失败或无实际文件变化不发布。数据回调只用于安排异步重查，不能重入当前 workspace 锁。~watch_notifications~ 继续只服务通知区域。

* 任务冲突与普通同步

任务冲突随文件末尾容器上传，不阻止普通同步。查询和普通编辑保护整个冲突子树，只有受控的冲突选择可以移除点。同步历史的文件结果完成后固定，不再按当前文件派生 pending／resolved 状态；日志展开项只为远端删除备份返回手机可阅读的备份元信息。

* 仓库重置与文件冲突标志

~OrgRepo.reset().await~ 清空本地目录内的文件、历史、基线、冲突快照、忽略规则与 outbox，保留 ~.sync/id~ 原字节和根目录。Core 负责仓库锁、暂存、恢复和更新发布；不访问远端，也不修改宿主配置。句柄身份过期时拒绝执行。完整故障边界见 [[file:同步核心设计.org::*仓库重置][同步核心设计]]。

~OrgFile.has_conflict() -> bool~ 与 ~OrgFileMetadata.has_conflict~ 从真实标题的 ~CONFLICT~ 自有标签取得，Serde 字段为 ~hasConflict~ 。源码块中的同名文本不参与；无冲突容器时不额外写文件头标记，宿主仅消费结果。

版本 4 的任务冲突额外在日志 conflicts 目录保存实际处理后带候选的完整文件，该快照与成功历史、基线同事务提交，全部解决后仍保留；不能把目录存在当作当前待解决的唯一依据。

* 任务卡片编辑

卡片通过该接口取得备注和检查清单；标题使用原始任务标题，编辑标签集合从 ~TaskEditContent.own_tags~ 读取，包含不展示的内部用途标签，以保留未操作的用途；继承标签通过 ~FilterTask.inherited_tags~ 读取。所有修改仍提交 ~OrgWorkspace.execute_task_operations~ ： ~NOTES~ 修改备注而不重建清单或日志； ~CHECKLIST~ 接收 ~TaskChecklistChange~ ，完成新增、编辑、勾选、删除或同级排序； ~SCHEDULE_DATE~ 和 ~DEADLINE_DATE~ 接收自然日字符串或空值，仅修改对应日期。数据结构与保真边界见 [[file:数据模型.org::*卡片编辑正文与检查清单][卡片编辑正文与检查清单]]。

~TITLE~ 更新后，Core 识别标题中已有或新输入的分数与百分比统计并重算；先校验标题没有被重新解释为状态、优先级或标签，再改写派生统计。~CHECKLIST~ 的新增、删除和完成状态切换更新 checkbox 统计；~TODO~ 设置、清除与切换更新父标题的子任务统计，按 ~COOKIE_DATA~ 的 ~recursive~ 配置向上更新。来源混合、递归继承边界与完成状态规则见 [[file:数据模型.org::*标题统计更新][标题统计更新]]，语义依据 [[info:org#Breaking Down Tasks][Org Info：任务分解]] 与 [[info:org#Checkboxes][Org Info：checkbox]] 。

统计修改与原操作在同一事务中提交，复用版本校验、回退历史与 ~watch_data_changes~ ；每个实际变更的仓库在提交后只广播一次数据失效事件，失败或最终字节未变化不广播。计数完成不会自动修改父任务状态。标题投影仍只读取文件中的统计值，宿主收到事件后重新查询，不自行计算进度或以操作返回值触发刷新。

调用方必须提交原文件版本。旧条目 ID、已变更文件和无效条目文字被拒绝，不自动换新版本重试；成功只返回提交完成，宿主通过数据变化监听后重新读取最新投影。

清单排序使用 ~Move { id, before_id }~ ，目标为空时移到本同级列表末尾。Core 投影直接父列表身份 ~sibling_group~ 并验证来源和目标同组，移动父项携带嵌套内容；宿主只维护拖动预览，松手后提交一次，成功后重新读取条目 ID 和文件版本。

* 文件历史结果与删除备份

历史结果在同步决策时写入 ~OrgRepoSyncFileRecord.outcome~ ，含 ~Created~ 、 ~Deleted~ 、 ~Unchanged~ 、 ~Updated~ 、 ~Merged~ 、 ~Conflict~ 、 ~Uploaded~ 、 ~Failed~ 、 ~Skipped~ ；旧字段缺失使用 ~Legacy~ 兼容推导。 ~history_detail~ 直接消费该结果，冲突结果固定为 ~Conflict~ ，不再存在 ~Resolved~ 投影。 ~Updated~ 表示远端改变、本地无变化， ~Merged~ 表示两端变化且自动合并完成， ~Uploaded~ 表示仅本地变化。

~WebDavSyncFileDetail.deleted_archive~ 保存删除前备份的 hash； ~history_file(sync_id, path, false)~ 可只读打开相应正文。备份材料和删除操作在同一仓库事务内提交，缺失或 hash 不符返回错误；不能据备份恢复远端存在状态。完整布局和保留规则见 [[file:同步核心设计.org::*远端删除备份][远端删除备份]]。 ~history_detail~ 的文件列表包含无变化项及其可用备份，供列表原地展开，不要求宿主另建详情页面。

* 冲突预览接口

完整规则见 [[file:冲突预览与合并设计.org][冲突预览与合并设计]]，字段见 [[file:数据模型.org::*冲突预览模型][数据模型]]。preview 不提供真实写回接口；finish 返回普通操作组，应用通过 execute_task_operations 提交。

file_at 从当前地址读取文件根快照，真实文件受仓库锁保护，临时地址只解析活动 UUID，不接受任意磁盘路径。节点读取包含普通无状态和已完成标题，排除冲突区；insertion_positions 由 Core 列举文件／标题首项及各直属节点之后的位置。

创建校验 source_version 和真实文件存在性，再将主树与冲突材料按语法分离，工作副本只写主树字节；不能以 OrgRepo.file 的未落盘空对象代替磁盘源文件。file、source_file 与临时 file_at 的正文、标题路径和 HTML 都没有冲突节点。source_version 始终是完整源文件的创建版本，用于真实提交；source_file 的内容版本是剥离后的主树哈希，两者不能互换。冲突描述改由 ConflictPreview.conflicts 独立返回，source_range 属于独立候选材料，建议目标仍指向主树。临时操作必须带主树版本及显式冲突选择路径，不允许真实路径混入。每个成功临时组追加原操作，失败组不记录。

~project~ 在同一 preview 锁内校验工作版本、冲突 ID 与目标，并通过正式取舍规则计算内存投影，返回候选正文、HTML、两端变化片段及版本化范围。它不写工作副本，不消费冲突材料，不追加操作；未选择任何取舍时仍不能 finish。目标无法唯一确定时返回 ~targetRequired~ 和本地候选，不猜测插入位置；材料不可用时返回 ~unavailable~ 。结构／顺序冲突可只读比较完整主树，正式采用仍需要显式 ~ReplaceMain~ 与页面确认。旧对象、过期版本或非法目标沿用预览错误机制。

finish 要求用户看到的 preview_version 与当前副本一致、主树不含冲突节点、取舍记录与已选择 ID 一致，未选择材料在独立集合中保持。它返回保持顺序且路径映射为 sourcePath 的 operations、创建时的真实 file_versions 和空 queue_repo_ids，同时结束副本。应用按当前配置填入 queue_repo_ids 后调用现有统一入口；真实版本校验、提交失败回滚、outbox、回退记录及事件仍遵循统一操作组契约。finish 不执行这些真实副作用。

~render_html~ 的标题节点携带 data-org-start、data-org-end 与唯一文档内锚点，范围来自同一 Core 语法树。共享控件按文件版本关联变化，缺少精确正文块锚点时定位至最近标题并提供精确源行差异。

| 错误 code | 条件 | 宿主行为 |
|-
| previewUnavailable | 私有目录不可用或与仓库重叠 | 保留源文件，提示重试 |
| previewExpired | 旧 UUID、旧对象或配置代次变化 | 不回落至真实文件，重新创建 |
| previewVersionMismatch | 临时操作或 finish 所见版本不是当前版本 | 重读活动副本 |
| sourceVersionMismatch | 创建时源文件已变化或不存在 | 重读真实文件，明确重新创建 |

| conflictDecisionRequired | 选定点尚未处理或没有成功记录 | 禁止结束预览 |
| mixedPreviewOperation | 临时组混入其他文件或上传意图 | 整组拒绝 |

结束后真实提交沿用统一操作接口已有的版本与存储错误。应用保留返回组；原版本仍有效可重试，版本变化禁止覆盖。错误类别由 bridge 透传，不靠中文消息进行业务判断。

* 任务完成状态访问

~FilterTask.done_keywords() -> &[String]~ 返回所属文件有效的完成状态列表，顺序与 ~OrgFile.todo.done_keywords~ 一致，名称不含快捷键和日志后缀。文件没有声明时继承全局默认配置，显式清空配置时返回空列表。调用方完成任务时使用第一项，通过 ~TaskModification::Todo~ 提交并携带当前文件版本；Core 继续负责状态校验、完成日志与重复任务调度。该快照与 ~file_version()~ 来自同一次读取。

* 批量任务查询

系统仅提供 ~query(queries: &[CoreQuery]) -> Result<Vec<CoreQueryResult>, CoreError>~ 异步查询接口，单查询也传单项数组。成功时结果数组长度与输入相同， ~results[i]~ 对应 ~queries[i]~ ；空命中和重复查询不改变位置。任一错误使整批失败，不返回部分结果。空批次不加业务锁、不读取仓库。

每仓库在本批锁内加载一次，只有所有查询种类都不需要的文件传入底层 ~ignore_files~ ；其余加载后在各项查询求值前排除。多仓库锁按规范化目录排序取得，完成全部加载后释放，后续计算消费本次独立快照。完整签名、错误路径与 Harmony 编组见 [[file:批量查询接口设计.org][批量查询接口设计]]。

* 结构化重复规则修改

~OrgFile.task_edit_content(path)~ 及查询结果 ~FilterTask.edit_content()~ 新增 ~scheduled_repeat~ 、 ~deadline_repeat~ ，各自返回可空的 ~TaskRepeatInfo { date, has_time, rule }~ 。规则结构、JSON 枚举与保真边界见 [[file:数据模型.org::*规划重复规则编辑][规划重复规则编辑]]。

通过原 ~execute_task_operations~ 提交 ~SCHEDULE_REPEAT~ 或 ~DEADLINE_REPEAT~ ， ~value~ 为 ~{ mode, interval, unit }~ 或 ~null~ 。无日期时须在同组先提交对应 ~SCHEDULE_DATE~ ／ ~DEADLINE_DATE~ ；不自动选择今天或改动另一规划项。错误与版本变化使整组不写入；停止规则保留原日期。重复任务完成时的日期推进继续由原 ~TODO~ 操作执行。

* 文件与任务的项目名称

~OrgFileMetadata.project() -> Option<&str>~ 返回文件项目名称， ~FilterTask.project() -> Option<&str>~ 直接委托同次共享元信息的方法，不读盘、不重新解析。文件头 ~FILETAGS~ 中存在大小写精确匹配的 ~project~ 标签时，该文件是项目文件；标题自身标签、候选 ~TAGS~ 或源码块中的字面声明不影响判断。

项目名称依次读取文件头 ~#+PROJECT_NAME:~ 、文件默认属性 ~PROJECT_NAME~ （包含顶部属性 drawer 与 ~#+PROPERTY:~ 声明），仍缺失时使用文件 ~TITLE~ 。标题自身的属性不改变所属文件项目名。项目文件的名称和标题均缺失或名称为空时返回 ~Some("")~ ，保留项目身份；非项目返回 ~None~ 。宿主将空项目名展示为“未命名项目”。例如：

#+begin_src org
,#+TITLE: 文件显示标题
,#+FILETAGS: :project:work:
,#+PROJECT_NAME: HarmonyOS 适配
,* TODO 确认桥接层接口
#+end_src

元信息的只读投影字段 ~project_name: Option<String>~ 承载该值，JSON 对应 ~projectName~ ，所有同文件任务共享该元信息。项目名称变更后重新查询取得新快照，已返回对象保持旧值。字段不写入同步记录或 outbox，不改变原 Org 文件字节。 ~TaskQuery~ 与 ~TaskQueryResult~ 定义保持不变。
