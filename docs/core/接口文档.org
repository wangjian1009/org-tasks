* 范围与状态

本文定义围绕 ~OrgWorkspace~ 与 ~OrgRepo~ 的目标 core 接口。数据结构与源码保真规则见 [[file:数据模型.org][数据模型]]，WebDAV 协议语义见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]，Harmony 的配置与凭据边界见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。

~core::model~ 包含核心数据、保真编辑、仓库加载、同步策略和同步记录存储端口； ~core::webdav~ 包含 WebDAV 的版本比较、下载、创建与条件更新编排。目录访问、HTTP 传输、认证、线程、重试、取消和进度通知仍由宿主适配层承担。

* 核心场景

** 初始化 Workspace

宿主读取配置后构造稳定的仓库标识与根目录。WebDAV 地址和凭据由 ~SyncPolicy~ 的 WebDAV 实现持有，不进入 ~OrgRepo~ 。

#+begin_src rust
let workspace = OrgWorkspace::new(vec![
    OrgRepo::new(repo_id, "/data/org".into())?,
])?;
#+end_src

~OrgWorkspace::new~ 校验仓库 ID 的唯一性； ~OrgRepo::new~ 校验根目录。初始化不能扫描目录、请求 WebDAV、创建后台线程或写入同步记录。

** 解析、编辑并写回 org 文件

调用方通过 ~OrgRepo.load~ 扫描目录，并让 parser 将每个源文件解析为 ~OrgFile~ 。随后用当前快照中的元素定位替换或插入内容。未编辑文件直接以读取时的原始字节写回；编辑只影响目标范围或锚点，编辑后的位置由编辑器更新。

#+begin_src rust
let repo = workspace.repos.iter_mut().find(|repo| repo.id == repo_id)?;
repo.load(&directory_loader, &parser)?;
let file = repo.files.iter_mut().find(|file| file.path == "inbox.org")?;

apply_edit(
    file,
    OrgFileEdit::ReplaceElement {
        target: OrgElementLocator::for_element(&entry_id, &title_element),
        kind: OrgElementKind::Title(updated_title),
        content: b"* TODO 更新后的标题\n".to_vec(),
    },
)?;

file_writer.write(&file.path, serialize_file(file))?;
#+end_src

调用方在下一次编辑前必须使用编辑器更新后的元素定位；旧的 ~SourceRange~ 不能跨文件快照复用。 ~Raw~ 与其他未建模内容不参与替换时必须保持原始字节。

** 同步一个仓库

宿主将同步策略传入仓库。WebDAV 策略在其自身配置中决定远端流程； ~OrgRepo.sync~ 只接受属于该仓库且已完成的记录，并追加至仓库的 ~syncRecords~ 。上传使用 ~serialize_file~ 的完整结果，不得在同步阶段格式化未修改区域。

#+begin_src rust
let record = repo.sync(&webdav_sync_policy, started_at).await?;
sync_record_store.append(record).await?;
#+end_src

* 接口定义

** 核心数据

*** OrgWorkspace

~OrgWorkspace~ 聚合应用中的零到多个仓库。它是运行时构造输入，不是持久化实体。

#+begin_src rust
impl OrgWorkspace {
    pub fn new(repos: Vec<OrgRepo>) -> Result<Self, OrgWorkspaceValidationError>;

    pub fn repos(&self) -> &[OrgRepo];

    pub fn repo(&self, repo_id: &OrgRepoId) -> Option<&OrgRepo>;
}
#+end_src

~new~ 必须拒绝重复的 ~OrgRepoId~ 。返回的集合不可由调用方原地修改；变更仓库集合应构造新的 workspace。

*** OrgRepo

~OrgRepo~ 定义一个本地 org 文件仓库。根目录仅在运行时使用，不能写入同步记录；文件快照与同步记录归属该仓库。

#+begin_src rust
impl OrgRepo {
    pub fn new(id: OrgRepoId, root_directory: String) -> Result<Self, OrgRepoValidationError>;

    pub fn contains_path(&self, path: &str) -> bool;

    pub fn files(&self) -> &[OrgFile];

    pub fn sync_records(&self) -> &[OrgRepoSyncRecord];

    pub fn load<L, P>(&mut self, loader: &L, parser: &P) -> Result<&[OrgFile], CoreError>
    where L: OrgRepoLoader, P: OrgRepoParser;

    pub async fn sync<P>(&mut self, policy: &P, started_at: TimestampMs)
        -> Result<OrgRepoSyncRecord, CoreError>
    where P: SyncPolicy;
}
#+end_src

~contains_path~ 必须拒绝绝对路径和包含 ~..~ 的路径。 ~load~ 通过 loader 扫描根目录，替换仓库的完整文件快照；重复或越界路径必须失败。 ~sync~ 不直接执行网络 I/O，而是委托给策略并只追加归属本仓库的完成记录。

*** OrgFile

~OrgFile~ 保存一次解析/编辑会话内的完整源字节与顶层条目。 ~sourceBytes~ 不得持久化，但它是保真序列化的唯一来源。

#+begin_src rust
impl OrgFile {
    pub fn new(
        repo_id: OrgRepoId,
        path: String,
        source_bytes: Vec<u8>,
        entries: Vec<OrgEntry>,
    ) -> Result<Self, OrgFileValidationError>;

    pub fn source_bytes(&self) -> &[u8];

    pub fn entries(&self) -> &[OrgEntry];
}
#+end_src

~new~ 必须验证所有 entry 与元素范围都位于 ~sourceBytes~ 内，且不改变输入字节。未应用 ~OrgFileEdit~ 时， ~serialize_file~ 必须逐字节返回 ~source_bytes~ 。

*** OrgEntry

~OrgEntry~ 表示一个 headline，以及其有序元素和递归子 headline。

#+begin_src rust
impl OrgEntry {
    pub fn id(&self) -> &OrgEntryId;

    pub fn elements(&self) -> &[OrgElement];

    pub fn children(&self) -> &[OrgEntry];

    pub fn find_element(&self, range: &SourceRange) -> Option<&OrgElement>;
}
#+end_src

~find_element~ 只在当前文件快照内按完整来源范围查找元素；同一 entry 的元素与 children 均须保持原始源码顺序。

*** OrgElement

~OrgElement~ 是标题、planning、property、timestamp、drawer、正文、块、keyword 或 ~Raw~ 片段的有序内容单元。每个元素必须带有来源范围。

#+begin_src rust
impl OrgElement {
    pub fn kind(&self) -> &OrgElementKind;

    pub fn source_range(&self) -> &SourceRange;

    pub fn contains(&self, position: &SourcePosition) -> bool;
}
#+end_src

~source_range~ 必须精确指向 ~OrgFile.sourceBytes~ 内该元素的完整来源。 ~Raw~ 是保留未知合法 org 语法的正常元素，不能因缺少结构化字段而在写回时删除。

*** SourcePosition 与 SourceRange

~SourcePosition~ 同时保存行号、列号和 UTF-8 字节偏移； ~SourceRange~ 是对同一文件快照的半开区间 ~[start, end)~ 。

#+begin_src rust
impl SourcePosition {
    pub fn new(line: u32, column: u32, byte_offset: u64) -> Result<Self, SourcePositionError>;
}

impl SourceRange {
    pub fn new(start: SourcePosition, end: SourcePosition) -> Result<Self, SourceRangeError>;

    pub fn contains(&self, position: &SourcePosition) -> bool;
}
#+end_src

行号从 1 开始，列号与字节偏移从 0 开始。替换以 ~byteOffset~ 执行；跨行编辑后必须从更新后的字节缓冲区重新计算受影响及后续元素的位置。

** 同步数据

*** OrgRepoSyncRecord

~OrgRepoSyncRecord~ 描述一次仓库同步的整体结果及各文件记录。

#+begin_src rust
impl OrgRepoSyncRecord {
    pub fn new(
        id: OrgRepoSyncRecordId,
        started_at: TimestampMs,
    ) -> Result<Self, OrgRepoSyncRecordError>;

    pub fn append_file(
        &mut self,
        file: OrgRepoSyncFileRecord,
    ) -> Result<(), OrgRepoSyncRecordError>;

    pub fn finish(
        &mut self,
        result: OrgRepoSyncResult,
        finished_at: TimestampMs,
    ) -> Result<(), OrgRepoSyncRecordError>;
}
#+end_src

~new~ 创建进行中的记录，其 ~result~ 与 ~finishedAt~ 均为 ~None~ 。同步记录不包含 ~repoId~ ，归属由外层 ~OrgRepo~ 和持久化目录表达。 ~finish~ 只能调用一次，并将结果固定为 ~Succeeded~ 、 ~Failed~ 、 ~Cancelled~ 或 ~Interrupted~ 。

*** OrgRepoSyncFileRecord

~OrgRepoSyncFileRecord~ 保存一次同步中一个相对路径的决策与最终版本元数据。

#+begin_src rust
impl OrgRepoSyncFileRecord {
    pub fn new(
        relative_path: String,
        action: OrgRepoSyncFileAction,
        state: OrgRepoSyncFileState,
    ) -> Result<Self, OrgRepoSyncFileRecordError>;

    pub fn with_versions(
        self,
        local: Option<LocalFileVersion>,
        remote: Option<RemoteFileVersion>,
    ) -> Self;

    pub fn with_error(self, error: OrgRepoSyncErrorSummary) -> Self;
}
#+end_src

记录只保存相对路径、版本、action、state 和脱敏错误摘要；不得保存完整 org 内容、绝对路径、远端完整 URL 或凭据。

*** LocalFileVersion 与 RemoteFileVersion

本地版本只保存内容哈希；远端版本只保存 ETag、修改时间和大小。

#+begin_src rust
impl LocalFileVersion {
    pub fn new(content_hash: String) -> Result<Self, CoreError>;
}

impl RemoteFileVersion {
    pub fn new(
        etag: Option<String>,
        modified_at: Option<TimestampMs>,
        size: Option<i64>,
    ) -> Result<Self, RemoteFileVersionError>;
}
#+end_src

** 运行时端口

*** OrgRepoLoader 与 OrgRepoParser

~OrgRepoLoader~ 是扫描仓库根目录的 I/O 端口；它只返回相对路径及原始字节。 ~OrgRepoParser~ 只解析一个源文件，不扫描目录、不访问文件系统、不写回文件或同步记录。

#+begin_src rust
pub struct OrgRepoSourceFile {
    pub path: String,
    pub source_bytes: Vec<u8>,
}

pub trait OrgRepoLoader: Send + Sync {
    fn scan(&self, root_directory: &str) -> Result<Vec<OrgRepoSourceFile>, CoreError>;
}

pub trait OrgRepoParser: Send + Sync {
    fn parse_file(
        &self,
        repo_id: &OrgRepoId,
        source: OrgRepoSourceFile,
    ) -> Result<OrgFile, CoreError>;
}
#+end_src

~OrgRepo.load~ 校验 loader 返回的路径与 parser 返回的 ~OrgFile.path~ 一致后，原子替换仓库的文件列表。解析器遇到尚未结构化的合法 org 语法必须产生 ~OrgElementKind::Raw~ ，不能静默丢弃内容。

*** OrgFileEdit 与保真序列化

编辑接口以已解析的单个 ~OrgFile~ 为边界。它只可修改一个元素来源范围，或在 entry 内的合法元素边界插入内容。

#+begin_src rust
pub struct OrgElementLocator {
    pub entry_id: OrgEntryId,
    pub source_range: SourceRange,
}

impl OrgElementLocator {
    pub fn for_element(entry_id: &OrgEntryId, element: &OrgElement) -> Self;
}

pub enum OrgFileEdit {
    ReplaceElement {
        target: OrgElementLocator,
        kind: OrgElementKind,
        content: Vec<u8>,
    },
    InsertElement {
        entry_id: OrgEntryId,
        anchor: SourcePosition,
        kind: OrgElementKind,
        content: Vec<u8>,
    },
}

pub fn apply_edit(
    file: &mut OrgFile,
    edit: OrgFileEdit,
) -> Result<(), OrgFileEditError>;

pub fn serialize_file(file: &OrgFile) -> &[u8];
#+end_src

~apply_edit~ 必须拒绝过期范围、越界锚点和不属于指定 entry 的目标。它不得格式化、重新缩进、对齐表格、规范化换行、重排元素或重建未修改节点。插入或替换后，受影响元素及后续元素的 ~SourceRange~ 必须更新；未修改范围的字节必须保持不变。

*** SyncPolicy 与 OrgRepoSyncRecordStore

~SyncPolicy~ 是同步 I/O 端口， ~core::webdav::WebDavSyncPolicy~ 实现该 trait； ~OrgRepoSyncRecordStore~ 可将仓库已经接受的记录持久化。面向本地 ~OrgRepo~ 的文件系统实现必须将记录追加到根目录内的 ~.sync/records/~ ，并从 ~.sync/id~ 读取仓库 ID；完整布局见 [[file:目录结构设计.org][目录结构设计]]。策略接收可变仓库，因此下载成功时可替换对应 ~OrgFile~ 快照。

#+begin_src rust
pub trait SyncPolicy: Send + Sync {
    fn synchronize(
        &self,
        repo: &mut OrgRepo,
        started_at: TimestampMs,
    ) -> impl Future<Output = Result<OrgRepoSyncRecord, CoreError>> + Send;
}

pub trait OrgRepoSyncRecordStore: Send {
    fn append(
        &mut self,
        repo_id: &OrgRepoId,
        record: OrgRepoSyncRecord,
    ) -> impl Future<Output = Result<(), CoreError>> + Send;

    fn list(
        &self,
        repo_id: &OrgRepoId,
        limit: usize,
    ) -> impl Future<Output = Result<Vec<OrgRepoSyncRecord>, CoreError>> + Send;
}
#+end_src

策略不得将密码、Authorization header、仓库绝对路径、远端完整 URL 或完整 org 文件内容写入同步记录或错误摘要。上传前必须使用 ~serialize_file~ 的完整字节，不能对未修改区域重新格式化。

*** WebDavSyncPolicy 与 WebDavTransport

~WebDavSyncPolicy~ 位于 ~core::webdav~ 。它用最近一次成功同步的本地哈希和远端版本作为基准，处理新建、下载、条件更新、冲突、远端删除和传输失败。 ~WebDavTransport~ 是唯一需要映射到 HTTP 的端口。

#+begin_src rust
let endpoint = WebDavEndpoint::new("https://dav.example.com/org/".into())?;
let policy = WebDavSyncPolicy::new(endpoint, transport, parser);
let record = repo.sync(&policy, started_at).await?;

pub trait WebDavTransport: Send + Sync {
    fn list(&self, endpoint: &WebDavEndpoint)
        -> impl Future<Output = Result<Vec<WebDavRemoteFile>, WebDavError>> + Send;
    fn get(&self, endpoint: &WebDavEndpoint, path: &str)
        -> impl Future<Output = Result<Vec<u8>, WebDavError>> + Send;
    fn put(&self, endpoint: &WebDavEndpoint, path: &str, source_bytes: &[u8],
        condition: WebDavPutCondition)
        -> impl Future<Output = Result<RemoteFileVersion, WebDavError>> + Send;
}
#+end_src

~list~ 映射 ~PROPFIND~ ， ~get~ 映射 ~GET~ ， ~put~ 的 ~CreateOnly~ 映射 ~If-None-Match: *~ ， ~Match~ 映射 ~If-Match~ 。传输实现不得把认证材料放入领域记录。

* 旧接口

旧的全局作业接口已移除。宿主不读取、不转换也不写入旧作业状态；使用旧版本数据时，应清理数据后按当前接口重新配置和同步。
