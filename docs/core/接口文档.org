* 范围与状态

本文定义围绕 ~OrgWorkspace~ 与 ~OrgRepo~ 的 core 接口。数据结构与源码保真规则见 [[file:数据模型.org][数据模型]]，WebDAV 协议语义见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]，Harmony 的配置与凭据边界见 [[file:../harmony/配置项设计.org][Harmony 配置项设计]]。

~core::model~ 是本地仓库管理能力，直接扫描目录、解析 org 文件、维护文件快照和同步记录数据； ~core::webdav~ 是 ~SyncPolicy~ 的 WebDAV 实现，执行版本比较、下载、文件写回、创建与条件更新，并生成同步记录。仓库加载、WebDAV I/O 与同步控制器任务均运行于 Tokio；HTTP 和 Harmony 只负责选择和操作本地仓库；其他同步方式通过实现 ~SyncPolicy~ 接入。

* 核心场景

** 初始化 Workspace

宿主读取配置后只构造仓库根目录。 ~OrgRepo.load~ 初始化时从 ~.sync/id~ 读取稳定仓库标识；文件缺失时由 core 生成 UUID 并持久化。WebDAV 地址和凭据由 ~SyncPolicy~ 的 WebDAV 实现持有，不进入 ~OrgRepo~ 。

#+begin_src rust
let mut repo = OrgRepo::new("/data/org".into())?;
repo.load::<WebDavSyncPolicy>().await?;
let workspace = OrgWorkspace::new(vec![repo])?;
#+end_src

~OrgWorkspace::new~ 校验已加载仓库的 ID 唯一性； ~OrgRepo::new~ 只校验根目录。 ~load~ 才会扫描目录并读取或创建 ~.sync/id~ ；它不会请求 WebDAV、创建后台线程或写入同步记录。

** 解析、编辑并写回 org 文件

调用方通过 ~OrgRepo.load~ 扫描并解析目录中的 org 文件。随后用当前快照中的元素定位替换或插入内容。未编辑文件直接以读取时的原始字节写回；编辑只影响目标范围或锚点，编辑后的位置由编辑器更新。

#+begin_src rust
let repo = workspace.repos.iter_mut().find(|repo| repo.id == repo_id)?;
repo.load::<WebDavSyncPolicy>().await?;
let file = repo.files.iter_mut().find(|file| file.path == "inbox.org")?;

apply_edit(
    file,
    OrgFileEdit::ReplaceRange {
        target: headline_range,
        content: b"* TODO 更新后的标题\n".to_vec(),
    },
)?;

file_writer.write(&file.path, serialize_file(file))?;
#+end_src

调用方在下一次编辑前必须使用重新解析后的来源范围；旧的 ~SourceRange~ 不能跨文件快照复用。未被替换的字节必须保持原始值。

** 同步一个仓库

宿主将同步策略传入仓库。 ~OrgRepo.sync~ 内部调用 ~load::<P>~ 恢复仓库身份、当前文件、outbox 和归属本仓库的完成历史，再构造 ~SyncContext~ 调用策略；调用方不传入历史，也不需要先加载旧快照。上传使用 ~serialize_file~ 的完整结果，不得在同步阶段格式化未修改区域。

#+begin_src rust
let record = repo.sync(
    &webdav_sync_policy, started_at,
    &SyncCancellation::default(), &SyncProgressReporter::default(),
).await?;
#+end_src

* 接口定义

** 核心数据

*** OrgWorkspace

~OrgWorkspace~ 聚合应用中的零到多个仓库。它是运行时构造输入，不是持久化实体。

#+begin_src rust
impl OrgWorkspace {
    pub fn new(repos: Vec<OrgRepo>) -> Result<Self, OrgWorkspaceValidationError>;

    pub fn repos(&self) -> &[OrgRepo];

    pub fn repo(&self, repo_id: &OrgRepoId) -> Option<&OrgRepo>;

    pub fn repo_mut(&mut self, repo_id: &OrgRepoId) -> Option<&mut OrgRepo>;

    pub fn add_repo(&mut self, repo: OrgRepo) -> Result<(), OrgWorkspaceValidationError>;

    pub fn remove_repo_by_root_directory(&mut self, root_directory: &str) -> Result<OrgRepo, OrgWorkspaceValidationError>;

    pub fn search(&self, filter: &Filter) -> Vec<FilterTask>;

    pub fn query(&self, query: &TaskQuery) -> Result<TaskQueryResult, CoreError>;
}
#+end_src

~new~ 与 ~add_repo~ 必须拒绝重复的仓库根目录，以及已加载仓库的重复 ~OrgRepoId~ 。新加入的仓库可以尚未加载；宿主必须逐个调用 ~OrgRepo.load::<P>~ 读取或创建稳定 ID、扫描文件并恢复同步记录。返回的集合不可由调用方原地修改。 ~remove_repo_by_root_directory~ 仅移除运行时集合中的仓库，不删除根目录、 ~.sync~ 历史或任何文件。对已加载仓库执行同步或编辑前，可用 ~repo_mut~ 按稳定 ID 取得该仓库。 ~search~ 汇总全部已加载仓库的 headline 任务投影，应用 ~Filter~ 并按其排序规则返回结果。结果中的 ~repoId~ 与相对路径共同标识来源文件；宿主不得自行遍历仓库并实现另一套过滤逻辑。

*** OrgRepo

~OrgRepo~ 定义一个本地 org 文件仓库。根目录仅在运行时使用；同步历史落盘于根目录的 ~.sync/history/~ ，由 ~load::<P>~ 返回，不作为仓库字段保留。

#+begin_src rust
impl OrgRepo {
    pub fn new(root_directory: String) -> Result<Self, OrgRepoValidationError>;

    pub fn contains_path(&self, path: &str) -> bool;

    pub fn files(&self) -> &[OrgFile];

    pub fn file_metadata(&self) -> Vec<OrgFileMetadata>;

    pub fn file(&self, path: &str) -> Result<OrgFile, CoreError>;

    pub async fn create_task(&mut self, path: &str, task: &NewTask,
        queue_upload: bool) -> Result<(), CoreError>;

    pub async fn pending_writes(&self) -> Result<Vec<OrgRepoWriteIntent>, CoreError>;

    pub async fn acknowledge_write(&self, path: &str,
        version: &LocalFileVersion) -> Result<(), CoreError>;

    pub async fn load<P: SyncPolicy>(&mut self)
        -> Result<Vec<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>>, CoreError>;

    pub async fn sync<P>(&mut self, policy: &P,
        started_at: TimestampMs,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter)
        -> Result<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>, CoreError>
    where P: SyncPolicy;

    pub async fn sync_with_options<P>(&mut self, policy: &P,
        started_at: TimestampMs,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter,
        options: SyncOptions)
        -> Result<OrgRepoSyncRecord<P::ContextDetail, P::FileDetail>, CoreError>
    where P: SyncPolicy;
}
#+end_src

~contains_path~ 必须拒绝绝对路径和包含 ~..~ 的路径。 ~load~ 先读取或创建 ~.sync/id~ ，再扫描根目录、跳过 ~.sync/~ 并解析 org 文件，最后替换仓库的完整文件快照；重复或越界路径必须失败。首次加载生成的 UUID 必须写入带换行的 ~.sync/id~ ，后续加载同一根目录必须复用该值。 ~sync~ 自行恢复最新文件与历史后委托策略执行同步，并只追加归属本仓库的完成记录；重复开始时间在调用策略前拒绝。

~file(path)~ 从当前已加载集合返回独立的 ~OrgFile~ 副本。路径尚不存在时构造未落盘的空文件，沿用该仓库的全局默认 TODO 配置；非法路径或仓库尚未加载时报错。该方法不读取磁盘、不修改仓库文件列表，也不写入 outbox。宿主需要最新内容时先加载仓库。

*** TaskScanRules

~OrgRepo.task_scan_rules~ 保存最近一次 ~load~ 从根目录 ~.orgzlyignore~ 加载的运行时规则；不改变 ~files()~ 和 ~file(path)~ 的完整文件访问，也不传入同步策略。 ~search~ 和 ~query~ 在 Core 生成任务记录时统一排除命中文件。

#+begin_src rust
impl TaskScanRules {
    pub fn parse(source: &str) -> Result<Self, CoreError>;
    pub fn excludes(&self, path: &str) -> bool;
}
#+end_src

~Default~ 表示没有忽略规则。 ~path~ 使用仓库内安全相对路径；非法相对路径不匹配。修改文件后需重新调用 ~load~ ，规则格式和作用范围见 [[file:目录结构设计.org][目录结构设计]]。

*** OrgFile

~OrgFile~ 保存一次解析/编辑会话内的完整源字节，并在运行时缓存 ~orgize::Org~ 无损语法树。缓存不属于 core 持久化模型； ~sourceBytes~ 是保真序列化的唯一来源。

#+begin_src rust
impl OrgFile {
    pub fn new(
        repo_id: OrgRepoId,
        path: String,
        source_bytes: Vec<u8>,
    ) -> Result<Self, OrgFileValidationError>;

    pub fn source_bytes(&self) -> &[u8];

    pub fn category(&self) -> Option<String>;

    pub fn title(&self) -> Option<String>;

    pub fn render_html(&self) -> String;
}
#+end_src

~new~ 必须验证 UTF-8 编码并构造 ~orgize~ 缓存，且不改变输入字节。未应用 ~OrgFileEdit~ 时， ~serialize_file~ 必须逐字节返回 ~source_bytes~ 。解析语义以 Emacs ~org-element.el~ 为准。

~category()~ 从当前文件的无损语法树读取文件头（第一个标题之前）中的第一条 ~#+CATEGORY:~ 声明。关键字不区分大小写，值去除首尾空白并保留内部空格与中文。未声明时返回 ~None~ ，显式空声明返回 ~Some(String::new())~ ，不以文件名或父目录补齐；源码块、示例块、注释及标题内部的声明不属于文件头配置。本接口只读取当前文件的声明，不展开 ~SETUPFILE~ 或标题属性。编辑和重新加载后读取当前语法树，不另存分类缓存或修改原文。

*** NewTask 与 OrgRepoWriteIntent

~NewTask~ 是任务创建的运行时输入，字段为 ~heading~ 、 ~scheduled~ 、 ~deadline~ 、 ~tags~ 与 ~priority~ 。日期为空或有效的 ~YYYY-MM-DD~ ，优先级为空或 ~A/B/C~ ，标题不能为空或包含控制字符，标签只允许字母、数字、中文及 ~_@#%~ 。标题中的隐式 Org 属性必须拒绝，避免与表单属性产生歧义。

~OrgRepo.create_task~ 要求仓库已加载，目标是控制目录外的安全相对 ~.org~ 路径，且路径中不得存在符号链接。它读取当前磁盘内容，在文件末尾通过 ~apply_edit~ 追加使用目标文件有效初始状态的一级标题和可选 planning 行，保留原有字节，并为新增内容采用原文件换行风格。追加后必须验证新标题可从 core 任务投影读取；未结束的源码块等不允许安全追加标题的文件会返回输入错误。

写入先在目标文件同级生成并刷新临时文件，提交前检查目标内容仍与读取时一致，再原子重命名并更新仓库快照。宿主必须串行调用同一仓库的编辑和同步；Harmony 通过 workspace 锁执行。该检查不能替代跨进程文件锁。

~queue_upload~ 为真时，提交目标文件前先持久化 ~OrgRepoWriteIntent { relative_path, content_hash }~ 到 ~.sync/outbox/~ 。为假时只保存本地任务。写入意图不保存标题、日期、标签、完整文件或绝对路径。重复保存生成独立意图；后续成功同步完整的当前文件后，可一起确认该路径的历史意图。

~pending_writes~ 恢复并校验意图；损坏的 JSON 或不安全路径使加载失败。 ~acknowledge_write~ 只有在仓库快照和磁盘文件都匹配已同步 ~LocalFileVersion~ 时才清除该路径的意图。 ~OrgRepo.sync~ 先持久化完整同步记录，再确认其中 ~Synchronized~ 文件；失败或冲突的文件意图保留。

*** SourcePosition 与 SourceRange

~SourcePosition~ 同时保存行号、列号和 UTF-8 字节偏移； ~SourceRange~ 是对同一文件快照的半开区间 ~[start, end)~ 。它们与 ~OrgFileEdit~ 、 ~apply_edit~ 和 ~serialize_file~ 一同定义在 ~core::model::editor~ ，不属于 workspace 或查询响应。

#+begin_src rust
impl SourcePosition {
    pub fn new(line: u32, column: u32, byte_offset: u64) -> Result<Self, SourcePositionError>;
}

impl SourceRange {
    pub fn new(start: SourcePosition, end: SourcePosition) -> Result<Self, SourceRangeError>;

    pub fn contains(&self, position: &SourcePosition) -> bool;
}
#+end_src

行号从 1 开始，列号与字节偏移从 0 开始。替换以 ~byteOffset~ 执行；跨行编辑后必须从更新后的字节缓冲区重新计算受影响及后续元素的位置。

** 同步数据

*** OrgRepoSyncRecord

~OrgRepoSyncRecord~ 描述一次仓库同步的整体结果及各文件记录。

#+begin_src rust
impl OrgRepoSyncRecord {
    pub fn new(
        id: OrgRepoSyncRecordId,
        started_at: TimestampMs,
    ) -> Result<Self, OrgRepoSyncRecordError>;

    pub fn append_file(
        &mut self,
        file: OrgRepoSyncFileRecord,
    ) -> Result<(), OrgRepoSyncRecordError>;

    pub fn finish(
        &mut self,
        result: OrgRepoSyncResult,
        finished_at: TimestampMs,
    ) -> Result<(), OrgRepoSyncRecordError>;
}
#+end_src

~new~ 创建进行中的记录，其 ~result~ 与 ~finishedAt~ 均为 ~None~ 。同步记录不包含 ~repoId~ ，归属由外层 ~OrgRepo~ 和持久化目录表达。 ~finish~ 只能调用一次，并将结果固定为 ~Succeeded~ 、 ~Failed~ 、 ~Cancelled~ 或 ~Interrupted~ 。

*** OrgRepoSyncFileRecord

~OrgRepoSyncFileRecord~ 保存一次同步中一个相对路径的决策与最终版本元数据。

#+begin_src rust
impl OrgRepoSyncFileRecord {

        action: OrgRepoSyncFileAction,
        state: OrgRepoSyncFileState,

*** LocalFileVersion 与策略文件细节

本地版本只保存内容哈希；远端版本由具体策略的 ~SyncFileDetail~ 实现保存。WebDAV 使用 ~WebDavSyncFileDetail { etag, modified_at, size }~ ，该值序列化到文件记录的 ~detail~ 。

#+begin_src rust

    pub fn from_bytes(source: &[u8]) -> Self;
}

** 运行时端口

*** 本地仓库加载与解析

~OrgRepo.load~ 是 core 的异步本地初始化操作。它先确保 ~.sync/~ 存在，读取合法的 ~.sync/id~ 并按指定 ~SyncPolicy~ 解析历史 detail ；若文件不存在，则生成 UUID 并以独占创建、写入与刷新持久化。之后递归扫描根目录中的普通 ~.org~ 文件，跳过符号链接和 ~.sync/~ ，并以原始字节构造 ~OrgFile~ 。扫描到重复、越界或非法的相对路径时必须失败，不能部分替换文件快照。

~orgize~ 解析结果必须保持无损；WebDAV 下载获得的字节也必须复用相同的 core 解析规则，而不是在 WebDAV 模块中定义另一套内容模型。

*** OrgFileEdit 与保真序列化

编辑接口以已解析的单个 ~OrgFile~ 为边界。它只可替换明确来源范围，或在明确来源位置插入内容；完成后重新构造 ~orgize~ 缓存。

#+begin_src rust
pub enum OrgFileEdit {
    ReplaceRange {
        target: SourceRange,
        content: Vec<u8>,
    },
    InsertAt {
        anchor: SourcePosition,
        content: Vec<u8>,
    },
}

pub fn apply_edit(
    file: &mut OrgFile,
    edit: OrgFileEdit,
) -> Result<(), OrgFileEditError>;

pub fn serialize_file(file: &OrgFile) -> &[u8];
#+end_src

~apply_edit~ 必须拒绝过期范围和越界锚点。它不得格式化、重新缩进、对齐表格、规范化换行或重建未修改节点；只允许对目标范围执行字节替换或在目标位置插入字节。未修改范围的字节必须保持不变。

*** SyncPolicy 与本地同步历史

~SyncPolicy~ 是同步策略接口，使用 ~KIND~ 标识历史所属策略，并包含 ~ContextDetail~ 与 ~FileDetail~ 两个关联类型； ~core::webdav::WebDavSyncPolicy~ 实现该接口。 ~OrgRepo.load::<P>~ 从 ~.sync/history/~ 恢复并返回完成记录，拒绝 ~kind~ 与 ~P::KIND~ 不一致的记录； ~OrgRepo.sync~ 在接受策略返回的完成记录后，将其原子写入 ~.sync/history/<started-at>.json~ 。历史归 ~OrgRepo~ 管理； ~sync~ 每次自行从本仓库恢复最新历史，控制器不缓存历史，宿主不向两者传递历史。 ~SyncPolicy.synchronize~ 只接收 ~SyncContext~ 、取消信号和进度对象；策略需要历史时通过上下文仓库的内部历史接口读取。策略接收可变仓库，因此下载成功时可替换对应 ~OrgFile~ 快照。

#+begin_src rust
pub trait SyncPolicy: Send + Sync {
    const KIND: &'static str;

    type ContextDetail: SyncContextDetail;
    type FileDetail: SyncFileDetail;

    fn synchronize(
        &self,
        context: &mut SyncContext<'_>,
        cancellation: &SyncCancellation,
        progress: &SyncProgressReporter,
    ) -> impl Future<Output = Result<OrgRepoSyncRecord<Self::ContextDetail, Self::FileDetail>, CoreError>> + Send;
}

#+end_src

策略不得将密码、Authorization header、仓库绝对路径、远端完整 URL 或完整 org 文件内容写入同步记录或错误摘要。上传前必须使用 ~serialize_file~ 的完整字节，不能对未修改区域重新格式化。

*** SyncContext 与策略细节

~SyncContext~ 表达一次同步，持有可变 ~OrgRepo~ 、 ~started_at~ 、仓库根路径 ~base~ 和本次调用的 ~SyncOptions~ 。历史仍由仓库内部管理，不作为策略接口参数。 ~SyncOptions~ 当前包含 ~excluded_directories~ ，默认由 Rust 提供为 ~["archive"]~ ，后续可扩展其他策略参数。 ~SyncContextDetail~ 与 ~SyncFileDetail~ 约束策略专属且可序列化的历史细节；前者保存到记录的 ~context_detail~ ，后者保存到每个文件的 ~detail~ 。

#+begin_src rust
pub struct SyncContext<'a> {
    pub repo: &'a mut OrgRepo,
    pub started_at: TimestampMs,
    pub base: PathBuf,
    pub options: SyncOptions,
}

#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default, deny_unknown_fields)]
pub struct SyncOptions {
    pub excluded_directories: Vec<String>,
}

impl Default for SyncOptions {
    fn default() -> Self {
        Self { excluded_directories: vec!["archive".into()] }
    }
}

pub fn default_sync_options() -> SyncOptions;

pub trait SyncPolicy: Send + Sync {
    const KIND: &'static str;

    type ContextDetail: SyncContextDetail;
    type FileDetail: SyncFileDetail;
}
#+end_src

~sync~ 使用 Rust 默认值； ~sync_with_options~ 使用本次传入的值。缺失的 JSON 字段采用默认值，显式空列表表示不排除任何目录。目录名按大小写敏感的完整路径组件匹配，只匹配文件路径中的目录部分；例如 ~archive/a.org~ 与 ~work/archive/a.org~ 被默认排除，而 ~archives/a.org~ 与 ~work/archive.org~ 不被排除。输入去除首尾空白、忽略空项并去重，不接受绝对路径、多级路径或控制字符。

过滤不删除已下载的本地文件，不改写历史或确认被过滤文件的 outbox；普通同步不为被过滤路径产生下载、上传、删除或冲突记录。规则只影响传输范围，本地浏览仍读取已有文件，已有冲突仍可从历史中查询。

*** OrgRepoSyncController

~OrgRepoSyncController~ 在 core 内持有一个 ~OrgRepo~ 与启动时传入的 ~SyncPolicy~ 。它通过 Tokio task 执行一次同步，并以快照让 UI 宿主读取当前状态；HTTP、Harmony 等宿主不得自行维护同步状态或伪造完成记录。调用 ~start~ 的宿主必须运行在 Tokio runtime 中。

#+begin_src rust
let controller = OrgRepoSyncController::new(repo, policy);
controller.start(started_at).await?;
let snapshot = controller.snapshot();
controller.cancel()?;
#+end_src

~start~ 在已有同步运行时返回错误。 ~cancel~ 仅设置 ~SyncCancellation~ ，策略在列举和文件边界检查该信号后以 ~Cancelled~ 完成当前记录。 ~snapshot~ 返回 ~Idle~ 、 ~Running~ 、 ~Cancelling~ 、 ~Succeeded~ 、 ~Failed~ 或 ~Cancelled~ ，以及阶段、已完成数量、总数、当前文件和最近完成记录。进度和取消句柄是运行时数据，不属于持久化记录。

进度快照可附带本轮按发生顺序排列的脱敏 HTTP 事件，内容仅包含请求方法、相对路径或根路径，以及“请求中”或响应状态码。它供宿主展示同步过程，不属于同步记录，也不得包含完整 URL、认证材料或传输正文。

*** WebDavSyncPolicy

~WebDavSyncPolicy~ 位于 ~core::webdav~ 。它用各路径最近一条 ~Synchronized~ 文件记录的本地哈希和远端版本作为基准，处理新建、下载、条件更新、冲突、远端删除和传输失败，并直接持有 HTTPS Basic 认证配置与 HTTP client；HTTP 宿主不实现 WebDAV 端口。

~WebDavSyncMonitor~ 是 WebDAV 同步的观察接口。通过 ~WebDavSyncPolicy.with_monitor~ 注入后，调用方可按顺序获得同步开始、列举、文件处理、HTTP 请求和响应、结束事件。事件只携带仓库 ID、相对路径、文件记录和 HTTP 状态，不含凭据、完整 URL、绝对路径或文件正文。

#+begin_src rust
let endpoint = WebDavEndpoint::new("https://dav.example.com/org/".into())?;
let policy = WebDavSyncPolicy::new(endpoint, username, password)?;
let record = repo.sync(
    &policy, started_at,
    &SyncCancellation::default(), &SyncProgressReporter::default(),
).await?;

pub trait WebDavSyncMonitor: Send + Sync {
    fn on_event(&self, event: WebDavSyncEvent);
}
#+end_src

~WebDavSyncPolicy.test_connection~ 提供不依赖本地仓库的独立连接检查：

#+begin_src rust
impl WebDavSyncPolicy {
    pub async fn test_connection(&self) -> Result<(), WebDavError>;
}
#+end_src

该方法只请求配置目录的 ~PROPFIND~ ，使用 ~Depth: 0~ 查询 ~resourcetype~ ，要求 ~207 Multi-Status~ 和目标自身成功返回的 DAV collection 属性。空目录可以通过，普通网页、文件地址、认证拒绝、无效或不完整 XML 均不能报告成功。请求与响应正文读取共享 15 秒总超时。方法不接收 ~OrgRepo~ ，不读写本地文件、历史、outbox 或日历，不上传下载文件；成功只证明认证与目录访问，不证明写权限。

策略内部的列举映射 ~PROPFIND~ ，下载映射 ~GET~ ，上传的 ~CreateOnly~ 映射 ~If-None-Match: *~ ， ~Match~ 映射 ~If-Match~ 。策略不得把认证材料放入领域记录。

* 旧接口

旧的全局作业接口已移除。宿主不读取、不转换也不写入旧作业状态；使用旧版本数据时，应清理数据后按当前接口重新配置和同步。


* 按同步比较与应用合并

比较对象可直接序列化、交给用户选择并回传，core 不持有准备会话或临时 ID 注册表。范围是一条仓库同步记录中尚未解决的全部冲突文件，不能加入其他同步的文件或遗漏待处理文件。

#+begin_src rust
impl WebDavSyncPolicy {
    pub async fn compare_merge(
        &self, repo: &mut OrgRepo, sync_id: &str,
    ) -> Result<WebDavMergeComparison, CoreError>;

    pub async fn apply_merge(
        &self, repo: &mut OrgRepo, comparison: &WebDavMergeComparison,
        started_at: TimestampMs,
    ) -> Result<WebDavMergeOutcome, CoreError>;
}

pub struct WebDavMergeOutcome {
    pub record: OrgRepoSyncRecord<WebDavSyncContextDetail, WebDavSyncFileDetail>,
    pub backups: Vec<WebDavMergeBackup>,
}
#+end_src

~compare_merge~ 自行加载仓库与历史，读取远端版本，返回统一的 ~changes~ 列表。每个差异带临时 ~id~ 、文件路径、新增/修改/删除候选、本地与远端版本，以及初始为空的 ~resolution~ 。未变化任务自动保留，不要求提交选择。差异来源是 Org 标题及自身 section，文件前言单独比较；无稳定 ID 的改名不能猜测为同一任务。

调用方将 ~mode~ 设为 ~MergeTasks~ ，为每个变化选择 ~Local~ 、 ~Remote~ 或 ~Remove~ ，再将整个比较对象传给 ~apply_merge~ 。选择不存在的一端即确认不保留该项； ~AcceptRemote~ 模式整份采用各文件的远端内容，包括确认远端已经删除的文件。来源、ID、类型、文件列表和版本字段都是只读数据，不可重写。

~apply_merge~ 重新加载整个仓库，并比较身份、全部 Org 文件的路径与内容、同步历史和 outbox 的组合版本；任何变化都在网络写入和备份之前拒绝。远端配置指纹和每个冲突文件的 ETag、正文指纹也必须一致。新出现或已经解决的冲突、缺少选择、重复 ID、修改来源内容、无效层级和过期对象均不能提交；调用方应重新比较。

所有文件通过预检后，先将本次同步的全部本地冲突文件备份到 ~.sync/backups/<started_at>/~ ，再逐文件执行条件上传与本地原子替换。已有远端文件必须使用 ~If-Match~ ，重新创建文件必须使用 ~If-None-Match: *~ 。保存失败、远端再次变化或 ~412~ 会成为该文件的失败记录，其他已完成文件保留成功结果，整体同步标为失败；不能跨多个远端文件承诺事务回滚。 ~OrgRepo.sync~ 统一追加一条合并作业记录，再确认成功文件的 outbox，已确认的本地删除也会在确认文件仍缺失后清理旧意图。

冲突备份返回相对于仓库的路径，不包含凭据。元数据中不写入完整比较对象、任务正文或备份内容。一次 apply 结束后，旧对象因同步历史发生变化而失效；进程重启本身不会使未过期对象失效。同一仓库的调用仍需串行执行，跨进程外部编辑不能替代文件系统事务。


* 同步历史回退与首次同步

同步状态按文件从新到旧回溯，使用最近一条 ~Synchronized~ 文件记录作为本地哈希和远端版本基准。整体结果为失败、取消或中断的作业中，已成功文件的基准仍然有效；该文件更晚的冲突、失败或未出现记录不能遮住最近成功版本。读取到损坏历史时必须报错，不得跳过后猜测基准，也不新增独立状态文件。

完全没有历史时，本地独有文件使用条件创建直接上传，远端独有文件直接下载；两端都存在但没有历史基线的文件生成 ~Conflict~ 记录，避免覆盖无法确认来源的内容。空目录因此可以正常接收远端文件；两端内容相同但没有基线时仍需合并确认。空目录的同步可以成功生成空记录；仅列举失败或取消产生的空记录不能视为已经建立了基准。

首次冲突记录生成后，后续普通同步仍保留这些无成功基准的待处理路径；不能因“历史现在非空”而绕过合并。后续已建立历史的新路径继续按既有新建/下载规则处理。合并接受本地缺失的远端文件时，比较对象以 ~localMissing~ 区分“文件不存在”和“空文件”；apply 保持版本校验并安全创建文件。只有存在本地原文件的路径才产生备份，不为远端独有文件伪造空备份。

* TODO 默认配置与文件元信息接口

默认值由 Rust ~Default~ 实现提供，外部负责保存自己的全局配置。配置可用结构化 ~TodoConfig~ 传入，或由原生 Org 声明文本经 ~from_settings~ 解析。空白设置文本表示空配置，不套用缺省值；配置只在运行时持有，不写入同步元数据。

#+begin_src rust
let defaults = TodoConfig::default();
let editable_settings = defaults.to_settings();
let configured = TodoConfig::from_settings(&editable_settings)?;
workspace.set_todo_defaults(configured.clone())?;
repo.set_todo_defaults(configured)?;
let file = OrgFile::with_todo_defaults(repo_id, path, bytes, defaults)?;
let metadata = &file.todo;
#+end_src

~OrgFile::new~ 使用 Rust 缺省配置， ~with_todo_defaults~ 使用外部默认配置。 ~OrgRepo.parse_file~ 在扫描、下载、创建与合并时统一传递配置。 ~OrgWorkspace.set_todo_defaults~ 校验并更新全部仓库与已加载文件， ~add_repo~ 将配置传给后续加入的仓库。配置更新失败时不产生部分重解析的状态。

每个文件快照公开 ~todo~ ，包含来源、带来源区间的文内声明、流程、状态类型、显式快捷键和日志要求、待办/完成集合与初始状态。现有 ~FilterTask.state_type~ 来自有效配置后的语法树，宿主不得用 DONE/CNCL 字面值推测完成状态。

~create_task~ 从目标文件有效配置取得初始状态；文件尚不存在时使用外部默认。无可用未完成状态时拒绝写入。合并也使用相同配置验证输出，并把默认配置纳入运行时仓库版本，以拒绝配置变化后的旧比较对象。

* 通用结构化任务查询

~OrgWorkspace.query(&TaskQuery)~ 返回 Core 过滤后的任务列表和分类摘要。请求字段为 ~expression~ 、 ~categories~ 、 ~excluded_files~ 、 ~include_done~ 与 ~include_compose_tasks~ ，完整 Rust 定义及语义见 [[file:查询语言设计.org][查询语言设计]] 。界面需求由 UI 组装为通用请求，Core 不持有收件箱或控件专属字段。所有任务过滤统一由 Core 执行，宿主不得对返回的列表再实现分类、完成、文件或父子关系过滤。

* 文件标题与轻量元信息

#+begin_src rust
pub struct OrgFileMetadata {
    pub repo_id: OrgRepoId,
    pub path: String,
    pub title: Option<String>,
    pub task_count: usize,
    pub byte_length: usize,
    pub modified_at: Option<TimestampMs>,
}
#+end_src

~OrgRepo.file_metadata()~ 从当前完整文件快照返回轻量清单；提供仓库 ID、相对路径、标题、标题记录数、原始字节数和本地磁盘修改时间，不克隆源字节、不构建任务对象。需要磁盘新状态时先调用 ~load~ 。 ~OrgFile.title()~ 复用已解析的无损语法树，仅在文件头中查找首条大小写不敏感的 ~#+TITLE:~ ，命中立即返回去除首尾空白的值。缺少为 ~None~ ，显式空值为 ~Some(String::new())~ ，标题内声明、注释与源码块不作为文件标题。不限定前几行，不以文件名补齐领域值。

当前轻量接口减少响应构建和跨层复制，首次加载仍需完整解析。后续若优化首次列表扫描，可评估由 Core 缓存文件版本与已解析元信息，或提供专门头部扫描；需要保持注释、块结构、第一条声明和文件头边界语义，并避免固定行数遗漏合法 TITLE。任何缓存都不得改变同步读取完整原始字节的要求。

~task_count~ 统计当前文件语法树中的所有标题，包括已完成和无 TODO 的标题；命中 ~.orgzlyignore~ 时为零，语义与 Core 的任务扫描一致。 ~byte_length~ 来自源字节长度， ~modified_at~ 使用扫描目录时已有的文件属性，转换为 Unix 毫秒时间，无可用值时为 ~None~ 。读取轻量清单不重新 stat 文件；需要最新信息时先加载仓库。文件对象的克隆与默认 TODO 设置更新保留已读取的磁盘时间，内存中直接创建的文件时间为 ~None~ 。这些信息不写入同步历史，也不用于替代同步版本判断。

* 整篇只读渲染

OrgFile.render_html() 直接遍历已有 orgize 语法树，返回不含宿主样式的 HTML 文档片段。它是运行时展示投影，不是新的解析模型，不修改 source_bytes，也不写入同步记录。标题层级及其子树、TODO 完成类型、优先级、标签、计划时间、属性抽屉、正文行内样式、链接文字、列表、表格及 TBLFM、代码块均按语法节点生成；没有标题的文件仍呈现文件前言。未专门排版的 HTML 导出块、snippet、LaTeX 等以转义后的字面文本呈现，不执行其内容。

标题使用嵌套 details，默认展开；drawer 默认收起，折叠只改变阅读状态。表格和代码块由宿主提供横向滚动容器，表格公式只展示、不求值。链接与图片引用以文字呈现，不加载远端资源或本地附件，也不提供状态修改或复选框写回行为。完整原文始终可从 source_bytes 获取。
