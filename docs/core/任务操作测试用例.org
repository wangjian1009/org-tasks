* 范围与约定

每个用例是独立黑盒场景，按测试目的分组。对应目录为 ~core/tests/task_operations_cases/<组>/<用例>/~ ，输入、操作、预期输出分别保存在 ~input/~ 、 ~operations/~ 、 ~output/~ 子目录； ~case.json~ 记录目的、错误与附加断言。本文列出全部用例的实际定义，具体程序使用方式由程序帮助发现。

操作中的仓库名称是用例占位身份，执行前绑定到该输入仓库的稳定 Core ID。成功时检查操作历史与回退快照、最终文件清单及每个字节；失败时比较初始化后的全部文件和控制目录，要求文件、outbox 与临时文件均无变化。文件清单中包含空文件，不以删除空文件代替删除节点。预期输出中的 {{TIMESTAMP}} 匹配本次操作生成的有效本地非活动时间戳，校验其落在执行时间窗口内，其他字节仍逐一比较。 ~{{DATE+28d}}~ 表示操作当日本地日期加 28 天及对应星期；跨午夜时允许实际经过的两个本地日期，旧日志中的固定日期保持逐字节比较。

说明中的换行展示为 LF；涉及 CRLF 的文件会另行标注，磁盘样例才是逐字节比较依据。行尾空格以 ␠ 展示；源码块内逗号是 Org 引用转义，均不属于输入文件。

* Rust 层补充验证

- 成功操作组连续追加准确 before、after；末尾操作失败不改变 workspace、历史或已有 outbox。
- 可选文件版本拒绝过期请求；正确版本执行成功，操作历史可完整序列化往返。
- 提交准备阶段遇到不可写 outbox 目标时，保留原文件、内存和历史。
- Core 创建时无条件生成 CREATED，重新加载后仍能投影创建时间和任务身份；拒绝显式修改时间或关闭自动创建时间。
- 完成状态来自文件有效配置，覆盖嵌套 SETUPFILE、文件内覆盖、配置重新读取、自定义完成与待办状态；按显式日志配置生成 CLOSED，恢复时清理已有 CLOSED，保留 CREATED、子条目和其他规划，失败整组回滚。
- 拒绝符号链接及不存在的父目录，不跟随链接或创建意外目录。
- 在四个不同提交阶段注入 I/O 故障，逐一验证两个文件和上传意图全部恢复；故障注入仅在 Core 模块内部测试使用。
