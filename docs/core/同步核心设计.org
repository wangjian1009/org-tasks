* 范围与状态

本文统一定义 Core 的内容合并、仓库事务、远端基线、冲突目录、历史、重置与通知。当前同步写入版本 4；旧版本兼容读取。协议请求与认证见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]，公开接口见 [[file:接口文档.org][接口文档]]。宿主只提供配置、调用接口并展示结果，不解析控制目录或实现另一套同步判断。

同一文件内采用三方操作重放：B 为最近确认的远端内容，L 为当前本地内容，R 为本轮确认的远端内容。独立修改合并，不能安全应用的修改保存为普通任务候选；整个合并结果直接上传，任务候选不阻止后续同步。事务边界是单个仓库。

* 同步目录与身份

** 路径约定

全文用 ~/path/to/A.org~ 表示从仓库根起算的文件占位路径，实际字段使用 ~path/to/A.org~ 这样的安全相对路径。拒绝越界、符号链接及不符合约定的类型；重置例外只移动或删除链接自身，不跟随链接目标。

~started_at~ 是十进制 Unix 毫秒值，用于历史文件和目录； ~sync_id~ 是记录 ID。宿主按记录 ID 调用 Core，不自行拼接控制路径。

** 完整布局

#+begin_example
<OrgRepo.rootDirectory>/
├── path/to/A.org
└── .sync/
    ├── id
    ├── .transaction.lock
    ├── remote_base/
    │   ├── current.json
    │   └── files/path/to/A.org/<revision>/
    │       └── A.org                    # 删除时为 A.removed
    ├── history/
    │   ├── <started-at>.json
    │   └── <started-at>/conflicts/path/to/A.org/
    │       └── A.org                    # 本轮实际上传的完整结果，不再追加解决结果
    ├── outbox/<uuid>.json
    ├── transactions/<uuid>/
    │   ├── journal.json
    │   └── committed
    └── reset/                          # 重置期间的临时恢复材料
        ├── journal.json
        ├── items/<index>
        └── committed
#+end_example

~.sync/~ 的整棵目录不参与普通 Org 扫描、查询或传输。Core 初始化或读取 ~id~ ，移动根目录、重新打开 workspace 和重置均保留身份。不能仅替换身份后复用旧历史。地址与用户名改变时，已有基线拒绝跨远端复用；密码不参与持久化。

** 冲突文件命名与路径隔离

每个原文件独立使用完整相对路径作为冲突目录；不增加固定的 projects 层级。同步结束时，存在任务候选的文件在该目录保存本轮处理后实际上传的完整结果，包括文件头标志和候选子树；不是仅保存合并前远端原文。没有冲突的普通文件不创建该目录。

历史快照保持原始文件名 ~A.org~ 。同步完成后历史 JSON 和原始快照固定，不再写入 ~A.resolved.org~ ，也不在读取时根据当前文件推导“已解决”状态。旧版本已存在的结果文件保留兼容只读，但不改变该次历史的文件结果。

* 文件内内容合并

纯函数 ~merge(base_data, local_data, remote_data)~ 接收三份完整 UTF-8 Org 原文，比较 B 与 L 的本地差异并应用到 R；不访问目录、网络、历史或凭据。稳定 Org ID 优先，无 ID 时回退文件内标题路径及出现次序，匹配不跨文件。文件前言始终接受远端，不生成前言候选。

标题路径与完整结构定位共用进度排除规则：逐段忽略 ~orgize~ 识别的标题直属 ~COOKIE~ 节点，涵盖空分数、分数与百分比；不移除代码、链接或强调内部的字面统计。父标题的进度变化不改变子标题的匹配键，不能把同一任务误判为删除和新增。规范化后同名的标题仍按出现次序区分，原始标题和进度作为内容保留并参与原有字段合并；同一字段的并发竞争仍保存冲突候选，不另建普通任务副本。

差异比较以最小标题节点为单位。每个节点只比较自身标题、直属规划行、属性与正文 section，不把子标题的字节并入父节点；发现一个任务存在差异后，子任务仍按各自身份单独比较。任务优先按稳定 ~Org ID~ 匹配，无 ID 时按规范化标题路径和出现次序匹配，匹配不跨文件。

任务自身再按字段拆分比较： ~TODO~ 状态、优先级、标题文字、标签新增、标签删除、 ~SCHEDULED~ 、 ~DEADLINE~ 、 ~CLOSED~ 和正文文本分别判断。标签按集合差异记录为新增与删除，保留未涉及标签的原始顺序与字节；规划字段只改动各自规划节点；标题中的进度 ~COOKIE~ 与标题文字分开处理。正文存在文字变化时才启用文本差异算法，按不重叠的行片段应用独立修改，重叠片段才升级为该任务的修改冲突。这样一端更新任务状态、标签或进度，另一端修改正文、规划或日志时可以合并，不把整个任务或其子树升级为冲突。

任务的 ~LOGBOOK~ 按日志行拆分；新增行和删除行分别形成独立差异，展示与应用顺序按日志行中的时间戳升序，缺少时间戳的行排在有时间戳的行之后并保持原顺序。相同日志行只抵消一次，避免重复日志被错误去重。

修改冲突始终记录修改后的完整任务记录，完整记录用于无法定位时的候选插入；同时保留由基线与本地版本计算出的字段差异，至少包括 ~TODO~ 、标签新增／删除、规划字段、日志行和正文文本片段。差异记录不替代完整原文，也不改变用户未涉及的字节。

** 冲突容器与设计原则

使用文件末尾唯一的一级标题“同步冲突”作为容器，自身同时带有大写 ~CONFLICT~ 与标准 ~ARCHIVE~ 标签，整个子树都是冲突区。旧文件只有 CONFLICT 标签时仍可识别；新生成容器统一使用 ~:CONFLICT:ARCHIVE:~ 。原先设计中的 ~CONFILICT~ 标签拼写统一为 ~CONFLICT~ 。容器的每个直接子标题是一个冲突点，增加定位属性 ~CONFILICT_ID~ 、节点内关键字 ~#+CONFLICT_REASON:~ 与展示祖先关键字 ~#+CONFLICT_ANCESTORS:~ ； ~CONFILICT_ID~ 按已确认的拼写保留，和旧的 ~CONFLICT_ID~ 不同。容器不另设属性，冲突点的完整原文作为其可见后代或 example 块保存，不再生成 ~CONFLICT_SOURCE~ 、 ~CONFLICT_ORIGIN~ 、 ~CONFLICT_PARENT~ 、 ~CONFLICT_PATH~ 或 ~CONFLICT_OPERATION~ 。用户原有属性与代码块字面文本保留，不按前缀清理。

#+begin_example
* 普通任务
远端内容

* 同步冲突 :CONFLICT:ARCHIVE:
** 普通任务
:PROPERTIES:
:CONFILICT_ID: <稳定定位值>
:END:
#+CONFLICT_REASON: modify
*** 普通任务
完整本地候选内容
#+end_example

合并先分离 B、L、R 的普通主树与既有冲突材料，旧冲突只单独协调，不参与主树比较，也不作为本轮合并失败的依据。本轮主树没有新冲突时，直接使用成功合并的主树并重新附加保留的旧冲突点；清单移动、普通修改和新增节点不能仅因文件中有旧冲突而变成新候选。

冲突点按 ~CONFILICT_ID~ 唯一定位，创建后 ID 与内容不变，只允许新增和删除，不比较或合并候选正文。设 B、L、R 分别为基线、本地、远端的冲突 ID 集合，结果为 (B ∩ L ∩ R) ∪ (L ∖ B) ∪ (R ∖ B)：基线中已有的 ID 仅在双方都保留时留下，任一端解决并删除就传播删除；基线外任一端新增的 ID 都保留，同一 ID 只保留一次。输出沿用远端保留节点的顺序，再按本地顺序追加本地独有的新增节点，候选原文直接复制。

双方解决同一旧冲突时，该 ID 不会恢复；解决操作应用到普通主树的结果仍按主树三方规则合并。双方选择相同结果时不产生新冲突，选择不同且不能自动合并时产生新的冲突点，旧 ID 仍保持删除。双方各自新增不同 ID 的冲突点时，两者同时出现在同一尾部容器中。最后一个冲突点被删除且主树没有新冲突时，移除整个容器。

本轮主树确实产生新冲突时，主树保留远端内容以及已经安全应用的本地字段差异；只有无法安全应用的最小任务差异进入冲突点，避免远端另一个任务发生冲突时把本地恢复任务一并误报。若 R 原本不含冲突区，移除输出的完整冲突块必须与本轮输入 R 逐字节一致；如果 R 已有容器，该回退边界对应分离后的 R 主树，旧冲突点仍单独协调。不得将上传后的文件冒充合并前 R。

容器总是追加在文件末尾，其生成的分隔换行属于完整冲突块。移除最后一个冲突点时一并移除容器及该分隔符，保留远端主树的空白、CRLF/LF 与原本无末尾换行的状态。系统不再增加 ~#+CONFLICT: true~ 或额外的文件头标签，避免在冲突区外留下生成内容。

** 冲突原因与内容

~CONFLICT_REASON~ 沿用实际合并分支的操作取值；同文件回退时，尚未应用的独立本地差异也使用其原操作类型。

| 取值 | 场景与内容 |
|-
| ~modify~ | 现有任务的本地字段修改无法安全应用，保存完整本地记录及字段差异；包括字段、父节点或层级竞争 |
| ~create~ | 新增节点内容竞争或回退后尚未应用的新增，保存完整本地新增子树 |
| ~delete~ | 删除意图未应用，复制当前远端子树作为可见材料，保留删除意图而不删除远端主树 |
| ~modify-missing~ | 远端目标消失，保存完整本地修改子树 |
| ~missing-parent~ | 父节点消失，保存不能安全放置的完整本地子树 |
| ~reorder~ | 实际代码中提取的本地 key 序列不同于基线，且远端序列既不同于基线也不同于本地；example 块保存完整本地文件 |
| ~structure~ | 重复身份、循环或无法安全渲染的结构，example 块保存完整本地文件 |

定位 ID 按生成期的仓库／文件上下文、操作来源、原因和完整来源内容确定，使同一文件重试稳定、不同文件可区分。此 ID 不参与普通任务身份匹配，也不要求为候选原文中的普通 Org ID 生成替代值。重复重放按定位 ID 协调已存在冲突点，不重复追加；任一端丢弃基线中已有的点时，后续同步会将该移除传播到另一端。

** 任务冲突的定位、记录与应用

冲突单位是任务自身，不包含其子任务。生成修改冲突时，Core 保存本地修改后的完整任务记录，记录自身标题、直属正文、属性、规划行、日志和子树原文；字段差异以任务为锚点保存，分别描述 ~TODO~ 、优先级、标题文字、标签新增／删除和正文文本片段。没有文字变化时不运行文本差异；只有文本变化才生成最小行片段。

解决修改冲突时，Core 先使用冲突点生成时的任务身份在当前远端主树中定位原记录。定位成功后，只把用户选择的本地字段差异应用到该任务，远端未涉及的字段、子任务和原始字节继续保留；应用前重新校验任务身份与文件版本，任何不安全的重定位都转为需要用户选择的候选。定位失败时不按标题猜测其他任务，只有用户明确选择插入位置后，才把保存的完整本地记录作为新任务插入，并维持原有层级与正文。

字段应用和完整记录插入都必须经过同一版本校验、冲突保护、事务提交、outbox 和历史记录流程。重复重试按冲突点 ID 与字段来源去重，不重复追加文本片段或任务记录；提交失败不消费完整候选和字段差异。

** 文件标记、查询与保护

~OrgFile.has_conflict()~ 及元信息 ~hasConflict~ 从真实标题节点的 ~CONFLICT~ 标签取得； ~OrgFile.conflict_ids()~ 对应文件对象的只读 ~conflictIds~ ，提供当前容器各冲突点的定位值。查询在表达式、完成／组合过滤与分类统计前，自动排除自身或祖先带 ~CONFLICT~ 的节点；显式查询该标签也不能取回冲突区。REFILE 目标、节点查询与文件任务数遵守同一边界，完整文件读取仍保留所有原文。

普通 Modification、Deletion、Movement、Creation 和原文区间编辑都不能修改冲突子树。保护覆盖从祖先删除／移动整棵树、向冲突区插入内容、从祖先替换其中链接等间接路径。失败不写工作文件、outbox 或操作回退历史；只有专门的操作组冲突选择可以受控地移除指定冲突点。

* remote_base 远端状态基线

** 目的与三种状态

~.sync/remote_base/current.json~ 是仓库当前生效的唯一索引，版本为 1。索引携带远端 URL 与用户名的绑定 hash，以及按原路径组织的条目；不保存凭据。条目包含 ~revision~ 、实际远端版本、正文 hash 或删除状态及来源同步 ID。

| 状态 | 表达 | 含义 |
|-
| 未建立 | 没有条目 | 没有已确认基线 |
| 远端存在 | hash 存在，版本引用完整 A.org | 包括真实零字节文件 |
| 远端已删除 | hash 为空，版本引用空 A.removed | 已确认不存在，不等于未建立 |

正文版本不可变，位于 ~files/path/to/A.org/<revision>/~ 。当前索引一次切换，不通过多个逐文件指针伪装仓库整体提交。读取校验版本号、来源绑定、路径、正文 hash 与空删除标记；损坏必须报错，不能猜测为空基线。

** 更新时机

整轮正常完成后，本地事务统一提交所有参与路径的最终远端状态，包括已经成功上传且仍含任务候选的内容。执行错误或取消不推进任何路径；被过滤路径不处理、不消费其意图。新版本正文只有随当前索引事务正式提交才生效。

即使结果仍包含旧冲突，成功同步后的工作文件、已确认远端正文、远端基线及成功历史正文也必须逐字节一致。没有新增编辑和远端修改时再次同步，文件动作应为 Unchanged，不再上传或增加冲突点，旧冲突点的定位 ID 与材料保持不变；仍显示未解决冲突的状态不表示本轮出现了新差异。

离线解决产生尚未上传的本地结果，不修改 remote_base。下次同步仍以实际确认过的远端快照为 B，成功传输后再推进基线。不能将 resolved 文件存在或本地编辑成功当作远端已更新。

可靠旧历史中的完整成功正文可用于迁移；失败记录与未上传结果不能构造基线。远端 origin 不一致时明确拒绝，用户可通过本地重置重新建立状态。

* 同步流程与删除决策

先递归列举并校验远端，再准备全部远端正文；只有强 ETag 相同且长度兼容时复用本地已确认缓存。发生变化时下载对应版本。全部读取与解析完成后再开始远端修改，避免准备阶段失败产生不必要上传。

按 B 与 L 推导本地操作，应用到 R。首次无基线时按空内容参与文件内合并：单端文件创建或下载，两端相同只保留一份，不同内容按节点合并或形成任务候选。

** 文件删除与修改并存：远端优先（最新确认）

文件存在性在内容合并之前处理；内容合并的空输入不表达文件不存在。

| 情况 | 决策 |
|-
| 已确认远端整文件删除，本地修改 | 采用远端删除 |
| 远端整文件修改，本地删除 | 恢复远端内容 |
| 仅本地删除，远端等于基线 | 条件 DELETE |
| 两端均删除 | 保持删除并记录删除基线 |
| 两端均存在 | 文件内重放与合并 |

列举失败不能解释为远端删除。上述整文件规则不扩展为所有任务节点的远端优先；节点删除与另一端修改竞争仍可以形成任务候选。

创建使用 ~If-None-Match: *~ ，更新与删除使用确认的强 ETag。没有可靠写入条件时拒绝执行变更，不进行无条件覆盖。排除目录不参与下载、删除或基线推进；任务扫描忽略规则不缩小 Org 文件同步范围。

* 同步提交与失败边界

仓库按需读盘、 ~load()~ 仅恢复身份、根目录 ~reset~ 与 ~sync~ 标记、每轮同步独立存活锁及网络阶段释放仓库锁的重构方案，统一见 [[file:仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]]。该文档明确区分已确认目标与实施状态；下述事务耐久性、远端副作用与版本保护仍需保持。

** 仓库级事务范围（已确认）

单个仓库一整轮同步是本地提交单位。全部远端处理成功后，通过同一可恢复事务提交工作文件、基线索引与正文、冲突快照、成功历史及 outbox 确认。任务候选不算执行失败；一个仓库失败不撤回另一个仓库已经完成的事务。

策略准备好结果或远端上传成功均不表示本地提交完成。只有仓库事务正式提交并释放仓库锁后，才将进度设为 ~Finished~ ，并通过 ~SyncPolicy.on_record_persisted~ 发布 WebDAV 完成事件。收到成功事件时，本轮工作文件、当前索引引用的基线正文、已确认远端正文、冲突快照和历史正文必须逐字节一致；普通文件没有冲突快照，删除文件使用一致的不存在状态。事务校验或历史写入失败时返回错误，不发布成功事件。

** 基线提交、失败与恢复

准备阶段保存正式文件的旧字节、新字节、创建目录清单及读取保护。提交前再次校验本地版本；写入临时文件、刷新、同目录原子替换后，最后写入并刷新完成标记。公开同步上下文保持原有结构，计划通过 Core 私有提交槽交回仓库。

完成标记之前中断时还原旧文件与旧基线；之后只清理恢复材料，不能回滚已经生效的同步。恢复先于扫描、查询和编辑。外部编辑与恢复状态不符时保留现场并报错，不覆盖新内容。同仓库使用进程内锁与支持平台上的文件锁，避免并发事务或跨进程误恢复。

执行失败与取消保持工作文件、当前基线、既有解决材料及 outbox；允许保存不参与成功状态恢复的诊断记录。正式成功后的清理失败不推翻已经完成的事务。

** 远端副作用与失败重试

多个 WebDAV 文件没有跨文件原子事务。A 的请求已经成功而 B 失败时，本地仍不提交，远端 A 不保证回滚。重试重新读取实际远端与旧基线，再重放本地操作；已存在的候选通过稳定身份去重，不能假装上次远端请求未发生。

* 历史记录与恢复

~history/<started-at>.json~ 是不可变完成记录，包含执行结果、文件动作、状态、脱敏错误及实际确认的完整 ~synced_source~ 。版本 4 的 Conflict 文件同样可能已经上传，应按实际动作计入传输数量。普通文件通过历史正文阅读；含冲突的文件额外保存目录快照，正文 hash 与记录相符。

读取只接受正式普通 JSON，校验开始时间、记录 ID 唯一性、类型与版本；不能跳过损坏记录后猜测当前状态。当前基线由 remote_base 决定，历史不与索引争夺优先级。

** 历史直接保存文件结果

新记录在每个 ~OrgRepoSyncFileRecord.outcome~ 保存同步决策结果，值与传输 ~action~ 、执行 ~state~ 分开：

| 结果 | 含义 |
|-
| ~Created~ | 首次或已确认删除之后，单端新增文件并成功创建／下载 |
| ~Deleted~ | 本次采用整文件删除 |
| ~Unchanged~ | 文件与基线无变化，或已确认双方均不存在 |
| ~Updated~ | 远端内容改变、本地无变化，采用远端内容 |
| ~Merged~ | 两端内容改变，自动合并成功 |
| ~Conflict~ | 自动合并仍有任务候选，需要人工处理 |
| ~Uploaded~ | 仅本地修改，上传成功 |
| ~Failed~ / ~Skipped~ | 执行失败或跳过 |

字段在同步决策时计算并随历史事务持久化，宿主不按传输方向重新推导“更新／合并”。旧记录缺失字段时按 ~Legacy~ 读取，仅由 Core 使用原 ~action/state~ 兼容投影，不能补造旧历史没有保存的两端变化信息。解决后的原历史文件结果仍为冲突，当前解决状态在读取时派生，不改写历史 JSON。

** 远端删除备份

确认远端删除并准备移除本地文件时，将删除前的本地完整原文写入 ~history/<started-at>/deleted/<原相对路径>/<原文件名>~ 。本地已经不存在时使用最近确认的基线正文；保留真实空文件。历史 ~detail.deleted_archive~ 仅保存备份 hash， ~synced_source~ 和最终 ~local_version~ 仍为空，远端基线仍为删除，备份不能伪装成同步后存在的文件。

备份与工作文件删除、基线、成功历史和 outbox 确认共用仓库事务。失败或取消不发布删除备份；下次双方均不存在时记录无变化，不重复创建备份。 ~history_file~ 根据该字段读取删除前的只读原文，校验安全路径、普通文件及 hash；缺失、损坏明确报错。旧日志未保存删除备份时不以当前文件或其他历史冒充。备份位于 ~.sync/~ ，不扫描、不上传。

** 当前冲突与历史冲突

历史中的冲突结果仅说明当次同步产生了冲突，完成后固定。当前文件的容器可因后续操作移除，但不会把历史改成“已解决”，也不会改变历史冲突数或备份内容。日志文件只有远端删除备份提供手机阅读入口；其他文件状态不显示进入箭头。

* 冲突选择与普通操作组

~TaskOperation::ConfilictSelection~ 使用文件根 path、id、action 和可选 target。id 定位 CONFILICT_ID；Discard 仅删除该点，UseLocal 按明确目标采用完整候选或删除意图。候选可用性、目标与范围由 Core 校验，最后一点移除后自动清除容器及其生成分隔符。多点按 ID 顺序定位，不受前序移除导致的字节位置变化影响。

手机逐点预览先将源文件分为主树与冲突材料，只把主树写入工作副本，冲突材料由 Core 独立保存。副本上通过同一个 execute_task_operations 执行并记录成功操作，选择候选时不会把冲突包装插回基础文档。finish 只重写路径并返回操作组，不写真实文件。应用随后通过统一操作入口提交返回组；创建时源版本作为约束，真实文件、outbox、回退记录及更新事件仍遵循普通操作组规则。完整流程见 [[file:冲突预览与合并设计.org][冲突预览与合并设计]]。

处理不访问远端、不改 remote_base、不产生新的同步历史或解决结果文件。丢弃全部仍使用一次普通操作组，并携带已读版本；读取或版本失败不能覆盖新内容。

* 通知查询与同步提示

统一批次中的 NotificationQuery 复用同次文件加载生成通知，每个含冲突标记的文件产生一条 ~SyncConflictNotification { repo_id, path }~ 。不绑定同步 ID、不按最近成功历史聚合，不维护“已解决”状态。手机以辅助色单行弱提示展示，点击按仓库身份和原文件路径直接打开“解决冲突”页。

统一批次中的 NotificationQuery 仅读取 ~remote_base/current.json~ 的已确认 hash，与本批已加载文件的字节 hash 比较，不运行三方合并、不解析基线正文或访问网络。比较范围为仓库 Org 文件和索引已跟踪路径，覆盖新增、修改、删除、空文件及已确认删除基线；索引缺失时已有本地文件视为待同步，索引损坏返回错误而不是无变化。

NotificationQuery 通过 ~OrgWorkspace.query(&[CoreQuery])~ 汇总文件冲突通知，只要任一仓库与基线不同，额外返回唯一的 ~{ "type": "syncRequired" }~ 。该通知由当前数据派生，不依赖进程标志或 outbox；重启后仍可重新发现，文件恢复为基线内容或成功同步推进基线后自然消失。点击复用普通全仓库同步。查询不写文件、索引或通知记录；宿主将通知与页面任务、文件元信息合批，失败保留已有通知快照。

数据提交仍通过仓库更新事件通知宿主重新读取正文与通知；普通查询不广播伪造的数据更新。

* 仓库重置

~OrgRepo.reset~ 清空仓库根目录内全部内容、同步历史、基线、冲突快照、扫描规则与 outbox，保留 ~.sync/id~ 的原始字节和运行中的锁。重新加载可创建空控制目录，与新建仓库状态相同；根目录、宿主配置及凭据不变，不访问远端、不产生远端删除请求。

重置要求有效已有身份，拒绝过期句柄和不安全根目录。与同步、编辑共用仓库锁；先持久化重置日志，再将顶层内容移动至受控暂存区，完成标记之前中断则恢复，之后只清理。目录中的链接只移动、删除链接本身，不跟随外部目标。恢复时若原位置出现外部内容则保留材料并报错。

仓库配置页显示“重置本地目录”，二次确认明确清空范围及不可撤销性。目标固定为保存配置中的目录，目录草稿变化时要求先保存；执行期间禁止返回和其他操作。成功后刷新仓库与通知，保留配置和身份，下次同步重新建立基线。

* 逐点预览与统一操作提交

[[file:冲突预览与合并设计.org][冲突预览与合并设计]] 定义仓库外唯一临时副本、共享全文控件与逐点交互。副本在保留地址域中定位，finish 返回映射为真实源路径的原操作序列；它本身不提交仓库。应用通过 execute_task_operations 完成真实修改，基线、历史和通知继续按本文定义维护。

* 冲突卡片的展示祖先

新生成的冲突通过 CONFLICT_ANCESTORS 保存从近到远的合并祖先身份 JSON 数组，供 Core 在主树中寻找最近仍存在的父节点。该信息只决定卡片展示位置，不自动确认插入或替换目标。旧材料不回填该关键字；无法定位时显示在文档根部，其他材料与重放规则保持。
