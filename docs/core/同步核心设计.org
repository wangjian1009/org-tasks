#+TITLE: 同步核心设计
#+LANGUAGE: zh-CN
#+OPTIONS: author:nil date:nil toc:2

Core 以单个仓库为单位同步工作文件、远端快照和本地合并祖先。同步记录当前写入版本 4。协议与认证由 WebDAV 策略接入，宿主通过 Core 接口提供配置并展示结果。 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]、[[file:接口文档.org][Core 接口文档]]

* 流程调度

** 锁与会话

| 保护范围 | 实现 | 持有时机 |
|-
| 仓库的一轮同步 | 固定文件 ~.sync/.sync.lock~ 上的非阻塞独占 ~flock~ | 从建立会话到完成回调返回，覆盖列举、下载、上传和本地提交。同仓库的其他同步发现锁忙时返回。 |
| 仓库读写与恢复 | 以规范化仓库根路径为键的进程内互斥锁，以及 ~.sync/.transaction.lock~ 上的独占文件锁 | 启动与恢复、读取本地快照、发布远端基线、合并准备和最终提交时持有。网络 I/O 期间释放，其他 Core 进程可以正常读取和编辑。 |

根目录 ~sync~ 保存当前会话 ID，对应会话目录里的 ~state.json~ 记录仓库 ID、开始时间和阶段。阶段转换在仓库锁内校验会话身份。固定同步锁是否可取得决定会话能否恢复，固定锁文件在清理和重置期间保留。进程退出释放锁后，下一次访问在仓库锁内恢复中断事务并清理遗留会话。各仓库持有各自的锁、会话与提交计划。 [[file:仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]]

** 一轮同步的顺序

1. 取得仓库锁，校验仓库身份并恢复遗留事务，分配开始时间、取得固定同步锁，写入会话状态后释放仓库锁。
2. 列举远端，短暂持有仓库锁读取文件清单和缓存，再释放仓库锁准备远端正文。按 ETag 复用缓存或下载，并将正文和版本清单写入本轮暂存目录。
3. 完整远端快照确认后，在仓库锁内独立发布远端索引，保留旧共同祖先。随后在仓库锁内重读当前工作文件，先生成比较组及其内容处理计划，再为每组启动一个 ~tokio::task~ 。每组将合并正文写入本轮暂存目录，返回正文 hash、删除状态及传输依据。调度器收齐结果并重新读取、校验暂存正文后，记录工作文件、待上传意图和受保护索引的提交约束。
4. 释放仓库锁，按计划执行条件上传与删除，每次确认远端改动后重新取得仓库锁，发布对应的远端状态。PUT 响应缺少强 ETag 时回读实际正文和版本。若内容已变，发布实际远端事实并结束本轮，留待重试。
5. 重新取得仓库锁，校验工作文件和受保护索引等读写依赖，统一提交已确认的暂存结果、共同祖先和完成记录。释放仓库锁后清理会话并发布 ~Finished~ 。固定同步锁随本轮调用结束释放。

下载期间发生的本地编辑在第 3 步重读时纳入合并。计划生成后，上传期间的本地编辑由提交前的字节及版本校验发现，版本不符则结束本轮并保留这些编辑。远端并发编辑由条件请求校验。调度器等待全部比较任务结束，按计划顺序汇总。任何组准备失败或本轮取消都会结束本轮，远端修改请求从所有组准备成功后开始。

** 同步提交与失败边界

本地提交以单个仓库为事务单位，包含工作文件、本轮参与路径的共同祖先、冲突快照、删除备份、成功历史和 outbox 确认。当前 WebDAV 在 Core 私有提交槽暂交计划，仓库追加完成历史后统一提交。冲突候选随成功结果保存并可上传。完成后参与路径的工作文件、远端确认正文、当前基线与成功历史正文逐字节一致，冲突文件的归档也保存同一正文。删除路径以不存在状态提交，删除备份保存删除前的原文。

远端快照发布和条件请求分别确认远端事实。举例来说，A 的 PUT 成功后 B 的请求失败，A 的远端写入与已发布的远端基线仍有效，工作文件和共同祖先保留提交前状态。重试读取实际远端和旧共同祖先，并重新生成计划。对响应不确定的请求，下一轮重新确认远端版本。各仓库的本地事务独立完成。

~FileProcessed~ 表示策略已处理该文件，正式成功事件在提交完成且释放仓库锁后，由 ~SyncPolicy.on_record_persisted~ 发出。失败或取消可以写入诊断记录，保留工作文件、旧祖先和未确认的 outbox。版本校验或历史写入失败时，本轮无法发布成功事件。

*** 日志与崩溃恢复

双副本索引及其校验和修复方式见目录结构说明。主索引与副本纳入同一可恢复事务。

提交前再次校验读取依赖，并将变更路径的旧字节、新字节与待创建目录写入事务日志。写入正式文件时先刷新临时文件，再在同目录原子替换。全部变更落盘并校验后，写入并刷新完成标记。

完成标记之前中断时，恢复工作文件与旧共同祖先，独立发布的远端基线继续有效。标记落盘后的恢复只处理清理。清理先将事务目录原子重命名为 ~cleanup-<uuid>~ 并刷新父目录，再递归删除。恢复会跳过已进入清理的事务。扫描、查询和编辑前先执行恢复。若外部编辑与事务日志不符，保留现场并报错。

** 解除远端关联后首次同步

~remove_sync_policy~ 清除仓库的同步基线、历史、待上传记录和已结束的同步恢复材料，保留工作文件、仓库身份及固定锁。借用可恢复的重置意图记录清理范围，在仓库锁内执行，等待活动同步结束。清理过程仅访问本机。

当前 WebDAV 在解除关联后按 Org 文件相对路径匹配。远端已有的路径采用远端字节，本机独有路径保留并上传。成功提交后恢复从新基线合并。已下载但尚未提交的远端基线不提前结束首轮规则。

** 仓库重置

~OrgRepo.reset~ 清空仓库根目录内全部内容、同步历史、基线、冲突快照、扫描规则与 outbox，保留 ~.sync/id~ 的原始字节和运行中的锁。重新加载时按新建仓库的规则创建空控制目录。重置只处理本地目录。

重置要求有效已有身份，拒绝过期句柄和不安全根目录。先在仓库锁内持久化 ~reset~ 意图，发现活动固定同步锁时释放仓库锁并等待。同步结束后继续清理，保留身份、仓库锁和固定同步锁文件。中断后恢复重置意图并继续清理。链接只删除链接自身，不跟随外部目标。

仓库配置页显示“重置本地目录”，二次确认明确清空范围及不可撤销性。目标固定为保存配置中的目录，目录草稿变化时要求先保存。执行期间暂停配置页导航和操作。成功后刷新仓库与通知，保留配置和身份，下次同步重新建立基线。

** 通知订阅与同步提示

通知仅通过 ~watch_notifications(repo_ids, monitor)~ 订阅，首次发送缓存快照，后续发送增删改。文件服务据已读取的版本和基线更新通知。 [[file:通知订阅设计.org][通知订阅设计]]。

同步完成后复用本轮已读取信息与事务字节，连同当前实际基线一起投递文件状态服务。已发布远端基线的失败也投递实际快照。解决冲突通过普通操作组提交后传递最终文件 checksum 与冲突状态。普通本地修改只传递已提交的文件版本与冲突状态，不重新扫描。

* 目录结构说明

** 路径与文件布局

下例以 ~path/to/A.org~ 表示从仓库根起算的安全相对路径。控制路径和工作路径都校验边界、类型及符号链接。重置删除链接自身。 ~.sync/~ 和根目录控制标记 ~sync~ 、 ~reset~ 均由 Core 管理，排除在普通扫描、查询和传输范围之外。

~.sync/id~ 保存 Core 仓库身份，移动仓库根目录、重新打开和重置后仍保留。 ~started_at~ 由 Core 读取已占用的历史时间后生成，时钟回退时推进到最近历史之后。历史目录使用该时间，宿主使用同步记录 ID 访问 Core。

** 会话暂存、待上传意图与恢复材料

| 路径 | 内容和用途 |
|-
| ~sessions/<session-id>/state.json~ | 本轮仓库身份、开始时间及持久化阶段。 |
| ~sessions/<session-id>/remote/~ 与 ~metadata/remote.json~ | 暂存本轮获取的远端正文和逐路径存在状态、版本清单。本轮以对应的内存快照构造持久远端代。 |
| ~sessions/<session-id>/merged/~ | 每个比较任务按目标相对路径写入候选正文。调度器校验 hash 后用同一份内容传输及提交。删除项通过计划中的缺失状态表达。 |
| ~sessions/<session-id>/requests/<index>.json~ | 记录条件请求意图与确认结果。重试以实际远端快照和持久化祖先为输入。 |
| ~outbox/<uuid>.json~ | 本地操作登记的待上传意图。收集已存在且版本匹配的记录，最终事务确认。本轮读取后新增的意图由后续同步处理。 |
| ~transactions/<uuid>/journal.json~ 与 ~committed~ | 工作文件和控制文件的变更前后字节及恢复边界。 |
| 根目录 ~reset~ 与 ~.sync/reset/~ | 持久化重置意图和清理恢复材料。 ~.sync/remote-detached~ 表示解除远端关联后的首轮状态。 |

** 远端缓存与共同祖先

~current.json~ 和 ~current.backup.json~ 共用一个受保护的索引。当前外层版本 3 含 checksum，内部版本 2 记录当前远端代 ~generation~ 、本地合并祖先代 ~local~ 、远端来源 ~origin~ 和逐路径的当前远端条目。两份索引通过同一可恢复事务发布。校验通过的旧版本 2 索引可迁移到双副本。来源地址与用户名变化时拒绝复用旧基线，凭据由宿主管理。 [[file:文件状态与通知设计.org::*current.json 的损坏与删除保护][索引校验与修复]]

| 快照 | 内容 | 用途 |
|-
| ~generation~ | 最近确认的远端正文及相应版本 | 列举得到的强 ETag 与缓存相同、长度相容且缓存有正文时，可跳过 GET。 |
| ~local~ | 上次已提交的本地合并祖先 | 供本轮三方比较。远端独立发布时保留旧引用，本地提交时只推进实际处理的路径。 |
| 本轮远端暂存 | 从缓存复用或通过 GET 获得的本轮正文 | 完整确认后构造新远端代，保护该正文与实际响应版本的对应关系。 |

每代目录以 ~manifest.json~ 记录来源和条目，以同级 ~A.org.meta.json~ 保存该正文对应的 ~revision~ 、远端版本、正文 hash 和 ~sync_id~ 。读缓存时校验索引、清单、同级元数据、正文 hash 和长度。只有元数据且 hash 为空的条目表示已确认删除，清单无条目表示尚未建立。现存零字节正文有自己的 hash。已发布的代只读。未变化的正文可从旧代硬链接，文件系统不支持时复制，工作文件保持独立。

构造新代前，在固定同步锁下清理无引用的旧代，保留 ~generation~ 和 ~local~ 所指向的代。基线损坏无法恢复时阻止同步，保留已有材料。成功历史仅供展示与恢复材料读取。

** 历史记录与恢复

每轮日志由 ~history/<started-at>/summary~ 、 ~context.json~ 和 ~files/<path-sha256>/record.json~ 组成，原文独立保存。summary 第一行固定为 ~started_at=<Unix 毫秒时间戳>~ ，其后按行保存名值对。成功、失败与取消均通过事务发布，零文件也有摘要。格式、字段独立解码及兼容细节见 [[file:同步日志存储与兼容设计.org][同步日志存储与兼容设计]]。

新同步从历史文件和目录名称分配时间。Core 以 kind、仓库 ID 和本轮时间生成完成记录 ID。列表读取 summary，展开后读取对应文件记录，打开原文只校验对应路径和 hash。单个旧字段或文档损坏产生读取诊断，不阻断新同步，不改写旧日志。旧 ~history/<started-at>.json~ 按需容错读取。显式完整导出要求必需字段可用。

日志加载使用独立的 ~SyncLogData~ 可选字段，可保留旧 appStartup、appBackground 及未知原因。普通正文按 ~source_hash~ 校验，冲突及删除备份按各自的目录和 hash 读取。

*** 历史直接保存文件结果

新记录在每个 ~OrgRepoSyncFileRecord.outcome~ 保存同步决策结果。传输记录在 ~action~ ，执行状态记录在 ~state~ 。

| 结果 | 含义 |
|-
| ~Created~ | 首次或已确认删除之后，单端新增文件并成功创建／下载 |
| ~Deleted~ | 本次采用整文件删除 |
| ~Unchanged~ | 文件与基线无变化，或已确认双方均不存在 |
| ~Updated~ | 采用远端内容更新本地，例如仅远端修改或无共同祖先时采用远端原文 |
| ~Merged~ | 两端内容改变，自动合并成功 |
| ~Conflict~ | 自动合并仍有任务候选，需要人工处理 |
| ~Uploaded~ | 仅本地修改，上传成功 |
| ~Failed~ / ~Skipped~ | 执行失败或跳过 |

字段在同步决策时计算并随历史事务持久化，宿主不按传输方向重新推导“更新／合并”。旧记录缺失字段时按 ~Legacy~ 读取，仅由 Core 使用原 ~action/state~ 兼容投影，不能补造旧历史没有保存的两端变化信息。解决冲突后，原历史文件结果仍为冲突，不按当前文件派生解决状态，也不改写历史 JSON。

*** 远端删除备份

确认远端删除并准备移除本地文件时，将删除前的本地完整原文写入 ~history/<started-at>/deleted/<原相对路径>/<原文件名>~ 。本地已经不存在时使用共同祖先正文，零字节正文照常备份。历史 ~detail.deleted_archive~ 保存备份 hash， ~synced_source~ 和最终 ~local_version~ 为空，远端基线记录删除。

备份与工作文件删除、基线、成功历史和 outbox 确认共用仓库事务。只有成功提交才发布删除备份。双方继续保持缺失时，后续同步记为无变化。 ~history_file~ 根据备份字段读取只读原文，校验安全路径、普通文件及 hash。缺失或损坏时报告对应错误。

*** 当前冲突与历史冲突

历史中的冲突结果记录当次同步结果仍含冲突，完成后固定。当前文件的容器可因后续操作移除，但不会把历史改成“已解决”，也不会改变历史冲突数或备份内容。手机日志为有远端删除备份的记录提供阅读入口。

* 同步计划

** 输入与比较

| 输入 | 取得方式 | 计划用途 |
|-
| 远端 R | 本轮完整列举及确认正文，保存实际路径与版本 | 与祖先比较远端文件是否出现、删除或修改，同时提供条件写入版本。 |
| 基线 B | ~remote_base~ 的 ~local~ 引用 | 共同祖先。该路径可能有正文、已确认删除或尚未建档。 |
| 本地 L | 网络下载之后在仓库锁内重新读取的工作文件 | 与祖先比较本地新增、删除和修改，同时作为提交校验依据。 |

WebDAV 从本地、远端、基线和待上传意图收集安全相对路径，再按文件身份建立比较组。远端确认缓存中的路径也参与枚举。排除目录不参与下载、删除或祖先推进。根目录 ~.orgzlyignore~ 使用独立的配置同步规则，任务扫描忽略规则只影响查询。 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]

比较时先判断文件是否存在，再比较正文原始字节。ETag 用于确认远端版本和条件请求。远端只有在完整列举成功后才能确认缺失。已存在的零字节基线仍是有效共同祖先。 ~generation~ 可以比 ~local~ 新，计划中的 B 始终从 ~local~ 取得。

** 文件级 ID 与路径匹配

从 L、R、B 各自的 Org 文件顶部属性抽屉读取显式、非空的 ~ID~ 。该值在仓库范围内识别同一个文件，任务节点的 ~ID~ 用于内容合并， ~.sync/id~ 标识仓库。文件 ID 可从已校验的缓存和祖先正文提取。

1. 为每个远端文件建立比较组。先用远端文件的 ID 在本地、共同祖先中各选择一个同 ID 的文件。任一快照内同一 ID 对应多个路径时，计划报身份歧义。
2. 全部远端文件完成 ID 匹配后，再对每组仍缺的一侧按安全相对路径补齐。各侧的文件最多选用一次。路径补齐允许两端有不同 ID。例如，共同祖先没有 ID，本地和远端各自添加不同 ID 时，三份文件仍进入同组，正文正常三方合并，文件顶部保留远端 ID。剩余的本地文件与共同祖先也先按 ID 再按路径配对，以处理远端缺失的情况。
3. 对两端都存在的文件决定最终路径和内容合并方法。有共同祖先时，单端改名沿用改名侧路径，双方改成同一路径时采用该路径。无共同祖先时采用远端路径。远端交换两个有稳定 ID 的文件名时，按各自 ID 读取旧基线和本地文件，在交换后的远端路径写入结果。双方改成不同路径、多个结果争用同一目标，或写入会覆盖另一比较组尚在使用的远端文件时，暂停本轮修改。已知本地或祖先的排除路径时，跳过对应比较组。
4. 先为所有比较组预留最终路径，再清理没有被结果占用的旧路径。创建新远端路径并确认内容后，才允许条件删除旧远端路径。本地工作路径和共同祖先的路径迁移归入同一仓库事务。若目标已创建而旧远端路径清理失败，重试时会发现两个同 ID 的远端路径，按身份歧义暂停，保留两侧内容。

文件 ID 用于组成比较组。暂存文件、基线索引、远端条件请求和历史记录使用各自实际的相对路径。

** 从比较得到执行计划

| B | L | R | 处理 |
|-
| 有正文 | 存在 | 存在 | 运行 ~merge_file_with_base~ 。以合并字节为目标，只有目标与某一侧字节不同时才需要写该侧。 |
| 无共同祖先正文 | 存在 | 存在 | 运行 ~merge_file_no_base~ 。目标采用远端原文。传入废纸篓引用时额外返回可独立执行的新增操作组。 |
| 有正文 | 存在 | 缺失 | 采用已确认的远端删除。移除本地文件和保存删除前原文进入同一事务。 |
| 有正文 | 缺失 | 路径与正文均与 B 相同 | 传播本地删除，以当前远端强 ETag 发出条件 DELETE。 |
| 有正文 | 缺失 | 路径或正文与 B 不同 | 采用远端文件的当前路径和正文。 |
| 无共同祖先正文 | 存在 | 缺失 | 条件创建远端文件。 |
| 无共同祖先正文 | 缺失 | 存在 | 下载远端文件。 |
| 任意 | 缺失 | 缺失 | 保持缺失，按实际确认的删除状态记录基线。 |

生成计划时选定内容入口及最终路径。每组由独立的 Tokio 任务生成目标字节或删除状态，再据目标与 L、R 的差异得到本地写回、远端创建／更新／删除或无传输。每项附带输入版本、输出冲突状态、删除备份需求及预期历史结果。远端以 ~If-None-Match: *~ 创建、以强 ~If-Match~ 更新和删除。全部计划项先校验条件请求能力，再执行首个远端修改。

例如，有基线时 L 与 B 相同而 R 改过，结果采用 R，只写回本地。L 改过而 R 与 B 相同，结果含可应用的本地修改，按差异上传。两端改动均可应用时，目标同时包含两端改动，按需写回两侧。两端已是同一结果时无需传输。

* 合并算法

** 文件内内容合并

两个异步函数接收已解析的 ~OrgFile~ 快照。仓库按相关版本的配置分别解析 B、L、R，包括各自的 ~SETUPFILE~ 上下文。任务匹配在同一个逻辑文件内，优先使用标题节点自身的 Org ~ID~ ，缺少 ID 时按规范化标题路径和同名出现次序匹配。路径忽略 ~orgize~ 识别的标题直属 ~COOKIE~ ，例如进度从 ~[1/2]~ 变为 ~[2/2]~ 时，父标题和子标题仍可匹配。每个节点比较自己的标题、属性、直属规划和正文，子标题独立比较。

*** 有基线的三方合并

~merge_file_with_base(local, remote, base)~ 以 R 为底稿重放 B 到 L 的变化，返回 ~MergeResult~ ，包含完整合并字节和结果中的未解决冲突状态。公开纯函数 ~merge(base_data, local_data, remote_data)~ 也使用这套内容算法，接收 UTF-8 字节并按文件自身声明与默认配置解析。

1. 将三份文件分成主树和旧冲突点。旧冲突独立按 ID 合并，主树按任务身份匹配。
2. 回放本地新增、删除、字段更新、父子结构和同级排序。同一任务一端更新 TODO、另一端编辑正文时可以合并。正文按不重叠的行差异重放，标签合并各自的增删， ~LOGBOOK~ 按日志项合并并保持时间顺序。普通文件前言采用远端原文，文件头关键字和顶部属性另外做三方比较。 [[file:文件头属性编辑设计.org][文件头属性编辑设计]]
3. 本地删掉任务且 R 对应子树与 B 一致时应用删除。R 已修改该子树时保留远端版本及删除候选。R 已删除而 L 有修改时保留本地修改候选。字段、结构或顺序无法安全合并时保留相应材料，独立改动仍合入主树。
4. 将保留的旧冲突和本轮新冲突附到文件末尾。普通内容沿用来源区间，保留与该次改动无关的字节。

*** 无基线的远端优先处理

远端原文就是同步目标。 ~merge_file_no_base(local, remote, trash_file)~ 返回 ~Result<Option<TaskOperationGroup>, CoreError>~ 。该分支不生成新冲突，远端原文已有的冲突区随文件保留。

传入 ~trash_file: Option<OrgFileRef>~ 时，比较两端普通标题。远端缺少对应任务或对应任务内容不同的，每个本地任务生成一条 ~TaskOperation::Creation~ 。每条操作用独立字段携带标题、正文、状态、优先级、标签、规划和属性，保留原日志并预填 ~SOURCE_*~ 来源属性。父任务和子任务分别生成，废纸篓目标使用文件根位置。操作组可在源文件采用远端版本后交给 ~execute_task_operations~ 执行。缺少废纸篓引用或没有待归档任务时返回 ~None~ 。当前 WebDAV 调用不传废纸篓引用。

*** 冲突容器与设计原则

使用文件末尾唯一的一级标题“同步冲突”作为容器，自身同时带有大写 ~CONFLICT~ 与标准 ~ARCHIVE~ 标签，整个子树都是冲突区。旧文件中只带 ~CONFLICT~ 标签的容器仍可识别。新容器统一使用 ~:CONFLICT:ARCHIVE:~ 。容器的每个直接子标题是一个冲突点，增加定位属性 ~CONFILICT_ID~ 、节点内关键字 ~#+CONFLICT_REASON:~ 与展示祖先关键字 ~#+CONFLICT_ANCESTORS:~ 。容器不另设属性，冲突点的完整原文作为其可见后代或 example 块保存，不再生成 ~CONFLICT_SOURCE~ 、 ~CONFLICT_ORIGIN~ 、 ~CONFLICT_PARENT~ 、 ~CONFLICT_PATH~ 或 ~CONFLICT_OPERATION~ 。用户原有属性与代码块字面文本保留，不按前缀清理。

#+begin_example
,* 普通任务
远端内容

,* 同步冲突 :CONFLICT:ARCHIVE:
,** 普通任务
:PROPERTIES:
:CONFILICT_ID: <稳定定位值>
:END:
,#+CONFLICT_REASON: modify
,*** 普通任务
完整本地候选内容
#+end_example

合并先分离 B、L、R 的普通主树与既有冲突材料，旧冲突只单独协调，不参与主树比较，也不作为本轮合并失败的依据。本轮主树没有新冲突时，直接使用成功合并的主树并重新附加保留的旧冲突点。

冲突点按 ~CONFILICT_ID~ 唯一定位，创建后 ID 与内容不变，只允许新增和删除，不比较或合并候选正文。设 B、L、R 分别为基线、本地、远端的冲突 ID 集合，结果为 (B ∩ L ∩ R) ∪ (L ∖ B) ∪ (R ∖ B)。基线中已有的 ID 只有双方都保留时才留下。基线外任一端新增的 ID 都保留，同一 ID 只保留一次。输出沿用远端保留节点的顺序，再按本地顺序追加本地独有的新增节点，候选原文直接复制。

双方解决同一旧冲突时，删除旧 ID，普通主树上的取舍结果照常做三方合并。双方选择相同结果时不产生新冲突，选择不同且不能自动合并时产生新的冲突点，旧 ID 仍保持删除。双方各自新增不同 ID 的冲突点时，两者同时出现在同一尾部容器中。最后一个冲突点被删除且主树没有新冲突时，移除整个容器。

本轮出现新冲突时，合并后的主树保留远端内容以及已经安全应用的本地变更，尾部冲突点保存无法应用的本地候选。已有冲突容器先从 R 分离，再按其 ID 集合合并。

容器总是追加在文件末尾，其生成的分隔换行属于完整冲突块。移除最后一个冲突点时一并移除容器及该分隔符，保留远端主树的空白、CRLF/LF 与原本无末尾换行的状态。系统不再增加 ~#+CONFLICT: true~ 或额外的文件头标签，避免在冲突区外留下生成内容。

*** 冲突原因与内容

~CONFLICT_REASON~ 表示候选由哪一类合并分支生成。

| 取值 | 场景与内容 |
|-
| ~header~ | 文件头声明或顶部属性竞争，保留本地声明作为候选 |
| ~modify~ | 任务字段、父节点或层级发生竞争，保留本地候选 |
| ~create~ | 新增节点内容竞争或回退后尚未应用的新增，保存完整本地新增子树 |
| ~delete~ | 删除意图未应用，复制当前远端子树作为可见材料，保留删除意图而不删除远端主树 |
| ~modify-missing~ | 远端目标消失，保存完整本地修改子树 |
| ~missing-parent~ | 父节点消失，保存不能安全放置的完整本地子树 |
| ~reorder~ | 两端均改变同级排序，且结果不同，以 example 块保存本地主树 |
| ~structure~ | 重复身份、循环或无法安全渲染的结构，以 example 块保存本地主树 |

定位 ID 按生成期的仓库／文件上下文、操作来源、原因和完整来源内容确定，使同一文件重试稳定、不同文件可区分。此 ID 不参与普通任务身份匹配，也不要求为候选原文中的普通 Org ID 生成替代值。重试时按定位 ID 对候选去重。

*** 任务冲突的定位、记录与应用

字段冲突以任务自身为单位。修改候选保存本地任务子树原文，供预览计算差异或按目标应用。

采用修改候选时，Core 在当前主树中定位并校验任务。当前对已有任务的应用用候选的标题和直属内容替换目标的对应区间，保留目标子任务。对于允许插入的候选，按明确的插入位置调整候选层级，保留其正文和子树。无法确定目标时要求用户选择。

应用候选经过版本校验、冲突保护和普通操作事务。成功提交时一并消费对应冲突点，登记 outbox 和操作历史。

*** 文件标记、查询与保护

~OrgFile.has_conflict()~ 及元信息 ~hasConflict~ 从真实标题节点的 ~CONFLICT~ 标签取得。 ~OrgFile.conflict_ids()~ 对应文件对象的只读 ~conflictIds~ ，提供当前容器各冲突点的定位值。查询在表达式、完成／组合过滤与分类统计前，自动排除自身或祖先带 ~CONFLICT~ 的节点。REFILE 目标、节点查询与文件任务数遵守同一边界，完整文件读取仍保留所有原文。

普通 Modification、Deletion、Movement、Creation 和原文区间编辑都不能修改冲突子树。保护覆盖从祖先删除／移动整棵树、向冲突区插入内容、从祖先替换其中链接等间接路径。通过专门的冲突选择操作移除冲突点。

新生成的冲突通过 ~CONFLICT_ANCESTORS~ 保存从近到远的合并祖先身份 JSON 数组，供 Core 在主树中寻找最近仍存在的父节点。该信息只决定卡片展示位置，不自动确认插入或替换目标。定位不到可用祖先时，将冲突显示在文档根部。

*** 冲突选择与普通操作组

~TaskOperation::ConfilictSelection~ 使用文件根 path、id、action 和可选 target。用 id 查找 ~CONFILICT_ID~ 。Discard 删除该点，UseLocal 按明确目标采用候选或执行删除意图。候选可用性、目标与范围由 Core 校验，最后一点移除后自动清除容器及其生成分隔符。多点按 ID 顺序定位，不受前序移除导致的字节位置变化影响。

手机逐点预览先将源文件分为主树与冲突材料，只把主树写入工作副本，冲突材料由 Core 独立保存。副本上的 ~execute_task_operations~ 执行并记录每次成功的取舍。 ~finish~ 将已记录操作映射到真实源路径，返回带源文件版本约束的操作组。应用通过统一操作入口提交。 [[file:冲突预览与合并设计.org][冲突预览与合并设计]]

冲突取舍通过本地事务更新工作文件。丢弃全部使用同一组操作和已读取的文件版本。
