* 范围与状态

本文统一定义 Core 的内容合并、仓库事务、远端基线、冲突目录、历史、重置与通知。当前同步写入版本 4；旧版本兼容读取。协议请求与认证见 [[file:WebDAV 同步能力设计.org][WebDAV 同步能力设计]]，公开接口见 [[file:接口文档.org][接口文档]]。宿主只提供配置、调用接口并展示结果，不解析控制目录或实现另一套同步判断。

同一文件内采用三方操作重放：B 为最近确认的远端内容，L 为当前本地内容，R 为本轮确认的远端内容。独立修改合并，不能安全应用的修改保存为普通任务候选；整个合并结果直接上传，任务候选不阻止后续同步。事务边界是单个仓库。

* 同步目录与身份

** 路径约定

全文用 ~/path/to/A.org~ 表示从仓库根起算的文件占位路径，实际字段使用 ~path/to/A.org~ 这样的安全相对路径。拒绝越界、符号链接及不符合约定的类型；重置例外只移动或删除链接自身，不跟随链接目标。

~started_at~ 是十进制 Unix 毫秒值，用于历史文件和目录； ~sync_id~ 是记录 ID。宿主按记录 ID 调用 Core，不自行拼接控制路径。

** 完整布局

#+begin_example
<OrgRepo.rootDirectory>/
├── path/to/A.org
└── .sync/
    ├── id
    ├── .transaction.lock
    ├── remote_base/
    │   ├── current.json
    │   └── files/path/to/A.org/<revision>/
    │       └── A.org                    # 删除时为 A.removed
    ├── history/
    │   ├── <started-at>.json
    │   └── <started-at>/conflicts/path/to/A.org/
    │       ├── A.org                    # 本轮合并后仍带冲突的完整文件
    │       └── A.resolved.org           # 显式解决后保存的本地完整结果
    ├── outbox/<uuid>.json
    ├── transactions/<uuid>/
    │   ├── journal.json
    │   └── committed
    └── reset/                          # 重置期间的临时恢复材料
        ├── journal.json
        ├── items/<index>
        └── committed
#+end_example

~.sync/~ 的整棵目录不参与普通 Org 扫描、查询或传输。Core 初始化或读取 ~id~ ，移动根目录、重新打开 workspace 和重置均保留身份。不能仅替换身份后复用旧历史。地址与用户名改变时，已有基线拒绝跨远端复用；密码不参与持久化。

** 冲突文件命名与路径隔离

每个原文件独立使用完整相对路径作为冲突目录；不增加固定的 projects 层级。同步结束时，存在任务候选的文件在该目录保存本轮处理后实际上传的完整结果，包括文件头标志和候选子树；不是仅保存合并前远端原文。没有冲突的普通文件不创建该目录。

历史快照保持原始文件名 ~A.org~ 。解决结果按 ~A.org -> A.resolved.org~ 命名；原名已经含 resolved 时继续插入，即 ~A.resolved.org -> A.resolved.resolved.org~ 。全部解决后保留冲突目录与原快照，表示该次同步曾经包含冲突。

目录存在只能说明该轮历史曾有冲突，不能单独判断当前文件仍待解决。旧版本 2 的目录保留原远端正文与结果文件语义，兼容阅读时不能冒充版本 4 的合并快照。

* 文件内内容合并

纯函数 ~merge(base_data, local_data, remote_data)~ 接收三份 UTF-8 Org 原文，返回合并后的字节；不访问目录、仓库、网络或历史。同步已有的 TODO 默认值与 SETUPFILE 上下文经私有解析入口复用同一个算法，公开内容接口仅使用原文自身声明与默认值。

仅在同一文件中匹配。稳定 Org ID 优先，无 ID 时回退文件内标题路径及出现次序；不使用仓库或文件名构造逻辑匹配键，不执行跨文件移动。独立字段和不相交正文编辑合并；同字段竞争、目标消失或结构歧义保留远端，再加入完整本地候选，避免丢失原文。

候选根标题加 ~(conflict)~ 后缀，根节点增加大写 ~CONFLICT~ 标签；后代不额外加该标签，原有用户标签保留。候选与后代生成独立 ID，内部来源属性保存原始身份、操作、路径及完整来源，重复重放不增加相同候选。候选尽量位于原 path 对应节点的整个子树之后；原节点不存在时依次按逻辑身份、邻近存活兄弟、最近存活祖先和文件末尾定位。

** 文件头冲突标志

存在候选时输出文件头 ~#+CONFLICT: true~ ，没有候选时移除该字段；不改写其他文件头与未涉及的正文。解决接口同样维护该标志。Core 从文件头的语法节点同时读取 TITLE 与 CONFLICT，不扫描源码块或子树中的同名文本。

~OrgFile.has_conflict()~ 和 ~OrgFileMetadata.has_conflict~ 对应宿主字段 ~hasConflict~ 。文件头缺失或不是 true 时为假。存储库只展示 Core 返回的值，不检查目录、解析 Org 或遍历任务推断冲突。标签查询仍能匹配系统标签，展示标签列表排除 ~CONFLICT~ ，与 ~ARCHIVE~ 一致。

* remote_base 远端状态基线

** 目的与三种状态

~.sync/remote_base/current.json~ 是仓库当前生效的唯一索引，版本为 1。索引携带远端 URL 与用户名的绑定 hash，以及按原路径组织的条目；不保存凭据。条目包含 ~revision~ 、实际远端版本、正文 hash 或删除状态及来源同步 ID。

| 状态 | 表达 | 含义 |
|-
| 未建立 | 没有条目 | 没有已确认基线 |
| 远端存在 | hash 存在，版本引用完整 A.org | 包括真实零字节文件 |
| 远端已删除 | hash 为空，版本引用空 A.removed | 已确认不存在，不等于未建立 |

正文版本不可变，位于 ~files/path/to/A.org/<revision>/~ 。当前索引一次切换，不通过多个逐文件指针伪装仓库整体提交。读取校验版本号、来源绑定、路径、正文 hash 与空删除标记；损坏必须报错，不能猜测为空基线。

** 更新时机

整轮正常完成后，本地事务统一提交所有参与路径的最终远端状态，包括已经成功上传且仍含任务候选的内容。执行错误或取消不推进任何路径；被过滤路径不处理、不消费其意图。新版本正文只有随当前索引事务正式提交才生效。

离线解决产生尚未上传的本地结果，不修改 remote_base。下次同步仍以实际确认过的远端快照为 B，成功传输后再推进基线。不能将 resolved 文件存在或本地编辑成功当作远端已更新。

可靠旧历史中的完整成功正文可用于迁移；失败记录与未上传结果不能构造基线。远端 origin 不一致时明确拒绝，用户可通过本地重置重新建立状态。

* 同步流程与删除决策

先递归列举并校验远端，再准备全部远端正文；只有强 ETag 相同且长度兼容时复用本地已确认缓存。发生变化时下载对应版本。全部读取与解析完成后再开始远端修改，避免准备阶段失败产生不必要上传。

按 B 与 L 推导本地操作，应用到 R。首次无基线时按空内容参与文件内合并：单端文件创建或下载，两端相同只保留一份，不同内容按节点合并或形成任务候选。

** 文件删除与修改并存：远端优先（最新确认）

文件存在性在内容合并之前处理；内容合并的空输入不表达文件不存在。

| 情况 | 决策 |
|-
| 已确认远端整文件删除，本地修改 | 采用远端删除 |
| 远端整文件修改，本地删除 | 恢复远端内容 |
| 仅本地删除，远端等于基线 | 条件 DELETE |
| 两端均删除 | 保持删除并记录删除基线 |
| 两端均存在 | 文件内重放与合并 |

列举失败不能解释为远端删除。上述整文件规则不扩展为所有任务节点的远端优先；节点删除与另一端修改竞争仍可以形成任务候选。

创建使用 ~If-None-Match: *~ ，更新与删除使用确认的强 ETag。没有可靠写入条件时拒绝执行变更，不进行无条件覆盖。排除目录不参与下载、删除或基线推进；任务扫描忽略规则不缩小 Org 文件同步范围。

* 同步提交与失败边界

** 仓库级事务范围（已确认）

单个仓库一整轮同步是本地提交单位。全部远端处理成功后，通过同一可恢复事务提交工作文件、基线索引与正文、冲突快照、成功历史及 outbox 确认。任务候选不算执行失败；一个仓库失败不撤回另一个仓库已经完成的事务。

** 基线提交、失败与恢复

准备阶段保存正式文件的旧字节、新字节、创建目录清单及读取保护。提交前再次校验本地版本；写入临时文件、刷新、同目录原子替换后，最后写入并刷新完成标记。公开同步上下文保持原有结构，计划通过 Core 私有提交槽交回仓库。

完成标记之前中断时还原旧文件与旧基线；之后只清理恢复材料，不能回滚已经生效的同步。恢复先于扫描、查询和编辑。外部编辑与恢复状态不符时保留现场并报错，不覆盖新内容。同仓库使用进程内锁与支持平台上的文件锁，避免并发事务或跨进程误恢复。

执行失败与取消保持工作文件、当前基线、既有解决材料及 outbox；允许保存不参与成功状态恢复的诊断记录。正式成功后的清理失败不推翻已经完成的事务。

** 远端副作用与失败重试

多个 WebDAV 文件没有跨文件原子事务。A 的请求已经成功而 B 失败时，本地仍不提交，远端 A 不保证回滚。重试重新读取实际远端与旧基线，再重放本地操作；已存在的候选通过稳定身份去重，不能假装上次远端请求未发生。

* 历史记录与恢复

~history/<started-at>.json~ 是不可变完成记录，包含执行结果、文件动作、状态、脱敏错误及实际确认的完整 ~synced_source~ 。版本 4 的 Conflict 文件同样可能已经上传，应按实际动作计入传输数量。普通文件通过历史正文阅读；含冲突的文件额外保存目录快照，正文 hash 与记录相符。

读取只接受正式普通 JSON，校验开始时间、记录 ID 唯一性、类型与版本；不能跳过损坏记录后猜测当前状态。当前基线由 remote_base 决定，历史不与索引争夺优先级。

** 当前冲突与历史冲突

Core 将某条历史快照的候选身份与当前本地文件的候选身份比较，不再把 resolved 文件存在性作为版本 4 的唯一状态。对应候选全部消失时，该条历史标为已解决；普通编辑也可改变候选状态。 ~A.resolved.org~ 仍保留显式保存结果，历史原快照不改写。

当前通知从最近成功同步派生；更早遗留记录可查看，但不阻止普通同步。存在冲突目录表示该次曾包含候选，目录保留不意味着当前仍有待处理候选。

** 读取边界与旧布局

旧版本 2 的远端备份、resolved 命名和缺少备份错误继续兼容。旧材料不主动删除，不将旧目录存在解释成新版本同步阻塞条件。未知格式、缺少被引用材料或 hash 不符明确报错，不以当前工作文件冒充历史内容。

* 点击时比较与一次性解决

已有同步详情继续调用 ~compare_conflict~ 与 ~resolve_conflict~ 。版本 4 从当前本地文件读取候选及其保存来源，与对应历史已上传快照核对版本；比较不持久化，不联网。完整选择只在页面内存维护，离开未保存则丢弃。

保存时重新检查当前文件 hash、历史快照 hash、缺失状态及全部选择。生成结果后，在同一可恢复事务中写工作文件、 ~A.resolved.org~ 与 outbox，清除已经解决的候选及文件头标志。离线解决不推进实际远端基线，也不新增同步作业。当前文件发生变化时拒绝旧请求，要求重新比较。

存储库列表由 hasConflict 展示冲突状态，点击带标志的文件进入“解决冲突”页面；该入口当前只提供文件信息和返回导航，内部交互待定。普通文件仍进入查看页，不在列表中执行合并。

* 解决后的同步提示通知

~CoreNotification::SyncRequired~ 序列化为 ~{ "type": "syncRequired" }~ ，不携带仓库、文件或同步记录字段。显式解决后的本地结果与已确认的远端内容不同、仍需上传时产生提示。

整个应用进程最多一条同类型通知，后来的提示不新增条目；内部按仓库确认代次防止多仓库提前清除。通知不持久化，应用重启不恢复；outbox 继续保留。点击由宿主发起普通同步，成功确认对应结果后清除，失败或取消保留。重置清除所属仓库的确认状态，不影响其他仓库的提示。

* 仓库重置

~OrgRepo.reset~ 清空仓库根目录内全部内容、同步历史、基线、冲突快照、扫描规则与 outbox，保留 ~.sync/id~ 的原始字节和运行中的锁。重新加载可创建空控制目录，与新建仓库状态相同；根目录、宿主配置及凭据不变，不访问远端、不产生远端删除请求。

重置要求有效已有身份，拒绝过期句柄和不安全根目录。与同步、编辑共用仓库锁；先持久化重置日志，再将顶层内容移动至受控暂存区，完成标记之前中断则恢复，之后只清理。目录中的链接只移动、删除链接本身，不跟随外部目标。恢复时若原位置出现外部内容则保留材料并报错。

仓库配置页显示“重置本地目录”，二次确认明确清空范围及不可撤销性。目标固定为保存配置中的目录，目录草稿变化时要求先保存；执行期间禁止返回和其他操作。成功后刷新仓库与通知，保留配置和身份，下次同步重新建立基线。
