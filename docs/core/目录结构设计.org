* 范围

本文定义 ~OrgRepo~ 普通内容目录、任务扫描和运行时任务操作回退的边界。 ~.sync/~ 的稳定身份、完整布局、历史格式、版本恢复、outbox、冲突目录和解决结果统一见 [[file:同步核心设计.org][同步核心设计]]，本文件不重复定义。

* 仓库内容布局

#+begin_example
<OrgRepo.rootDirectory>/
├── .orgzlyignore      # 可选，任务扫描规则
├── path/to/A.org     # 任意相对路径的 Org 内容
└── .sync/            # Core 控制目录，详细布局见同步核心设计
#+end_example

全文用 ~/path/to/A.org~ 表示从仓库根目录起算的文件占位路径，实际领域字段使用 ~path/to/A.org~ 这样的安全相对路径。普通文件由用户管理， ~.sync/~ 的全部后代由 Core 管理。

* 初始化与扫描隔离

~OrgRepo.load~ 只确认根目录并读取或创建稳定仓库 ID，不扫描业务文件、不读取历史，也不检查 ~reset~ 、 ~sync~ 或恢复材料。后续业务访问在锁内统一执行状态检查与恢复，详见 [[file:仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]]。

~OrgRepo.load_files(ignore_files)~ 在每次调用时按需扫描并返回独立文件集合； ~ignore_files~ 为当前仓库的安全相对路径，匹配文件在读取正文之前排除。根目录 ~reset~ 、 ~sync~ 以及 ~.sync/sessions/<sync-id>/~ 都是 Core 控制内容。

扫描、任务查询及同步策略均强制跳过 ~.sync/~ 整棵目录，不跟随符号链接。普通文件写入器拒绝控制目录和越界路径，文件管理器隐藏、平台备份规则及 ~.gitignore~ 不能代替此校验。

复制整个仓库会保留稳定身份，需要独立仓库时应初始化新的空目录；不能只替换 ~.sync/id~ 后复用旧历史。同步目录兼容性与旧备份边界见 [[file:同步核心设计.org::*读取边界与旧布局][读取边界与旧布局]]。

* 任务扫描忽略规则

仓库根目录可以提供 UTF-8 的 ~.orgzlyignore~ 。规则兼容 Orgzly 使用的 Gitignore 风格：每行一条，支持空行与 ~#~ 注释、 ~*~ 、 ~?~ 、 ~**~ 通配符、根目录锚定的 ~/~ 、目录规则结尾 ~/~ 、 ~!~ 反选以及转义字符；规则大小写敏感，后匹配的规则优先，未直接命中时检查父目录。支持 LF、CRLF 和文件开头的 UTF-8 BOM。只读取每个仓库根目录的该文件，不读取子目录中的同名文件，也不应用父目录或 Git 全局忽略配置。

#+begin_example
# 隐藏指定文件、任意层级的同名目录及私有笔记中的任务
/root-only.org
private/
*.private.org
!notes/keep.private.org
#+end_example

每次 ~load_files~ 或单文件读取都重新读取并编译配置；没有文件或文件为空时不忽略任务，修改或删除后在下次操作生效。不可读取、非 UTF-8 或无效规则返回明确错误；不把读取失败当成空任务集合。配置必须是普通文件，不跟随配置文件符号链接。

忽略只发生在 Core 从完整文件模型投影任务记录时：普通搜索、 ~TaskQuery~ 及其分类摘要均使用同一结果。完整 ~load_files~ 结果仍包含被任务规则隐藏的文件， ~OrgRepo.file(path)~ 仍按需读取原始内容；文件和任务身份不跨仓库合并。同一相对路径在另一仓库没有命中规则时仍正常参与查询。

忽略规则不改变 Org 文件的 WebDAV 上传、下载、冲突判断或待上传意图确认，也不删除或改写 Org 文件。Org 文件传输的过滤继续只由调用时的 ~SyncOptions~ 控制；即使整个文件的任务被忽略，同步仍使用其完整本地内容和版本基准。

WebDAV 额外读取远端根目录的 ~.orgzlyignore~ ，校验 UTF-8 与规则后原子保存到本地，并立即更新运行时规则。配置以普通同步文件记录保存内容哈希、远端版本和 ~synced_source~ ，不生成任务指纹、不加入 Org 文件清单或 outbox，也不向远端上传。首次远端没有配置时保留本地规则；远端删除此前下载的配置时，只删除仍与成功基线相同的本地副本并清空规则。本地副本已被修改且与远端不同、下载失败或远端规则无效时明确失败，保留本地字节，不进入任务合并流程。仅读取根目录配置，不下载子目录同名文件。

* 任务操作回退历史

~TaskOperationHistory~ 由 Core workspace 在内存中管理；每次成功操作组生成一个 ~TaskFallbackGroup~ ，保存实际变更文件的完整 before、after 原文与是否原先存在。它不写入同步历史、不生成持久化操作历史文件，也不参与 WebDAV。undo、redo 与重启恢复尚未实现。

旧任务整理产生的 ~.sync/backups/task-edit-<nonce>/~ 目录不主动删除，但新接口不再创建该类备份；提交期间的同目录 rollback 文件仅用于恢复本次普通 I/O 失败。同步冲突与解决结果见 [[file:同步核心设计.org][同步核心设计]]。执行与失败边界见 [[file:接口文档.org::*统一任务操作组执行][统一任务操作组执行]] 。

* 冲突预览临时文件

workspace 由宿主提供独立 preview_root，Core 验证其在全部仓库根目录之外，在 ~<preview_root>/workspace-<workspace_nonce>/<preview_id>/working.org~ 保存唯一活动主树副本；冲突点原文仅存于 Core 会话的独立集合，working.org 中没有冲突容器。workspace 通过 .lease 独占租约标记存活，支持的平台只清理已退出的会话目录。副本不进入真实仓库的文件加载结果，不初始化仓库身份、同步目录或扫描规则，不能放在 .sync 或普通仓库目录内。

逻辑定位为 ~{ repoId: "<preview>", file: UUID }~ ，原路径单独保存。finish 返回真实操作组并清理副本；真实修改仍由统一数据接口提交。详细契约见 [[file:冲突预览与合并设计.org][冲突预览与合并设计]]。
