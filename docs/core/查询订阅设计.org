* 模块与入口

~OrgWorkspace~ 属于上层 ~core::workspace~ ，是对外组合入口。 ~core::query_subscription~ 是独立模块，只依赖现有查询、模型与数据通知能力，不引用 Workspace。Workspace 负责创建句柄、注册既有数据监控、执行一次查询、装配初始结果和取消订阅。 ~model~ 与 ~editor~ 不引用查询订阅模块；修改执行、提交、触发器与原始事件生成流程保持现有行为。

查询层提供通用的同次读取投影，普通查询继续只返回原有结果；订阅启动从同一次加载取得求值所需的临时原始投影与文件版本，不重复查询、不重复加载。原始投影只在启动期间使用，随后释放。

* 对外接口

#+begin_src rust
impl OrgWorkspace {
    pub async fn subscribe_query(
        &self,
        requests: Vec<QuerySubscriptionRequest>,
    ) -> Result<Vec<QuerySubscriptionStart>, CoreError>;

    pub fn unsubscribe_query(&self, subscription: &mut QuerySubscription);
    pub fn query_subscription_status(&self, subscription: &QuerySubscription) -> QuerySubscriptionStatus;
}

pub struct QuerySubscriptionRequest {
    pub query: CoreQuery,
    pub callback: Box<dyn Fn(DataChangeEvent) + Send + Sync>,
}

pub struct QuerySubscriptionStart {
    pub data: CoreQueryResult,
    pub subscription: QuerySubscription,
}

pub enum QuerySubscriptionStatus {
    Current,
    AwaitingEvents,
    Invalidated,
    Closed,
}
#+end_src

~subscribe_query~ 只接收订阅项数组，不保留单项参数协议。每项携带自己的 ~query~ 和 ~callback~ ，结果数组按输入位置逐项返回独立的 ~QuerySubscriptionStart~ 。所有查询共享一次 ~query_snapshot~ ：每个涉及的仓库只加锁、扫描目录与加载文件一次，各项的包含／排除范围取所需文件并集；空数组不扫描文件，任一项校验或加载失败使整批失败，并清理本批已注册的监控。

共享仅限初始读取。每项仍持有独立固定查询、成员身份、版本状态与回调；同一原始变化分别按各项查询过滤和转换，结果直接发送到各自 callback。各 callback 的事件语义保持原样，单项取消不影响同批其他订阅。重复查询保留独立位置、结果与生命周期。

~Task~ 和 ~File~ 查询均受支持； ~Notification~ 不属于数据订阅，返回输入错误，继续使用原有通知监控。所有参数验证、仓库范围、安全路径、忽略规则、表达式、分类及排序沿用普通查询。查询定义在创建后固定，句柄对外不提供查询条件的修改入口；状态也通过 Workspace 读取。

~data~ 与普通查询的结果类型相同，所有权直接交给调用方。页面数据集使用这个返回值，不再另发初始查询。订阅句柄不保存完整任务、文件快照、正文或 AST，也不提供原始事件的公共处理入口。长期状态只有按文件组织的成员 ID 集合、文件版本与分类数值摘要；排序和分类所需的完整启动数据在返回后释放。

句柄析构自动解除监控；显式取消通过 Workspace 执行，重复取消无副作用。取消不打断已经进入的回调。订阅、取消与事件通过当前 Workspace 的 NotificationCenter channel 交给 process；回调在该处理任务内、查询成员状态锁外串行执行。修改返回前及初始结果装配前均等待此前入队事件处理确认，调用方应将事件排队交给数据集，不能在回调内同步等待当前 Workspace 的后续业务命令；通知过程与命令过程是同一宿主 runtime 上的独立异步 task。注册失败、查询失败或启动 future 被取消时，临时句柄自动解除监控。

* 事件过滤与成员变化

只复用现有 ~DataChangeEvent::RepositoryChanged~ ，不新增查询专用事件类型，不生成修改请求。事件中的 ~repo_id~ 与 ~operation_id~ 原样透传，不使用操作来源编号去重；同一操作可有多个仓库通知或后续关联变化。

成员变化以旧 ID 是否存在于命中集合、最终记录是否命中固定查询为依据。一次事件先处理全部旧身份，再装入全部最终身份，避免重名出现序号互换时误删刚加入的成员。改名与移动直接沿用原事件的旧新映射，不靠标题、字节偏移或文件差分猜测。

| 原先是成员 | 最终命中 | 订阅数据变化 |
|-
| 否 | 否 | 不通知该记录 |
| 否 | 是 | ~Created~ ， ~before=None~ |
| 是 | 否 | ~Deleted~ ， ~after=None~ |
| 是 | 是 | ~Updated~ ，明确移动时保留 ~Moved~ |

这里的删除表示从订阅结果移除，不代表删除源实体，不能形成第二个操作。跨仓库移动按各仓库已确认文件版本分别应用，可以在两个通知中表现为移出和移入；两侧共享 ~operation_id~ 。

底层提交事件已经携带受影响文件的全部最终节点。继承标签、系统标签匹配和文件标签条件直接用本次事件临时求值，处理后释放，不为不命中的任务建立记录缓存。查询求值在原始标签上完成，发送给调用方的任务投影继续隐藏系统标签。退出查询的旧快照也遵循同样的展示规则。

任务查询的 ~categories~ 是完整分类摘要，继续包含未选中分类的可选计数。模块仅缓存每个文件的数值计数；某个未选分类的记录变化也可以产生仅含分类摘要的事件。普通数据通知省略此字段。

文件查询的 ~files~ 只包含仍命中或新加入查询的文件，新加入时 ~before=None~ 。离开查询的文件通过 ~removed_files: Vec<OrgFileRef>~ 表达，JSON 为 ~removedFiles~ ；不删除真实文件。普通通知的空移除列表不序列化。未匹配的任务变化不进入文件订阅的 ~changes~ 。

* 启动交错、版本与边界

先为本批全部项注册独立监控，再执行一次批量查询。启动期间事件排队，比较初始文件版本与事件的前后版本：快照已经包含的事件链整体去重，查询之后的事件合并进返回的初始数据，不先发送一个过期快照再要求调用方重查。

运行中只有当前版本与事件前版本衔接时才应用增量；最终版本已经确认的重复事件不再次通知。乱序事件等待前序版本，不回滚到旧数据，也不重新读取磁盘。事件处理与通知分发均在模块内部排序。暂存队列最多保留 256 个原始事件，长期正常状态不保存事件载荷。

~AwaitingEvents~ 表示等待缺失的版本前序， ~Invalidated~ 表示已无法保证当前完整性。同步、重置等入口的 ~files=None~ 没有增量载荷，模块仅标记失效，不把失效通知转发为数据变化，也不自动查询。超过事件暂存边界同样标记失效。任务查询固定启动时的本地日期，跨自然日后标记失效；仓库集合或默认配置变化后应显式重建订阅。恢复由调用方显式重新启动订阅完成，不在事件回调或修改后隐式启动查询。

Core 接口和 Harmony bridge 已接通，任务页面由 DataSetManager 合并订阅调用并清理各订阅 ID，各 DataSet 继续独立消费自己的结果与变化事件。同步等旧入口补充完整增量前，不能声称所有外部变化均可自动校正。

* 一次性完整文件投影

Task 查询可通过 ~full_files~ 让初始查询返回完整文件；文件与初始节点同次加载。订阅状态会移除该投影请求，只保留任务范围、成员、版本与计数。修改仍按原有事件增量确认，不因曾请求完整文件而失效或重读。完整文件只归初始结果调用方，后续回调没有完整文件，语法树不进入订阅状态。
