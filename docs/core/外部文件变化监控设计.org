* 事件与职责

普通操作组已携带文件与任务的精确增量，继续通过查询订阅直接更新数据集。原 ~DataChangeEvent::RepositoryChanged~ 改名为 ~DataChangeEvent::NotificationEvent~ ，JSON 为 ~notificationEvent~ ，保留原字段并增加 ~notifications: Vec<CoreNotification>~ 。通知处理 task 在分发前附加当前缓存中的该仓库消息列表；应用级通知订阅仍按自己的范围提供完整列表，不由页面重查。

同步、Reset 和整文件删除使用外部文件变化，使用独立文件监控接口；事件不包含任务内容，不尝试从文件增删改推断任务移动或任务身份。

#+begin_src rust
pub enum ExternalFileChangeKind { Created, Deleted, Updated }
pub struct ExternalFileChange {
    pub file: OrgFileRef,
    pub kind: ExternalFileChangeKind,
}
pub struct ExternalFileChanged {
    pub change_files: Vec<ExternalFileChange>,
}
impl OrgWorkspace {
    pub fn watch_external_file_changes<F>(&self, callback: F) -> ExternalFileSubscription
    where F: Fn(ExternalFileChanged) + Send + Sync + 'static;
}
#+end_src

~OrgFileRef~ 包含 Core 仓库 ID 和仓库相对路径。JSON 使用 ~type: "externalFileChanged"~ 、 ~changeFiles~ 和 ~created | deleted | updated~ 。订阅句柄只保留取消令牌；析构解除监控。回调在所属 Workspace 的通知处理 task 内执行，不能同步等待该 Workspace 的后续业务命令，不向其他 Workspace 广播。

* 生成与提交边界

同步使用事务已有的 before／after 字节生成文件清单，不为生成事件增加目录扫描、文件读取或解析。仅在事务实际提交后发送；相同字节、 ~.sync/~ 元数据和只上传但本地未改变的文件均不进入清单。删除与空文件不同，新建空文件仍为 ~Created~ 。一次事务清单同时包含全部已提交的新增、删除和更新路径。

reset 在持有仓库锁、确认没有活动同步后收集将删除的相对路径，不读取正文、不解析任务。清空完成后按实际删除路径发送 ~Deleted~ ，保留的身份与锁文件不进入事件；空仓库不发送空文件事件。

业务收尾先由 Core 更新通知快照，按 ~SyncConflict~ 与 ~SyncRequired~ 各自的条件比较并广播列表变化，然后发布文件事件并等待分发确认。失败同步可能已经发布远端基线，因此没有工作文件变化时仍需更新通知，但不伪造文件变化。通知快照加载失败保留最近成功结果，文件变化仍送达数据管理层，以免界面永久保留旧数据。

该接口监听 Core 已知的外部业务变化，不新增操作系统目录轮询或跨进程文件监听。

* 数据集更新

每个 ~DataSetManager~ 注册一个文件监控，并统一持有跨自然日检查。收到事件后根据每项查询的仓库范围、 ~includeFiles~ 与 ~excludeFiles~ 判断是否相关；宿主仓库别名先通过仓库根目录映射为 Core ID。有限文件包含集合无交集时跳过事件。没有包含限制时覆盖仓库内所有变更路径。

查询范围只命中 ~Deleted~ 时，Core 从查询订阅清除对应文件的版本、成员与分类贡献，通过 ~notificationEvent.removedFiles~ 发出文件引用。 DataSet 删除相同仓库和路径的任务或元信息，使用 Core 返回的分类计数。文件删除和 Reset 均沿用此路径，订阅保持有效。

查询范围命中 ~Created~ 或 ~Updated~ 时，Core 将订阅标记失效，DataSetManager 合并受影响的数据集并提交一次 ~subscribeQuery~ 。该批每仓库共享一次扫描和加载。

完整结果按输入位置交给各 ~DataSet~ ，由其比较新旧快照、维护稳定行身份并向已注册 Monitor 发布 ~insert~ 、 ~remove~ 、 ~update~ 或混合 ~refresh~ 。相同内容不重复发布数据变化， ~ready~ 只表示读取完成。刷新期间的新文件事件保留到下一批；配置换代、过期回调和关闭按 generation／identity 边界清理。缓存保存等待刷新、提交与事件归并完成。

通知模块不注册文件监控，也不根据文件变化触发通知查询。它只接收 Core 已维护的通知列表。侧边栏、角标及完整阅读数据管理对象按自己的职责监听数据增量或文件事件，复用原有刷新合并与失败保留行为。
