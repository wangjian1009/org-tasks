#+TITLE: 冲突解决界面改进设计
#+LANGUAGE: zh-CN
#+OPTIONS: author:nil date:nil toc:2

* 背景

改进前，冲突解决页在冲突列表中切换项目后，正文会重新加载，但页面只显示整篇“当前文件／合并预览”切换。用户需要先选择取舍、选择目标并生成预览，才能看到变化卡片；目标不明确时甚至看不到可比较的内容。因此切换冲突不能立即回答“应用前会是什么、应用后会是什么”。

本方案已接入 ArkTS 与 Core，只读投影与构建验证已完成，实际设备交互仍待验收。设计稿维护于 [[file:../../design/Orgzly界面细节.fig][界面图谱]] 的“47 Harmony 冲突详情操作（当前实现）”画板，包含正文、详情卡、树形放置和底部左右切换状态。

* 设计目标

- 切换冲突点后立即显示该点的应用前、应用后差异，不要求先选择取舍。
- 保留完整文件上下文、变化定位和现有逐点应用语义。
- 让正文先展示，详情卡在正文下方；操作只放在展开详情卡内，避免底部重复操作。
- 在手机窄屏上使用纵向信息层级，颜色只辅助表达增删，文字同时说明状态。

* 页面结构

** 工具栏与文件上下文

工具栏继续使用冲突处理图标、文件 TITLE 和返回按钮。工具栏下方显示仓库名与相对路径。更多菜单继续提供“丢弃全部冲突”和“文档目录”。

** 冲突详情卡

正文先显示完整文件内容，详情卡通过共享阅读控件的尾部插槽放在正文之后，与正文一起滚动。卡片包含冲突标题、一句按原因生成的描述、应用前／应用后摘要和两个操作按钮；点击标题可收起或展开细节。

应用前表示当前主树中的内容，应用后表示 Core 根据当前候选计算出的临时结果。按钮默认显示“应用”和“丢弃”；~create~ 显示“插入”，~modify-missing~ 与 ~missing-parent~ 显示“放置”，~delete~ 显示“删除”。选择冲突或目标时自动读取只读预览；目标明确后，单次点击操作即可提交当前冲突。

** 正文预览区

正文只负责阅读、渲染差异和编辑定位，不提供“当前文件／应用后”切换，也不显示变化计数或“定位此冲突”按钮。目标未确定时正文保留当前上下文，等树形目标选择完成后再展示应用结果。

** 底部选择与放置

底部只保留左右切换按钮和当前位置，例如“‹　3 / 5　›”，不打开冲突列表。详情卡位于正文下方；未定位时，树形目标选择框位于详情卡下方和左右按钮上方。树形框按父子层级展示文件节点，不使用线性列表。已定位时正文滚动到目标附近，底部只显示紧凑的目标框，可更换位置。

目标不明确时显示“请先选择目标，再查看应用后结果”；树中点击父节点、子节点或插入点后只生成对应预览，不记录取舍。展开按钮仅改变树的可见层级；原始路径和重复标题的出现序号始终由 Core 提供，不通过标题文字重建身份。

* 交互流程

** 进入页面

进入页面后选中第一个冲突点，创建只读的冲突差异投影。页面先展示正文，详情卡位于正文下方；底部显示左右切换和当前位置，不打开冲突列表。

** 切换冲突点

用户点击底部左右按钮或在底部导航栏横向滑动后：

1. 保留当前滚动位置作为返回上下文。
2. 重新读取当前冲突的正文和详情卡摘要。
3. 清除上一个冲突点的临时取舍和目标选择；已经提交的结果不回退。

如果投影正在读取，正文和详情卡保留当前冲突标题并显示加载状态；读取失败时显示重试按钮和“丢弃”可用提示。

** 选择取舍与应用

用户从正文下方的详情卡点击“应用／插入／放置／删除”或“丢弃”，在同一操作中将取舍写入副本、结束预览并通过统一操作组提交。结构与顺序冲突显示“替换主树”，经确认后提交。应用成功后不自动跳到下一个冲突点，保留当前阅读位置并更新底部当前位置。最后一点应用成功后显示最终全文和“此文件的冲突已全部处理”。

** 离开、过期与失败

切换冲突或返回前仍按现有规则确认未应用的手动调整。原文件变化时保留正文、详情卡和阅读位置，禁用“应用／插入／放置／删除”，提示重新创建预览。应用失败保留详情卡和操作按钮，允许重试。

* 数据与实现边界

Core 继续负责冲突材料、候选解码、变化范围和版本校验。为支持本方案，预览接口通过 project 提供当前冲突点的只读差异投影，包含应用前／应用后片段、完整正文与 HTML、变化范围、定位锚点和候选状态；该投影不写入主树，也不产生操作记录。

Harmony 只负责正文、详情卡、树形目标框、左右切换和操作状态展示。Core 负责候选解码、目标校验、预览和版本约束；页面不解析 Org 或猜测目标。整篇阅读嵌入同一原生滚动容器，渲染标记使用 Core 的来源区间定位，原文使用同一快照的行号定位；读取回调校验快照代次。

在可用预览中点击正文节点进入既有任务编辑器，编辑只发生在副本中。返回后“应用”提交已记录取舍与手动修改；“丢弃”先确认放弃手动修改，再仅提交丢弃该冲突的操作。

* 验收要点

- 任意冲突点通过左右按钮切换后，正文下方详情卡在一次读取完成后出现应用前和应用后摘要。
- 未选择取舍时可以查看差异；查看、定位和切换不会改变副本版本、真实文件或通知。
- 详情卡和正文保持同一冲突上下文；切换不会覆盖新的预览内容。
- 目标不明确时在正文下方打开树形选择，不能因查看正文而自动插入或放置。
- 应用成功后剩余冲突数量、全文内容和通知与现有逐点流程一致。
- 原文件版本变化、读取失败和应用失败都保留现场，且不会误启用应用按钮。
