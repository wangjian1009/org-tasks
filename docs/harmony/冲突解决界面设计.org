* 文档与卡片

冲突解决页是一篇连续滚动的文档，全部待处理冲突同时以卡片嵌入正文。正文和卡片由同一个 Web 阅读视口绘制并在视口内滚动，组件高度由可用屏幕空间决定；不将组件撑到全文高度，保证长文档仍能正常绘制。底部定位、目录和位置恢复共用该视口的滚动坐标。工具栏保留返回、文件标题、丢弃全部和文档目录；路径显示真实仓库与文件。当前画板为 [[file:../../design/Orgzly界面细节.fig][界面图谱]] 的“47 Harmony 文档内冲突卡片（当前实现）”。

明确定位的修改、删除卡片占据对应主树节点的位置，不重复展示该节点；修改卡片先显示修改后的完整候选，不设计修改前后对比。删除卡片展示当前待删子树，帮助用户判断删除范围。新增卡片展示完整候选和子节点，正文格式复用 Core 的安全 HTML，不在界面解析 Org。

卡片以“新增”“修改”“删除”文字配合低饱和绿色、暖黄色、暗红色表达意图。操作按钮位于每张卡片内部，随卡片滚动；新增使用“插入”，删除使用“删除”，修改使用“应用”，各卡均有“丢弃”。长文字自然换行，不用摘要截断隐藏候选。

* 无法定位的卡片

Core 为新生成的冲突保存从近到远的祖先身份。无法定位原节点时，按这些身份在当前主树中寻找最近仍存在的父节点，将卡片放在该节点的正文之后、子标题之前。没有匹配父节点、空主树或旧材料没有祖先信息时放在文档根部；不按相似标题猜测节点。

展示锚点只决定阅读位置，不等同于应用目标。点击“插入”或无法自动定位的“应用／删除”后打开树形目标面板；选择节点或插入点只生成只读投影，不提前写入。关闭面板后回到文档，点击卡片操作提交当前取舍。结构与顺序候选继续要求确认替换完整主树。

* 底部辅助导航

底部只显示“‹　当前位置 / 总数　›”。点击左右按钮或在导航栏左右滑动，滚动到相应卡片并展开其父级；全部卡片和正文保持同一快照，不因定位而重建或替换正文，也不读取新的候选投影。正文始终可以自由上下滚动。

* 提交与保护

卡片操作复用既有独立 preview、统一操作组和真实文件版本保护。应用成功后重新读取主树和剩余冲突，保留阅读位置。最后一张卡片处理后保留最终全文和“完成”按钮。预览不改变其他页面、通知或同步状态；提交期间禁止重复操作。原文件变化时保留现场并要求重新读取，失败允许重试相同待提交操作组。

本轮优先完成新增、删除的展示与操作；修改只显示候选内容，后续另行设计前后差异。正文点击不再自动进入任务编辑器，避免阅读卡片时隐式记录取舍。
