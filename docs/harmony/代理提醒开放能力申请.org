* 开发阶段的验证路径

代理提醒能力审核与应用上架审核是不同流程。控制台实际验证：版本信息尚有介绍、截图等未填写项时，仍可保存中国大陆地区的版本草稿，能力申请页的地区校验随后通过；不需要为此点击“提交审核”。

当前还需在“应用上架 → 应用信息”选择符合真实用途的具体分类；任务管理应用建议为“效率”类。补齐分类并保存后，再准备办公类提醒的场景说明与截图，提交代理提醒能力申请。获批并开启能力后，更新调试 Profile 即可用于开发阶段真机验证，无需先发布正式版本。

本次浏览器控制权已由用户接管，停在分类信息补齐之前；未替用户填写主体证件、隐私声明或提交应用上架。

* 申请原因草稿

小清单是一款基于 Org-mode 的任务管理应用。用户为自己创建的待办任务主动设置唯一提醒时间，用于个人日程、工作事项和任务到期提醒。用户可以修改或清除提醒时间，也可以通过本机总开关关闭全部任务提醒。

申请代理提醒能力的目的是：当应用切至后台或进程退出后，由系统在用户指定时间继续交付任务提醒，避免遗漏用户主动设定的待办事项。提醒内容来自用户自己的任务标题，不用于广告、营销、运营推广或批量推送。

每个任务只登记一个日历提醒实例，按任务身份和提醒时间去重。任务改期、完成、取消、删除或清除提醒后，应用会撤销或更新对应实例；关闭本机提醒开关时撤销本应用管理的实例。遵守系统提醒容量，超出名额的任务按时间顺序等待，不通过重复登记扩大名额。

* 申请材料

- 场景截图：任务卡片的提醒时间入口、提醒日期时间选择，以及“有提醒的任务”列表。
- 应用分类截图：从开发者中心“应用上架 → 应用信息”取得该应用实际登记的分类，不以推测分类代填。
- 核对申请对象：包名必须为 ~com.example.orgtasks~ ，并确认该应用由当前账号管理。

* 激活顺序

1. 在开发者中心找到该应用的“基础信息 → 开放能力管理 → 开放能力申请 → 代理提醒”，核对状态。
2. 未申请时使用上述草稿及实际截图准备申请；审核中时等待平台结果。通用指南说明为 8 个工作日，本次控制台申请页显示 3 个工作日，以实际申请页为准。
3. 已通过时启用代理提醒能力并保存，重新生成匹配应用、证书和调试设备的 Profile。
4. 用新 Profile 替换本地签名材料，保持现有包名、证书和密钥配套，重新执行项目的手动签名构建及安装。
5. 在隔离任务上核对登记返回的系统 ID 和实际提醒清单，然后验证到点通知、应用退出后的交付，以及完成、取消和改期后的撤销。

能力申请、签名更新和实际投递验证是不同步骤，任何一步未完成都不将界面状态提前改为成功。
