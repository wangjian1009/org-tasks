* 范围与结论

核对依据为本地 Orgzly Revived 参考仓库的 ~app/src/main/res/xml/prefs*.xml~ 、仓库配置界面，以及 Harmony 设置入口、Preferences、Asset Store、WorkScheduler 和 core 调用。参考 XML 共 108 个叶项，其中包含按钮动作；分组和导航项不重复计数。存储库表单独立核对，不混入这 108 项。

108 个参考叶项的对应结果为：已支持 2、固定行为 26、部分支持 4、未支持 76。这里“已支持 2”只统计参考 XML 的对应选项，当前 Harmony 的 8 类配置还包括单独核对的仓库表单及本应用新增配置，二者不是同一统计口径。

当前 Harmony 提供 8 类用户可编辑配置，均有消费方；没有发现已显示且保存后完全不读取的用户配置字段。大量参考选项未移植；固定行为不能视为支持相应配置开关。下表“建议不纳入”是范围建议，确认前不代表永久取消；“未支持”仅陈述当前实现。

本报告属于手机应用范围核对，功能交付状态仍以 [[file:../手机应用功能清单.org][手机应用功能清单]] 为准。现有参考截图与设计文件保留原貌，以便后续对照。

* 当前支持并保留的配置

| 配置 | 当前字段 | 保存位置 | 消费方与限制 |
|-
| 本地 Org 目录 | ~repos[].rootDirectory~ | Preferences | core 扫描与 WebDAV 本地文件；只能使用应用可访问的绝对目录。没有系统目录授权选择器。 |
| WebDAV 启用 | ~repos[].webdavEnabled~ | Preferences | NativeCoreService 决定是否构造 WebDAV 策略；关闭后仍是本地仓库。 |
| WebDAV 地址 | ~repos[].webdavUrl~ | Preferences | WebDavSyncPolicy 使用；表单限定 HTTPS。 |
| WebDAV 用户名 | ~repos[].webdavUsername~ | Preferences | WebDavSyncPolicy 认证参数。 |
| WebDAV 密码 | ~repos[].webdavPassword~ | Asset Store；内存中临时装配 | WebDavSyncPolicy 认证参数；Preferences 仅有同名空字符串占位。 |
| 新增任务收集箱 | ~inboxFile~ | Preferences | AddTask 调用 core 在所选仓库内追加任务。它不等同于系统分享默认笔记本。 |
| 日历名称 | ~calendarName~ | Preferences | 手动与后台 CalendarSync 创建/选择本地日历；颜色、提醒和筛选不可配置。 |
| 后台同步间隔 | ~syncInterval~ | Preferences | BackgroundSyncService 注册/替换作业，至少 20 分钟；没有停用开关。 |

存储库配置 ID、已保存查询 ID/名称/表达式、最后同步时间和日历事件映射分别是身份、查询或运行状态，不额外计为用户配置项。

* 未完成能力与实现偏差

- 解析投影：现有笔记详情只读，正文为普通文本；日期投影只保留年月日；新建使用文件有效初始状态、尾部追加，A/B/C 为可选单次值。提醒、时间、重复器、富文本和默认值偏好不能据参考截图宣称支持。
- 子目录：本地扫描递归目录并排除根目录 ~.sync~ ；WebDAV ~PROPFIND~ 使用 ~Depth: 1~ ，没有递归遍历。两者不能合并称为“支持仓库子目录开关”。
- 日历：目前固定创建绿色日历，日历开启提醒；有截止日期时设置固定提醒值。没有提醒开关、提醒时间偏好、同步范围或日历停用开关，不等同于独立提醒服务。
- 身份： ~RepoConfig.id~ 目前由宿主生成，用于配置项和 Asset Store；core 仓库身份另从 ~.sync/id~ 取得。两者尚未统一，不能在文档中写成已实现的单一 repoId。修复需要单独评估凭据重绑定。
- 状态存储： ~lastSyncTime~ 和 ~calendar_sync_state~ 仍是 ~org_tasks_config~ 的键；设计要求的状态隔离尚未落地。它们不是未支持的配置，不应直接删除导致状态丢失。
- 配置持久化：保存全局配置会遍历并写入所有仓库凭据，本地仓库加载也读取 Asset Store；文档所述仅按远端需求读写及失败回滚尚未全部实现。

* 本次可直接清理的残留

- 文档中不存在的 ~version: 3~ 、 ~calendar.name~ 、 ~scheduler.intervalMinutes~ 配置模型改为实际 ~AppConfig~ 字段，避免把规划结构列为已支持。
- 移除无调用方的旧 ArkTS ~OrgParser~ 和 ~OrgParseResult~ ，清除其固定 TODO 列表、旧文本生成与正则解析；运行路径继续使用 core。
- 修正功能清单中“OrgParser 负责解析”“已提取进度”等失实表述；当前 bridge 的结构化进度固定为 -1，原文仍完整保留。

* 参考配置逐项核对

状态定义：已支持表示存在对应设置及消费方；固定行为表示功能有默认实现但没有此配置项；部分支持表示仅覆盖部分流程；未支持表示没有配置或主流程。所有“待定”项均没有添加空入口。
