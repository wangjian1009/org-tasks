* 定位与对象职责

Rust bridge 位于 ~harmony~ Cargo crate，与 ~http~ 同为 core 的宿主模块。TS 按 ~Workspace -> Repo -> OrgFile~ 访问领域对象；WebDAV 操作由 ~WebDavSyncPolicy~ 提供。ArkTS 不解析 Org、不推导任务状态，也不实现同步决策。

#+begin_example
ArkTS CoreWorkspace / CoreRepo / OrgFile / CoreWebDavSyncPolicy
  -> C++ N-API Workspace / Repo / OrgFile / WebDavSyncPolicy
  -> harmony C ABI 与工作线程
  -> core OrgWorkspace / OrgRepo / OrgFile / WebDavSyncPolicy
#+end_example

拥有行为和资源的对象使用 class，Rust 的结构体数据投影使用 interface；Rust 字段在 TS 中保留为属性，行为保留为方法，使用 camelCase 命名。涉及 core 锁、文件或网络 I/O 的操作返回 Promise；文件对象中的只读值可同步访问。JSON 只在 bridge 内部编组，不作为 TS 调用参数或公开的仓库/文件快照接口。

* 接口设计规范

本节是 Harmony TS 领域接口的固定约定。新增或修改接口时，必须同时检查 Rust 类型定义、N-API 声明、ArkTS wrapper、调用方及本文对照表，不能只调整 TS 类型声明。

1. 对象层级必须与 Rust 的领域边界一致，以 ~Workspace -> Repo -> OrgFile~ 导航；文件行为通过文件对象调用，例如 ~file.category()~ ，不得退回 ~repo.category(path)~ 这种由上层对象代理文件行为的接口。
2. Rust 公开字段映射为 TS 数据属性，读取身份和元信息时不使用无行为的 getter 方法，例如 ~repo.id~ 、 ~repo.rootDirectory~ 、 ~file.path~ 和 ~file.todo~ 。Rust 方法映射为 camelCase 方法，例如 ~source_bytes() -> sourceBytes()~ 。在 native class 上，身份和来源字段必须提供只读属性。
3. 拥有行为或生命周期的领域类型使用 class；纯数据结构、调用参数、事件和结果使用 interface 或判别联合；任务需要完成判断行为时使用 Task class。不能为了统一外观把所有数据结构改为 class，也不能把领域对象退化为需要调用方解释的普通 JSON 快照。
4. 方法必须归属于 Rust 中实际承担行为的对象；日志备份读取归属 ~OrgRepo.historyFile~ ，冲突选择与其他任务修改统一归属 ~Workspace.executeTaskOperations~ ，不依赖 WebDAV 策略。
5. 结构化 Rust 参数必须通过 TS 对象传入。禁止公开 ~optionsJson~ 、 ~requestJson~ 或要求调用方 ~JSON.stringify~ 的参数；序列化与反序列化只发生在 bridge 内部。查询表达式和 Org 设置文本是领域输入，不属于 JSON 编组参数。
6. 访问 core、仓库锁、文件或网络的操作必须在 worker 中执行，并返回 Promise。已经返回的独立文件对象可同步读取属性、分类和原始字节；同步 getter 不得隐式重新加载仓库或发起网络请求。
7. Rust 的 ~Option<T>~ 结果映射为 ~T | null~ ，不能用虚构默认值替代缺失值；显式空字符串与 ~null~ 必须区分。Rust 的 ~Result~ 失败通过 Promise 拒绝或同步接口异常表达，不能转换为空对象、空列表或成功结果。
8. ~OrgFile~ 是取得时刻的独立值对象。源字节使用 ~Uint8Array~ ，每次返回副本；调用方修改返回数组不得改写内部数据。仓库刷新不改变已返回文件对象，读取新状态必须重新获取对象。
9. 默认参数与领域校验由 Rust 提供。ArkTS 只保存外部配置、收集输入和显示结果，不另建解析器、状态分类、任务匹配或同步规则。
10. 历史归 ~OrgRepo~ 内部管理，不作为 TS 同步入参，也不作为 ~SyncPolicy.synchronize~ 的显式入参。对象设计不能扩大同步记录的持久化范围。

跨语言必需的适配必须在本文列明，包括 Promise、命名转换、查询/设置文本解析和面向手机的结果投影；适配不能成为随意改变行为归属的理由。修改既有接口时必须迁移全部调用方，并验证对象方法、空值、错误传播、字节保真和异步生命周期。

* Rust 与 TS 对照

| Rust | TS | 语义与适配边界 |
|-
| ~OrgWorkspace~ | ~Workspace~ | workspace 管理仓库集合；仓库通过 workspace 取得。 |
| ~OrgWorkspace.repos()~ | ~await workspace.repos()~ | 返回仓库对象，不返回仓库 DTO。 |
| ~CoreQuery::Notification~ | ~workspace.query([{ type: 'notification', query: {} }])~ | 返回 Core 判定的通知结果分支，复用同次文件与基线读取。 |
| ~OrgRepo.id~ 、 ~root_directory~ | ~repo.id~ 、 ~repo.rootDirectory~ | 只读属性；core 的 ID 来自本地 ~.sync/id~ 。 |
| ~OrgRepo.load_files(ignore_files)~ | ~await repo.loadFiles(ignoreFiles)~ | 相对排除路径原样透传；按次读盘返回独立对象数组，仓库不持有文件集合。 |
| ~OrgRepo.file(path)~ | ~await repo.file(path)~ | 返回已有文件的副本；路径尚不存在时返回未落盘空文件。 |
| ~OrgFile.repo_id~ 、 ~path~ 、 ~todo~ | ~file.repoId~ 、 ~file.path~ 、 ~file.todo~ | 属性承载数据，TODO 完成类型由 Rust 计算。 |
| ~CoreQuery::File~ | ~workspace.query([{ type: 'file', query: {} }])~ | 返回文件结果分支，可与任务、通知混合；不复制正文或生成文件对象。 |
| ~OrgFile.title()~ | ~file.title()~ | 文件头 TITLE，多行按空格合并；未配置为 ~null~ ，显式空声明为空字符串。 |
| ~OrgFile.title_parts()~ | ~file.titleParts()~ | Core 解析文件标题中的文字与外部链接，返回有序 ~TitlePart[]~ 。 |
| ~FilterTask.title_parts()~ | ~task.headingParts~ | bridge 在构造任务对象时投影，C++ 保留可枚举只读属性，路由传递不丢失链接。 |
| ~OrgFile.category()~ | ~file.category()~ | 未配置或文件分类为 ~ARCHIVE~ 时为 ~null~ ，显式空声明为空字符串。 |
| ~FilterTask.category()~ 、 ~is_repeating()~ | ~task.category~ 、 ~task.isRepeating~ | 只读、可枚举的查询快照；分类保留 ~null~ 与空字符串，重复标志来自 Core 的时间戳解析。 |
| ~FilterTask.created_at()~ 、 ~modified_at()~ | ~task.createdAt~ 、 ~task.modifiedAt~ | 只读、可枚举的可空时间快照；创建时间来自标题自身的 ~CREATED~ 属性，修改时间仅来自当前标题自身的 ~LAST_MODIFIED~ 属性；缺失或无效为 ~null~ ，不读取文件 mtime。 |
| ~OrgFile.source_bytes()~ | ~file.sourceBytes()~ | 返回原始 UTF-8 字节的独立 ~Uint8Array~ 副本。 |
| ~SyncOptions~ | ~SyncOptions~ | 结构化参数；默认值与校验来自 Rust。 |
| ~OrgWorkspace.query(&[CoreQuery])~ | ~workspace.query(queries)~ | 结构化请求数组在一次 worker 调用中透传 Core，按输入顺序返回任务及分类统计数组。 |
| ~OrgWorkspace.set_todo_defaults(TodoConfig)~ | ~workspace.setTodoDefaults(settings)~ | 宿主编辑 Org 设置文本，Rust 构造 ~TodoConfig~ 。 |
| ~OrgRepo.load()~ | ~repo.load()~ | 仅恢复稳定 ID；Core 原泛型返回类型保留为空集合，TS 只等待完成。 |
| ~OrgRepo.load::<WebDavSyncPolicy>()~ 与 ~sync_history_summaries~ | ~await repo.history()~ | Core 从仓库 ~.sync/history~ 恢复已完成记录并生成执行结果、传输方向与冲突处理摘要；bridge 只编组字段，ArkTS 不读取控制目录。 |
| ~sync_history_detail(history, sync_id)~ | ~await repo.historyDetail(syncId)~ | 按当前仓库的同步记录 ID 返回摘要、文件结果与已有错误消息；Core 计算冲突解决状态，不返回源内容快照。 |
| ~FilterTask.support_tags()~ | ~task.supportTags~ | 可空只读配置，结构为 ~{ tags: string[], groups: string[][] }~ ；缺少配置映射为 ~null~ ，显式空配置保留空数组，互斥组不展平。 |
| ~FilterTask.is_done()~ | ~task.isDone()~ | Rust 根据文件有效配置计算完成结果，native Task 方法原样返回。 |
| ~OrgRepoSyncRecord~ 、 ~FilterTask~ | ~SyncRecord~ 、 ~Task~ | 同步记录为数据投影；任务为含只读字段和行为的对象，不是 Rust 结构体的全部字段。 |

这些适配差异不改变所属对象或领域规则；跨语言类型与同步/异步边界不要求逐字符一致。

同步记录保留原有 ~result~ 、 ~conflicts~ 、时间与文件数，另增 ~executionResult~ 、 ~transfer~ 、 ~downloadedFiles~ 、 ~uploadedFiles~  、 ~errorCategory~ 与 ~errorMessage~ 。 ~result~ 继续承载原始作业结果，避免改变现有同步编排；日志行按 ~executionResult~ 展示结果图标，只有冲突而无执行错误时为 ~succeeded~ 。 ~transfer~ 为 ~unchanged~ 、 ~download~ 、 ~upload~ 或 ~bidirectional~ ，只统计 Core 已确认成功的文件动作。冲突路径仅反映当次固定结果，UI 显示固定冲突数，不再提供待处理／已解决计数。

~errorCategory~ 与 ~errorMessage~ 分别为既有文件记录的错误分类和消息，缺失时为 ~null~ 。ArkTS 优先显示已有错误消息，缺失时使用结果或分类生成标题；列举失败的空记录保留 ~failed~ ，没有已记录原因时显示“执行失败”。不扩展原始历史格式或补造旧错误。取消与中断保留原结果及独立的辅助色图标。实时 ~repo.sync()~ 复用相同摘要字段；冲突字段在完成时固定，不随后续文件操作变化。C++ 在工作线程请求后完整透传摘要， ~NativeCoreService~ 不重复判断传输或冲突状态。

* 文件对象与生命周期

Rust C ABI 返回的字符串由 Rust 分配，C++ 通过 ~TakeRustString~ 复制后交给 ~org_tasks_harmony_free_string~ 释放。释放接口在 Rust 声明为 ~unsafe extern "C"~ ：非空参数必须是本 bridge 返回、尚未释放的原始指针，不得改变字符串长度，释放后不得访问或再次释放；空指针无操作。错误字符串使用同一所有权约定。Rust 调用方在 ~unsafe~ 块中保证这些条件；C++ 保持原有 C ABI，ArkTS 接口不暴露字符串指针。

同步的网络阶段使用从当前仓库配置和身份取得的独立执行对象，不持有整个 workspace mutex；本轮同步锁和分阶段仓库锁由 Core 内部管理。成功后 bridge 仅短暂交回稳定身份，不用旧执行对象覆盖并发请求的快照；文件列表请求重新通过 Core 读盘；新增 ~loadFiles(ignoreFiles)~ 及其 C ABI、N-API 接入，替换原文件集合访问；其他请求与结果字段保持原约定。该变化允许同进程页面请求在下载和上传期间进入 Core，具体协议与缓存迁移边界见 [[file:../core/仓库访问与跨进程同步设计.org][仓库访问与跨进程同步设计]]。

~Workspace~ 与 ~Repo~ 持有同一个 opaque workspace handle 的引用；最后一个引用释放后，Harmony session 释放 core workspace。 ~Repo~ 从 workspace 取得，不能直接构造。

~repo.load()~ 仅恢复 ID。 ~repo.loadFiles(ignoreFiles)~ 等待 Core 加载本次文件集合，参数仅为仓库相对路径； ~repo.file(path)~ 按路径从磁盘读取。路径不存在时，Core 构造未落盘的空文件供新增读取默认元信息，不创建文件或 outbox；非法路径和 I/O 失败使 Promise 拒绝。

~OrgFile~ 是取得时刻的独立文件值对象，保存 Rust 投影的元信息和源字节。 ~category()~ 只返回 Rust 的 ~OrgFile.category()~ 结果，不在 C++ 或 ArkTS 解析头部； ~sourceBytes()~ 每次返回独立副本，修改该数组不会改写文件对象或仓库文件。仓库重新加载、修改全局设置或移除仓库后，已取得对象仍保留原值；需要新值时重新获取文件对象。

文件对象不再持有 workspace 锁或 handle。C++ finalizer 释放其数据引用；异步仓库请求保留 ~Repo~ 强引用，策略比较与 apply 同时保留策略和仓库引用，防止执行期间被 GC 回收。对象创建失败必须拒绝 Promise，不能留下未完成请求。

* 创建、同步与合并

~Workspace.executeTaskOperations~ 接受 Core 定义的结构化 ~TaskOperationGroup~ ，由 C++ 在工作线程调用 Rust。操作按顺序在 Core 内存快照中执行，统一提交；Promise 成功只返回 ~void~ ，失败时以 Promise rejection 传播 Core 错误。仓库数据变化由独立 ~watchDataChanges~ 订阅转发，C++ 和 ArkTS 不生成反向操作、不重建 Org 内容。

收件箱合并调用 ~Workspace.taskMergeOperations({ paths, fileVersion })~ ，paths 保持用户选择顺序。C++ 在工作线程调用 Rust ABI ~org_tasks_harmony_workspace_task_merge_operations~ ，返回 Core 生成的 ~TaskMergePlan { operationGroup, mainPath }~ 。该操作组只含现有的 Deletion 与 Modification，不新增操作种类，也不创建编辑会话或预览界面。

~InboxService~ 先验证当前收件箱配置，加载对应仓库取得稳定 Core 身份，再请求操作组；仅补充 ~queueRepoIds~ ，随后通过原 ~Workspace.executeTaskOperations~ 一组提交。页面直接显示选择顺序与目标标题，点击合并后完成规划和提交；期间冻结选择并防止重复执行。版本变化保留选择并要求刷新，提交成功后刷新失败只重读。结果在同一收件箱列表中高亮并展示 Core 提供的正文列表，不新增路由、弹窗或确认界面。ArkTS 不解析或拼接 Org 内容。

创建通过 Creation 提交插入位置、标题、正文和状态，捕捉功能从文件元信息取得初始状态，由 Core 自动补齐 CREATED。任务与备忘修改通过 Modification 的 TITLE、BODY 字段执行，删除通过 Deletion；备忘新增通过 Creation 创建无状态标题和正文。NoteService 只编排配置、Core 仓库身份与文件版本，不解析 Org；旧正文快照参数改为可选的文件版本约束。地址更新通过 ADDRESS_LINK 字段指定新旧 URI。CREATED 与 CLOSED 不接受显式字段修改，创建参数不包含 recordCreated 或 closed；Core 新建时自动记录创建时间，TODO 修改按含 SETUPFILE 的文件有效状态自动写入或清理关闭时间。收件箱整理以字段清理和 Movement 组合为一个操作组。

旧 Repo.createTask、Repo.updateTaskLocation、Repo.updateTask、Repo.deleteTask 与 Workspace.editTask 均已删除，native 导出、类型声明和宿主 wrapper 不保留兼容入口。

~Repo.sync~ 接收策略和 ~SyncOptions~ 对象。C++ 在工作线程临时构造 core policy，并调用 ~OrgRepo.sync_with_options~ 。历史由仓库内部恢复，不传给 TS 或 ~SyncPolicy.synchronize~ 。省略参数使用 Rust 默认值，显式空列表关闭目录过滤； ~monitor~ 可为 ~undefined~ ，后台调用仍能传入 options。事件通过 N-API thread-safe function 回到 ArkTS，包含相对路径、处理结果与 HTTP 状态，不包含凭据或正文。

~defaultSyncOptions~ 读取 Rust 默认配置； ~normalizeSyncOptions~ 接受数据对象，由 Rust 验证并返回规范化对象。Preferences 只保存外部配置，core 不读取宿主配置存储。

冲突选择使用 ~Workspace.executeTaskOperations~ 的 ~ConfilictSelection~ 变体，path 明确定位真实文件或当前 preview，动作包含 discard 与 useLocal。临时文件由 ConflictPreview 管理，其 finish 返回源路径操作组；真实提交继续通过同一个 Workspace.executeTaskOperations 完成。


* 默认 TODO、查询与结果投影

~defaultTodoSettings~ 从 Rust 默认配置生成原生 Org 声明文本。 ~Workspace.setTodoDefaults~ 由 core 解析、验证并用于后续每次文件解析；文件内声明和仓库内 ~SETUPFILE~ 按 core 的现有规则处理。TS 从 ~OrgFile.todo~ 读取流程、待办/完成状态、快捷键和日志标记；任务 ~todoKind~ 来自 Rust 有效配置后的分类，不能以 DONE/CNCL 字面值猜测。

~Workspace.query~ 将结构化请求交给 ~OrgWorkspace.query~ ，由 Core 内部解析表达式并求值。返回结果中的 ~tasks~ 为原生 ~Task~ 对象，用于列表、日历和详情； ~Task.id~ 保留通用展示身份， ~Task.taskId~ 透传 Core 的可空任务专属身份 ，为仓库路径、文件相对路径及归一化任务标题链的明文 JSON 编码；算法见 [[file:../core/数据模型.org::*任务逻辑身份][任务逻辑身份]]。~repoId~ 与 ~filePath~ 继续标识来源文件， ~level~ 保留真实标题层级，源字节偏移只在 Core 当前快照内定位。ArkTS 服务可以组合这些对象用于显示，但不另建 AST 或过滤算法。

* 错误与扩展

异步 core 操作失败时 Promise 拒绝 ~CoreError~ ，其 ~code~ 为 ~invalidInput~ 、 ~invalidState~ 、 ~store~ 或 ~bridge~ ，中文 ~message~ 保留 core 错误说明。 ~WebDavSyncPolicy.testConnection~ 不依赖仓库，在 worker 中执行独立目录访问检查；返回成功不保证写权限。

新增能力先在 core 定义数据和行为，再由 Harmony 编组为相应对象方法或数据属性。C++ 只处理参数、worker、Promise、对象投影和资源释放；同步记录与 outbox 不写入绝对路径、密码、完整远端 URL 或文件正文。文件对象中供界面读取的原文只存在于内存。

* 任务完成对象

~Workspace.query~ 在 Task 结果分支的 ~result.tasks~ 中返回原生 ~Task~ 对象。 ~Task.isDone(): boolean~ 对应 ~FilterTask.is_done()~ ，结果由 Rust 根据文件有效配置计算；C++ 只保存并返回布尔值，ArkTS 不另行检查 DONE/CNCL 名称。任务的标题、状态和来源保留为只读、可枚举字段，路由仍能传递到详情页；序列化的数据不包含方法。已取得任务的完成状态不随仓库重载而改变，需要最新状态时重新查询。逻辑 ~id~ 相同不表示内容相同；ArkUI 列表用可枚举任务快照生成渲染键，使状态、进度、正文和路由参数同步更新。C++ 不计算任务身份，ArkTS 不按标题或位置重建任务身份。

* 通用查询与 UI 职责边界（固定设计原则）

~Workspace.search~ 及其 FFI、N-API 和 ArkTS 封装已删除，不保留兼容入口。任务列表、后台日历与任务操作后的快照统一调用 ~Workspace.query~ 。 ~NativeCoreService.loadWorkspace~ 和 ~syncWorkspaceWebDav~ 返回 ~CoreTask[]~ ，不再返回包含 workspace 与同步摘要的聚合响应类型。

* 文件只读阅读投影

Rust 的 OrgFile.render_html() 对应 TS 的 file.renderHtml()。repo.file(path) 与 repo.loadFiles(ignoreFiles) 在现有 N-API worker 内生成 renderedHtml 字符串，并与文件值对象快照一起返回；C++ 方法仅读取该快照，ArkTS 不解析 Org。已有对象的 HTML 与其源字节、TODO 配置一致，不随仓库后续刷新变化。轻量文件列表不生成或传递 HTML。

文件详情通过 NotebookService.open 按仓库 ID 和相对路径取得目标文件；先校验文件清单，避免将 Core 为缺失路径提供的新增草稿误显示为空白文件。不再读取整个工作区的任务投影或在 UI 按文件过滤任务。Web 只加载内存文档，关闭网络、本地文件、数据库与 DOM storage 访问；CSP 禁止文内脚本及外部资源，固定的宿主 JavaScript 仅修改标题 details 的 open 状态，不注册写入接口。

* 任务正文与 LOGBOOK 展示

Core 的 FilterTask.render_content() 返回 RenderedTaskContent。Harmony 在现有查询 worker 内调用它，将 body_html、logbook_html、has_list 与 has_text 分别映射为 Task.bodyHtml、Task.logbookHtml、Task.hasList 与 Task.hasText；N-API 以只读、可枚举属性保留这些字段，保证路由传递任务后仍可展示。原始 Task.body 保留完整正文，搜索、日历和其他调用方的原有语义不变。

TaskEditor 直接显示 Core 的两段 HTML，不在 ArkTS 解析或删除 LOGBOOK。正文和日志共用 OrgContentView，初始空白页加载结束后以 URL 编码加载内存 HTML；嵌入任务编辑内容时由 DOM 尺寸确定组件高度，折叠 drawer 后更新高度。文件详情则占满内容区域，并按 Preferences 的展示方式显示渲染或原文；文件展示模式不改变任务正文的渲染方式。

文件快照的 ~titleParts~ 由 Core 的 ~OrgFile.title_parts()~ 生成，native 文件对象通过 ~titleParts()~ 同步读取；文件列表元信息增加只读 ~titleParts~ 数组。任务快照的 ~headingParts~ 由 ~FilterTask.title_parts()~ 生成，与原始 ~heading~ 同时保留，C++ 为 native Task 定义可枚举只读属性，供列表、规划与编辑页跨路由使用。 ~NativeCoreService~ 导出对应 ~CoreTitlePart~ 类型，宿主只组合显示片段和调用系统打开链接，不解析 Org。

~ExternalLinkService~ 统一处理点击后的平台接入，网页地址使用 ~UIAbilityContext.openLink~ ，邮件地址使用系统隐式 Want；坐标和文字地址查询已安装的高德地图与花瓣地图，并由宿主自定义底部选择器展示两项，未安装项保留显示但禁用点击。花瓣地图文字搜索使用 Map Kit；高德坐标使用官方 ~amapuri://route/plan~ 参数，高德文字搜索使用官方 ~https://uri.amap.com/search?keyword=...~ URI API（当前 HarmonyOS 文档未提供高德 App 的文字搜索 ~amapuri~ 入口）。选择已安装应用后以显式 ~viewData~ Want 启动它。 ~addr:~ 文字地址先转换为 ~geo:0,0?q=...~ 查询 URI； ~geo:0,0~ 缺少 ~q~ 时直接提示链接无效。坐标地址遵循 Org 外部链接形式，例如 ~[[geo:39.9042,116.4074][北京市]]~ ，文字地址例如 ~[[addr:北京市朝阳区][北京市朝阳区]]~ 。 ~OrgContentView~ 拦截用户触发的主框架链接导航，交给同一 service 后阻止 Web 页面跳转；阅读页仍禁用网络资源、文件访问和文内脚本。打开失败只展示提示，保留文档与滚动位置。

~TitlePart.is_link~ 映射为 ~isLink~ ；该标记保留链接与普通文字的语义区别， ~href=null~ 的链接仍可显示为辅助文字色虚线下划线。普通文字没有下划线，只有非空 ~href~ 才绑定系统打开操作。

~TitlePart.count~ 与嵌套的 ~completed~ 、 ~total~ 由 Core 生成，经 Rust 序列化与 C++ JSON 编组原样透传，适用于文件元信息、文件标题与任务标题，不添加同步请求或原文解析。 ~NativeCoreService~ 导出 ~CoreTitleCount~ ，计数随标题片段进入任务快照渲染键。 ~TitleCountBadge~ 使用 ArkUI 的 ~ProgressType.Ring~ 在运行时按有效比例绘制； ~TitleCounts~ 管理多个计数的换行与窄屏图标回退。 ~TitleText~ 只组合普通文字、链接与计数标记；今天收起行单独为计数和日期保留宽度，展开与任务编辑共用同款标记，不重复“已完成”说明。文件阅读使用 Core 的安全标题 HTML 与宿主样式绘制同款圆环。
* 快速捕捉复用

快速捕捉复用 ~Workspace.executeTaskOperations~ 的 ~Creation~ ，提交 ~title~ ，以文件根节点作为 ~position.parent~ 让新标题出现在收件箱顶部，不新增独立捕捉领域 API。保存时由 Harmony 的 ~CaptureEntityService~ 调用华为 Natural Language Kit 识别地址和时间；完整输入保留为 ~title~ ，地址链接通过已有 ~body~ 字段传递，归一化时间转换为完整 Org 时间戳后通过已有 ~scheduled~ 字段传递。识别失败时正文为空、计划时间为空，不改动 bridge 类型或复制 Core 的写入校验、Org 解析与同步规则。Core 在实际保存时按设备本地时间写入 ~:CREATED: [YYYY-MM-DD Ddd HH:MM]~ ，草稿阶段不生成时间，后续读取与同步不更新时间。应用内“+”和外部文字、语音及意图入口共用 ~CaptureService.save~ 。所有外部入口先进入同一前台捕捉窗口；分享扩展只传递标题，不另建仓库写入会话。 ~NativeCoreService.workspaceFor~ 串行取得或初始化共享 session，避免两个窗口冷启动时为同一配置同时创建不同 workspace；后续编辑与同步继续使用该 workspace 的 native 锁。

捕捉窗口首屏不静态导入 native service。草稿读取由轻量 ~CaptureDraftStore~ 负责； ~CaptureSaveSession~ 在首屏显示后异步导入宿主捕捉服务、取得共享 workspace。页面输入不等待初始化，保存请求等待同一初始化 Promise，再沿用 ~Workspace.executeTaskOperations~ 完成提交；初始化失败会在保存时返回，下一次保存可重新初始化。

** 任务列表项展示提示

查询 worker 将 ~FilterTask.is_repeating()~ 、 ~RenderedTaskContent.has_list~ 与 ~RenderedTaskContent.has_text~ 投影为 ~Task.isRepeating~ 、 ~Task.hasList~ 与 ~Task.hasText~ 。C++ N-API 将三者定义为只读且可枚举的属性，随完整任务快照参与渲染键与路由传递； ~CoreTask~ 原样导出 native 类型。重复器由 Core 按 Org-mode 的 ~+Nunit~ 、 ~++Nunit~ 、 ~.+Nunit~ 及可选 ~/N~ 或 ~/Nunit~ 规则解析，ArkTS 只根据布尔值选择循环图标和正文／列表提示；正文规划行同样由 Core 在 ~bodyHtml~ 投影阶段排除，宿主不扫描 Org 或 HTML 推断领域结构。

~TaskListItem~ 复用 ~OrgContentView~ 展示正文；阅读控件允许调用方提供背景色和嵌入左右内边距，仍使用同一安全 HTML 页面与链接拦截。展开／收起及内容测高属于 UI 状态，不发起 Core 请求、不写回文件。


* 独立分享捕捉

候选任务由 UI 将仓库配置与备忘文件身份组装为通用查询：所有已配置仓库中的 ~it.todo~ ，加上配置备忘文件中的 ~it.none~ ，再与 ~has.address~ 组合并设置 ~includeDone=false~ 。未配置或失效的备忘文件不回退到其他文件。Core 返回的 ~address_links~ 原样映射到 ~Task.addressLinks~ ，宿主显示全部候选，不按条数截断、不解析正文。查询继续通过既有 ~expression~ 字段传入 worker，不新增 native 方法或界面专属查询字段。

地点与配置加载完成后自动发起候选查询，不等待用户展开，也不阻塞创建入口。页面按请求序号接收完整候选和对应仓库映射，旧请求不得覆盖新分享的结果；返回非空结果后才显示“更新地址”分区，查询中或空结果不显示分区及提交按钮。标题复用共享分区控件，候选卡片和地址选择仍只负责展示 Core 的结果。

点击创建立即向已配置收件箱调用 Creation 操作组 ，写入成功后以 ~page=inbox~ 启动或唤起 ~EntryAbility~ ，直接加载收件箱并关闭分享窗口；不查询新任务快照、不展示结果卡片或确认。导航失败保留写入成功状态，重试只打开收件箱，不重复创建。

~Task.addressLinks~ 在 C++ 原生任务对象上以只读、可枚举属性保留。地址更新提交一个 Modification， ~path~ 使用 ~Task.fullPath~ ，字段为 ADDRESS_LINK。Core 返回操作后路径；ArkTS 从新投影中取得该路径对应任务，包含最新地址、正文 HTML 与完成行为。FFI 返回既有释放函数管理的 JSON 字符串，C++ 只编组与构造对象。


更新成功后将该快照序列化为 Want 的 ~task~ 字符串参数，以 ~page=taskEdit~ 唤起 ~EntryAbility~ ，主窗口加载收件箱并通过该窗口的 ~LocalStorage~ 交接快照。收件箱在 ~onPageShow~ 中一次性领取并清除参数，等根页面就绪后通过原有路由打开 ~pages/TaskEdit~ ，随后关闭分享窗口；不在窗口内容加载回调中连续推入路由，避免页面初始化覆盖跳转。窗口之间不依赖各自 ArkUI 上下文中的 ~AppStorage~ 传递任务。任务编辑页继续只读取原有路由参数，其布局、元数据、正文和返回行为均不修改；返回进入收件箱。导航失败时保留已更新快照供重试，不再次替换链接。

~CaptureShareExtension~ 读取系统分享的标题和链接后启动独立 ~ShareLocationAbility~，不再启动 ~CaptureAbility~ 。页面解析花瓣地图坐标 URL、高德短链接和 ~geo:/addr:~ URI；创建任务调用 ~Workspace.executeTaskOperations~ 写入正文链接，更新任务调用 ~Workspace.executeTaskOperations~ 保留其他字节。解析失败只允许保存原始链接或返回地图。

* 收件箱目标与任务整理

~Workspace.refileTargets(query?: RefileTargetQuery): Promise<RefileTarget[]>~ 继续返回 REFILE 目标，增加由 Core 生成的 ~fullPath~ ，保留 category 与 fileVersion。每个 Task 增加 ~taskId: string | null~ 、 ~fullPath: TaskPath~ 和 ~fileVersion~ ；仓库和文件也提供完整路径。新的 ~Workspace.executeTaskOperations(group)~ 是唯一任务写入入口。

~InboxService~ 将启用 WebDAV 的配置根目录匹配为 Core 仓库 ID。普通移动提交 Movement，目标 parent 使用放置目标 fullPath；备忘先以 Modification 清除 TODO、优先级、SCHEDULE、DEADLINE，由 Core 随状态自动清理 CLOSED，再以 Movement 移入配置的备忘文件；删除提交 Deletion。源、目标可携带文件版本，将来，也许先以 Modification 设置 TODO 并清除 SCHEDULE、DEADLINE，由 Core 随状态自动清理 CLOSED，再以 Movement 移到所配置某天文件中的首个 REFILE 标题。源与所选放置目标携带文件版本；失败保留当前浮层与用户选择。

* Query 文件引用与创建日期扩展

~TaskQuery.excludedFiles~ 统一改为 ~OrgFileRef[]~ ，元素使用 Core 仓库 ID 与文件相对路径；旧字符串数组输入拒绝，不保留平行的路径排除接口。 创建日期条件继续使用 ~expression~ ，最近三天请求为 ~cr.ge.-2d cr.le.today .o.created~ ，按今天及前两天三个本地自然日匹配。ArkTS wrapper 原样透传，C++ 通过既有 JSON 编组进入 Rust ~TaskQuery~ ，不实施过滤。查询得到的 ~Task.createdAt: number | null~ 、 ~Task.modifiedAt: number | null~ 和 ~Task.isCancelled: boolean~ 为只读可枚举属性，分别由 Core 的 ~FilterTask.created_at()~ 、 ~FilterTask.modified_at()~ 和 ~FilterTask.is_cancelled()~ 投影；时间值缺失时保留 ~null~ 。取消标记由 Core 根据实际识别的 ~CNCL~ 状态投影；它不改变文件 TODO 定义或 ~isDone()~ 结果。

~InboxService.recent~ 通过既有 ~Workspace.query~ 发送 ~cr.ge.-2d cr.le.today .o.created~ ，同时设置 ~includeDone=true~ 和 ~includeComposeTasks=true~ ，使用 ~excludedFiles: OrgFileRef[]~ 精确排除当前收件箱。 ~InboxPresentation~ 仅按 ~Task.createdAt~ 的本地日期组织连续列表，不追加创建日期、状态或文件过滤。分享地址候选的原有查询也继续使用同一 ~Workspace.query~ 入口，其搜索与截断问题的后续建议见查询语言设计。

* 同步详情投影

~Repo.historyDetail(syncId)~ 在工作线程重新加载所选仓库的历史，返回 ~SyncRecordDetail~ 的 ~summary~ 、 ~files~ 和 ~errors~ 。 ~files~ 每项包含 ~path~ 、 ~outcome~ 、Core 提供的 ~section~ 与可空备份元信息 ~backup~ ；结果枚举为 ~unchanged~ 、 ~downloaded~ 、 ~uploaded~ 、 ~created~ 、 ~deleted~ 、 ~updated~ 、 ~merged~ 、 ~conflict~ 、  ~failed~ 或 ~skipped~ 。 ~errors~ 中每项只含关联的相对 ~path~ 与原记录已有的 ~message~ 。JSON 编组仍位于 bridge 内部，C++ 通过原有 async work 生命周期完整透传， ~CoreRepo.historyDetail~ 不解释文件状态。

日志列表展开项传配置仓库 ID 与同步 ID， ~SyncLogDetails~ 重新取得当前投影；不存在的仓库或历史应明确失败，不能退回其他记录。摘要不包含源内容快照，正常、冲突和失败记录均使用同一个同步详情接口。

* 配置文件范围与将来，也许快捷移动

~RefileTargetQuery~ 含 ~files?: OrgFileRef[]~ 与 ~excludedFiles?: OrgFileRef[]~ ，经 C++ 原有工作线程和 Rust bridge 透传 Core。普通目标请求在生成 CATEGORY 前排除已配置的收件箱与某天两个具体文件；将来，也许入口单独通过 ~files~ 查询某天文件，使用 Core 返回的第一个 REFILE 目标。配置仓库 ID 必须先映射到实际 Core 仓库 ID，不按路径跨仓库排除，也不在 ArkTS 过滤目标结果。

快捷移动提交通用目标选项 ~todoState: 'TODO'~ 与 ~clearPlanning: true~ ，Core 验证目标状态并保真改写根标题、清理规划信息。目标文件未配置、失效、被忽略或没有 REFILE 时不回退到其他文件，不新建文件；缺少 TODO 状态时拒绝提交。备忘转换和普通移动沿用原有选项。


* 待关注事件

NotificationQuery 通过统一批量接口返回当前文件与基线派生的事件。文件冲突形状为 ~{ type: 'syncConflict', repoId, path }~ ，每个文件独立一条；Rust bridge 附带 ~rootDirectory~ 供宿主映射配置仓库，Core 事件本身不保存绝对路径。通知复用本批读取的文件与基线索引，保证外部文件变化在下次批次可见；点击校验仓库身份后按文件路径进入 ~ConflictFile~ 。

~{ type: 'syncRequired' }~ 为 workspace 级无载荷事件；只要任一仓库本地字节 hash 与基线索引不同就生成一条，点击执行普通同步。它不依赖进程内去重标记，重启后可重新发现。Core 负责当前状态判断，ArkTS 只展示快照，读取失败保留既有快照。

* 文件冲突与普通操作组

Repo 不提供独立的网络比较／解决会话；文件读取与 Core ConflictPreview 对象提供当前完整内容、冲突描述及变化。普通 ~OrgFile~ 对象增加只读 ~conflictIds: string[]~ ，Rust 从文件末尾容器读取 ~CONFILICT_ID~ ，C++ 必须在 N-API 类上注册同名只读属性并通过 ~OrgFileProperty~ 取得数组；没有可定位冲突点时返回空数组。该属性与类型声明及 ArkTS 读取保持一致，不能只保留 Rust JSON 字段而遗漏原生对象属性； ~hasConflict~ 根据真实节点标签取得，不解析旧文件头。

~Workspace.executeTaskOperations~ 接受新增 ~{ type: 'ConfilictSelection', data: { id, action: 'discard' } }~ ，经原有结构化请求和 worker 进入 Core。 ~TaskConfilictSelection~ 的拼写保持约定，参数之外不携带同步 ID、来源正文或服务端比较会话。最终文件版本、完整回退和待上传意图由普通执行器统一生成。C++ 不实现新的合并算法。

日志备份仍经 ~historyFile~ 和历史 ABI 读取。只有远端删除备份有手机入口，旧结果文件的读取兼容不代表当前仍存在“已解决”状态；新冲突丢弃不再写入历史目录。

* 通知更新监控与生命周期

~Workspace.watchNotifications(monitor): Promise<void>~ 在 worker 中调用 ~org_tasks_harmony_workspace_watch_notifications~ ，注册 Core 的 ~watch_notifications~ 。回调通过独立 TSFN 转发 ~NotificationUpdate~ 联合类型 ，不复用同步进度回调。 ~stopWatchingNotifications~ 及 Workspace 释放时解除订阅；旧订阅替换、异步注册过期和注册失败均释放回调资源。Rust 闭包持有监控句柄，最后一次在途调用退出后才释放 TSFN，已排队事件由 Node-API 正常清理。

~CoreNotificationService~ 统一持有通知订阅并发布页面批次中的通知结果，不再独立读取。仓库事件由数据订阅触发页面重查，全局通知事件也只标记数据失效，避免同一更新发起两次查询。 ~AppShell~ 只按通知模块的数据版本使当前可见页面重新查询；隐藏页面恢复时检查遗漏版本。同步区域不再持有数据版本、冲突列表或通知刷新职责， ~RepositorySyncService~ 的 Promise 完成不直接刷新页面；解决结果保存后同样由 Core 通知触发。普通本地同步通过 ~Workspace.reload~ 由 Core 发出更新；任务操作组成功提交后也由 Core 统一发布受影响仓库的更新，无实际变更或失败时不发布，避免在宿主补造完成通知。

~lastEffectSync~ 返回最近成功同步的摘要或空，已解决、无冲突和缺备份的成功记录都可以返回。通知区域不调用此方法，唯一注意事项数据源是统一查询的 Notification 结果分支 。

* 备忘标签候选

~OrgFileMetadata.tagOptions: string[]~ 和 ~tagGroups: string[][]~ 分别由 Core 的 ~OrgFile.tag_options()~ 与 ~tag_groups()~ 生成，通过既有文件元信息 JSON 原样透传；C++ worker 与 文件结果包装不解析标签，不增加独立 native 请求。 ~FileTargetService.resolve~ 只保留所选文件的候选和互斥组， ~FileTargetService.query~ 在现有任务与分类结果旁携带这些配置；其他文件或仓库配置不混入。

Core 仅解释文件头 ~#+TAGS:~ ，提取标签名称、去掉快捷键并保留花括号互斥组，不为任务赋标签。备忘页把候选与完整 ~Task.tags~ 快照合并，按配置顺序区分各组；同组单选、组间交集，未分组标签按并集匹配，其他页面仍使用原有筛选方式。 ~TAGS~ 中未使用的候选可以显示，但只有任务实际标签参与匹配；不在 ArkTS 解析 Org。

* 正文首行与修改时间排序

~FilterTask.body_first_line()~ 在 Rust 查询投影时映射为只读、可枚举的 ~Task.bodyFirstLine: string | null~ ，C++、ArkTS wrapper 与路由完整透传，空正文保留 ~null~ 。任务 ~modifiedAt~ 通过 Core 的 ~modified_at()~ 获取，Core 仅解释标题自身的 ~LAST_MODIFIED~ 属性；属性缺失时为 ~null~ 。备忘摘要只组合 ~modifiedAt ?? createdAt~ 的本地日期、有效 ~tags~ 与 ~bodyFirstLine~ ，不从原始正文或 HTML 推断第一行。

~FileTargetService.query~ 的备忘文件请求使用 ~b."路径" .o.modified~ ，完成与组合标题开关均开启。排序与缺失值置末由 Core 统一处理；宿主沿用返回顺序。固定卡片点击进入既有 ~MemoEdit~ ，左滑删除继续通过 ~NoteService.remove~ 提交带完整路径和文件版本的 Deletion。

* 任务卡片原位编辑

任务对象新增只读、可枚举的 ~ownTags~ 、 ~inheritedTags~ 与 ~editContent~ 。自身标签取自 Core 原始标题标签，包含不展示的用途标签，操作普通标签时保留原用途；继承标签标记来源且不在当前任务取消； ~editContent~ 包含 ~notes~ 和 ~checklist~ ，条目字段为 ~id~ 、 ~text~ 、 ~checked~ 、 ~partial~ 、 ~depth~ 、 ~siblingGroup~ 。C++ 只透传嵌套对象，ArkTS 不解析正文或 checkbox。

~TaskModificationField~ 接入 ~NOTES~ 、 ~CHECKLIST~ 、 ~SCHEDULE_DATE~ 和 ~DEADLINE_DATE~ ，仍通过原有异步 ~Workspace.executeTaskOperations~ 提交。 ~TaskChecklistChange~ 使用辨别字段 ~type~ ，值为 ~add~ 、 ~edit~ 、 ~setChecked~ 、 ~remove~ 或 ~move~ 。排序使用 ~{ type: 'move', id, beforeId }~ ， ~beforeId~ 为同级目标 ID 或 ~null~ ，移动与分组投影均原样透传，Core 校验同级身份和原快照版本。修改成功只确认提交，当前编辑卡片需要最新版本时通过既有查询接口重新读取；收件箱、备忘和分享入口在数据变化订阅或页面生命周期中重新载入，通知订阅接口保持不变。

标签候选合并当前文件的 ~tagOptions~ 、当前任务标签与 workspace 已用标签，不合并其他文件未使用的候选。新建标签通过赋给当前任务落盘，不创建独立标签配置。

编辑会话由 ~TaskInlineSession~ 管理，同一窗口只展开一个任务；Core 通知照常更新，列表重查询推迟至会话结束，避免响应本次保存时重建输入控件。切换任务前先完成失焦保存，失败阻止切换；收件箱定时重新读取在编辑期间暂停，结束后使用既有通知刷新。

* 同步提示通知接入

同步目录、历史与新增通知的全部领域规则统一见 [[file:../core/同步核心设计.org][同步核心设计]]，bridge 不扫描目录比较 resolved 与远端文件，也不在 ArkTS 去重或持久化提示。

TS 的 ~CoreNotification~ 联合类型新增 ~{ type: 'syncRequired' }~ ，复用统一查询的 Notification 分支读取。一个应用进程最多一条，后来同类通知由 Rust 丢弃；不因多仓库、重复读取或 workspace 重建增加实例，应用重启不恢复。

通知组件点击后复用 ~RepositorySyncService~ 发起当前配置全部仓库的普通同步；已有会话不并发重启，错误走现有反馈。Core 在成功确认待上传结果后清除提示，失败或取消时保留。C++ 和 ArkTS 不提前删除本地展示来模拟消费。

通知更新联合类型增加全局变体，匹配 Core 的 ~RepositoryChanged { repo_id }~ 与 ~GlobalNotificationsChanged~ ：前者沿仓库身份过滤，后者让所有订阅重新查询，不虚构 Core 仓库 ID。Rust、C ABI 编组、C++ TSFN、TS 类型、wrapper 与展示调用方保持同一联合类型。

* 内容合并的 Core 边界

现有 UI 同步调用经原有 Repo 同步入口进入 Core，复用文件内三方合并。 ~org_tasks_core::merge~ 是直接接收 Org 原文的 Rust 纯函数，不新增 C ABI、C++ N-API 或 ArkTS 方法。冲突丢弃使用普通 ~executeTaskOperations~ 的 ~ConfilictSelection~ ；任务候选不阻止后续同步。完整目录与基线语义见 [[file:../core/同步核心设计.org][同步核心设计]]。

* 仓库重置与冲突展示

~Repo.reset(): Promise<void>~ 经 ~org_tasks_harmony_repo_reset~ 在既有 N-API async worker 调用 Core。worker 持有 Repo 至完成，异常拒绝 Promise；Rust bridge 成功后移除该仓库的内存操作回退快照。仓库 ID、配置 ID、凭据和远端保持不变，ArkTS 不删除文件或清理同步状态。

文件元信息增加 ~hasConflict: boolean~ ，文件对象提供同名只读属性。Rust bridge 直接投影 ~OrgFile.has_conflict()~ ，N-API 与 ArkTS 不解析节点标签。存储库据此显示醒目的冲突标签，并通过所属配置仓库 ID 导航唯一的 ~ConflictFile~ 页面；该页提供冲突列表与完整预览，finish 后通过普通操作组提交。历史项仅为删除备份提供阅读。

* 历史列表展开接入

手机移除独立 ~SyncDetail~ 路由，保留既有 ~Repo.historyDetail(syncId)~ 异步方法用于展开项读取；C++ 与 Rust 的方法归属、worker 生命周期和错误传播保持一致。Rust 透传 Core 的 ~updated~ 、 ~merged~ 等结果，不在 bridge 按 action/state 推断业务状态。 ~section~ 新增 ~merge~ 与 ~unchanged~ ，展开列表直接展示全部 ~files~ 。 ~backup~ 可包含远端删除前的备份元信息，点击使用原 ~historyFile~ 参数读取；宿主不拼接删除备份路径。

* 任务可配置标签投影

Rust 的 ~SupportTags~ 由 Core 解析， ~HarmonyBridgeTask.support_tags~ 仅克隆结果供跨语言编组；C++ 在原生 ~Task~ 上定义可枚举只读 ~supportTags~ 属性，ArkTS 使用 ~CoreSupportTags~ 类型别名。查询、修改操作返回的新任务使用同一投影路径；无配置保留 ~null~ ，不以空数组掩盖缺失。

#+begin_src ts
interface SupportTags { readonly tags: string[]; readonly groups: string[][] }
// Task 上的只读查询快照
readonly supportTags: SupportTags | null
#+end_src

标签窗口直接消费当前任务的 ~supportTags~ 、 ~ownTags~ 和 ~inheritedTags~ ，不再额外查询全部任务或补读文件元信息来拼接候选。任务已有但未列入候选的标签仍保留显示，便于删除；新建标签沿用现有 Core 写入接口，不修改候选配置。选择同一互斥组的另一项只替换当前任务自身的同组标签；父标题继承的互斥项不能在子任务删除或同时选择其同组项。

* 冲突预览对象接入

应用复用长期 Workspace，进入冲突页时通过异步 setPreviewRoot 提供私有缓存根目录，Core 验证隔离并管理副本与租约。字段和目标直接映射 [[file:../core/数据模型.org::*冲突预览模型][Core 类型]]，JSON 仅用于 ABI 内部编组，ArkTS 使用结构化对象。

#+begin_src ts
interface ConflictPreviewRequest {
  file: TaskPath
  conflictId: string
  sourceVersion: string

interface ConflictPreviewFinishOptions { previewVersion: string }
interface ConflictPreviewProjectionRequest {
  conflictId: string

}

  private constructor()
  readonly id: string
  readonly sourcePath: TaskPath

  sourceFile(): Promise<OrgFile>
  conflicts(): Promise<FileConflict[]>

// fileAt(path: TaskPath): Promise<OrgFile>

ConflictPreview 是原生活动对象，file／sourceFile 只返回主树快照，异步 conflicts 方法从独立材料集合返回待选冲突；不再从副本 OrgFile.conflicts 取得列表。由 Rust session 绑定 Core 句柄，C++ 对象保留 workspace 引用。所有 I/O 通过 async work 在 worker 执行，finalizer 只释放句柄和引用，不隐式提交。旧 UUID 或对象返回 previewExpired，不映射为真实文件。OrgFile 仍为独立快照，节点、锚点、候选描述与变化全部由 Core 产生。

预览 fullPath 使用固定 ~repoId="<preview>"~ 和 ~file=UUID~ 。临时 executeTaskOperations 与真实修改一样只返回 void；页面通过 preview.file 的节点方法显式重读副本，不查询全 workspace 来寻找它。NoteService 与任务编辑组件直接使用同一操作组和版本机制，临时保存不登记上传，也不要求匹配真实仓库配置。

finish 返回保持原顺序、路径已映射至源文件的 TaskOperationGroup。ConflictFile 按当前源仓库配置填 queueRepoIds，再调用既有 Workspace.executeTaskOperations；不增加另一个真实写入接口。结束后提交失败保留返回组与已显示快照，重试不再次 finish。原文件变化仍由统一数据接口版本约束拒绝。

页面初次加载即取得主树快照与独立冲突列表，并选中首个冲突调用只读 project。切换点继续复用未操作的副本，只在用户选择取舍时执行操作。project 在 C++ 通过 PreviewRequest 的 async work 传入结构化 request，Rust 直接调用 Core 并返回普通投影对象，不构造可编辑 OrgFile，也不消费候选。投影工作版本与投影正文版本分别校验；界面按请求代次、对象 ID 和冲突 ID 拒绝迟到结果。进入子编辑器再返回时读取同一 preview，不因 onPageShow 再复制。Core 在成功操作组后记录操作，失败组不记录；退出 discard 不执行这些操作。Rust、C++ N-API、声明、ArkTS wrapper 与调用方共同维护此契约。

* 查询结果与文件加载生命周期

Rust ~OrgRepo~ 不持有 ~files~ 或扫描规则，TS 也不暴露可复用的仓库文件快照。 ~load_files~ 经新增的 ~org_tasks_harmony_repo_load_files~ 在既有 N-API worker 中执行，JSON 数组只在 ABI 内编组为相对路径列表； ~Repo.loadFiles~ 返回独立值对象。任务请求继续使用既有 ~TaskQuery.excludedFiles~ ，Core 按仓库 ID 提取相对路径，不在 ArkTS 执行文件筛选。

~FilterTask.file_version()~ 和 ~edit_content()~ 在 Core 投影时从同一文件产生，bridge 直接构造既有 ~Task.fileVersion~ 与 ~editContent~ ，不再二次查找源文件。结果字段、版本算法和错误枚举不变；Rust 磁盘接口采用异步 ~Result~ ，TS 保持 Promise 错误传播。

* 任务完成状态接入

Rust bridge 将 ~FilterTask.done_keywords()~ 投影为 ~HarmonyBridgeTask.done_keywords~ ，C++ 在 ~Task~ 注册只读、可枚举的 ~doneKeywords: string[]~ 属性，ArkTS 的 ~CoreTask~ 类型别名直接透传。列表前部 checkbox 仅对待办任务开放完成操作，使用 ~doneKeywords[0]~ 组装 ~TODO~ 修改，经原有异步 ~Workspace.executeTaskOperations~ 提交文件版本约束；不在宿主解析文件或硬编码完成关键词。空列表禁用操作，提交期间阻止重复点击，失败显示 Core 错误；成功释放编辑会话，由数据通知刷新当前视图。

* 批量查询与锁边界

~Workspace.query(queries: CoreQuery[]): Promise<CoreQueryResult[]>~ 是唯一通用任务查询入口，旧单对象请求拒绝；单查询提交单项数组并取第零项结果。Rust、C ABI、C++ N-API 与 ArkTS wrapper 一次传递整批，C++ 将 Task 结果分支的 ~tasks~ 包装为 Task 对象。 ~results[i]~ 对应 ~queries[i]~ ，空结果和重复查询均保留位置。

Harmony 每批只取得一次 workspace 业务 Mutex，Core 每仓库加锁一次并加载一次。 ~Workspace.addRepo~ 在加入仓库前初始化稳定 ID，查询不再逐仓库调用 ~Repo.load~ 。空数组不取得业务锁、不加载文件。任一请求校验、文件加载、查询或编组失败使整个 Promise 拒绝，不返回部分结果。全部排除条件与快照契约见 [[file:../core/批量查询接口设计.org][批量查询接口设计]]。

侧边栏将八项任务查询、三个目标文件元信息与通知合为一个批次，并按输入位置显示计数。收件箱、某天和备忘以 Core 仓库 ID 与相对路径隔离同名文件，空文件与失效文件通过同批 File 结果区分。

* 规划重复规则编辑接入

~Task.editContent~ 新增 ~scheduledRepeat~ 与 ~deadlineRepeat~ ，类型为 ~TaskRepeatInfo | null~ ，内部包含 ~date~ 、 ~hasTime~ 与可空 ~rule~ 。 ~TaskRepeatRule~ 使用 ~mode~ 、 ~interval~ 、 ~unit~ ，名称与 Core 的 camelCase 序列化保持一致。Rust 直接投影 Core 值，C++ 的只读可枚举 ~editContent~ 属性原样透传嵌套对象，不新增解析或线程入口。类型声明、 ~NativeCoreService~ 别名及调用方同步维护。

原 ~TaskModification~ 联合值扩展为可接收 ~TaskRepeatRule~ ，字段新增 ~SCHEDULE_REPEAT~ 、 ~DEADLINE_REPEAT~ 。 ~TaskRepeatDialog~ 仅维护草稿、中文摘要与字段操作，不生成 Org 时间戳；保存经原 worker、 ~Workspace.executeTaskOperations~ 和文件版本约束一次提交。卡片先结束文字输入，再打开重复编辑；保存由原数据事件重读，失败保留输入。独立任务详情经 ~NoteService.modify~ 复用正式文件与预览副本的提交边界，提交后从原文件对象重新取得节点；写入成功但重读失败时停用后续修改，返回重开，不重复提交。

* 项目名称与项目任务区块

~Task.project()~ 与文件元信息的 ~project()~ 只返回 Rust 生成的 ~projectName~ 快照；Task 字段只读且可枚举，文件元信息的同名字段也固定为只读。C++ 注册同步方法，不解析文件标签或 ~PROJECT_NAME~ 。方法不会执行文件 I/O，序列化保留字段值而不包含方法。Core 的 ~FilterTask.project()~ 直接委托共享的 ~OrgFileMetadata.project()~ 。

文件头 ~FILETAGS~ 包含 ~project~ 时，项目名优先取 ~#+PROJECT_NAME:~ ，不存在时取文件 ~TITLE~ 。非项目为 null，未命名项目为空字符串，由界面显示“未命名项目”。项目元信息与任务来自同次加载，不增加查询或回查文件。

今天页保持原有 CATEGORY 一级分区，仅在分类内把项目任务按名字组装为带左上角弱角标的区块；普通任务直接排列，随时页继续只按分类。项目分组只组织已取得任务快照，保持每条任务和项目内相对顺序，不做额外任务过滤。来源行在原分类文字后显示“ · 项目名”，布局见 [[file:项目分类布局设计.org][项目分类布局设计]]。

* 唯一统一查询接口

系统已移除 ~org_tasks_harmony_workspace_notifications~ 与 ~org_tasks_harmony_repo_file_metadata~ 两个 FFI 符号、对应 N-API 方法、类型声明和 ArkTS 读取封装。通用读取只有 ~Workspace.query(queries: CoreQuery[]): Promise<CoreQueryResult[]>~ ，旧 TaskQuery 数组协议拒绝；TaskQuery 字段不变，作为 Task 分支的 query 参数。

JSON 请求按 ~type~ 区分 task、file、notification，结果使用对应 type 与 result。C++ 只在 Task 结果中包装原生 Task，在 File 结果中为元信息注册项目访问方法，Notification 结果直接透传。一次 async work 调用整个批次，整个结果组装成功后才 resolve，任一包装失败 reject 整个 Promise。

页面统一通过 PageQueryService 组装请求并从同批发布通知；AppShell 生命周期只注册数据订阅，不再自行查询通知。收件箱本页与最近新增、目标元信息和通知一次返回；今天等通用视图和某天、备忘各自使用一个批次，侧边栏同样只调用一次 query。请求类型、过滤与锁边界见 [[file:../core/统一批量查询接口设计.org][统一批量查询接口设计]]。
