* 定位

Rust bridge 位于 ~harmony~ Cargo crate，与 ~http~ 同为 core 的宿主模块。它把 HarmonyOS 的 N-API 调用转换为 ~Workspace~ 和 ~Repo~ 对象方法，调用 core 已有 API，并把文件、任务和同步结果转换为 DTO；它不是 core 的领域子模块。

* 分层

#+begin_example
ArkTS CoreWorkspace / CoreRepo
  -> C++ N-API Workspace / Repo class
  -> harmony C ABI workspace handle
  -> harmony bridge session
  -> core OrgWorkspace / OrgRepo / WebDavSyncPolicy
#+end_example

~openWorkspace~ 在 worker thread 中加载 core workspace 并返回 native ~Workspace~ 实例。~Workspace.repos~ 返回 native ~Repo~ 实例；~Workspace.snapshot~ 、~Workspace.search~ 和 ~Workspace.syncWebDav~ 均在同一 session 上执行。~Repo.snapshot~ 只读取所属仓库快照。

~Workspace~ 与 ~Repo~ 分别持有同一个 opaque workspace handle 的引用。对象终结时 N-API finalizer 释放引用，最后一个引用释放后 Harmony session 才释放 core ~OrgWorkspace~ 。ArkTS 不解析 org AST、不计算同步决策，也不保存同步领域状态。C++ 只负责参数编组、worker thread、Promise、对象终结和字符串资源释放。

#+begin_src ts
function openWorkspace(rootDirectory: string): Promise<Workspace>

class Workspace {
  repos(): Promise<Repo[]>
  snapshot(): Promise<string>
  search(expression: string): Promise<string>
  syncWebDav(webdavUrl: string, username: string, password: string): Promise<string>
}

class Repo {
  id(): string
  snapshot(): Promise<string>
}
#+end_src

* 请求与响应

~Workspace~ 当前提供 ~repos~ 、~snapshot~ 、~search~ 和 ~syncWebDav~；~Repo~ 提供 ~id~ 和 ~snapshot~。打开 workspace 时构造 ~OrgWorkspace~ 并加载其仓库；WebDAV 同步按既有顺序调用 ~OrgRepo.load~ 、~WebDavSyncPolicy~ 和 ~OrgRepo.sync~；搜索调用 ~OrgWorkspace.search~。这些调用序列属于 Harmony 宿主适配；~OrgRepo~ 、~OrgWorkspace~ 、~Filter~、~SyncPolicy~ 、WebDAV 传输和 org 解析算法仍只定义在 core。

响应包含仓库稳定 ID、相对 org 文件路径、原始 UTF-8 内容、字节长度，以及可选同步记录摘要。WebDAV 密码只作为同步请求输入，不能出现在响应、日志或同步记录中。

* 扩展规则

新增查询、编辑或同步能力时，先在 core 定义可复用领域 API 和数据结构；再在 ~harmony/src/bridge.rs~ 添加对应 action；最后扩展 C++ 类型声明和 ~NativeCoreService~ 。不得在 ArkTS、C++ 或 bridge 重写 core 的 org 解析或同步规则。
