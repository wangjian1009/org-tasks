* 定位

Rust bridge 位于 ~harmony~ Cargo crate，与 ~http~ 同为 core 的宿主模块。它把 HarmonyOS 的 N-API 调用转换为 ~Workspace~ 和 ~Repo~ 对象方法，调用 core 已有 API，并把文件、任务和同步结果转换为 DTO；它不是 core 的领域子模块。

* 分层

#+begin_example
ArkTS CoreWorkspace / CoreRepo / CoreWebDavSyncPolicy
  -> C++ N-API Workspace / Repo / WebDavSyncPolicy class
  -> harmony C ABI workspace handle
  -> harmony bridge session
  -> core OrgWorkspace / OrgRepo / WebDavSyncPolicy
#+end_example

~new Workspace()~ 创建空的 native ~Workspace~ 实例。~Workspace.addRepo(rootDirectory)~ 返回 native ~Repo~ 实例，~Workspace.removeRepo(rootDirectory)~ 仅将其从运行时 workspace 移除。~Repo.load()~ 扫描该仓库并生成稳定 ID；~Workspace.repos~ 返回全部已添加仓库，~Workspace.search~ 直接返回结构化任务数组。~WebDavSyncPolicy~ 是由 URL、用户名和密码构造的调用参数，不在 Rust bridge session 中持有；~Repo.sync~ 在 worker thread 中临时构造 core policy，并以该策略调用 ~OrgRepo.sync~。~Repo.snapshot~ 直接返回所属仓库的结构化文件快照。

~Workspace~ 与 ~Repo~ 分别持有同一个 opaque workspace handle 的引用。对象终结时 N-API finalizer 释放引用，最后一个引用释放后 Harmony session 才释放 core ~OrgWorkspace~ 。ArkTS 不解析 org AST、不计算同步决策，也不保存同步领域状态。C++ 只负责参数编组、worker thread、Promise、对象终结和字符串资源释放。

#+begin_src ts
interface NewTask {
  heading: string
  scheduled: string
  deadline: string
  tags: string[]
  priority: string
}

class WebDavSyncPolicy {
  constructor(webdavUrl: string, username: string, password: string)
  testConnection(): Promise<void>
}

class Workspace {
  constructor()
  repos(): Promise<Repo[]>
  addRepo(rootDirectory: string): Promise<Repo>
  removeRepo(rootDirectory: string): Promise<void>
  search(expression: string): Promise<Task[]>
}

class Repo {
  id(): string
  rootDirectory(): string
  load(): Promise<void>
  createTask(path: string, task: NewTask, queueUpload: boolean): Promise<void>
  snapshot(): Promise<RepositorySnapshot>
  sync(policy: WebDavSyncPolicy, monitor?: WebDavSyncMonitor): Promise<SyncRecord>
}
#+end_src

* 请求与响应

~Workspace~ 当前提供 ~repos~ 、~addRepo~ 、~removeRepo~ 和 ~search~；~Repo~ 提供 ~id~ 、~rootDirectory~、异步 ~load~、~snapshot~ 和异步 ~sync~。ArkTS 必须按 ~new Workspace() -> addRepo() -> repo.load()~ 的顺序初始化每个仓库；~addRepo~ 仅在 core workspace 中保存仓库目录，~Repo.load~ 扫描对应仓库。~Repo.sync(policy, monitor)~ 在调用期间构造 ~WebDavSyncPolicy~，以原生 ~WebDavSyncMonitor~ 订阅脱敏进度事件，并直接调用对应仓库的 ~OrgRepo.sync~，由其内部恢复当前文件和同步历史；同步结束后策略随调用释放。C++ 通过 N-API thread-safe function 将事件投递回 ArkTS 回调；搜索调用 ~OrgWorkspace.search~。C++ N-API 解析 Rust DTO 后直接向 ArkTS 返回对象或数组，不把 JSON 字符串暴露给 ArkTS。这些调用序列属于 Harmony 宿主适配；~OrgRepo~ 、~OrgWorkspace~ 、~Filter~、~SyncPolicy~ 、WebDAV 传输和 org 解析算法仍只定义在 core。

响应包含仓库稳定 ID、相对 org 文件路径、原始 UTF-8 内容、字节长度，以及可选同步记录摘要。WebDAV 密码只作为同步请求输入，不能出现在响应、日志或同步记录中。

异步方法失败时 Promise 拒绝 ~CoreError~ 对象，其 ~code~ 为 ~invalidInput~、~invalidState~、~store~ 或 ~bridge~，~message~ 保留 core 的中文错误说明。ArkTS 应读取 ~message~ 展示错误，不能以 ~JSON.stringify(error)~ 代替。

~Repo.createTask~ 接受结构化任务和相对目标路径。C++ 将输入编组为 JSON，并在 ~napi_create_async_work~ 工作线程调用 Rust；Rust 只反序列化 ~core::NewTask~ ，加载对应仓库并调用 ~OrgRepo.create_task~ 。保存期间保留 native ~Repo~ 引用；同一 workspace 的加载、编辑和同步由 bridge session 锁串行执行。成功返回空值，失败保留 core 的错误分类与中文消息。ArkTS 不生成 org 文本，不直接写文件或维护 outbox。

手机从完整配置对应的 workspace 选择目标仓库，本地仓库只保存文件，WebDAV 仓库通过 ~queueUpload~ 登记意图。保存成功后阻止重复提交；后续手动或后台同步上传当前 org 文件。WebDAV 同步返回失败、冲突或取消时，应用显示未完成提示并保留待上传任务。

* 扩展规则

新增查询、编辑或同步能力时，先在 core 定义可复用领域 API 和数据结构；再在 ~harmony/src/bridge.rs~ 添加对应 action；最后扩展 C++ 类型声明和 ~NativeCoreService~ 。不得在 ArkTS、C++ 或 bridge 重写 core 的 org 解析或同步规则。

* 界面所需的来源与层级投影

任务 DTO 的 ~repoId~ 直接来自 ~FilterTask.repo_id~ ， ~level~ 来自 core 投影的真实标题层级，不再固定返回 0。文件列表以仓库 ID 和相对路径联合关联任务；层级、折叠和面包屑仅是宿主显示，不产生新的 Org AST。 ~CoreRepositorySnapshot.rootDirectory~ 由 ArkTS wrapper 的既有 ~Repo.rootDirectory()~ 补齐，属于运行时显示信息，不写入 core 的持久化记录。

存储库配置提交前，宿主用独立 workspace 调用既有 ~Repo.load~ 验证目录。该临时 workspace 不替换正在浏览或同步的活动 workspace；bridge 没有增加解析、扫描或同步算法。

* 无仓库的 WebDAV 连接测试

原生 ~WebDavSyncPolicy.testConnection~ 由 C++ ~napi_create_async_work~ 在工作线程调用 ~org_tasks_harmony_webdav_test_connection~ 。worker 复制调用时的地址和凭据，不依赖 native 对象继续存活；完成时销毁请求副本并释放异步工作资源。该方法不持有 workspace handle，也不占用仓库 session 锁。

Rust bridge 临时构造 core ~WebDavSyncPolicy~ ，在 Tokio runtime 中调用 ~test_connection~ 。认证/访问被拒绝映射为 ~invalidInput~ ，网络、超时、证书或协议/目录响应失败映射为 ~invalidState~ ，返回固定的脱敏中文说明。成功兑现 ~Promise<void>~ ，失败拒绝已有 ~CoreError~ 类型。协议请求和 XML 校验全部位于 core，ArkTS 与 C++ 不实现 WebDAV 算法。


* 同步级合并比较与 apply

原生 ~Repo.conflicts()~ 返回按同步记录分组的冲突路径，重放规则全部由 ~core::webdav::conflict_syncs~ 提供。~Repo.compareMerge(policy, syncId)~ 返回当前同步的比较对象，~Repo.apply(policy, comparison)~ 直接接收用户选择后的对象。没有准备会话、准备 ID 或 bridge 侧任务匹配表；重新比较和全仓库版本校验均在 core 执行。

#+begin_src ts
enum CoreMergeMode {
  AcceptRemote = 'acceptRemote',
  MergeTasks = 'mergeTasks'
}
enum CoreMergeResolution {
  Local = 'local',
  Remote = 'remote',
  Remove = 'remove'
}

const comparison = await repo.compareMerge(policy, syncId)
comparison.mode = CoreMergeMode.MergeTasks
comparison.changes[0].resolution = CoreMergeResolution.Remote
// 所有差异均选择后，将同一个比较对象直接提交。
const outcome = await repo.apply(policy, comparison)
#+end_src

比较对象包含 ~syncId~ 、 ~repoId~ 、 ~repositoryVersion~ 、 ~endpointVersion~ 、逐文件版本、 ~unchangedCount~ 与统一 ~changes~ 。每项变化含临时 ~id~ 、 ~path~ 、新增/修改/删除类型、两端来源和可空的 ~resolution~ 。仅 ~mode~ 与 ~resolution~ 可修改；源正文、ID、类型与版本都由 core 重新核对。未变化项不出现在列表中。

C++ 复制输入对象与当前策略凭据，在 ~napi_create_async_work~ 工作线程通过 Rust ABI 调用 core。异步期间持有 native ~Repo~ 强引用，防止 workspace handle 被提前释放。返回普通结构化对象；Rust/FFI 字符串在 C++ 解析后释放。仓库锁继续串行保护加载、编辑、同步与合并调用。bridge 不实现比较算法、备份路径规则、ETag 决策或任务拼接。

结果包含本次合并同步的 ~syncId~ 、 ~result~ 和逐文件相对备份路径。备份位于 ~.sync/backups/<本次合并开始时间>/~ ，文件名包含本地日期时间；元数据和正文不会写入 Preferences。部分失败仍返回同步结果和备份，失败项由下一次比较重新生成。仓库变化、远端变化、无效对象或备份失败会拒绝 Promise，界面提示重新比较。


* 同步历史由仓库恢复

Harmony 的 ~repo_sync_json~ 不再先读取历史或把历史传入同步接口，直接调用 ~OrgRepo.sync(policy, started_at, cancellation, progress)~ 。ArkTS 在启用 WebDAV 的仓库上也不再预先执行 ~Repo.load~ ；本地仓库浏览仍显式调用 load。历史回退、首次无历史时的全文件冲突和部分成功基准均由 Rust core 处理。

比较对象的 ~files[].localMissing~ 指示本地缺失的远端文件，与空文件区分。界面原样传递该版本信息，apply 校验缺失状态后创建文件；仅已有本地文件被备份，返回的 ~backups~ 可以少于冲突文件数量。UI 不计算或补造版本基准。
