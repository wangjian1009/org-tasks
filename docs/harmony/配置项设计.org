* 范围与边界

本文定义 Harmony 宿主的配置、凭据与保存边界。Harmony 从 Preferences 与安全存储取得仓库根目录和远端配置，再调用 core 打开并维护本地 ~OrgRepo~ 。core 负责 org 文件扫描和解析； ~core::webdav~ 负责同步文件写回与同步记录生成。核心模型见 [[file:../core/数据模型.org][数据模型]]，仓库 API 见 [[file:../core/接口文档.org][接口文档]]，本地控制目录见 [[file:../core/目录结构设计.org][目录结构设计]]。

配置、凭据与持久化状态必须分离。密码、令牌和客户端证书不能写入 Preferences、core 同步记录、HTTP 请求日志、进度事件或错误摘要。 ~repoId~ 由仓库根目录的 ~.sync/id~ 持久化，是连接 Harmony 凭据与 core 同步历史的唯一稳定标识；Preferences 不得复制保存该值。

~OrgWorkspace~ 是应用级核心结构；一个应用通常只构造一个。WorkScheduler 调度、CalendarKit 映射、N-API service 实例和活动同步任务都是 Harmony 运行时概念，不是 ~OrgWorkspace~ 或 ~OrgRepo~ 的字段。

* 配置模型

目标配置以一个带版本的 ~HarmonyAppConfig~ 保存于 Preferences。 ~repos~ 至少可为空；每个仓库映射到一个 core ~OrgRepo~ 。当前单仓库页面只保存根目录与远端配置；首次加载根目录时由 ~OrgRepo.load~ 创建或读取 ~.sync/id~ ，扩展为 ~HarmonyAppConfig~ 前也不得复制该 ID。

#+begin_src ts
interface HarmonyAppConfig {
  version: 3
  calendar: { name: string }
  scheduler: { intervalMinutes: number }
  repos: HarmonyOrgRepoConfig[]
}

interface HarmonyOrgRepoConfig {
  rootDirectory: string
  inboxFile: string
  remote?: HarmonyWebDavConfig
}

interface HarmonyWebDavConfig {
  kind: 'webdav'
  baseUrl: string
  username: string
}
#+end_src

| 配置范围 | 字段 | 保存位置 | 约束 |
|-
| 全局日历 | ~calendar.name~ | Preferences | 默认 ~Org Tasks~ ；只用于 Harmony CalendarKit。 |
| 后台调度 | ~scheduler.intervalMinutes~ | Preferences | 默认 15 分钟；仅控制 WorkScheduler 唤醒，不保存同步结果。 |
| 仓库根目录 | ~rootDirectory~ | Preferences | 非空目录路径；构造时映射为 ~OrgRepo.rootDirectory~ ，不写入 core 同步记录。 |
| inbox 目标 | ~inboxFile~ | Preferences | 相对 ~rootDirectory~ 的 ~.org~ 路径；是 Harmony 产生写入意图的目标。 |
| WebDAV 地址 | ~remote.baseUrl~ | Preferences | HTTPS 根目录 URL；由 ~core::webdav::WebDavSyncPolicy~ 使用，不进入核心数据模型。 |
| WebDAV 用户名 | ~remote.username~ | Preferences | 非机密标识；不得拼接入日志 URL。 |
| WebDAV 密码 | 不属于该结构 | Asset Store | 按 ~repoId~ 保存，永不序列化进 Preferences。 |

删除远端配置等同于不构造 WebDAV ~SyncPolicy~ ，仓库仍是本地 ~OrgRepo~ 。不得用 ~webdavEnabled~ 之类与策略类型重复的布尔开关表示。

* 凭据与 Workspace 构造

每个 WebDAV 仓库的秘密以独立 Asset Store 记录保存，别名为 ~org-tasks.webdav.<repoId>.password.v1~ 。 ~repoId~ 必须先从 ~rootDirectory/.sync/id~ 读取或初始化后才能定位该别名。记录必须设置 ~DEVICE_FIRST_UNLOCKED~ 、持久化和覆盖语义，以支持已解锁后的后台同步。用户名、地址和密码更新时，密码先写入 Asset Store，再提交 Preferences 配置；若 Preferences 写入失败，宿主必须保留可重试的清理或恢复动作，不能把密码写回 Preferences。

Harmony 根据 ~repos~ 构造一个 ~OrgWorkspace~ 。对每个 ~HarmonyOrgRepoConfig~ ，宿主把根目录交给 core 打开本地 ~OrgRepo~ ，由 core 读取或初始化 ~rootDirectory/.sync/id~ 并加载文件快照；存在 WebDAV 远端时再读取该 ~repoId~ 的凭据并创建 ~core::webdav::WebDavSyncPolicy~ 。无远端的仓库不读取 Asset Store。控制目录缺失时可初始化；ID 或布局格式无效时，构造对应仓库失败并返回可显示的本地存储错误，不触发网络同步。

根目录、WebDAV 地址、用户名和密码是宿主运行时输入，不能写入 core 的 ~OrgRepoSyncRecord~ 或 ~OrgRepoSyncFileRecord~ 。 ~OrgRepo~ 不承担远端地址或认证字段。

* 持久化职责

| 数据 | 所有者 | 保存位置 | 内容与限制 |
|-
| 用户配置 | Harmony | Preferences 的 ~org_tasks_config~ | ~HarmonyAppConfig~ ；不保存密码、同步历史或完整文件。 |
| WebDAV 密码 | Harmony | Asset Store | 每个 ~repoId~ 独立秘密记录。 |
| 仓库同步记录与身份 | core ~OrgRepo~ | ~rootDirectory/.sync/~ | ~id~ 保存唯一 ~repoId~ ； ~history/~ 追加保存 ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ 。不保存绝对路径、凭据或完整 org 内容。 |
| 日历映射 | Harmony | Preferences 的 ~calendar_sync_state~ | entry ID、日历事件 ID 和指纹；不得与用户配置混写。 |
| WebDAV 缓存与旧写入队列 | 旧实现 | 不属于当前配置 | 当前接口不读取或转换这些数据。 |

~lastSyncTime~ 不是配置。首页和后台状态应从指定 ~repoId~ 的 ~OrgRepoSyncRecord~ 历史读取，而不是写入 Preferences。

* 设置、更新与删除

设置页面编辑 ~HarmonyAppConfig~ 草稿，不得在字段变化时直接重配已运行的 service。保存成功后，应用在下一次解析或同步前根据完整配置重建 workspace。活动同步的取消、等待或中断标记由 Harmony 运行时决定，不进入 core 数据结构。

新增仓库按以下顺序执行：校验根目录和远端地址、初始化或读取 ~rootDirectory/.sync/id~ 、写入可选秘密、写入 Preferences、在下一次构造注册仓库。更新远端地址时保留现有 ~repoId~ 。更换根目录会切换到其自身的 ~.sync/id~ 与同步历史，不能假定两者属于同一逻辑仓库。删除仓库时先阻止活动同步，再删除 Preferences 条目和对应 Asset Store 秘密；根目录内 ~.sync~ 历史保留或清除必须由用户明确选择，默认保留以便诊断。

* 配置初始化

新配置创建时在仓库根目录创建或读取稳定的 ~.sync/id~ ，并从一开始使用别名 ~org-tasks.webdav.<repoId>.password.v1~ 保存密码。当前接口不读取、不转换旧 Preferences、旧密码别名、旧同步记录、缓存、待上传文件或 ~sync-state.json~ ；旧安装数据需要清理后按当前配置重新填写和同步。

* 验收标准

- 两个仓库可拥有独立根目录、 ~.sync/id~ 、WebDAV 地址、用户名、密码与 core 同步历史。
- Preferences 导出内容不包含密码、令牌、绝对 core 数据路径或同步结果。
- 重建 workspace 时，同一根目录的 ~.sync/id~ 能查询其历史；修改地址不会创建新的历史分区，更换根目录则使用该目录自己的历史。
- 删除仓库不会影响其他仓库的凭据和记录。
- 不存在旧配置、旧密码或旧同步状态到当前模型的自动迁移路径。
