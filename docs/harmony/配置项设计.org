* 范围与边界

本文定义 Harmony 宿主的配置、凭据与保存边界。Harmony 从 Preferences 与安全存储取得仓库根目录和远端配置，再调用 core 打开并维护本地 ~OrgRepo~ 。core 负责 org 文件扫描和解析； ~core::webdav~ 负责同步文件写回与同步记录生成。核心模型见 [[file:../core/数据模型.org][数据模型]]，仓库 API 见 [[file:../core/接口文档.org][接口文档]]，本地控制目录见 [[file:../core/目录结构设计.org][目录结构设计]]。

配置、凭据与持久化状态必须分离。密码、令牌和客户端证书不能写入 Preferences、core 同步记录、HTTP 请求日志、进度事件或错误摘要。core 的 ~repoId~ 由仓库根目录的 ~.sync/id~ 持久化；现有宿主另用配置 ID 定位秘密，身份统一尚未落地，差异见本文末尾。

~OrgWorkspace~ 是应用级核心结构；一个应用通常只构造一个。WorkScheduler 调度、CalendarKit 映射、N-API service 实例和活动同步任务都是 Harmony 运行时概念，不是 ~OrgWorkspace~ 或 ~OrgRepo~ 的字段。

* 配置模型

当前运行代码使用 ~AppConfig~ ，直接将 ~repos~ 、 ~inboxFile~ 、 ~captureRepoId~ 、 ~somedayFile~ 、 ~memoFile~ 、 ~calendarName~ 、 ~syncInterval~ 、 ~todoDefaults~ 和 ~fileDisplayMode~ 作为 Preferences 键保存，没有 ~version~ 字段或嵌套的日历、调度对象。每个配置项对应一个本地仓库目录；统一存储库文件页与配置表单负责增删改，core 在加载目录时读取或创建 ~.sync/id~ 。完整参考选项核对见 [[file:配置项移植核对.org][配置项移植核对]]。

#+begin_src ts
interface AppConfig {
  repos: RepoConfig[]
  inboxFile: string
  captureRepoId: string
  somedayFile: string
  memoFile: string
  calendarName: string
  syncInterval: number
  todoDefaults: string
  fileDisplayMode: 'rendered' | 'source'
}

interface RepoConfig {
  id: string
  name: string
  rootDirectory: string
  webdavEnabled: boolean
  webdavUrl: string
  webdavUsername: string
  webdavPassword: string
  excludedDirectories: string[]
}
#+end_src

~RepoConfig.webdavPassword~ 是内存中的临时值，真实秘密保存在 Asset Store；序列化的 ~repos~ 中同名字段固定为空字符串。目前 ~RepoConfig.id~ 由宿主生成，与 core 目录的仓库身份并非同一值；后续统一身份前，不能混用两者。

| 配置范围 | 当前字段 | 保存位置 | 约束 |
|-
| 全局日历 | ~calendarName~ | Preferences | 默认 ~Org Tasks~ ；由 CalendarSync 创建/选择应用日历。 |
| 全局 TODO 默认 | ~todoDefaults~ | Preferences | 外部保存声明文本；未保存时调用 Rust 默认接口，已保存空值不回退。 |
| 文件展示 | ~fileDisplayMode~ | Preferences | 默认 ~rendered~ ，可选 ~source~ ；旧配置缺失或值无效时使用渲染。 |
| 后台调度 | ~syncInterval~ | Preferences | 默认 20 分钟；由 BackgroundSyncService 配置 WorkScheduler。 |
| 仓库配置 ID | ~repos[].id~ | Preferences | 当前用于列表定位、编辑和 Asset Store 别名；与 core 仓库身份不同。 |
| 仓库显示名 | ~repos[].name~ | Preferences | 可为空，保存时去除首尾空白；旧配置缺失时按空值处理，显示时回退根目录末级名称，不改变仓库或凭据身份。 |
| 仓库根目录 | ~repos[].rootDirectory~ | Preferences | 非空绝对目录路径；构造时映射为 ~OrgRepo.rootDirectory~ ，不写入 core 同步记录。 |
| 收件箱文件 | ~inboxFile~ | Preferences | 可为空的安全相对 ~.org~ 路径；新配置默认空，旧保存值继续沿用。新增任务相对于所选仓库解析。 |
| 快速捕捉目标 | ~captureRepoId~ | Preferences | 默认空；单仓库自动选择，多仓库需明确指定宿主配置 ID。失效的非空 ID 不回退到其他仓库。 |
| 某天文件 | ~somedayFile~ | Preferences | 可为空的安全相对 ~.org~ 路径，默认空；某天入口查询此文件中的未完成记录。 |
| 备忘文件 | ~memoFile~ | Preferences | 可为空的安全相对 ~.org~ 路径，默认空；备忘入口查询该文件中的全部标题记录。 |
| WebDAV 启用 | ~repos[].webdavEnabled~ | Preferences | 决定是否为该仓库构造 WebDAV 策略。 |
| WebDAV 地址 | ~repos[].webdavUrl~ | Preferences | 表单限定 HTTPS；由 WebDavSyncPolicy 使用，不进入核心数据模型。 |
| WebDAV 用户名 | ~repos[].webdavUsername~ | Preferences | 非机密标识；不得拼接入日志 URL。 |
| WebDAV 密码 | ~repos[].webdavPassword~ | Asset Store | Preferences 只保留空值占位；运行时载入，不能写入日志和 core 记录。 |
| WebDAV 过滤目录 | ~repos[].excludedDirectories~ | Preferences | 同步调用时作为 ~SyncOptions~ 传入 core；默认值由 Rust 提供，当前为 ~archive~ 。 |

关闭 ~repos[].webdavEnabled~ 时不构造 WebDAV ~SyncPolicy~ ，仓库仍是本地 ~OrgRepo~ 。

* 凭据与 Workspace 构造

每个仓库的秘密以独立 Asset Store 记录保存，当前别名为 ~org-tasks.webdav.<configId>.password.v1~ ，其中 ~configId~ 是 ~RepoConfig.id~ ，不是 core 的目录 ID。记录设置 ~DEVICE_FIRST_UNLOCKED~ 、持久化和覆盖语义，以支持已解锁后的后台同步。保存时先写秘密再提交 Preferences；失败后的回滚/清理尚未实现，不能将其描述为已有能力。

Harmony 根据 ~repos~ 构造一个 ~OrgWorkspace~ ，由 core 加载各根目录并读取或创建 ~.sync/id~ 。AppConfigService 常规读取配置时为所有仓库查询 Asset Store；快速捕捉使用不含凭据的读取方式，仅取得本地写入配置。同步时仅为启用 WebDAV 的仓库创建 ~core::webdav::WebDavSyncPolicy~ 。控制目录或布局无效时加载失败，不触发网络同步。

根目录、WebDAV 地址、用户名和密码是宿主运行时输入，不能写入 core 的 ~OrgRepoSyncRecord~ 或 ~OrgRepoSyncFileRecord~ 。 ~OrgRepo~ 不承担远端地址或认证字段。

* 持久化职责

| 数据 | 所有者 | 保存位置 | 内容与限制 |
|-
| 用户配置 | Harmony | Preferences 的 ~org_tasks_config~ | ~AppConfig~ ；不保存真实密码、同步历史或完整文件；现有状态键混存问题见下文。 |
| WebDAV 密码 | Harmony | Asset Store | 每个 ~RepoConfig.id~ 独立秘密记录。 |
| 仓库同步记录与身份 | core ~OrgRepo~ | ~rootDirectory/.sync/~ | ~id~ 保存唯一 ~repoId~ ； ~history/~ 追加保存 ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ ， ~outbox/~ 保存待上传路径与哈希 。元数据不保存绝对路径、凭据或完整 org 内容；确认后的原始冲突文件单独保存在 ~backups/~ 。 |
| 日历映射 | Harmony | ~org_tasks_config~ 中的 ~calendar_sync_state~ 键 | 当前保存日历名称、任务 ID、事件 ID 和指纹；尚未按目标设计隔离到独立存储。 |
| 捕捉草稿 | Harmony | Preferences 的 ~org_tasks_capture~ | ~drafts~ 仅保存草稿 ID 与未保存标题；独立于配置、凭据、Org 文件与同步记录；成功保存后移除对应草稿。 |
| 已保存搜索 | Harmony | Preferences 的 ~org_tasks_saved_searches~ | 仅保存搜索 ID、名称与完整查询表达式；不保存完整任务、文件内容、绝对路径或凭据。 |
| WebDAV 缓存与旧写入队列 | 旧实现 | 不属于当前配置 | 当前接口不读取或转换这些数据。 |

~lastSyncTime~ 不是配置。后台日历同步把完成时间写入 ~org_tasks_config~ ；当前不提供独立日历同步页面。它不是按仓库的 core 同步历史。后续应隔离日历同步状态，并从 core 历史展示仓库同步状态，不能直接删除现有键。

* 设置、更新与删除

设置页面编辑 ~AppConfig~ 草稿，不在字段变化时直接重配 service。目录集合变化时 workspace 重建；目录不变时沿用 session，WebDAV 策略在下一次同步按新参数临时构造。活动同步控制由 Harmony 运行时负责，不进入 core 数据结构。

当前新建流程：校验表单、按需创建应用管理的目录、调用 core 验证目录并初始化其身份、写入凭据、写入 Preferences。配置 ID 在 core 验证前由宿主生成，不随目录 ID 变化。删除时经用户确认移除配置与密码，保留本地文件。

* 已有约束与待修复差异

| 约束 | 当前实现差异 | 处理边界 |
|-
| core 仓库 ID 为稳定身份来源 | 配置 ID 与 core ID 分离，凭据仍绑定配置 ID | 需专门设计秘密重绑定；本次不修改或清空已有 ID。 |
| 状态与配置分离 | 日历映射和最后日历同步时间混存在配置 Preferences | 需隔离状态存储；本次不删除事件映射。 |
| 秘密写入失败恢复 | 写入所有仓库秘密后提交 Preferences，没有事务回滚 | 需单独修复凭据持久化流程。 |
| 本地仓库无远端时不读取秘密 | 当前加载所有配置都会查询 Asset Store | 属于调用收敛问题，不是未支持的配置开关。 |
| 删除配置前阻止活动同步 | 当前页面只能限制本页操作，没有全应用同步互斥控制 | 需补齐宿主活动任务控制，不能宣称已验收。 |

上述约束仍是改进方向，不应作为已交付功能写入清单。参考配置的保留/不纳入范围以核对表及用户确认结果为准。

* 界面配置入口

本轮界面将全局设置与单个存储库草稿分开： ~Settings.ets~ 编辑收件箱、某天、备忘文件、日历与后台间隔； ~Files.ets~ 管理存储库与文件列表； ~RepositorySettings.ets~ 编辑目录和 WebDAV。表单保存时重新载入其他配置，保持未编辑字段的最新值。新建 WebDAV 默认使用应用私有目录，宿主只创建该目录，扫描、仓库身份和内容加载仍由 core 验证。

当前不提供独立的手动日历操作入口。后台作业使用已保存的日历名称与本地任务，先同步文件再写入日历；今天页下拉仅执行存储库文件同步，不读取或更新 ~lastSyncTime~ ，也不请求日历权限。

后台间隔默认及输入下限均为 20 分钟，以匹配当前 HarmonyOS 的系统约束。低于下限的既有值在显示与调度时按 20 分钟处理。保存后由 ~BackgroundSyncService.configure~ 比较现有 WorkScheduler 作业，必要时替换同一作业。调度配置不进入 core 同步记录。

* 保存前连接测试

WebDAV 表单的“测试连接”使用当前草稿中的地址、用户名和密码构造 ~CoreWebDavSyncPolicy~ ，调用原生 ~testConnection()~ 。该操作不要求配置已保存或本地目录存在，不访问 Preferences、Asset Store、活动 workspace、同步历史或日历，也不把测试结果持久化。

测试仅验证认证与目标目录访问，最多等待 15 秒。成功不代表具有上传权限；实际条件写入仍在同步时验证。失败消息不包含密码、完整 URL 或响应正文。测试期间禁止修改字段、重复测试、保存和返回；完成后恢复。地址、用户名、密码或 WebDAV 启用状态变化时立即清除旧结果。保存仍是独立操作，不强制先测试，也不因测试成功自动提交配置。


* 合并比较与冲突备份

任务合并没有新增 Preferences 配置。比较结果是一次同步的运行时对象，可直接交给 core apply；其中的仓库与远端版本、临时变化 ID 和任务正文不持久化为配置。界面只填写处理枚举，保留未变化任务。

按已确认的冲突处理规则，备份保存在所属仓库的 ~.sync/backups/<合并开始时间>/~ ，保留相对子目录，文件名附带本地日期时间与随机后缀。该目录是完整本地冲突文件的专用备份区，是控制目录不保存完整内容规则的明确例外；历史和 outbox 仍只保存元数据，备份不会被扫描、查询或上传。

原有单文件备份留在应用私有目录中的副本不会自动删除；新合并统一使用按同步分组的目录。 ~WebDavSyncFileDetail.task_versions~ 是可选的身份/内容指纹元数据，不是任务快照；旧历史仍可读取。Core 不将比较对象、密码或绝对备份路径写入历史。

* TODO 全局默认与文件覆盖

“设置 → 笔记与笔记本 → 默认 TODO 流程”编辑全局 Org 声明文本，由外部保存到 ~org_tasks_config.todoDefaults~ 。唯一缺省值来源是 Rust ~TodoConfig::default()~ ，Harmony 通过异步 ~defaultTodoSettings()~ 获取初始值或恢复编辑草稿；ArkTS 不维护另一套默认关键词。 ~DEFAULT_CONFIG.todoDefaults~ 的空值仅用于加载前占位，实际加载根据 Preferences 是否存在该键决定是否使用默认值。

保存前通过 native ~Workspace.setTodoDefaults~ 调用 Rust 校验。其他配置页面保存时保留当前 ~todoDefaults~ ，同步设置页不覆盖未编辑的 TODO 设置。配置不写入 Org 文件、同步历史或 outbox，恢复默认也只修改编辑草稿，保存后才生效。

每次取得 workspace 时由外部显式传入默认配置。目录不变时沿用 session；设置变化时更新同一 native workspace 并重解析文件。文件自己的声明整组覆盖全局值，查询、后台同步、日程、笔记本与新增任务共用相同配置。合并提交前重新读取外部配置，使旧对象受到 core 版本校验。

空全局配置表示默认不识别 TODO；文件仍可用声明启用自己的流程。文件内空 ~#+TODO:~ 则清空该文件的状态。输入错误明确显示，不能静默改成固定 TODO/DONE。快捷键和日志标记只作为元信息返回，当前不自动写状态变更日志。

* WebDAV 同步过滤目录

每个存储库在 WebDAV 表单提供“同步过滤目录”输入行，以逗号分隔目录名。“恢复默认过滤目录”从 Rust 读取默认值，当前为 ~archive~ 。旧配置缺失 ~excludedDirectories~ 时从 Rust 补齐；已保存空列表时保持为空，表示不排除任何目录。保存前通过原生 ~normalizeSyncOptions(options)~ 调用 core 验证目录名，校验失败不写入凭据和 Preferences。

前台与后台同步从已保存配置构造 ~SyncOptions~ 并传入 ~Repo.sync~ ，不把规则存入凭据或 policy。规则仅影响 WebDAV 传输；已有本地文件及待上传意图保留。

* 顶部文件入口配置与缺失反馈

~inboxFile~ 、 ~somedayFile~ 与 ~memoFile~ 都保存到 ~org_tasks_config~ ，留空表示未配置；已有收件箱 Preferences 值不迁移或清空。新安装不以 ~inbox.org~ 自动代填，输入框中的示例不代表已保存配置。三个字段都使用安全相对 ~.org~ 路径，不接受绝对路径、目录回退、反斜杠或 ~.sync~ 控制目录。

点击未配置的收件箱、某天或备忘时弹出中文提示，“前往设置”进入笔记与笔记本分组；取消后保留当前页面。空配置不执行空路径查询，也不创建文件。已配置但文件不存在时显示零记录。清空收件箱后新增任务显示需配置目标的消息并保持不可保存。

存储库增删改和其他设置分组保存时必须保留这三个字段，不能因为表单未编辑它们而写回默认空值。笔记与笔记本分组保存时允许同时配置或清空三个字段。收件箱记录包含完成记录；某天只显示未完成记录，差异由 UI 的通用查询请求表达，Core 不读取这些宿主设置。

* 应用配色

全 App 固定为与侧边栏一致的深色配色，不新增 Preferences 开关。启动时设置应用颜色模式为深色，系统状态栏、导航栏和启动背景使用 ~#2D2C2B~ ，弹窗和原生输入控件沿用深色模式。页面颜色从 ~UiColor~ 读取，具体色值见 [[file:UI导航设计.org][UI 导航设计]]。

* 备忘文件入口

“设置 → 笔记与笔记本 → 文件入口”新增 ~memoFile~ ，默认空字符串，使用与收件箱/某天相同的路径校验与保存方式。存储库增删改和其他设置页面保存时必须保留该字段。备忘请求通过 ~overviewTaskQuery('memo', ..., memoFile)~ 生成文件表达式，并设置 ~includeDone=true~ 、 ~includeComposeTasks=true~ ，由 Core 返回全部标题记录；UI 不自行过滤。

备忘未配置时点击侧边栏入口显示“尚未配置备忘”并提供前往设置；清空后恢复该状态，不清理原文件或内容。

仓库设置页为本地与 WebDAV 仓库提供“名称”输入。清空后恢复当前仓库名作为默认显示值，不把该默认值固化为配置名称；因此目录变更后的缺省名称随新目录更新。只修改名称不更改配置 ID、Core 的 ~.sync/id~ 、根目录、远端配置或凭据别名。

存储库配置的删除入口仅位于已保存项目的配置页底部。 ~AppConfigService.removeRepository~ 重新读取设置，保存剔除目标 ID 的仓库集合并保留全部其他全局配置，再清除该 ID 对应的 Asset Store 密码。该过程不删除磁盘目录、Org 文件、 ~.sync~ 或远端数据；新建表单没有删除入口。文件清单中的空存储库与读取失败的存储库仍保留配置入口。

存储库配置编辑后通过工具栏返回或系统返回保存，不再提供应用/保存按钮。加载时保留规范化草稿用于变更比较；未修改直接返回，新建未编辑草稿不落盘。保存前重新读取其他配置，防止覆盖全局设置；正在测试连接、保存或删除时阻止重复返回。保存失败不退出，可继续编辑或放弃修改。

* 文件展示方式

“设置 → 笔记与笔记本 → 文件展示 → 文件展示方式”提供“渲染（默认）”和“原文”，选择后沿用该页的“保存设置”统一提交。打开文件时读取已保存的 fileDisplayMode，rendered 显示整篇 Org 渲染内容，source 显示可复制的完整等宽原文；文件页不再显示阅读/原文切换或只读提示行。文件 TITLE 只在工具栏显示，正文不重复生成文件标题；真实 Org 标题仍正常显示。

此设置仅控制文件详情，不影响任务详情的富文本正文和独立日志区域。旧用户没有该键时保持默认渲染。存储库增删改及其他设置保存必须保留当前展示方式，不能将其恢复为默认；该偏好只写入宿主 Preferences，不写入 Org、Core 同步记录或 outbox。重新进入文件或同步刷新后采用已保存值。

* 快速捕捉目标与草稿

“设置 → 笔记与笔记本 → 快速捕捉”维护 ~captureRepoId~ ，保存后生效。捕捉面板不提供目标切换，默认存储库统一在该设置分组保存。空值仅在恰好一个存储库时自动选择；多个存储库时必须明确指定，非空但已失效的 ID 一律要求重新选择。仓库删除仍保留失效 ID，避免错误回退到其他存储库。仓库表单、其他设置分组与删除操作均保留此字段。

捕捉只提交标题，使用 ~inboxFile~ 指定的相对路径，目标文件初始状态与所有写入校验沿用 Core。外部入口不能指定绝对目录、其他文件或凭据。日期文字保留在标题中，不创建计划日期、截止日期、标签、优先级或正文。

草稿保存在独立 Preferences 的 ~drafts~ 数组，每项只有 ~id~ 和 ~title~ 。输入更新、新请求接入与清理按顺序执行；外部新标题与旧草稿分别保留，不覆盖旧标题。保存成功后只删除已提交草稿，其他草稿在后续空白捕捉时按最近顺序自动恢复；面板不显示草稿选择器。语音录音只在内存中传给平台识别服务，不保存音频；标题与识别原文不进入日志。语音优先尝试离线引擎，离线引擎不可用时回退在线引擎；文字捕捉始终先写本地。
