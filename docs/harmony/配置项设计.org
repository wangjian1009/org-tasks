* 范围与边界

本文定义 Harmony 宿主的配置、凭据与保存边界。Harmony 从 Preferences 与安全存储取得仓库根目录和远端配置，再调用 core 打开并维护本地 ~OrgRepo~ 。core 负责 org 文件扫描和解析； ~core::webdav~ 负责同步文件写回与同步记录生成。核心模型见 [[file:../core/数据模型.org][数据模型]]，仓库 API 见 [[file:../core/接口文档.org][接口文档]]，本地控制目录见 [[file:../core/目录结构设计.org][目录结构设计]]。

配置、凭据与持久化状态必须分离。密码、令牌和客户端证书不能写入 Preferences、core 同步记录、HTTP 请求日志、进度事件或错误摘要。core 的 ~repoId~ 由仓库根目录的 ~.sync/id~ 持久化；现有宿主另用配置 ID 定位秘密，身份统一尚未落地，差异见本文末尾。

配置、捕捉草稿和日历映射通过 ~PreferencesStore~ 处理 Preferences 的同步异常与异步失败。封装将读取、写入和刷新失败统一作为 Promise 拒绝交给调用方，不在存储层返回缺省值或报告保存成功；日历映射读取失败仍由原调用方决定恢复方式。错误摘要仅包含操作说明与平台错误码，不包含键值、文件路径或凭据；既有存储名称、字段和保存顺序保持原样。

~OrgWorkspace~ 是应用级核心结构；一个应用通常只构造一个。CalendarKit 映射、N-API service 实例和退出同步的后台运行任务都是 Harmony 运行时概念，不是 ~OrgWorkspace~ 或 ~OrgRepo~ 的字段。

* 配置模型

当前运行代码使用 ~AppConfig~ ，直接将 ~repos~ 、入口文件路径及其仓库 ID、 ~calendarName~ 、 ~todoDefaults~ 和 ~fileDisplayMode~ 作为 Preferences 键保存，没有 ~version~ 字段或嵌套的日历、调度对象。每个入口由仓库 ID 与相对文件路径共同确定；统一存储库文件页与配置表单负责增删改，core 在加载目录时读取或创建 ~.sync/id~ 。手机用户可见配置与交付范围见 [[file:../手机应用功能清单.org][手机应用功能清单]]。

#+begin_src ts
interface AppConfig {
  repos: RepoConfig[]
  inboxFile: string
  inboxRepoId: string
  somedayFile: string
  somedayRepoId: string
  memoFile: string
  memoRepoId: string
  calendarName: string
  todoDefaults: string
  fileDisplayMode: 'rendered' | 'source'
}

interface RepoConfig {
  id: string
  name: string
  rootDirectory: string
  webdavEnabled: boolean
  webdavUrl: string
  webdavUsername: string
  webdavPassword: string
  excludedDirectories: string[]
}
#+end_src

~RepoConfig.webdavPassword~ 是内存中的临时值，真实秘密保存在 Asset Store；序列化的 ~repos~ 中同名字段固定为空字符串。目前 ~RepoConfig.id~ 由宿主生成，与 core 目录的仓库身份并非同一值；后续统一身份前，不能混用两者。

| 配置范围 | 当前字段 | 保存位置 | 约束 |
|-
| 全局日历 | ~calendarName~ | Preferences | 保留旧日历名称，默认 ~Org Tasks~ ；当前无日历同步入口，设置页不编辑该值。 |
| 全局 TODO 默认 | ~todoDefaults~ | Preferences | 外部保存 TODO 流程声明文本；未保存时调用 Rust 默认接口，已保存空值不回退。 |
| Core 状态分类设置 | ~coreSettings~ | Preferences | 结构化 ~CoreSettings~ JSON；保存 ~additionStates~ ，固定默认状态由 Core 内部管理。 |
| 文件展示 | ~fileDisplayMode~ | Preferences | 默认 ~rendered~ ，可选 ~source~ ；旧配置缺失或值无效时使用渲染。 |
| 仓库配置 ID | ~repos[].id~ | Preferences | 当前用于列表定位、编辑和 Asset Store 别名；与 core 仓库身份不同。 |
| 仓库显示名 | ~repos[].name~ | Preferences | 可为空，保存时去除首尾空白；旧配置缺失时按空值处理，显示时回退根目录末级名称，不改变仓库或凭据身份。 |
| 仓库根目录 | ~repos[].rootDirectory~ | Preferences | 非空绝对目录路径；构造时映射为 ~OrgRepo.rootDirectory~ ，不写入 core 同步记录。 |
| 收件箱文件 | ~inboxFile~ + ~inboxRepoId~ | Preferences | 由应用内仓库分区文件列表选择；只保存已存在且未命中 ~is_ignore~ 的仓库与文件。 |
| 某天文件 | ~somedayFile~ + ~somedayRepoId~ | Preferences | 通过同一应用内仓库分区文件列表选择；某天入口查询所选文件中的未完成记录。 |
| 备忘文件 | ~memoFile~ + ~memoRepoId~ | Preferences | 通过同一应用内仓库分区文件列表选择；备忘入口查询所选文件中的全部标题记录。 |
| WebDAV 启用 | ~repos[].webdavEnabled~ | Preferences | 决定是否为该仓库构造 WebDAV 策略。 |
| WebDAV 地址 | ~repos[].webdavUrl~ | Preferences | 表单限定 HTTPS；由 WebDavSyncPolicy 使用，不进入核心数据模型。 |
| WebDAV 用户名 | ~repos[].webdavUsername~ | Preferences | 非机密标识；不得拼接入日志 URL。 |
| WebDAV 密码 | ~repos[].webdavPassword~ | Asset Store | Preferences 只保留空值占位；运行时载入，不能写入日志和 core 记录。 |
| WebDAV 过滤目录 | ~repos[].excludedDirectories~ | Preferences | 同步调用时作为 ~SyncOptions~ 传入 core；默认值由 Rust 提供，当前为 ~archive~ 。 |

关闭 ~repos[].webdavEnabled~ 时不构造 WebDAV ~SyncPolicy~ ，仓库仍是本地 ~OrgRepo~ 。

旧已保存查询的读取服务与界面入口已删除；不再读取或写入 ~org_tasks_saved_searches~ ，已有 Preferences 数据不迁移、不主动删除。

* 通知授权状态

通知授权流程使用独立 Preferences ~org_tasks_notification~ ，仅保存布尔值 ~notificationPromptHandled~ ，缺失默认为假；不属于 ~AppConfig~ ，不随仓库保存、删除或重置改写，也不进入 Core 或同步目录。主界面前台发现系统已允许时补记为真；首次请求前保存为真，拒绝后保留，技术失败或发起前退到后台时撤回为假。普通重启与升级保留标记，清除应用数据后重新开始；已有用户升级后也按缺失字段处理，若系统已允许则不弹窗。实际授权状态每次从系统读取，不持久化为本地权限副本。

* 凭据与 Workspace 构造

每个仓库的秘密以独立 Asset Store 记录保存，当前别名为 ~org-tasks.webdav.<configId>.password.v1~ ，其中 ~configId~ 是 ~RepoConfig.id~ ，不是 core 的目录 ID。记录设置 ~DEVICE_FIRST_UNLOCKED~ 、持久化和覆盖语义，以支持已解锁后的后台同步。保存时先写秘密再提交 Preferences；失败后的回滚/清理尚未实现，不能将其描述为已有能力。

Harmony 根据 ~repos~ 构造一个 ~OrgWorkspace~ ，由 core 加载各根目录并读取或创建 ~.sync/id~ 。AppConfigService 常规读取配置时为所有仓库查询 Asset Store；快速捕捉使用不含凭据的读取方式，仅取得本地写入配置。同步时仅为启用 WebDAV 的仓库创建 ~core::webdav::WebDavSyncPolicy~ 。控制目录或布局无效时加载失败，不触发网络同步。

根目录、WebDAV 地址、用户名和密码是宿主运行时输入，不能写入 core 的 ~OrgRepoSyncRecord~ 或 ~OrgRepoSyncFileRecord~ 。 ~OrgRepo~ 不承担远端地址或认证字段。

* 持久化职责

| 数据 | 所有者 | 保存位置 | 内容与限制 |
|-
| 用户配置 | Harmony | Preferences 的 ~org_tasks_config~ | ~AppConfig~ ；不保存真实密码、同步历史或完整文件；现有状态键混存问题见下文。 |
| WebDAV 密码 | Harmony | Asset Store | 每个 ~RepoConfig.id~ 独立秘密记录。 |
| 仓库同步记录与身份 | core ~OrgRepo~ | ~rootDirectory/.sync/~ | ~id~ 保存唯一 ~repoId~ ； ~history/~ 追加保存 ~OrgRepoSyncRecord~ 与 ~OrgRepoSyncFileRecord~ ， ~outbox/~ 保存待上传路径与哈希 。不保存凭据或绝对路径；实际远端基线、历史正文与冲突快照由 Core 按统一同步设计保存。 |
| 日历映射 | Harmony | ~org_tasks_config~ 中的 ~calendar_sync_state~ 键 | 当前保存日历名称、任务 ID、事件 ID 和指纹；尚未按目标设计隔离到独立存储。 |
| 捕捉草稿 | Harmony | Preferences 的 ~org_tasks_capture~ | ~drafts~ 仅保存草稿 ID 与未保存标题；独立于配置、凭据、Org 文件与同步记录；成功保存后移除对应草稿。 |
| 桌面备忘卡片 | Harmony | 每个卡片独立的 ~org_tasks_memo_card_<formId>~ Preferences | ~tag~ 保存此实例选择的一个标签，空字符串表示全部备忘；不保存任务内容、凭据或文件副本，移除卡片时清理。 |
| WebDAV 缓存与旧写入队列 | 旧实现 | 不属于当前配置 | 当前接口不读取或转换这些数据。 |

日历映射中的任务 ID 直接使用 Core 的明文逻辑路径编码，不再采用“仓库 ID、文件路径、字节偏移”的旧格式。已有映射保留，定时日历同步入口已移除；后续重新接入日历同步时仍须遵循 Core 逻辑身份，不猜测旧偏移与新标题的对应关系。状态、首尾进度和无关记录增删不再因位置变化重建日历身份；仓库根路径、文件路径或任务祖先标题变更仍会产生新身份。

~lastSyncTime~ 是旧版日历同步留下的状态，不是配置或按仓库的 Core 同步历史。移除定时同步后不再读取或写入该键，保留原值和 ~calendar_sync_state~ ，不因关闭调度删除用户已有的系统日历事件。

* 设置、更新与删除

设置页面编辑 ~AppConfig~ 草稿，字段修改后自动保存；保存时重新读取其他配置，避免覆盖文件入口或其他页面的更新。TODO 默认流程变化后更新活动 workspace，文件展示方式只影响后续普通文件详情和历史备份阅读页面。目录集合变化时 workspace 重建；目录不变时沿用 session，WebDAV 策略在下一次同步按新参数临时构造。活动同步控制由 Harmony 运行时负责，不进入 core 数据结构。

当前新建流程：校验表单、按需创建应用管理的目录、调用 core 验证目录并初始化其身份、写入凭据、写入 Preferences。配置 ID 在 core 验证前由宿主生成，不随目录 ID 变化。删除时经用户确认移除配置与密码，保留本地文件。

* 已有约束与待修复差异

| 约束 | 当前实现差异 | 处理边界 |
|-
| core 仓库 ID 为稳定身份来源 | 配置 ID 与 core ID 分离，凭据仍绑定配置 ID | 需专门设计秘密重绑定；本次不修改或清空已有 ID。 |
| 状态与配置分离 | 日历映射和最后日历同步时间混存在配置 Preferences | 需隔离状态存储；本次不删除事件映射。 |
| 秘密写入失败恢复 | 写入所有仓库秘密后提交 Preferences，没有事务回滚 | 需单独修复凭据持久化流程。 |
| 本地仓库无远端时不读取秘密 | 当前加载所有配置都会查询 Asset Store | 属于调用收敛问题，不是未支持的配置开关。 |
| 删除配置前阻止活动同步 | 当前页面只能限制本页操作，没有全应用同步互斥控制 | 需补齐宿主活动任务控制，不能宣称已验收。 |

上述约束仍是改进方向，不应作为已交付功能写入清单。参考配置的保留/不纳入范围以核对表及用户确认结果为准。

* 界面配置入口

本轮界面将全局设置与单个存储库草稿分开： ~Settings.ets~ 编辑文件展示、TODO 默认流程与任务状态分类，字段修改后自动保存且不显示保存按钮； ~Files.ets~ 管理存储库与文件列表； ~RepositorySettings.ets~ 编辑目录和 WebDAV。保存时重新载入其他配置，保持未编辑字段的最新值。新建 WebDAV 默认使用应用私有目录，宿主只创建该目录，扫描、仓库身份和内容加载仍由 core 验证。

当前不提供日历同步入口。启动、下拉和退出同步仅执行存储库文件同步，不读取或更新 ~lastSyncTime~ ，也不请求日历权限。

定时同步策略已移除：不注册 WorkScheduler 作业，不提供同步间隔配置，旧 ~syncInterval~ Preferences 键不再读取或写入。应用启动时仅由 ~LegacySyncScheduleService~ 枚举并取消旧版 ~workId=1001~ 且目标为 ~SyncWorkExtension~ 的持久化作业；不影响其他作业，清理失败时下次启动重试。旧扩展入口已从模块清单删除。

主界面首次显示并处于前台时以 ~Reuse~ 请求一次同步，不申请后台任务或发布同步通知。启动标记、会话句柄和 ~Wait~ 队列只在进程内保存，不新增 Preferences 字段；普通恢复前台不重新触发。

主界面退后台后按本地变化执行单次文件同步，不依赖时间间隔，不新增自动同步开关或 Preferences 字段。先不读取凭据，仅对已启用 WebDAV 的仓库查询 Core 本地变化；需要执行时由共享同步入口以 ~Reject~ 受理请求，已有会话不重复启动。手动入口以 ~Wait~ 入队，在轮到执行时读取最新配置与 Asset Store 凭据。变化状态来自 Core 文件与基线比较，不持久化宿主 dirty 标记、最后上传时间或实况窗进度；失败不清除本地变化。该触发仅同步文件，不写 ~lastSyncTime~ 或日历映射。实况窗复用已有通知授权与数据传输后台任务，不在后台申请用户授权。

* 保存前连接测试

WebDAV 表单的“测试连接”使用当前草稿中的地址、用户名和密码构造 ~CoreWebDavSyncPolicy~ ，调用原生 ~testConnection()~ 。该操作不要求配置已保存或本地目录存在，不访问 Preferences、Asset Store、活动 workspace、同步历史或日历，也不把测试结果持久化。

测试仅验证认证与目标目录访问，最多等待 15 秒。成功不代表具有上传权限；实际条件写入仍在同步时验证。失败消息不包含密码、完整 URL 或响应正文。测试期间禁止修改字段、重复测试、保存和返回；完成后恢复。地址、用户名、密码或 WebDAV 启用状态变化时立即清除旧结果。保存仍是独立操作，不强制先测试，也不因测试成功自动提交配置。


* 合并比较与冲突备份

任务合并没有新增 Preferences 配置。比较结果是一次同步的运行时对象，可直接交给 core apply；其中的仓库与远端版本、临时变化 ID 和任务正文不持久化为配置。界面只填写处理枚举，保留未变化任务。

按已确认的冲突处理规则，备份保存在所属仓库的 ~.sync/backups/<合并开始时间>/~ ，保留相对子目录，文件名附带本地日期时间与随机后缀。该目录是完整本地冲突文件的专用备份区，是控制目录不保存完整内容规则的明确例外；历史和 outbox 仍只保存元数据，备份不会被扫描、查询或上传。

原有单文件备份留在应用私有目录中的副本不会自动删除；新合并统一使用按同步分组的目录。 ~WebDavSyncFileDetail.task_versions~ 是可选的身份/内容指纹元数据，不是任务快照；旧历史仍可读取。Core 不将比较对象、密码或绝对备份路径写入历史。

* TODO 全局默认与文件覆盖

“设置 → 笔记与笔记本 → 默认 TODO 流程”编辑全局 Org 声明文本，由外部保存到 ~org_tasks_config.todoDefaults~ 。唯一缺省值来源是 Rust ~TodoConfig::default()~ ，Harmony 通过异步 ~defaultTodoSettings()~ 获取初始值或恢复编辑草稿；ArkTS 不维护另一套默认关键词。 ~DEFAULT_CONFIG.todoDefaults~ 的空值仅用于加载前占位，实际加载根据 Preferences 是否存在该键决定是否使用默认值。

保存前通过 native ~Workspace.setTodoDefaults~ 调用 Rust 校验。其他配置页面保存时保留当前 ~todoDefaults~ ，同步设置页不覆盖未编辑的 TODO 设置。配置不写入 Org 文件、同步历史或 outbox，恢复默认也只修改编辑草稿，保存后才生效。

每次取得 workspace 时由外部显式传入默认配置。目录不变时沿用 session；设置变化时更新同一 native workspace 并重解析文件。文件自己的声明整组覆盖全局值，查询、后台同步、日程、笔记本与新增任务共用相同配置。合并提交前重新读取外部配置，使旧对象受到 core 版本校验。

空全局配置表示默认不识别 TODO；文件仍可用声明启用自己的流程。文件内空 ~#+TODO:~ 则清空该文件的状态。输入错误明确显示；分类、快捷键和日志标记由 Core 解释，状态日志按有效配置触发。

** 任务状态分类设置

“设置 → 笔记与笔记本 → 任务状态分类”逐一展示 ~Todo~ 、 ~Doing~ 、 ~Wait~ 、 ~Done~ 、 ~Cancel~ 。默认状态作为只读文本展示，附加状态提供输入、添加与移除；非法状态或重复归属显示中文错误并保留输入。分类用于识别运行状态，与文件 ~CATEGORY~ 分类及普通 ~TAGS~ 配置独立。

~CoreSettings~ 通过 ~Workspace.getSettings()~ 与 ~Workspace.setSettings()~ 读写，Preferences 的 ~org_tasks_config.coreSettings~ 以 JSON 保存 ~{ additionStates: [{ name, category }] }~ ，与原有 TODO 流程文本独立。缺失时从空 Workspace 获取默认对象，不将固定默认状态复制到 ArkTS。设置页按五类组织附加值，每组显示“内置默认状态不可修改”；添加与移除只修改附加列表，错误保留输入。分类设置随全部前后台 Core 请求传入。旧配置中的 ~Cancle~ 通过 Core 的兼容反序列化规范为 ~Cancel~ ，设置界面与后续保存统一使用新名称；加载时不改写 Preferences。恢复 TODO 流程默认值不清除附加状态。

Core 固定默认值、跨配置来源合并顺序与分隔规则见 [[file:../core/数据模型.org::*任务运行状态分类][任务运行状态分类]]。文件或 ~SETUPFILE~ 可携带相同声明，随原 Org 配置读取；手机设置编辑的仅为全局附加值。

* WebDAV 同步过滤目录

每个存储库在 WebDAV 表单提供“同步过滤目录”输入行，以逗号分隔目录名。“恢复默认过滤目录”从 Rust 读取默认值，当前为 ~archive~ 。旧配置缺失 ~excludedDirectories~ 时从 Rust 补齐；已保存空列表时保持为空，表示不排除任何目录。保存前通过原生 ~normalizeSyncOptions(options)~ 调用 core 验证目录名，校验失败不写入凭据和 Preferences。

前台与后台同步从已保存配置构造 ~SyncOptions~ 并传入 ~Repo.sync~ ，不把规则存入凭据或 policy。规则仅影响 WebDAV 传输；已有本地文件及待上传意图保留。

* 顶部文件入口配置与缺失反馈

三个文件入口都在应用内自定义页面按仓库分区展示 Core 返回的文件列表，过滤 ~is_ignore=true~ 项；选择后同时保存仓库 ID 和相对路径。入口未选择时保存为空，不显示系统文件选择器，也不让用户手写路径猜测目标。旧版只有路径的配置保留原路径供识别，但不推测或自动补齐仓库 ID，即使仅有一个仓库也要求重新选择。仓库被删除后保留原有绑定身份，防止误指向后来添加的仓库。

点击未配置的收件箱、某天或备忘时弹出中文提示，“前往设置”进入笔记与笔记本分组；取消后保留当前页面。空配置不执行空路径查询，也不创建文件。已配置但仓库或文件失效、文件被忽略时提示重新选择；已选文件存在且没有标题时显示零记录。清空收件箱后新增任务显示需配置目标的消息并保持不可保存。

存储库增删改和其他设置分组保存时必须保留这三个字段，不能因为表单未编辑它们而写回默认空值。笔记与笔记本分组保存时允许同时配置或清空三个字段。收件箱记录包含完成记录；某天只显示未完成记录，差异由 UI 的通用查询请求表达，Core 不读取这些宿主设置。

* 应用配色

全 App 固定为与侧边栏一致的深色配色，不新增 Preferences 开关。启动时设置应用颜色模式为深色，系统状态栏、导航栏和启动背景使用 ~#2D2C2B~ ，弹窗和原生输入控件沿用深色模式。页面颜色从 ~UiColor~ 读取，具体色值见 [[file:UI导航设计.org][UI 导航设计]]。

* 备忘文件入口

“设置 → 笔记与笔记本 → 文件入口”新增 ~memoFile~ ，默认空字符串，使用与收件箱/某天相同的路径校验与保存方式。存储库增删改和其他设置页面保存时必须保留该字段。备忘请求通过 ~FileTargetService.query(config, 'memo')~ 生成文件表达式，并设置 ~includeComposeTasks=true~ ，表达式不限制状态，由 Core 返回全部标题记录；UI 不自行过滤。

备忘未配置或失效时点击侧边栏入口显示“备忘文件未选择或已失效”并提供前往设置；清空后恢复该状态，不清理原文件或内容。

桌面备忘卡片使用相同的文件入口配置，不增加来源设置。 ~MemoFormExtension~ 运行于独立扩展进程，每次刷新先通过 ~removePreferencesFromCache~ 清除自身的 ~org_tasks_config~ 缓存，再以不含凭据的方式读取配置，并由 Core 重新加载目标本地仓库；不请求 WebDAV 密码或执行网络同步。可见性回调与系统定时刷新只更新卡片展示，不修改入口、Org 文件或同步记录。

卡片长按菜单的编辑入口由服务卡片配置 ~formConfigAbility=ability://MemoCardConfigAbility~ 声明。系统传入的 ~form_identity~ 使用完整字符串作为实例身份，不转为 JavaScript 数字，缺失或无效时不写设置。 ~MemoCardService~ 按实例读取、保存和清理独立 Preferences，每次读取先清除本进程缓存；默认 ~tag~ 为空。独立存储避免不同卡片的跨进程保存覆盖彼此，卡片配置不进入 ~AppConfig~ 或 Org 文件。修改标签仅在点击“确定”后通过 ~PreferencesStore.put~ 与 ~flush~ 持久化，再调用 ~formProvider.updateForm~ 更新当前实例；返回不保存，写入或更新失败不报告完成。扩展后续刷新继续使用该实例的标签，标签不再存在时保持空结果，不静默改为全部备忘。

仓库设置页为本地与 WebDAV 仓库提供“名称”输入。清空后恢复当前仓库名作为默认显示值，不把该默认值固化为配置名称；因此目录变更后的缺省名称随新目录更新。只修改名称不更改配置 ID、Core 的 ~.sync/id~ 、根目录、远端配置或凭据别名。

存储库配置的删除入口仅位于已保存项目的配置页底部。 ~AppConfigService.removeRepository~ 重新读取设置，保存剔除目标 ID 的仓库集合并保留全部其他全局配置，再清除该 ID 对应的 Asset Store 密码。该过程不删除磁盘目录、Org 文件、 ~.sync~ 或远端数据；新建表单没有删除入口。文件清单中的空存储库与读取失败的存储库仍保留配置入口。

存储库配置编辑后通过工具栏返回或系统返回保存，不再提供应用/保存按钮。加载时保留规范化草稿用于变更比较；未修改直接返回，新建未编辑草稿不落盘。保存前重新读取其他配置，防止覆盖全局设置；正在测试连接、保存或删除时阻止重复返回。保存失败不退出，可继续编辑或放弃修改。

* 文件展示方式

“设置 → 笔记与笔记本 → 文件展示 → 文件展示方式”提供“渲染（默认）”和“原文”，选择后立即自动保存。打开文件时读取已保存的 fileDisplayMode，rendered 显示整篇 Org 渲染内容，source 显示可复制的完整等宽原文；文件页不再显示阅读/原文切换或只读提示行。文件 TITLE 只在工具栏显示，正文不重复生成文件标题；真实 Org 标题仍正常显示。

此设置仅控制文件详情，不影响任务详情的富文本正文和独立日志区域。旧用户没有该键时保持默认渲染。存储库增删改及其他设置保存必须保留当前展示方式，不能将其恢复为默认；该偏好只写入宿主 Preferences，不写入 Org、Core 同步记录或 outbox。重新进入文件或同步刷新后采用已保存值。

项目文件进入独立 ~ProjectDetail~ ，默认以文档渲染；“查看原文”只切换当前阅读会话，不读取或修改 ~fileDisplayMode~ 。任务展开状态与阅读锚点也只保存在当前页面，按仓库 ID、相对路径和文件版本隔离，不写入 Preferences、Org 文件或同步记录。配置字段与既有存储保持不变。

* 快速捕捉与草稿

快速捕捉不提供独立目标设置，直接使用“设置 → 笔记与笔记本 → 文件入口”中已选择的 ~inboxRepoId~ 与 ~inboxFile~ 。没有有效收件箱目标时明确提示配置。

捕捉保留完整输入作为标题，使用 ~inboxFile~ 指定的相对路径，目标文件初始状态与所有写入校验沿用 Core。保存时调用华为 Natural Language Kit 尝试识别地址和时间：地址以 ~addr:~ 链接写入正文，首个有效日期时间通过 ~Creation.scheduled~ 写入 ~SCHEDULED~ 。无结果、服务异常或不支持时仍保存完整标题。外部入口不能指定绝对目录、其他文件或凭据；不新增识别开关、Preferences 字段或草稿字段，识别结果仅随任务保存在 Org 文件中。

快速捕捉保存时自动请求 Core 写入 ~CREATED~ 属性，值为设备本地时间的非活动时间戳，精确到分钟。创建时间只保存在新任务的 Org ~PROPERTIES~ drawer 中，不新增 Preferences 配置或草稿字段；草稿等待和录音阶段不生成时间，已有记录不回填，读取与同步不重写。

草稿保存在独立 Preferences 的 ~drafts~ 数组，每项只有 ~id~ 和 ~title~ 。输入更新、新请求接入与清理按顺序执行；外部新标题与旧草稿分别保留，不覆盖旧标题。保存成功后只删除已提交草稿，其他草稿在后续空白捕捉时按最近顺序自动恢复；面板不显示草稿选择器。语音录音只在内存中传给平台识别服务，不保存音频；标题与识别原文不进入日志。语音优先尝试离线引擎，离线引擎不可用时回退在线引擎；文字捕捉始终先写本地。

文件入口选择页使用当前配置中的仓库名称分区，主行展示 Core 文件标题、辅行展示完整相对路径，并标记已选文件。点击文件后立即保存，返回设置后显示“仓库名称 / 相对路径”；“清除选择”同时清空仓库 ID 和文件路径。保存期间禁用重复选择与返回。提交前重新读取配置与 Core 文件元信息，拒绝已经删除或被忽略的文件；仅更新当前入口，不覆盖其他入口、TODO 草稿或其他页面的新配置。设置页返回时刷新入口显示并保留尚未提交的其他设置草稿。

入口查询、侧边栏计数与捕捉保存共用 ~FileTargetService~ 的目标校验，只向所选仓库发送基于相对路径的 Core 查询。空仓库 ID 不表示全仓库查询，失效 ID 不回退到首个仓库；捕捉不得因目标删除而新建同名文件。普通存储库浏览默认隐藏命中忽略规则的文件，可通过工具栏按钮显示完整文件列表；忽略状态仍只影响选择候选和 Core 任务扫描。

* 收件箱整理目标

底部移动面板的普通目标来自 Core REFILE 快照，分类来自所在文件 CATEGORY，不把目标快照保存到 Preferences。左滑的“备忘”快捷操作直接使用已配置的 ~memoRepoId~ 与 ~memoFile~ ，提交前检查仓库、路径和忽略状态；失效时提示重新选择，不回退到其他文件。成功移动到备忘文件顶部，并清除根条目的任务状态、优先级及 ~SCHEDULED~ 、 ~DEADLINE~ 、 ~CLOSED~ 规划信息，保留正文、标签、 ~CREATED~ 等属性和子条目。移动面板当前快照、高度与选择保留在页面内存，最近点选按 [[*移动位置最近选择][移动位置最近选择]] 单独保存。

* 将来，也许快捷入口

移动托盘的“将来，也许”复用现有 ~somedayRepoId~ 与 ~somedayFile~ ，不新增文件选择或 Preferences 字段。该文件与当前收件箱一起通过 ~RefileTargetQuery.excludedFiles~ 在 Core 生成 CATEGORY 前排除；其 REFILE 标题不形成普通分组。快捷入口使用 ~files~ 单独查询所选文件，移动到首个 REFILE 节点的第一个子节点，清除根任务规划信息并设置 TODO。配置失效或 TODO 不被目标文件接受时明确提示，不能回退到首个仓库或其他同名文件。

* 重置本地目录的配置边界

仓库重置只调用 ~Repo.reset~ ，保留 ~RepoConfig~ 、Asset Store 密码、入口文件绑定与原 Core 仓库 ID。它与“删除存储库”不同，不移除配置或凭据；绑定的文件重置后暂不存在，相关入口沿用已有缺失提示。确认目标使用保存配置中的根目录，未保存的目录草稿不得用于重置。重置不访问远端，下次同步重新建立本地基线。

* 冲突预览缓存

ConflictFile 进入时把 ~<cacheDir>/org-conflict-previews~ 作为 setPreviewRoot 参数传给同一长期 Workspace。它是运行时私有缓存位置，不增加 Preferences 配置项，不保存凭据或可恢复草稿。Core 验证其在全部仓库之外，通过 workspace 租约与 UUID 子目录维护临时文件；结束、取消或会话清理后删除，重启从真实源文件重新开始。临时身份固定为带尖括号的 ~<preview>~ ，不属于配置仓库 ID 或 Core 真实仓库 ID。

* 移动位置最近选择

~MoveTargetHistoryService~ 使用独立 Preferences ~org_tasks_move_targets~ 的 ~recentTargets~ 字符串键保存 JSON 数组，最多保留 100 个去重后的目标键，最新点选位于数组头部。各入口共用串行写入队列，点选即记录，不要求已执行移动；打开时自动恢复选择不另记一次点选。存储失败沿用 ~PreferencesStore~ 的拒绝语义，面板显示读取重试或重新选择提示，不把存储成功作为移动提交结果。

目标键是 Core 仓库 ID、相对文件路径、 ~fullPath.titles~ 与 ~occurrence~ 的结构化 JSON，不包含文件版本、字节位置、密码或绝对目录。标题定位沿用 Core 的规范路径，因此统计进度变化不改变位置键；同名位置按出现次序区分。每次打开用本次 Core 目标快照匹配历史，失效键不形成候选或提交目标；不依据名称跨仓库、文件或同名次序回退。分组顺序取组内最靠前的历史位置，组内按历史顺序排列，未选择位置沿用初始顺序。重启和升级保留此偏好，清除应用数据后恢复默认；不属于 ~AppConfig~ 、Core 仓库元数据或同步内容。
