* 目标与范围

快速捕捉只收集一个标题，统一写入已配置存储库的收件箱文件。日期、标签、优先级和正文不属于本轮捕捉表单；语音内容中的日期只作为标题文字保留。保存复用 Core 的任务创建、有效初始状态、保真编辑和离线上传意图。

本轮先统一完成代码、配置与设计画板，再统一构建，在 HarmonyOS 模拟器与真机验收。系统推荐曝光、小艺云端分发和真实语音识别分别记录实际验证范围，不以构建通过代替端到端验收。

* 入口与一致交互

| 入口 | 本轮交付 |
|-
| 桌面服务卡片 | 提供“记一条”和“说一句”，只提供 ~1*2~ 最小尺寸，只显示两个操作，支持桌面固定与上滑图标展开。 |
| 负一屏 | 复用同一服务卡片；能否固定和系统是否展示以设备系统宿主为准，不建立独立捕捉实现。 |
| 语音录入 | 麦克风按钮接入平台语音识别，识别结果填入标题，允许修改后保存；权限拒绝或服务不可用时可继续打字。 |
| 小艺意图 | 注册携带标题的前台捕捉意图，进入统一确认界面；不自动解析任务属性，不在后台静默写入。 |
| 系统分享 | 接收文字和链接，转换为单行标题并进入统一确认界面；不额外保存正文或附件。 |
| 长按图标 | 提供文字与语音捕捉快捷操作。 |
| 应用内 | 保持 master 的新增入口移除状态，不增加快速捕捉按钮或完整新增任务入口；设置中仅维护默认捕捉目标。 |
| 外部调用 | 提供只传标题的显式入口与应用链接，统一走前台确认。 |

单仓库时直接使用该仓库；多仓库时在设置中明确选择默认捕捉仓库，捕捉时只输入标题。默认目标使用宿主配置 ID，不混用 Core 仓库 ID。收件箱未配置、仓库被删除或无可用初始状态时保留标题并引导修正配置，不自动改写到其他位置。

所有入口共用标题输入、草稿、保存状态和失败反馈。保存期间阻止重复提交，成功后关闭捕捉窗口并回到来源；返回或中断保留未保存标题。新外部请求不得覆盖已有未保存草稿。标题和识别原文不写入日志。

* 开发步骤

** DONE 1. 统一捕捉流程与默认目标

- 新增仅标题捕捉界面、宿主编排服务、独立捕捉窗口和草稿持久化。
- 新增默认捕捉仓库设置，所有配置读写入口保留该值；删除目标后显式要求重新选择。
- 复用现有异步 bridge，串行调用仓库创建与同步，不在宿主生成 Org 文本。

** DONE 2. 平台入口统一接入

- 注册服务卡片、长按快捷操作、分享接收和外部调用入口。
- 处理冷启动、热启动和多次请求，捕捉窗口独立于当前浏览页面。
- 卡片只提供 ~1*2~ 最小尺寸；两个操作分别打开键盘或自动语音捕捉。

** DONE 3. 语音与小艺意图

- 接入前台麦克风授权、语音引擎、识别结果与取消/释放生命周期。
- 注册只包含标题参数的捕捉意图；缺少标题时仍可手工录入。
- 服务不可用、取消和识别失败保留原草稿，不产生空任务。

** DONE 4. 文档与界面设计同步

- 更新 UI 导航、配置设计和手机应用功能清单。
- 在现有界面图谱内补充快速捕捉、卡片、默认目标与语音状态画板。
- 检查 Org 行内标记边界，并通过 Org AST 确认代码标记。

** TODO 5. 统一构建与设备验收

统一编码结束后开始此阶段，修复构建或模拟器发现的问题后重新验证受影响路径。

| 验收项 | 通过条件 |
|-
| 文字捕捉 | 仅输入标题即可写入目标收件箱，原文件其他字节保持原样。 |
| 目标配置 | 无仓库、未配置收件箱、多仓库选择和目标删除均有明确反馈，草稿保留。 |
| 保存生命周期 | 空标题不能保存；重复点击仅产生一条；成功关闭并能在收件箱看到新记录。 |
| 草稿与重入 | 返回、重启和外部新请求不会丢弃原草稿；成功后再次打开不重现已保存内容。 |
| 平台入口 | 卡片两种操作、长按快捷方式、外部标题传入、分享标题传入均进入同一界面。 |
| 语音 | 验证授权、取消、服务不可用和文字回退；识别可用时验证真实转写与保存。 |
| 小艺与负一屏 | 验证包内注册与可触达路径；模拟器缺少宿主或账号能力时明确记为未验证。 |
| 离线与回归 | 离线本地保存成功；任务浏览、收件箱规划、设置和既有下拉同步仍可使用；应用内不恢复新增入口。 |

* 轻量面板与启动优化

文字与语音采用相同的底部面板，只显示标题输入与“保存”。去除关闭按钮、草稿选择、目标文件、目标切换和语音切换；点击面板外或系统返回时保留内容并关闭。语音入口自动录音，保存时统一等待最终识别结果，再提交到收件箱；成功后关闭窗口并恢复进入时的来源状态。

启动路径拆分为轻量草稿存储与延迟加载的 Core 保存会话；本地捕捉不读取安全存储凭据。首屏可立即输入，页面显示后后台准备 Core；保存按钮不以初始化完成作为启用条件，保存请求等待同一初始化 Promise。失败后保留内容并允许重试。

本轮签名构建与 19 项宿主检查通过，覆盖初始化等待、失败重试、凭据跳过、录音启动等待和最终语音结果等待。真机验证了 Core 不可用时首屏仍可输入、保存失败保留标题、点击面板外关闭、实际保存后恢复来源窗口，以及语音入口的相同极简面板；测试后按原字节恢复原配置与草稿。卡片声明已收紧为仅提供 ~1*2~ ，实际口述转写和小艺调用等待验项保持单独记录。
