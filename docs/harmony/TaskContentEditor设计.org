* 当前实现与待确认范围

已新增 ~TaskContentEditor~ 并接入任务与项目正文，统一管理四类子控件；当前消费 Core 现有平铺区块，按内容、类型和当前定位匹配控件身份，未变化区块重用原引用。前方插入、删除和重排不再仅按数组索引复用错误的子控件，编辑定位更新仍使用真实当前版本。

下面的嵌套逻辑树需要 Core 新增投影字段，具体接口尚待确认。现有内部滑动和操作保持原状，统一横向手势留待下一阶段。现有检查列表的平铺深度展示保持可用，不能据此宣称普通列表已具备独立的嵌套控件树。

* 范围

~TaskContentEditor~ 统一管理任务正文的逻辑结构、差异比较和子控件树。支持普通文本段落、表格、普通列表与检查列表，列表项可继续包含段落、表格和子列表。标题、规划、属性、日志与后代任务不作为本控件的正文元素。源码、引用等已有正文保持原安全阅读片段，作为不可再拆分的文本区块兼容展示，不在本次扩展其内部语法。

Org 元素边界和列表嵌套遵循 Emacs org-element，由 Core 基于现有 orgize 无损语法树提供。控件负责消费 content 对应的投影、建立逻辑树、比较前后差异和更新渲染节点，不在 ArkTS 通过正则解析 Org，也不从 HTML 反推元素。

* 待确认的 Core 投影扩展

现有 ~ContentBlock~ 只有平铺顶层区块；普通列表的嵌套被包含在 HTML 中，检查列表额外有带深度的平铺条目。为提供统一逻辑结构，建议在既有模型上增加以下只读投影：

#+begin_src rust
pub enum ContentBlockKind { Text, List, Table, Checklist, ListItem }
pub enum ContentCheckbox { Unchecked, Checked, Partial }
pub struct ContentListItem {
    pub marker: String,
    pub checkbox: Option<ContentCheckbox>,
}
// ContentBlock 保留已有字段，并增加：
// pub children: Vec<ContentBlock>,
// pub list_item: Option<ContentListItem>,
#+end_src

JSON 对应 ~children~ 、 ~listItem~ ，后者包含 ~marker~ 与 ~checkbox~ 。顶层继续使用原有四种类型；普通列表和检查列表的子节点为 ~ListItem~ ，列表项再包含段落、表格和子列表。段落与表格作为叶节点，不额外扩展行、单元格或行内元素类型。普通列表和 checkbox 混排时保留每个列表项实际 checkbox 状态。

新增字段随 ~TaskEditContent.blocks~ 和 ~DocumentSection.blocks~ 一并提供，复用现有快照透传，不增加 Workspace 查询入口或独立解析服务，不修改 Org 文件或持久化格式。历史缓存缺失新字段时按空子节点兼容。清单原有 ~items~ 和结构化修改保持可用。

编辑定位的 ~id~ 继续只在当前文件版本内有效。现有 ~CONTENT_BLOCK~ 仍对顶层区块执行原文替换和链接修改；嵌套阅读节点将编辑动作交给所属顶层区块，单项 checkbox 修改沿用现有结构化接口。不得为了重用控件实例，把旧位置 ID 静默绑定到新文件版本。

* 逻辑树与控件树

正文为有序根列表。每个节点具有稳定的界面身份、Core 类型、当前定位上下文、展示载荷及有序子节点。界面身份与 Core 字节位置分开维护；前方插入段落导致后续字节位置整体移动时，后续阅读控件仍可复用，同时更新各自编辑上下文。

#+begin_example
content
  paragraph
  list
    listItem
      paragraph
      checklist
        listItem [unchecked]
          paragraph
        listItem [checked]
          paragraph
    listItem
      paragraph
      table
  paragraph
#+end_example

~TaskContentEditor~ 按逻辑树创建相应文本、表格、列表容器和清单子控件；嵌套列表按父子关系递归渲染。列表标志和 checkbox 状态来自 Core 投影，缩进、交互与布局由展示层维护。只读模式使用同一树和布局，关闭写操作。

* 差异更新

同一层先匹配未变化节点，再比较发生变化的节点及子列表。相同区块重用原展示载荷与控件身份；新增、删除和移动只调整对应节点。重复段落按顺序和相邻未变化节点匹配，不把内容哈希当作唯一身份；结构不明确时关闭旧编辑会话并按现有版本冲突规则保留草稿。

比较分为展示载荷与编辑上下文。仅文件版本、源字节位置或同文件其他任务变化时，更新定位上下文，不重载正文 WebView，不更新未变化的段落、表格或列表展示。某个嵌套条目改变时，仅替换该条目的载荷和必要祖先的子列表关系，其他分支维持原引用。

状态底色由任务卡片外壳绘制，正文持续使用透明背景；切换进行中不重建正文，也不异步切换正文底色。真正的段落或表格 HTML 变化才更新相应阅读视图；链接编辑始终保留真实版本校验。

* 验证边界

需覆盖单段修改、表格修改、普通／检查列表嵌套、混合条目、重复段落、头部插入导致定位整体移动、删除与重排，以及状态切换和版本推进但正文不变。模拟器交替通过 API 修改和界面操作核对展示、局部更新、嵌套清单交互、草稿保留与重开结果。

本文的 Core 投影扩展尚未修改实现，待具体接口方案确认后同步模型、bridge、控件与接口文档。

* 当前阶段模拟器结果

2026-11-16 在独立模拟器仓库验证：

| 场景 | 实际结果 |

| 段落、表格与嵌套清单展示 | 当前 Core 平铺区块与原生清单深度正常显示；独立的嵌套逻辑控件树尚未实现。 |

临时验收任务通过同一 Workspace 的 API 创建、修改和删除，未直接改写仓库文件。新增差异比较验证覆盖未变化引用复用、单段修改、头部插入、定位偏移、删除、重排、重复内容与类型变化。
