* 范围与环境

使用独立 OrgAppDataQA 模拟器、HarmonyOS API 24 和隔离的本地仓库，覆盖应用级共享数据的十个页面。每个场景先停止应用进程、删除页面缓存目录并检查目录不存在，再把目标页面指定为首屏启动。全过程不通过切换页面来代替首次加载。

本次包含十组自然冷启动和十组受控读取等待。自然冷启动的首次布局采样均已完成加载；受控场景由模拟器测试包暂时持有真实仓库事务文件锁，使 Core 处于实际等待状态，再释放锁观察完成。正式页面和 Core 未加入验收延时。

二十组场景均通过。每组加载完成后，HTTP 返回的当前路径与指定首屏一致，读取提示消失，页面出现预期数据或空态；随后生成的唯一任务缓存为 ~app.json~ ，其中 22 个命名数据集的首次确认版本均为 1。

自然冷启动采样时未观察到中间读取提示；十组受控场景均实际捕获读取提示和完成后的布局、截图，未出现一直停留在读取状态的情况。受控场景包含主动持锁等待，不用于评价加载性能。

* 冷启动入口修复

验收发现，原 EntryAbility 在解析 Want 的目标路径前先异步初始化系统仓库；窗口生命周期可能先到达，从而先加载默认今天页。现已在任何异步等待之前解析启动路径，仓库初始化未完成时也直接加载指定页面；初始化结束不再额外加载默认页或重建目标页。宿主回归使用尚未完成的初始化 Promise 验证此边界。

测试启动的页面范围与普通启动隔离，契约见 [[file:../core/APP内嵌HTTP接口.org][APP 内嵌 HTTP 接口]]。项目详情、完整文件阅读及其他独立入口不属于本次共享页面矩阵。
