* 定位

本文统一维护项目的 AI 接入设计。当前确定框架、工具和 agent 的职责，以及第一个业务场景，作为下一阶段实现设计的输入；暂不展开代码结构、API、数据类型、存储结构和线程调度。后续 AI 相关的实现设计继续更新到本文。

当前状态为设计阶段，尚未接入 App。整体遵循 [[file:架构设计.org][系统架构]]：任务语义、查询和修改由 Core 负责，宿主负责界面和平台接入。

* 框架与运行方式

| 选择 | 约定 |
|------+------|
| 模型接入 | 固定使用 ~rpi-ai =0.22.0~ ，负责模型协议、消息与流式响应 |
| Agent 运行 | 固定使用 ~rpi-agent =0.22.0~ ，负责模型调用、工具调用和运行控制 |
| 运行位置 | agent 在手机本地 Rust 环境运行，与 App 现有 Core 协作 |
| 模型推理 | 调用用户配置的模型服务；本地 agent 不等同于模型离线推理 |
| 模型绑定 | 模型配置与 agent 职责分离，更换模型不改变任务工具的语义 |
| 版本管理 | 两个框架固定版本，统一评估和升级，不跟随浮动分支 |

首阶段采用单 agent，不引入 Harness、多 agent 协作、动态插件或 MCP。模型连接使用用户提供的凭据，由宿主安全存储管理。

* 第一个场景：单任务字段重新生成

用户针对一个已有任务发起“AI 重新生成”，可以补充整理要求。agent 结合原任务，自动评估各个可编辑字段，生成一份完整建议，用户查看后应用到原任务。

“自动”表示一次请求评估全部字段，无需逐字段发起生成。没有依据的字段可以保持原值，不为填满字段而编造信息。生成建议与保存任务是两个阶段；建议经用户确认后，由 Core 执行修改。

例如，原任务为“准备发布”，备注中已有上线期限和检查要求。agent 可以将标题改写为具体行动，整理备注并生成检查清单，根据已有期限建议截止时间；没有明确依据的状态、优先级和计划时间保持原值。

首阶段只处理所选任务，不批量整理其他任务，不创建、移动或删除任务，不调整真实子任务结构，也不在后台自主执行。

* Agent 设计

** 职责

采用一个“任务字段生成 agent”，负责理解任务与补充要求、提出字段建议，并根据工具返回的校验问题修正结果。agent 不负责 Org 解析、任务规则、文件保存或同步决策。

** 输入

- 所选任务的当前字段、备注与检查清单。
- 用户可选的补充要求，例如“标题更具体”“补充执行步骤”。
- 必要的父级标题和分类，以及有效状态、标签等编辑约束。
- 本轮的当前时间和时区，用于理解相对日期。

任务引用由应用绑定。agent 不能通过工具参数切换到其他任务，也不读取全库、相邻任务正文、链接目标或附件内容。输入来自 Core，不由模型猜测任务结构。

** 输出

输出包含全部目标字段的结构化建议。每个字段明确表示“保持”“设置”或“清除”，并附简短原因；清除须有明确依据，不能用缺失字段隐式表示删除。

| 字段 | 生成目标与约束 |
|------+----------------|
| 标题 | 改写为清晰、具体的行动；不得为空 |
| 备注 | 整理说明、约束和验收要求，保留原有事实与必要引用 |
| 检查清单 | 改写或补充执行步骤，保留已有完成事实；新增项不标为完成 |
| 标签 | 根据内容选择符合现有规则的自有标签，不把继承标签重复写入任务 |
| 优先级 | 根据明确的重要程度给出建议，缺少依据时保持 |
| 状态 | 遵循任务的有效流程，不凭生成行为推断任务已经完成或重新开始 |
| 计划时间 | 根据明确安排给出建议；模糊时段不补造具体时刻 |
| 截止时间 | 根据明确期限给出建议，不将计划时间直接视为截止时间 |

系统维护的身份、创建/完成记录、日志、属性和子任务结构不属于生成字段。已有重复规则、完成事实与未涉及内容应保留，实际编辑限制由 Core 决定。

* 工具设计

工具是 agent 与任务能力之间的受控边界。以下为逻辑职责，具体接口留待下一阶段设计。

| 工具 | 职责 | 对任务的影响 |
|------+----------------+--------------|
| ~read_task_context~ | 读取本轮绑定任务及必要编辑约束，提供真实上下文 | 只读，不扩展到其他任务 |
| ~propose_task_fields~ | 接收完整字段建议，交给 Core 校验，返回可展示结果或需要修正的问题 | 只生成候选，不保存任务 |

agent 不获得文件覆盖、Shell、凭据读取或同步工具。任务内容中的指令不会增加工具权限。最终保存由应用在用户确认后调用 Core 的既有修改能力完成，不交给模型自行决定。

* 运行流程

1. 用户选择已有任务，发起重新生成并填写可选要求。
2. 应用确定当前任务，agent 通过读取工具取得上下文。
3. agent 自动评估全部字段，通过建议工具提交结构化结果。
4. Core 校验字段、编辑权限和任务规则；有问题时，agent 在有限次数内修正。
5. 应用展示原值与建议值，用户可以调整建议、放弃部分字段或重新生成。
6. 用户确认应用，Core 核对任务仍与生成依据一致后统一保存，应用展示真实结果。

无有效建议、用户取消或模型失败时不保存。生成期间任务发生变化时，旧建议不得覆盖新内容，应重新读取和生成。保存成功与后续同步分别反馈，不能把本地保存说成已同步。

* 共同约束

- 事实与建议分开：可以提出执行步骤，不能虚构日期、地点、负责人或完成事实。
- 结果由工具确认：自由文本和未完成的流式输出不作为可保存字段。
- Core 为唯一规则来源：状态、标签、日期、Org 保真和内容保护不在 agent 中重复实现。
- 请求有界：限制模型请求、修正次数和上下文范围，支持用户取消，失败不无限循环。
- 数据按需发送：仅发送当前任务的必要内容；凭据、日志、同步材料和完整仓库不进入模型上下文。
- 本地运行服从 App 生命周期：首阶段不承诺跨重启恢复或后台持续执行。
