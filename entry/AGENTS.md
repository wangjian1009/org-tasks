# entry 模块规范

本文件适用于 `entry/` 及其子目录。项目级规范、Rust 架构约束、文档规范与提交规范见父目录 `AGENTS.md`。

## 核心约束

- ArkTS 只负责界面与平台接入，不解析 Org、不实现同步规则；默认不再次过滤任务，今天、等待、随时、某天和备忘的共享标签筛选条仅筛选本页已加载快照，作为展示层例外。
- Core 请求必须通过 bridge 在工作线程执行，不阻塞 ArkUI；跨语言接口保持 Rust 对象边界，参数使用结构化对象。
- 修改 bridge 时同时更新 Rust、`src/main/cpp/napi_init.cpp`、`src/main/cpp/types/liborg_tasks_harmony/index.d.ts`、ArkTS wrapper、调用方与接口设计。
- 仓库与凭据身份保持稳定；真实密码只通过 `CredentialService` 存入 Asset Store。

目录职责、线程、对象映射和平台约束见 [架构设计](../docs/架构设计.org)；修改 bridge 或配置前分别遵循 [Rust bridge 设计](<../docs/harmony/Rust bridge设计.org>) 和 [配置项设计](../docs/harmony/配置项设计.org)。修改配置项、保存位置或凭据处理时，同步更新配置项设计。

## 布局与设计同步

修改页面布局、侧边栏入口位置或交互范围时，必须同步更新 `docs/harmony/设计文件索引.org` 中对应功能的当前 Harmony 画板（源文件位于 `design/当前实现/`，共享规范位于 `design/规范/`）、`docs/harmony/UI导航设计.org` 和手机应用功能设计；不能仅修改实现或仅添加说明。

## 构建与设备

使用根目录 `make help` 查阅命令；常用 `make build`、`make deploy`、`make devices` 和 `make log`。本机环境见根目录 `AGENTS.local.md`。

## 数据驱动界面验收

- 涉及数据集、订阅、缓存或编辑控件接入时，必须在专用模拟器中，通过 APP 内嵌 HTTP API 配合界面操作验证功能完整性。
- 服务仅在 APP 进程运行期间提供，只通过 APP 的测试启动参数临时开启，正常点击图标启动不提供服务，不保存开关；REST 只提供查询和批量修改能力，不增加服务控制、仓库管理等接口。接口契约统一见 [APP 内嵌 HTTP 接口](../docs/core/APP内嵌HTTP接口.org)。
- API 必须使用界面当前的同一个 Workspace，复用 Core 查询和修改入口。通过 API 创建、修改、删除记录后，观察当前页面的真实通知与刷新链路，不能用直接改磁盘文件或手动重开页面代替外部更新验收。
- 外部更新由数据管理对象启动刷新，页面不能直接回查底层；界面自身的字段修改依靠带 operationId 的事件归并，不以事件接收再触发修改。
- 交替使用界面编辑与 API 查询，核对仅修改了用户提交的字段，并验证查询成员移入／移出、触发器等关联更新、连续排队提交与失败回滚，不重复提交或产生操作循环。
- 验证缓存恢复版本 0、首次查询版本 1、后续阶段递增，以及全部修改提交且事件处理完成后才保存缓存。关闭重开后通过 API 与界面共同核对内容。
- 验收使用独立测试仓库，记录实际结果；停止测试服务或退出 APP 后确认监听端口释放。接口、测试程序的操作参数通过对应接口文档或程序帮助发现，不在此复制实现细节。
